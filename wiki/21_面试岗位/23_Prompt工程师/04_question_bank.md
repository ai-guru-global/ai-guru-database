# Prompt Engineer 题库

> 中文简称：Prompt Engineer 题库

> **难度标注**: ⭐ Basic | ⭐⭐ Intermediate | ⭐⭐⭐ Advanced
> **频率标注**: 🔴 高频 | 🟡 中频 | 🟢 低频

> 提示工程（Prompt Engineering）是大模型时代最关键的应用层技能之一。本题库围绕"如何用语言高效地驱动 LLM 产出可靠输出"展开，既考查对 in-context learning、CoT、ReAct 等机制的理解，也考查在 RAG、Agent、结构化输出等真实系统中的工程落地能力。相关背景见 [[05_大模型/07_提示工程/index|提示工程]]。

## 高频问题与应答策略

| 问题类型 | 典型问题 | 应答策略 |
|----------|----------|----------|
| 概念题 | 解释 CoT / ICL 原理 | 定义 + 机制直觉 + 适用场景 + 局限 |
| 对比题 | Prompt vs Fine-tuning；指令驱动 vs 示例驱动 | 维度对比 + 成本/效果/适用场景 + 选型建议 |
| 设计题 | 设计一个 RAG / Agent 的 Prompt 链 | 需求拆解 + 链路设计 + 权衡 + 失败兜底 |
| 经验题 | 一个 Prompt 效果不达预期的排查 | 现象 + 假设 + 验证 + 量化结果 + 复盘 |
| 开放题 | 看待自动 Prompt 优化趋势 | 现状 + 优势/风险 + 落地判断 |

## 面试评分维度

| 维度 | 优秀表现 | 一般表现 | 不佳表现 |
|------|----------|----------|----------|
| 机制理解 | 理解注意力/采样/ICL 深层原理 | 知道用法但不知为何 | 凭直觉拼凑 Prompt |
| 工程化 | 版本管理/评测/A/B 系统化 | 偶尔手动评测 | 无评测全靠目测 |
| 系统思维 | 兼顾链路/失败/成本/安全 | 单点可用 | 忽略边界与约束 |
| 表达能力 | 逻辑清晰、先框架后细节 | 能讲但发散 | 混乱、答非所问 |
| 迭代能力 | 有方法论地迭代优化 | 能改但缺度量 | 改了不知道好坏 |

## 检查清单

- [ ] 基础概念（ICL/CoT/采样参数）已系统掌握
- [ ] 主流提示技术（CoT/ToT/ReAct/Self-Consistency）能讲清原理与适用场景
- [ ] 至少准备 1 个 RAG 与 1 个 Agent 的 Prompt 链设计
- [ ] 掌握 Prompt 评估方法论（评测集/A/B/敏感度分析）
- [ ] 了解 1-2 个自动 Prompt 优化方法（APE/OPRO/DSPy）
- [ ] 准备 2-3 个场景实战案例（代码/抽取/对话）
- [ ] 理解 prompt injection / 越狱防护的基本手段
- [ ] 准备一份"Prompt 即代码"的工程化实践思路
