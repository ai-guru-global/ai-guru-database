## 2. Claude Code

### 2.1 核心特点

```
Claude Code 特点
═══════════════════════════════════════════════════════════════════

✅ 优势:
─────────────────────────────────────────────────────────────────
• Anthropic 官方支持，Claude 模型深度集成
• 完整的文件系统访问和命令执行
• 内置安全审计和敏感信息检测
• 优秀的代码理解能力
• 清晰的执行计划和确认机制

❌ 局限:
─────────────────────────────────────────────────────────────────
• 需要手动触发操作
• 不具备完全的自主执行能力
• 上下文窗口受限于 Token 限制
```

### 2.2 适用场景

```bash
# Claude Code 最佳场景
claude-code: "fix the authentication bug in the login flow"
claude-code: "add unit tests for the user service"
claude-code: "refactor this module to use dependency injection"
```

| 功能 | 描述 |
|------|------|

| **Tab** | 上下文感知的智能补全 |

```
SWE-agent: 专为 SWE-bench 设计
═══════════════════════════════════════════════════════════════════

Princeton 研究团队开源的 SWE-bench 专用 Agent:

设计目标:
─────────────────────────────────────────────────────────────────
• 在 SWE-bench 基准上达到最优
• 处理真实 GitHub Issue
• 端到端问题解决

架构特点:
─────────────────────────────────────────────────────────────────
• 专门的代码库理解模块
• 精确的工具调用
• 测试驱动的验证

性能 (SWE-bench Lite):
─────────────────────────────────────────────────────────────────
• 成功率: ~30-40%
• 平均步数: 10-20
• 运行时间: 2-5 分钟/任务
```

### 6.2 技术细节

```python
# SWE-agent 核心组件

class SWEAgent:
    """SWE-bench 专用 Agent"""
    
    def __init__(self, model="claude-3-5-sonnet"):
        self.model = model
        self.codebase = CodebaseIndex()
        self.tester = TestRunner()
        self.file_editor = FileEditor()
    
    def solve(self, issue: Issue) -> Solution:
        """解决 GitHub Issue"""
        
        # 1. 理解 Issue
        understanding = self.understand(issue)
        
        # 2. 定位相关代码
        relevant_files = self.codebase.find_relevant(understanding)
        
        # 3. 分析和修改
        changes = self.analyze_and_fix(relevant_files, understanding)
        
        # 4. 测试验证
        if self.tester.run(changes):
            return Solution(changes)
        
        # 5. 迭代修复
        for _ in range(self.max_retries):
            error = self.tester.get_error()
            changes = self.fix_error(error)
            if self.tester.run(changes):
                return Solution(changes)
        
        return Solution(failed=True)
```

## 7. GitHub Copilot

### 7.1 核心特点

```
GitHub Copilot: 代码补全 + 聊天
═══════════════════════════════════════════════════════════════════

定位: 编程助手，不是 Agent
─────────────────────────────────────────────────────────────────

功能层级:
─────────────────────────────────────────────────────────────────
┌─────────────────────────────────────────────────────────────┐
│                     Copilot Chat                           │
│  (自然语言对话、代码解释、调试辅助)                          │
├─────────────────────────────────────────────────────────────┤
│                     Copilot Edits                           │
│  (多文件编辑、项目级修改)                                   │
├─────────────────────────────────────────────────────────────┤
│                     Copilot Completions                     │
│  (行级/函数级补全)                                          │
└─────────────────────────────────────────────────────────────┘
```

| 功能 | 描述 | Agent 能力 |
|------|------|------------|
| **Completions** | 代码补全 | 无 |
| **Edits** | 多文件修改 | 有限 |
| **Chat** | 对话辅助 | 有限 |
| **Agent** | 自主操作 | 有 |

### 7.2 适用场景

```bash
# GitHub Copilot 最佳场景
✓ 日常代码补全
✓ 快速生成样板代码
✓ 代码片段解释
✓ 简单的代码转换

✗ 不适合:
✗ 复杂的多步骤任务
✗ 需要深度代码理解的任务
✗ 自主执行复杂操作
```
