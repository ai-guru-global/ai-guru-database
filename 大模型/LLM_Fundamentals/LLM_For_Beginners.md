# 大语言模型入门：从文字接龙到推理部署

> **一句话理解**: 大语言模型（LLM）干的事情看似简单——根据上文预测下一个词（Next Token Prediction）；但当模型规模、数据规模、训练算力同时上去，能力就会发生跃迁；它的诞生走完"预训练（上大学）→ 微调（岗前培训）→ RLHF（实习）"三步，而让这个巨兽"跑起来"的推理工程，是一场关于显存与带宽的精密接力赛。

> 本文聚焦零基础视角的 LLM 全景。技术深度请参见 [[LLM_Fundamentals]]、[[Transformer_Architecture]]、[[LLM_Inference_Deep_Dive]]。

---

## 1. 语言模型的演变：从模板机到真人

### 1.1 三个时代

为什么几十年前的聊天机器人像"模板机"，现在更像真人？因为方法变了——从定规则，到统计学，再到"大力出奇迹"。

| 时代 | 代表 | 工作方式 | 局限 |
| :--- | :--- | :--- | :--- |
| **远古时代（1964-）** | Eliza（MIT，扮演心理医生） | 套公式（If/Else）：用户说"I am X"就回复"Why are you X?" | 稍微复杂就露馅 |
| **统计时代（2011）** | Siri | 不懂你在说什么，但算过"明天天气"有 90% 概率是想看天气预报，本质是"查表" | 经常听不懂人话，只在预设框架回答 |
| **大模型时代（2018-）** | GPT 系列 | 不依赖人工规则，在大规模语料上预训练；给定上文预测下一个 token | 能力随规模/数据/算力跃迁 |

> 从规则驱动（Rule-based）到数据驱动（Data-driven），这是 AI 变聪明的根本原因。详见 [[NLP_Fundamentals]]。

### 1.2 下一代的想象

10 年后的 AI 看来，现在的模型可能也只是"过渡阶段的助手"。下一代 AI 会在推理、工具使用、长程规划、世界模型等方向超越现在。详见 [[AI_Reasoning_Models_Guide]]、[[AI_New_Architectures]]。

## 2. 大模型原理：你眼中的"思考"，AI 眼里只是"概率计算"

### 2.1 Next Token Prediction：就这？

LLM 到底在干什么？一句话说清：**预测下一个词（Next Token Prediction）**。

- 你说："白日依山"
- 模型算了一下，"尽"字出现概率是 99%
- 于是它说："尽"

你可能会问"就这？这也能叫智能？"——是的，就这。但当阅读量达到千亿级别时，奇迹发生了：它不仅能接"白日依山尽"，还能接代码、接论文、接菜谱。**当"接龙"能力达到极致，外在表现出来的就是"智能"。**

> 这呼应了 [[Deep_Learning_For_Beginners]] 的核心：深度学习是"概率的黑魔法"，幻觉（Hallucination）正是源于此——只管概率通顺，不管事实真假。

### 2.2 Token：AI 的"积木块"

AI 不认识"字"，它只认识 **Token**。Token 由 **分词器（Tokenizer）** 切出来，不是固定的"一个字/一个词"：

| 语言 | Token 粒度 | 例子 |
| :--- | :--- | :--- |
| **英文** | 一个词、词的一部分（如 `ing`）、标点空格 | "Hello, world!" ≈ 4 个 token |
| **中文** | 经常接近 1 个汉字，也可能切词组/数字/英文混排 | 视分词器而定 |

> 近年来前沿模型的上下文窗口已达百万 token 级别（如 Gemini 3.1 Pro 为 1M token、Llama 4 Scout 达 10M token），意味着它一次能"记住"大量积木块的顺序。详见 [[Long_Context_Models_2026]]。

### 2.3 温度：AI 的性格开关

调用 AI 时有一个重要参数叫 **温度（Temperature）**：

| 温度 | 性格 | 行为 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **温度 = 0** | 理工男 | 每次都选概率最高的词，绝对严谨但极度无聊 | 写代码、做数学题 |
| **温度 = 1（或更高）** | 艺术家 | 尝试选概率没那么高但新奇的词；继续升高（部分可达 2）会"语无伦次" | 写诗、发散脑洞 |

> 通过调节温度，我们赋予了那个冰冷的计算器以"性格"。

## 3. Transformer 的注意力机制：探照灯

> 本节是直觉版。技术深度见 [[Transformer_Architecture]]、[[Transformer_Deep_Dive]]。

### 3.1 要解决的核心问题：一词多义

在自然语言里，同一个词在不同上下文中可能有完全不同的含义："我吃苹果"中苹果=水果；"苹果发布新品"中苹果=公司。传统 RNN 逐字处理，当关键信息在 100 个字之后，之前的信息会被"遗忘"。Transformer 不再逐个处理，而是 **"一下子看遍全部，然后根据上下文重新理解每个字"**。

### 3.2 注意力的三重奏：Query、Key、Value

用图书馆找书类比：

| 角色 | 含义 | 图书馆类比 |
| :--- | :--- | :--- |
| **Query（查询）** | 当前词在"找什么" | 读者说"我要找关于猫的书" |
| **Key（索引）** | 每个词的"身份标签" | 书单记忆：第 1 本讲狗、第 2 本讲猫咪故事、第 3 本讲猫科进化 |
| **Value（内容）** | 每个词的实际内容 | 每本书的具体内容 |

Query 和 Key 算匹配度（点积），softmax 转成权重，再用权重组合 Value。数学表达：

`Attention(Q, K, V) = softmax(QKᵀ / √dₖ) · V`

- `QKᵀ`：Query 和 Key 的匹配度
- `softmax`：匹配分数转成权重（加起来=1）
- `√dₖ`：平衡因子，防止权重太极端
- `× V`：用权重组合实际内容

### 3.3 自注意力 vs 交叉注意力 vs 多头

| 机制 | 做法 | 用在哪 |
| :--- | :--- | :--- |
| **自注意力（Self-Attention）** | 一句话内部各词相互看 | GPT 理解上下文；图像/文字内部各自理解 |
| **交叉注意力（Cross-Attention）** | 一句话的部分去看另一句话 | 机器翻译（中文"我"对齐英文"I"）；多模态（文字去"看"图像） |
| **多头注意力（Multi-Head）** | 多个不同视角同时关注 | 一个头看语法关系、一个看语义、一个看逻辑——现代 LLM 有 64/96/128 个头 |

### 3.4 位置编码与二次复杂度

Transformer 一次性并行处理全部词，本身没有"顺序"概念，所以需要 **位置编码（Positional Encoding）** 给每个位置一个独特"指纹"（原始用 sin/cos 三角函数；现代 LLM 多用 **旋转位置编码 RoPE** 等相对位置方案，以支持比训练时更长的序列）。

> **为什么不能处理"无限"上下文？** 注意力矩阵大小是 O(n²)——token 数量翻倍，计算量翻四倍。这是长上下文成本爆炸的根源，也是 Mamba/Hyena 等新架构挑战 Transformer 的切入点。详见 [[AI_New_Architectures]]、[[Long_Context_Models_2026]]。

## 4. 预训练与微调：通才与专才

> 通用大模型是"通才"，垂直行业模型是"专才"。预训练练内功，微调练招式。

### 4.1 三阶段流水线

| 阶段 | 类比 | 做什么 | 成本 | 目标与结果 |
| :--- | :--- | :--- | :--- | :--- |
| **预训练（Pre-training）** | 上大学 | 把全网数据喂给它，不分学科什么都学（自监督学习） | 极其昂贵（超大规模 GPU 集群，按月计算） | 掌握语言规律和世界知识，变成博学但不懂规矩的"野人" |
| **监督微调（SFT）** | 岗前培训 | 雇人类老师写标准"问答对"，教它如何对话、有礼貌 | 便宜得多 | 把"野人"变成客服/医生/程序员，学会遵循指令 |
| **RLHF** | 实习 | 人类标注员对候选回答做偏好排序，用强化学习让模型偏好人类喜欢的回答 | 中等 | 学会什么该说什么不该说，输出风格贴近人类沟通 |

详见 [[LLM_Training_Deep_Dive]]、[[Fine_tuning_Techniques]]。

### 4.2 不只一条路：RAG、工具调用与工作流

在真实项目里，很多团队不会一上来就微调，而是先做更便宜、更快落地的方式：

| 方式 | 做法 | 适用 |
| :--- | :--- | :--- |
| **RAG（检索增强生成）** | 先查企业私有资料，再让模型回答 | 企业知识库、客服 |
| **工具调用（Tool Use）** | 让模型调用数据库、搜索、日历、ERP 等外部系统 | 需要实时/精确数据的场景 |
| **工作流编排（Workflow）** | 把"检索→生成→校验→审批"串成可追踪流程 | 合规要求高的业务 |

> 多数情况下，RAG 和工具调用能先解决 80% 的需求，比"从零训练/深度微调"更快、更便宜。详见 [[Context_Engineering_Guide]]。

### 4.3 选型直觉：培养律师的两种方式

很多公司想要"行业大模型"（如法律大模型）。不需要从头做预训练（太贵），而是在通用模型基础上微调。这就好比：你是想自己从幼儿园开始培养一个律师（预训练），还是直接招一个法学毕业生、培训两周公司规定（微调）？多数选后者。

## 5. 主流大模型全景（2026 快照）

> 这个领域变化太快，不要死记硬背排名，要看懂各家的"独门绝技"。以下为 2026-06-09 的学习快照，生产选型必须回到官方模型页和价格页重新核验。

### 5.1 三大闭源巨头

| 厂商 | 特点 | 取舍 |
| :--- | :--- | :--- |
| **OpenAI（GPT 系列）** | 综合能力和产品生态通常很强，工具链较完整 | 闭源能力强，但需关注数据治理和"供应商绑定"风险 |
| **Anthropic（Claude 系列）** | 长文本理解、写作、代码任务常有突出表现，风格相对稳健 | 产品功能节奏和生态覆盖各有长短 |
| **Google（Gemini 系列）** | 多模态能力强，与 Google Workspace、搜索整合紧密 | 优势常在 Google 生态内，跨生态体验看具体产品 |

> 它们在不同评测（代码、数学、写作、工具调用）名次会持续变化，不存在"永久第一"。

### 5.2 开源之光：LLaMA

如果说闭源是 iOS，Meta 的 **LLaMA** 更像 Android 阵营的关键基座。2025 年 4 月发布的 **Llama 4** 系列首次采用 MoE（混合专家）架构：

- **Scout**：109B 总参数，16 专家 / 17B 活跃参数，支持 10M 上下文
- **Maverick**：400B 总参数，128 专家 / 17B 活跃参数，支持 1M 上下文

> **MoE 的关键特性**：每个 token 在推理时只激活部分专家（活跃参数），而非全部参数，从而在保持强能力的同时降低推理成本。详见 [[AI_New_Architectures]] 中关于 MoE/MLA 的创新。开源生态还包括 Qwen、Mistral、Gemma 等多条路线。

### 5.3 中国的"百模大战"

中国 AI 在应用落地、中文能力、成本效率上竞争激烈。详见 [[大模型/Chinese_LLM_Ecosystem/README|中国大模型生态]]、[[大模型/Global_LLM_Ecosystem/README|国际大模型生态]]。

| 厂商 | 代表 | 擅长 |
| :--- | :--- | :--- |
| **阿里** | 通义千问 Qwen | 开源生态活跃，工程化强；中文写作与 Qwen-VL 图像识别顶尖 |
| **百度** | 文心 | 搜索与知识图谱结合深 |
| **DeepSeek** | V3（MoE）/ R1（推理，MIT 开源） | 高性价比与推理/代码能力出圈 |
| **Kimi（月之暗面）** | Kimi | 长文档阅读和信息整合突出 |

## 6. 部署与推理：让巨兽跑起来

> 在网页上提问几秒后 AI 流利回答，背后是调用成千上万张显卡的复杂系统工程。详见 [[LLM_Inference_Deep_Dive]]。

### 6.1 算力 vs 显存：谁更重要？

很多人以为推理最耗费算力（GPU 处理速度），但实际"卡脖子"的往往是 **显存容量** 和 **显存带宽**。大模型回答分两个截然不同的阶段：

| 阶段 | 行为 | 瓶颈 | 体验指标 |
| :--- | :--- | :--- | :--- |
| **阅读阶段（Prefill 预填充）** | 一次性"吃下"历史上下文和提示词，GPU 开足马力并发矩阵运算 | 极度消耗算力（Compute-bound） | **首字延迟（TTFT）**——能否秒回 |
| **回答阶段（Decode 解码）** | 像打字机一个字一个字蹦答案（必须等上一个字才能猜下一个） | 受限于内存带宽（Memory-bound），GPU 大部分时间在等数据搬运 | **词间延迟（ITL）**——流式是否流畅 |

> 类比：一个跑得飞快的厨师，却被狭窄的厨房运菜通道挡住了。

### 6.2 显存占用的可计算规则

**1. 纯权重显存** = 参数量 × 每参数字节数。以 Llama 3 70B（700 亿参数）为例，默认半精度（FP16/BF16，2 字节）：
`70 × 10⁹ × 2 bytes ≈ 140GB`——**单张 80GB 顶级显卡根本装不下哪怕仅仅是模型本身**。

为此工程师引入 **量化技术（Quantization）**：把权重压缩成 INT8（1 字节）或 INT4（0.5 字节）。压到 INT4 后纯权重只需约 40GB，80GB 显卡才有剩余空间推理。

**2. KV Cache 显存**：模型把读过写过的字的中间结果存进"记事本"（KV Cache），上下文越长、并发用户越多，显存消耗急剧增加。没有 PagedAttention 等内存分页技术（如 **vLLM** 引擎），显存会碎片化导致崩溃（OOM）。

### 6.3 分布式推理：把显卡组装成超级大脑

单张/单机显卡装不下，就用网络把十几台甚至几百台服务器的显卡连起来（**分布式部署**）：

- **切分模型**：半边神经网络交显卡 A，另半边交显卡 B，通过高速内部网络（NVLink 或专用高速以太网）微秒级交换数据。
- **解耦工厂**：前沿 AI 公司甚至把数据中心切两波——一波纯粹负责"阅读长文"（计算集群），另一波纯粹负责"逐字打字"（显存带宽集群）。像餐厅前台极速点单备菜，后厨快速出餐。

> 隐藏在幕后的"推理技术"决定了 AI 公司的成本底线与回答速度。当你惊叹大模型一秒写出几十个词，背后是成百上千张昂贵显卡在高速光缆连接下进行精妙绝伦的硬件接力赛。

## 6.5 关键术语速查

| 术语 | 含义 |
| :--- | :--- |
| **Token** | AI 处理的最小单位（子词片段），不是固定一个字/词 |
| **上下文窗口（Context Window）** | 模型一次能"看到"的 token 上限，决定记忆长度 |
| **参数量（Parameters）** | 模型内部可学习权重数量，如 70B = 700 亿；越多通常越强但越贵 |
| **MoE（混合专家）** | 每个 token 只激活部分专家，保持强能力同时降低推理成本 |
| **量化（Quantization）** | 把权重从 FP16 压成 INT8/INT4，省显存换轻微精度损失 |
| **KV Cache** | 推理时缓存已读 token 的中间结果，上下文越长显存占用越大 |
| **TTFT / ITL** | 首字延迟（能否秒回）/ 词间延迟（流式是否流畅） |
| **幻觉（Hallucination）** | AI 编造看似合理但虚假的内容，源于"只管概率通顺不管真假" |

## 7. 给初学者的行动建议

1. **抓住"预测下一个词"这一本质**：理解了它，就理解了 LLM 的强大（涌现）与缺陷（幻觉）的同源性。
2. **三步训练流水线要烂熟于心**：预训练→微调→RLHF，对应"通识教育→岗前培训→实习"。
3. **落地优先 RAG/工具调用**：别一上来就微调，先用 RAG 和工具调用解决 80% 需求。
4. **推理成本是产品生死线**：显存（尤其 KV Cache）往往比算力更卡脖子；如果推理成本降到现在的 1/100，会催生大量新应用。
5. **选型看独门绝技而非排名**：闭源看综合能力与生态，开源看 MoE 活跃参数与上下文长度，国产看中文/性价比/合规。
