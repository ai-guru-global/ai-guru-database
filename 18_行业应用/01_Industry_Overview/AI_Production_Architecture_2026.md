# AI 生产架构 2026

> 中文简称：AI 生产架构 2026

2026 年，AI 系统已经从实验室走向核心业务链路。无论是金融风控的毫秒级决策、医疗影像的辅助诊断，还是自动驾驶的感知规划、零售电商的个性化推荐，生产环境的 AI 架构都需要同时回答五个问题：数据如何高质量流入、模型如何稳定服务、系统如何横向扩展、风险如何被持续治理、成本如何被精确归因。本文从跨行业视角出发，给出一套通用的五层生产架构框架，并针对金融、医疗、自动驾驶、零售、制造五个典型行业提供参考模板，最后围绕模型治理、安全合规、FinOps 与落地 checklist 给出可直接复用的工程实践。

## 1. 通用 AI 应用架构分层

生产级 AI 应用通常可抽象为五层：数据层、模型层、服务层、网关层、应用层。层与层之间通过定义良好的接口解耦，使得业务团队能够独立迭代应用逻辑，而平台团队能够独立优化模型性能与基础设施成本。

### 1.1 数据层

数据层负责原始数据的采集、清洗、标注、特征工程、向量化与血缘追踪。在生产环境中，数据层必须同时支持批处理与流处理两种模式，并保证训练数据与推理数据在分布上的一致性。

- **数据湖与数仓**：使用 Iceberg、Delta Lake 或 Hudi 管理结构化与非结构化数据，实现时间旅行、分区演进与 ACID 事务，满足模型训练、审计与回滚需求。
- **特征平台**：通过 Feast、Tecton、SageMaker Feature Store 或阿里云 PAI-FeatureStore 统一管理在线/离线特征，避免训练-服务偏差（Training-Serving Skew）。
- **向量数据库**：RAG 与语义检索依赖 Milvus、Weaviate、Pinecone、Qdrant 或 pgvector 存储 Embedding。选型时需权衡召回延迟、容量、多租户隔离与混合检索能力。
- **数据血缘与质量**：使用 OpenLineage、Marquez、Great Expectations 或 dbt tests 建立数据契约，对缺失值、分布偏移、schema 变更进行门禁。
- **隐私与合规**：在数据入湖前完成 PII/PHI 识别与脱敏；对敏感数据实施差分隐私、联邦学习或基于角色的访问控制（RBAC/ABAC）。

### 1.2 模型层

模型层是 AI 能力的核心资产，包括模型训练、版本管理、压缩优化与实验可复现性。对于 LLM/Agent 场景，模型层还需要管理基础模型、适配器（Adapter/LoRA）、Prompt 模板与模型卡。

- **模型仓库与版本化**：使用 MLflow、Weights & Biases、DVC 或 Neptune 保存模型权重、超参数、训练环境与评估指标。每次上线必须附带模型卡（Model Card），说明适用场景、性能基线、已知偏见与限制。
- **训练平台**：SageMaker Training、Google Vertex AI、Azure Machine Learning、Databricks Mosaic AI、阿里云 PAI、火山引擎方舟等提供弹性 GPU/TPU 训练与实验追踪。
- **推理优化**：针对大模型部署，采用 vLLM、TensorRT-LLM、TGI、SGLang 或 llama.cpp 进行 KV Cache 管理、Prefix Caching、Continuous Batching、量化（INT8/INT4/AWQ/GPTQ）与投机解码（Speculative Decoding）。
- **模型压缩与蒸馏**：在 CV 与 NLP 场景中广泛使用知识蒸馏、剪枝、量化与神经架构搜索（NAS），以在边缘设备或低成本实例上满足延迟与功耗约束。
- **可信执行与保护**：使用 TEE（如 Intel TDX、AMD SEV-SNP、NVIDIA Confidential Computing）或模型加密/水印技术保护高价值模型资产。

### 1.3 服务层

服务层将模型能力封装为可被业务系统调用的服务单元，包括同步推理、异步批处理、Agent/RAG 编排、缓存与事件驱动工作流。

- **模型服务框架**：KServe、Seldon Core、NVIDIA Triton Inference Server、BentoML、Ray Serve 提供自动扩缩容、A/B 测试、金丝雀发布与多模型并发。
- **Agent 与 RAG 编排**：LangGraph、AutoGen、CrewAI、Haystack 或自研编排器负责工具调用、记忆管理、状态机与多 Agent 协作。生产环境应优先采用无状态设计，将会话状态外置到 Redis、PostgreSQL 或 Temporal。
- **异步任务队列**：对长流程生成、批量评估或重试任务使用 Celery、RabbitMQ、Kafka、Temporal 或 Argo Workflows，避免阻塞主服务。
- **缓存与加速**：Redis/Memcached 缓存高频查询结果、Embedding 与 Prompt 模板；使用 CDN 缓存生成式内容的静态部分。
- **弹性设计**：引入熔断、限流、重试、降级与兜底策略。对关键链路提供多模型 Fallback，例如主模型不可用时切换至本地小模型或规则引擎。

### 1.4 网关层

网关层是生产 AI 架构的“流量入口与治理中枢”，统一处理鉴权、路由、配额、审计、成本归因与安全防护。

- **LLM Gateway**：LiteLLM、Portkey、Cloudflare AI Gateway、Kong AI Gateway、Apigee 或自研网关提供跨模型商的路由、Fallback、重试与负载均衡。
- **访问控制与密钥管理**：集成 OAuth 2.0 / OIDC、RBAC、API Key 轮换与 Vault（HashiCorp Vault、AWS Secrets Manager）管理模型提供商密钥。
- **配额与限流**：按项目、用户、模型设置 RPM/TPM/成本预算，防止单租户耗尽资源。超出阈值时触发降级或排队。
- **审计与合规日志**：记录请求上下文、输入输出摘要、token 用量、模型版本与决策链，满足可追溯、可解释与合规留痕要求。
- **护栏集成**：与 Llama Guard、Nemo Guardrails、Guardrails AI、AWS Bedrock Guardrails 或自研规则引擎联动，实时检测 Prompt Injection、Jailbreak、PII 泄露与毒性输出。

### 1.5 应用层

应用层直接面向最终用户或业务流程，负责将 AI 输出转化为业务价值。设计时需明确人机协作边界、反馈闭环与产品指标。

- **交互模式**：Copilot（人机协同）、Autonomous Agent（自主执行）、Embedded AI（嵌入现有工作流）、Recommendation（推荐/排序）是四种主流模式。
- **反馈闭环**：收集显式反馈（点赞/点踩、修改痕迹）与隐式反馈（点击率、转化率、停留时长），回流到数据层与模型层进行迭代。
- **A/B 测试与实验**：通过特征开关（LaunchDarkly、Unleash）或自研实验平台比较模型版本、Prompt 模板与业务规则的效果。
- **可观测性**：建立业务指标（GMV、风险拦截率、诊断准确率）与技术指标（P99 延迟、错误率、成本/token）的统一 Dashboard。

## 2. 关键生产决策与工程实践

在落地五层架构时，团队需要在多个维度做出关键决策。这些决策往往没有唯一正确答案，而取决于行业监管、延迟要求、数据敏感性与预算约束。

- **延迟 vs. 准确率 vs. 成本**：金融风控要求 <50ms 且可解释；医疗影像允许秒级推理但需要高置信度；自动驾驶要求 <10ms 的感知延迟。通过模型蒸馏、量化和边缘部署进行权衡。
- **批处理 vs. 实时推理**：风险评分、推荐排序多采用实时推理；报告生成、内容审核可采用异步批处理；混合架构（实时 + 离线纠偏）常见于医疗与制造。
- **云 vs. 私有化/边缘**：金融与医疗偏好私有云或本地化部署以满足数据主权；自动驾驶车端推理必须本地化；零售推荐可充分利用公有云弹性。
- **自研 vs. 采购**：基础模型能力可通过 API（OpenAI、Anthropic、Google、阿里云百炼）快速验证；当数据隐私、成本或延迟成为瓶颈时，转向开源模型（Llama、Qwen、DeepSeek、Mistral）私有化部署。
- **单体 vs. 微服务**：早期产品可用单体快速迭代；规模化后按数据、模型、网关、应用拆分服务，独立扩缩容与故障隔离。
- **集中式 vs. 联邦式治理**：大型企业通常建立中央 AI Platform 团队提供统一模型注册、网关与可观测性，同时允许业务团队拥有应用层与部分特征工程。

工程实践上，推荐采用 GitOps 管理基础设施（Terraform、Pulumi、Helm），将 Prompt、Skill、Config 与护栏规则版本化并纳入 CI/CD。模型上线前必须通过自动化测试（单元测试、集成测试、模型评估、对抗测试）与人工审核（合规、安全、业务）。

## 3. 行业架构模板

以下五个行业的模板并非标准答案，而是基于生产实践提炼的共性模式。实际落地时，需要结合企业现有的技术栈、数据成熟度与监管要求进行裁剪。

### 3.1 金融风控

金融风控是 AI 生产化最成熟的领域之一，对延迟、可解释性与审计要求极高。

- **数据层**：整合核心系统交易流水、KYC 数据、征信数据、设备指纹、关系网络与第三方黑名单。使用流处理（Flink、Spark Streaming、Kafka Streams）实时构建特征。
- **模型层**：传统 XGBoost/LightGBM/CatBoost 负责额度与欺诈评分；GNN（Graph Neural Network）识别团伙欺诈；LLM 用于可疑交易报告（SAR）生成与监管问答。
- **服务层**：规则引擎（Drools、自研）与模型评分并行执行，支持规则热更新；对高敏感度决策要求“人机共审”，提供 SHAP/LIME 解释。
- **网关层**：API Gateway 统一鉴权、限流与审计；所有评分请求必须留痕，满足反洗钱（AML）与监管审计要求。
- **合规重点**：等保三级、PCI-DSS、EU AI Act 高风险系统、GDPR、模型公平性（Fair Lending）与可解释性。

典型指标：欺诈识别率 >95%、误报率 <5%、P99 延迟 <50ms、模型决策可解释覆盖率 100%。

### 3.2 医疗影像

医疗影像 AI 直接涉及患者安全，因此强调临床验证、漂移监控与人机协作。

- **数据层**：对接 PACS/RIS 系统，按 DICOM 标准管理影像；通过 FHIR 接入电子病历；在入湖前完成去标识化（de-identification）。
- **模型层**：CNN、Vision Transformer（ViT）、SAM/MedSAM 用于分割与病灶检测；多模态大模型用于影像-文本联合报告生成。模型必须通过临床验证（敏感性、特异性、AUC）与 FDA/CE/NMPA 审批路径。
- **服务层**：影像 AI 服务嵌入放射科工作流（PACS Viewer、RIS 报告系统），提供置信度、热力图与医生标注回流接口。
- **网关层**：严格控制 PHI 访问，记录每一次推理的医生、患者、设备与模型版本；支持审计与追溯。
- **合规重点**：HIPAA、GDPR、FDA SaMD、NMPA 第三类医疗器械、ISO 13485、临床指南与伦理审查。

典型指标：病灶检出敏感性 >90%、医生采纳率 >70%、报告生成时间缩短 30% 以上。

### 3.3 自动驾驶

自动驾驶系统是典型的安全关键型（Safety-Critical）AI 系统，对冗余、仿真与 OTA 更新有极高要求。

- **数据层**：车端传感器（摄像头、激光雷达、毫米波雷达、GNSS/IMU）数据通过数据回传链路进入数据湖；使用场景挖掘与自动标注生成训练集；HD Map 与仿真数据作为补充。
- **模型层**：BEVFormer、Occupancy Network、端到端驾驶模型（UniAD、VAD）负责感知与规划；影子模式（Shadow Mode）持续收集人类司机与模型决策差异。
- **服务层**：车端 ECU/Orin/Thor 进行实时推理；云端负责模型训练、仿真验证、地图更新与车队管理；OTA 系统负责模型版本灰度发布与回滚。
- **网关层**：车云通信通过 mTLS 与双向认证；网关层负责指令鉴权、数据脱敏与固件签名验证。
- **合规重点**：ISO 26262（功能安全）、ISO 21448（SOTIF）、ASIL-D、UN R79/R157、网络安全法规（UN R155/R156）、数据跨境与隐私。

典型指标：感知延迟 <10ms、规划决策延迟 <30ms、仿真场景覆盖率 >99%、OTA 成功率 >99.9%。

### 3.4 零售推荐

零售推荐系统以数据规模大、实时性要求高、ROI 可量化著称。

- **数据层**：整合浏览/点击/加购/支付行为、商品目录、库存、价格、用户画像与上下文（位置、时间、设备）。实时特征通过 Flink 写入 Feature Store。
- **模型层**：双塔模型（Two-Tower）用于召回，DeepFM/DIN 用于排序，LLM 用于商品描述生成、智能搜索与个性化文案；强化学习用于动态定价与库存清货。
- **服务层**：推荐服务通过召回→粗排→精排→重排多阶段漏斗实现低延迟；A/B 测试平台持续优化策略。
- **网关层**：按商家/品类/用户分桶限流，防止大促流量击穿；归因系统记录每个推荐位对 GMV 的贡献。
- **合规重点**：消费者权益保护、算法推荐管理规定、反歧视、AIGC 标识、数据最小化。

典型指标：点击率提升 10-20%、转化率提升 5-15%、P99 推荐延迟 <100ms、单次推荐成本 <0.001 美元。

### 3.5 智能制造

智能制造 AI 需要与 OT（Operational Technology）系统深度融合，并兼顾边缘延迟与工厂数据主权。

- **数据层**：从 PLC、SCADA、MES、ERP 与 IoT 传感器采集时序数据；工业相机采集视觉质检图像；数据通常不出厂或仅在私有云中处理。
- **模型层**：时序异常检测（Prophet、LSTM、Transformer、Isolation Forest）用于预测性维护；YOLO/SegFormer 用于缺陷检测；物理信息神经网络（PINN）用于工艺仿真与数字孪生。
- **服务层**：边缘网关（NVIDIA Jetson、Advantech、华为 Atlas）承载实时质检与异常告警；云端负责模型训练、版本管理与跨工厂模型联邦更新。
- **网关层**：OT/IT 边界网关执行协议转换（OPC UA、MQTT）、访问控制与数据脱敏；所有控制指令需经安全审计。
- **合规重点**：ISO/TS 16949、IEC 61508（功能安全）、IEC 62443（工控安全）、数据主权、环境保护与职业安全。

典型指标：设备非计划停机降低 20-40%、质检漏检率 <1%、边缘推理延迟 <50ms。

## 4. 模型治理、漂移检测与退市流程

模型治理是生产 AI 架构的“免疫系统”，目标是让模型从上线到退役的完整生命周期都可审计、可控制、可回滚。

### 4.1 模型治理框架

- **模型目录与模型卡**：每个上线模型必须登记名称、版本、 owner、训练数据、评估结果、适用场景、已知风险与依赖服务。
- **风险分级**：参考 EU AI Act 将模型划分为禁止类、高风险、有限风险、最小风险；高风险系统需执行风险管理、数据治理、人工监督与 FRIA。
- **审批工作流**：建立数据科学、法务、安全、业务多方参与的上线审批；重大变更需重新评估。
- **血缘与可复现**：记录数据、代码、环境、超参数与模型权重之间的完整链路，确保任意时刻可复现训练结果。
- **权限与访问控制**：模型仓库、推理服务与训练数据实施最小权限原则，敏感模型禁止未授权下载。

### 4.2 漂移检测

漂移检测是持续监控模型性能与数据分布的核心手段。

- **数据漂移（Data Drift）**：使用 PSI、Kolmogorov-Smirnov、Wasserstein 距离或最大均值差异（MMD）监控输入特征分布变化。
- **概念漂移（Concept Drift）**：监控标签分布、业务目标与模型预测之间的关系变化，如 Covariate Shift 与 Concept Shift。
- **特征漂移与上游变更**：当特征管道、数据源或第三方 API 升级时，自动触发分布对比与影响评估。
- **Embedding / RAG 漂移**：对 LLM/RAG 场景，监控 query 分布、检索结果相关性、上下文忠实度与答案一致性。
- **工具链**：Evidently AI、Arize、WhyLabs、Fiddler、NannyML、Arthur AI、AWS SageMaker Model Monitor、Azure ML Data/Model Drift。
- **响应机制**：设定漂移阈值，触发告警、人工复核、自动重训练或模型切换。

### 4.3 模型退市流程

模型退役是治理闭环的重要环节，常被忽视。

- **退役触发条件**：业务价值下降、性能持续退化、维护成本过高、监管政策变化、模型被新版本替代或出现不可接受的安全风险。
- **退役准备**：通知下游消费者、制定 API 弃用时间表、归档训练/推理数据与模型 artifact、保留法律要求的日志。
- **灰度下线**：先关闭新流量入口，保留只读查询能力；再逐步停止推理服务；最后清理存储与依赖。
- **知识保留**：将模型经验、失败案例与合规审计记录沉淀为组织资产，避免“人走模型亡”。

## 5. 安全合规 checklist

不同行业面临的合规框架各异，但核心关注点高度一致：数据安全、访问控制、审计留痕、算法透明、人类监督与应急响应。

### 5.1 中国等保 2.0

- 身份鉴别：多因素认证、统一身份管理。
- 访问控制：基于最小权限的 RBAC/ABAC，模型与数据分级分类。
- 安全审计：操作日志、推理日志、管理员日志集中存储，保留 ≥6 个月。
- 数据安全：传输与存储加密，密钥托管，备份与恢复演练。
- 通信安全：API 双向 TLS、VPC 隔离、DDoS 防护。

### 5.2 EU AI Act

- 风险分类：确认系统是否属于禁止类、高风险、通用 AI 模型或有限风险。
- 高风险系统要求：建立风险管理体系、数据治理流程、技术文档、日志记录、透明度义务、人工监督机制。
- 通用 AI 模型：≥10^25 FLOPs 训练算力的模型需履行系统性风险评估、红队测试与事件报告。
- 市场准入：高风险 AI 系统需通过符合性评估并加贴 CE 标识。
- 基本权利影响评估（FRIA）：在公共部门或高风险场景部署前完成。

### 5.3 HIPAA（医疗）

- 业务伙伴协议（BAA）：与所有处理 PHI 的供应商签署。
- 最小必要原则：仅访问完成工作所需的最少 PHI。
- 访问控制：基于角色的用户身份管理、自动会话超时。
- 审计控制：记录对 PHI 的访问、修改与披露。
- 加密与传输安全：静态与传输中加密； breach notification 流程。

### 5.4 FDA（医疗器械软件 SaMD）

- 分类与审批路径：确定是 510(k)、De Novo 还是 PMA。
- 质量管理体系（QSR/ISO 13485）：设计控制、风险管理、软件验证。
- 临床验证：证明在目标人群与使用场景中的安全性与有效性。
- 网络安全指南：实施安全开发生命周期、威胁建模、漏洞管理。
- 上市后监督：持续收集真实世界性能与不良事件。

### 5.5 跨行业通用 checklist

| 检查项 | 负责人 | 频率 |
|--------|--------|------|
| 数据分类分级与标签策略 | 数据治理 | 每季度 |
| 模型卡与风险评估文档更新 | AI 平台/合规 | 每次上线/重大变更 |
| Prompt/护栏规则版本化与回滚测试 | 安全/MLOps | 每次发布 |
| 访问权限与 API Key 轮换 | 安全 | 每季度 |
| 对抗样本与 Prompt Injection 测试 | 红队/安全 | 每半年 |
| 漂移监控告警与处置演练 | MLOps | 每月 |
| 第三方模型供应商合同与 SLA 审查 | 采购/法务 | 每年 |
| 事件响应与数据泄露演练 | 安全/SRE | 每半年 |

## 6. 成本优化与 FinOps

AI 生产系统的成本往往呈现“非线性爆炸”：GPU 训练、推理实例、向量数据库、模型 API 与数据存储都可能迅速超出预算。FinOps 的目标是在不影响业务价值的前提下，让每一分算力都可被归因、可被优化。

### 6.1 成本可见性

- **多维标签体系**：为每个模型、项目、团队、环境、客户打上成本标签，实现 showback/chargeback。
- **单位经济**：定义核心指标，如每次推理成本（Cost per Inference）、每次决策成本（Cost per Decision）、每千 token 成本、每个用户会话成本。
- **成本归因工具**：Kubecost、CloudHealth、DoiT、FinOps Foundation 开放规范、云厂商 Billing API。

### 6.2 计算优化

- ** right-sizing**：根据实际 GPU 利用率选择实例类型；对低吞吐任务使用 CPU/GPU 混合调度。
- **Spot / 抢占式实例**：训练任务使用可中断实例降低成本，配合 checkpoint 自动恢复。
- **自动扩缩容**：基于队列深度、GPU 利用率、token 速率进行 HPA/VPA；避免常驻空闲实例。
- **批处理与合并请求**：提高 batch size、使用 continuous batching、合并小请求以降低单位成本。
- **模型压缩与蒸馏**：在满足准确率的前提下使用更小模型、量化权重、蒸馏学生模型。
- **缓存策略**：KV Cache、Prefix Caching、Prompt Cache、Embedding Cache 与结果缓存可显著降低重复计算。
- **模型路由**：简单查询路由到小模型或缓存，复杂查询才调用大模型。

### 6.3 存储与数据成本

- **数据生命周期**：热数据使用高性能对象存储/SSD，冷数据归档至 Glacier/S3 Glacier/低频存储。
- **向量数据库优化**：定期 compaction、删除过期索引、选择合适距离算法与量化索引（IVF_PQ、HNSW）。
- **日志与可观测性采样**：对高 QPS 推理日志进行采样或聚合，避免存储成本失控。

### 6.4 组织与流程

- **FinOps 文化**：建立跨职能 FinOps 小组，定期审查成本报告，设定预算告警与冻结机制。
- **预算与告警**：按项目设定月度/季度预算，触发 50%、80%、100% 多级告警。
- **供应商谈判**：根据用量锁定预留实例（RI）或 Savings Plans；对模型 API 进行多供应商比价与谈判。

## 7. 风险与生产落地 checklist

生产 AI 系统面临技术、安全、合规与组织四类风险。以下 checklist 帮助团队在生产上线前完成系统性自检。

### 7.1 常见风险

- **模型性能风险**：漂移、过拟合、长尾场景失败、训练-服务偏差、数据质量问题。
- **基础设施风险**：GPU 故障、推理延迟抖动、依赖服务超时、模型仓库不可用、网络分区。
- **安全风险**：Prompt Injection、Jailbreak、数据投毒、模型窃取、API 密钥泄露、供应链攻击。
- **合规风险**：监管变化、跨境数据传输、未充分告知用户、算法歧视、未履行人类监督义务。
- **业务风险**：模型输出误导用户、人机协作边界不清、ROI 不达预期、组织变革阻力。

### 7.2 生产上线 checklist

**数据准备**
- [ ] 训练/验证/测试数据集已审计，分布覆盖目标场景。
- [ ] 数据血缘与 schema 变更流程已建立。
- [ ] PII/PHI/敏感数据已完成脱敏或获得合法授权。

**模型验证**
- [ ] 模型性能指标达到业务基线并通过回归测试。
- [ ] 已进行公平性、鲁棒性、对抗样本与红队测试。
- [ ] 模型卡、风险评估与上线审批文档已完成。

**基础设施准备**
- [ ] 推理服务具备自动扩缩容、多可用区部署与故障转移能力。
- [ ] 网关层已完成鉴权、限流、Fallback、审计与护栏配置。
- [ ] 可观测性覆盖 metrics、logs、traces 与业务指标。

**安全与合规**
- [ ] 完成等保/EU AI Act/HIPAA/FDA 等适用框架的 gap analysis。
- [ ] Prompt/护栏规则已纳入 CI/CD 与版本管理。
- [ ] API Key、模型权重与 PHI 访问已实施最小权限与加密。

**运营与成本**
- [ ] 已制定 SLO/SLI/SLA，并与业务方达成一致。
- [ ] 回滚方案、事故响应流程与 on-call 值班表已就绪。
- [ ] 成本归因与预算告警已配置，单位经济指标已定义。

**上线后**
- [ ] 前 7 天进行密切监控与灰度放量。
- [ ] 漂移监控与反馈闭环已启动。
- [ ] 定期复盘模型 ROI 与用户满意度。
