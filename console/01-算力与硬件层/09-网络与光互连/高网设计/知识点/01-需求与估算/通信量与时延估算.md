# 通信量与时延估算

> 用三个公式（梯度字节、Ring 流量、α–β 模型）把"这张网要多快"从拍脑袋变成手算。

## 解决什么问题

定网卡口径、算轨比、决定 8×400G 还是 4×800G 之前，必须先知道每卡每步要收发多少字节、允许多长时间。本篇给出一组可手工执行的估算公式与一个 70B 千卡算例，作为一切带宽配比决策的底稿。

## 核心原理

**1. 通信数据量（S）**：混合精度训练的通信主体是梯度。S = 参数量 N × 每参数字节：BF16 梯度 2 B/参数、FP32 4 B、FP8 压缩后约 1 B（含量化因子开销略增）。参数 AllGather、激活 P2P 按张量形状同法展开。

**2. Ring AllReduce 每卡流量**：AllReduce 等价于 ReduceScatter + AllGather，两阶段各走 N−1 步，每卡收发合计 = 2(N−1)/N×S ≈ 2S（大 N 时）。ReduceScatter / AllGather 单独使用时减半为 (N−1)/N×S。

**3. α–β（Hockney）模型**：完成时间 = 时延项 + 带宽项。Ring AllReduce：T ≈ 2(N−1)·α + 2(N−1)/N × S / B。α 是单步启动时延（含 NIC–交换–NIC 往返），B 是路径可用带宽（多网卡取聚合有效值）。大消息 S/B 主导，小消息 α 主导。

**4. 跨机叠加项**：机内 NVLink/PCIe 时延为百纳秒级；跨机一次 RDMA 读写端到端单向典型 3–5 µs（NIC 处理 1–2 µs + 每交换跳数百纳秒，芯片代际差异大，此处为量级参考）；集合通信要把该时延乘上算法步数。MB 级以上消息这些 µs 项可忽略，KB 级（PP 激活、decode A2A）时它们就是全部。

**手算例（70B、1000 卡 DP）**，假设明示：BF16 梯度、单步一次梯度 AllReduce、通信完全暴露（不记 overlap）、每卡 1×400 Gbps NDR、有效 busbw 按 45 GB/s（约 360 Gbps，2023—2025 常见实测口径）计：
- S = 70e9 × 2 B = 140 GB/卡
- 每卡收发 = 2 × (999/1000) × 140 ≈ 280 GB
- 带宽项 T ≈ 280 / 45 ≈ 6.2 s/步；时延项 2×999×5 µs ≈ 10 ms，可忽略
- 结论：400 Gbps/卡下纯 DP 每步仍有 6 秒级通信，梯度分桶重叠可掩盖大部分，但任一次拥塞直接加进步长；200 Gbps/卡则翻倍至约 12.4 s。这就是 DP 万卡必须 400G 起步且强依赖 overlap 的原因。

## 关键数字

| 项 | 公式/数值 | 备注 |
|---|---|---|
| 梯度字节 S | N×2B（BF16）/ 4B（FP32）/ 1B（FP8） | N 为参数量 |
| Ring AllReduce 每卡流量 | 2(N−1)/N×S ≈ 2S | 收+发合计 |
| ReduceScatter / AllGather 每卡流量 | (N−1)/N×S | ZeRO/FSDP 主力算子 |
| P2P（PP 激活） | micro-batch×seq×hidden×2B | 单向一次 |
| EP All-to-All 每卡 | ≈(N−1)/N×人均 token×hidden×2B | 流量按路由矩阵，非均匀 |
| Ring 时延项 | 2(N−1)·α | α 取端到端单跳 RTT |
| 跨机单跳 RTT（同机房） | ~5–10 µs 量级 | NIC+1–2 跳交换（待核实具体平台） |
| 手算例 70B/1000 卡 BF16 | 280 GB/卡，≈6.2 s @45 GB/s | 假设见上文 |
| 多网卡聚合效率 | 有效值约峰值 85–95% | 经验区间（待核实具体代际） |

## 设计要点与权衡

- 先算"暴露通信"再定口径：可完全被计算掩盖的通信不消耗步长，网络只需满足"通信时间 ≤ 可掩盖窗口"；TP/EP 这类不可重叠通信按全额带宽配置。
- 小消息看 α、大消息看 B：推理 decode 与 PP 激活属前者，堆带宽无效，要减跳数、走低时延路径与低时延协议（LL/LL128）。
- 收敛比进入 B：跨轨流量出现后，有效带宽由最窄链路决定，估算按最坏路径做。
- 估算输出是一份需求上界清单：每卡双向带宽、每节点聚合带宽、任意两点 RTT 上界、集合通信可用并发流数——后续拓扑与选型都在这份清单内做。
- 算例只覆盖 DP：TP/EP/PP 用上表公式按各自频次逐项累加，别拿 DP 单次结论代表全模型。

## 常见坑

- 忘记 AllReduce 收发双向都占网卡："每卡 2S 流量"指收+发合计，口径混了差 2 倍。
- 用线速代替有效带宽：400 Gbps 线速的 NCCL busbw 实测约 360–380 Gbps，直接按 50 GB/s 算会低估 20–30%。
- 时延项误判：Ring 的 2(N−1)α 对秒级大 AllReduce 无关紧要（1000 卡约 10 ms），但对每层 KB 级 PP 通信是主要项——两类场景别用同一把尺子。
- 拿训练峰值需求推所有平面：KV Cache 专网、带外管理网的量级完全不同，分层估算。
