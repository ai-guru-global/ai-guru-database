# AI 智能体入门

> 一句话理解：智能体是 **能规划任务、调用工具、观察结果并根据反馈调整行为的 AI 系统**，不只是聊天，还能做事。

## 1. 智能体 vs 聊天机器人

| 维度 | 聊天机器人 (Chatbot) | 智能体 (Agent) |
|------|---------------------|---------------|
| 输出 | 只能输出文字 | 调用工具、执行操作 |
| 验证 | 无法查证信息（幻觉风险） | 通过工具验证事实 |
| 行动力 | 无（只能建议） | 有（在授权边界内执行） |
| 反馈 | 无闭环 | 观察结果 → 调整策略 |

## 2. ReAct 模式：智能体的基本工作流程

ReAct（Reasoning + Acting）是最经典的智能体思考模式，形成三步循环：

```text
思考（Thought）→ 行动（Action）→ 观察（Observation）→ 思考 → …
```

**示例**：用户问 "周杰伦现在年龄 × 2 = ?"

```text
1. 思考：需要查出生日期 → 行动：Search("周杰伦 出生日期")
2. 观察：1979-01-18 → 思考：需要当前日期 → 行动：GetTime()
3. 观察：2026-02-13 → 思考：已过生日，47岁 → 行动：Calculate(47×2)
4. 观察：94 → 最终回答：47 岁，乘以 2 是 94
```

智能体不靠"猜"，靠"查"和"算"。

## 3. 规划与反思

复杂任务需要更高级的能力：

- **任务分解**：把大任务拆成子任务（Sub-goals）
- **反思（Reflection）**：根据报错信息修正方案，再试一次
- **基于反馈迭代**：这是智能体最有价值的能力之一

## 4. 低代码智能体平台

| 平台 | 定位 | 特点 |
|------|------|------|
| **Coze（扣子）** | 小白入门 | 免费、插件丰富、可视化工作流、多智能体编排 |
| **Dify** | 企业/极客 | 开源可自部署、RAG 引擎强、模型中立 |
| **Zapier / Make** | App 连接 | 连接 5000+ 应用，自动化工作流 |

选平台时比较：**可维护性**、**可迁移性**、**合规性**。

## 5. 多智能体协作

### 单个 AI 的局限

| 问题 | 说明 |
|------|------|
| 无人质疑 | 所有决策都是最终的，没有审查过程 |
| 无分工精专 | 要求什么都会，结果什么都不精 |
| 无深度验证 | 错误信息可能被当作事实 |
| 推理上限 | 超过复杂度阈值就开始犯错 |

### 四种协作模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **串行流程** | AI1 → AI2 → AI3 | 内容创作：草稿→编辑→排版 |
| **并行执行** | 多 AI 同时工作，汇总结果 | 产品评审：设计/工程/商业并行 |
| **辩论式** | 正方 vs 反方 + 仲裁 | 项目决策：是否启动 |
| **分层决策** | 决策 AI 指挥多个专家 AI | 战略分析：市场/工程/运营 |

### Agent-to-Agent 协议（A2A）

Google 2025 年 4 月发布，让不同 AI 智能体互相通信和协作：

- **统一消息格式**：结构化请求/响应
- **能力声明（Agent Card）**：声明能力和约束，便于编排层路由
- **实际好处**：可替换、可扩展、跨供应商协作

A2A 与 MCP 互补：MCP 管 Agent↔工具，A2A 管 Agent↔Agent。

## 6. 智能体生产上线三大基线

| 基线 | 内容 |
|------|------|
| **评测体系（Evals）** | 端到端测试集：成功率、平均耗时、Token 成本 + 对抗性 Red-teaming |
| **行动边界（Guardrails）** | 工具沙盒化 + 最小权限 + 高危操作 Human-in-the-loop 二次批准 |
| **可观测性（Observability）** | 时间戳、Trace ID、完整输入输出、API 响应耗时 → 精准回放 |

没有这三件套，智能体容易停留在"演示可用、生产翻车"的隐患阶段。

## 7. 设计原则

1. **角色明确**：每个 AI 只做自己最擅长的事
2. **输入输出清晰**：明确格式、职责范围、失败模式
3. **逐步组合**：先 2 个 AI 验证有效，再逐步扩展
4. **成本意识**：多智能体增加 API 和编排成本，用质量/耗时/返工率衡量是否值得
