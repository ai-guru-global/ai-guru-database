## 引言：为什么AI应用需要专属的生命周期管理

对于所有AI应用来说，一个重要的问题是AI功能的相关性。由于AI是一个快速发展的领域，为了确保你的应用保持相关性、可靠性和稳健性，你需要持续监控、评估和改进它。这就是**生成式AI生命周期**的意义所在。

生成式AI生命周期是一个指导你开发、部署和维护生成式AI应用各阶段的框架。它帮助你：

- 定义目标和衡量性能
- 识别挑战并实施解决方案
- 使应用符合领域及利益相关者的伦理和法律标准

通过遵循生成式AI生命周期，你可以确保应用始终提供价值并满足用户需求。

本课将涵盖以下内容：

- 从MLOps向LLMOps的范式转变
- LLM生命周期的完整流程
- 生命周期工具链
- 生命周期度量与评估

## 一、从MLOps到LLMOps的范式转变

### 为什么需要新的范式

大型语言模型（LLM）是人工智能武器库中的一项新工具，在应用的分析和生成任务中极为强大，但这股力量在我们简化AI和经典机器学习任务时也带来了一些影响。

因此，我们需要一个新的范式来动态适应这一工具，并激励正确的导向。我们可以将较早的AI应用归为"机器学习应用（ML应用）"，而较新的AI应用称为"生成式AI应用（GenAI应用）"或简称"AI应用"，反映当时的主流技术和方法。

### MLOps与LLMOps的详细对比

以下表格展示了两个范式在各维度上的关键差异：

| 维度 | MLOps（传统ML） | LLMOps（生成式AI） |
|------|----------------|-------------------|
| **核心角色** | 数据科学家 | 应用开发者 |
| **模型来源** | 自定义训练模型 | 模型即服务（Models-as-a-Service） |
| **关键集成点** | 数据管道 | 应用集成 |
| **核心关注** | 模型准确性 | 响应质量 |
| **有害内容** | 不关注 | 负责任的AI（RAI） |
| **输出依据性** | 特征重要性 | 回答是否有逻辑和事实依据 |
| **成本模型** | 训练成本 | 每次推理的预算 |
| **延迟指标** | 批量推理时间 | 平均生成一个token的时间 |
| **质量提升** | 更多数据、调参 | 提示工程、RAG、微调 |
| **评估方式** | 精确率/召回率 | 质量、伤害、诚实度、成本、延迟 |

### LLMOps的五大核心指标

在LLMOps中，我们需要关注以下五个关键指标：

1. **质量（Quality）**：响应的整体质量，包括准确性、相关性、连贯性
2. **伤害（Harm）**：负责任AI的评估，确保输出不包含有害、偏见或歧视性内容
3. **诚实度（Honesty）**：响应的依据性——回答是否有逻辑？事实是否正确？
4. **成本（Cost）**：解决方案的总预算，包括API调用费用、基础设施成本
5. **延迟（Latency）**：平均生成一个token的时间，直接影响用户体验

## 二、LLM生命周期的完整流程

### 生命周期全景图

LLM生命周期与传统的MLOps生命周期有显著不同。LLM有许多新需求：

- **提示工程**：设计和优化提示以获得最佳输出
- **质量提升技术**：微调（Fine-Tuning）、RAG（检索增强生成）、元提示（Meta-Prompts）
- **负责任AI评估**：确保输出符合伦理标准
- **新评估指标**：质量、伤害、诚实度、成本和延迟

### 三大核心阶段

LLM生命周期可以分解为三个核心阶段，加上一个贯穿始终的管理周期。

#### 阶段一：创意/探索（Ideating/Exploring）

这是生命周期的起点，根据业务需求进行探索和验证。

**核心活动**：
- 理解业务需求和用户场景
- 构建原型验证假设
- 使用提示工程尝试各种LLM
- 探索可能性，验证假设是否成立

**工具与方法**：
- 使用[PromptFlow](https://microsoft.github.io/promptflow/index.html?WT.mc_id=academic-105485-koreyst)构建原型
- 快速迭代不同的提示策略
- 评估不同LLM的适用性
- 确定基线性能指标

**关键输出**：
- 验证的概念原型
- 初步性能基线
- 技术可行性评估
- 下一步行动计划

#### 阶段二：构建/增强（Building/Augmenting）

这是实施阶段，开始评估更大规模的数据集并实施技术以增强解决方案。

**核心活动**：
- 在更大规模数据集上评估性能
- 实施质量提升技术
- 验证解决方案的稳健性
- 如不行则重新实现或调整

**质量提升技术**：

| 技术 | 描述 | 适用场景 |
|------|------|----------|
| **提示工程优化** | 精细调整提示格式和内容 | 快速改进输出质量 |
| **RAG** | 检索增强生成，引入外部知识 | 需要特定领域知识 |
| **微调** | 在特定数据上继续训练模型 | 需要高度定制化输出 |
| **元提示** | 使用提示来生成更好的提示 | 系统性地优化提示策略 |

**迭代循环**：
- 测试当前流程和规模
- 如果不满足指标，重新实现
- 添加新的流程步骤
- 重组数据结构
- 重复测试直到满足所有指标
- 准备进入下一阶段

#### 阶段三：运营（Operationalizing）

这是集成阶段，将系统部署到生产环境并持续运营。

**核心活动**：
- 添加监控和告警系统
- 部署到生产环境
- 集成到应用程序中
- 建立持续改进流程

**监控指标**：
- 实时跟踪五大核心指标（质量、伤害、诚实度、成本、延迟）
- 设置阈值告警
- 收集用户反馈
- 定期进行红队测试

### 管理周期

贯穿三个阶段的是一个整体的管理周期，重点关注：

- **安全性**：确保应用免受攻击和滥用
- **合规性**：遵守相关法律法规和行业标准
- **治理**：建立明确的决策流程和责任体系

### 实践案例：Contoso Chat

[Contoso Chat演示](https://nitya.github.io/contoso-chat/?WT.mc_id=academic-105485-koreyst)展示了一个完整的LLMOps实践案例。这个零售聊天机器人应用展示了如何：

- 从业务需求出发进行创意探索

- 部署到Azure并持续监控

## 三、生命周期工具链

### Azure AI平台

微软提供了[Azure AI平台](https://azure.microsoft.com/solutions/ai/?WT.mc_id=academic-105485-koreyst)，让生命周期实现更加便捷且迅速。

#### Azure AI Studio

[Azure AI Studio](https://ai.azure.com/?WT.mc_id=academic-105485-koreyst)是一个网页门户，提供以下功能：

- **模型探索**：浏览和比较不同的AI模型
- **示例和工具**：丰富的示例代码和开发工具
- **资源管理**：管理计算资源、API密钥等
- **UI开发流程**：可视化界面引导开发
- **代码优先开发**：提供SDK和CLI选项

Azure AI平台的核心能力：

| 能力 | 描述 |
|------|------|
| 模型目录 | 浏览和部署各种AI模型，包括OpenAI、Hugging Face等 |
| 项目管理 | 组织和管理AI项目资源 |
| 向量搜索 | 内置向量搜索能力，支持RAG应用 |
| 数据库集成 | 支持多种数据库服务 |
| 运营管理 | 监控、告警、日志管理 |

### PromptFlow

[PromptFlow](https://microsoft.github.io/promptflow/index.html?WT.mc_id=academic-105485-koreyst)是一个专门的LLM应用开发工具，支持从概念验证（POC）到大规模应用构建的完整流程。

#### PromptFlow的三大核心能力

**1. 设计和构建**

- 在VS Code中设计和构建应用
- 提供可视化工具和功能工具
- 支持拖拽式流程设计
- 支持代码优先的开发方式

**2. 测试和微调**

- 轻松测试和微调应用
- 实现高质量AI输出
- 支持批量测试和评估
- 提供调试和追踪功能

**3. 集成和部署**

- 使用Azure AI Studio进行集成和迭代
- 快速推送到云端
- 部署为API端点
- 实现快速集成到现有应用

#### PromptFlow工作流程

```
设计阶段（VS Code）
    ↓
测试阶段（本地/云端）
    ↓
评估阶段（批量测试）
    ↓
部署阶段（Azure AI Studio）
    ↓
监控阶段（持续运营）
```

### 工具选型建议

| 阶段 | 推荐工具 | 理由 |
|------|----------|------|
| 探索 | Azure AI Studio + PromptFlow | 快速原型和实验 |
| 构建 | PromptFlow + SDK | 系统化开发和测试 |
| 运营 | Azure AI Platform | 监控、告警、部署 |
| 管理 | Azure AI Studio | 合规、安全、治理 |

## 四、生命周期度量与评估

### 评估框架

在LLMOps中，评估不再是简单的精确率/召回率指标，而是多维度的综合评估。

#### 质量评估

- **相关性**：回答是否与问题相关
- **准确性**：事实信息是否正确
- **完整性**：回答是否全面覆盖问题
- **连贯性**：回答是否逻辑清晰、结构合理

#### 安全评估

- **有害内容检测**：是否包含暴力、色情、仇恨言论等
- **偏见检测**：是否存在性别、种族、宗教等方面的偏见
- **隐私保护**：是否泄露个人信息

#### 依据性评估

- **事实依据**：回答是否有可靠的信息来源
- **逻辑一致性**：推理过程是否合理
- **引用准确性**：引用的信息是否准确

### 持续改进循环

LLM生命周期不是线性的，而是集成的循环、迭代的：

1. **监控** → 收集实时指标和用户反馈
2. **分析** → 识别问题和改进机会
3. **优化** → 调整提示、更新RAG数据、微调模型
4. **验证** → 在测试环境验证改进效果
5. **部署** → 将改进推送到生产环境
6. **回到步骤1**

## 五、从MLOps迁移到LLMOps的实践建议

### 组织层面

- 将团队重心从数据科学家转向应用开发者
- 建立跨职能团队（包含AI、安全、UX专家）
- 制定负责任AI政策和流程

### 技术层面

- 优先使用模型即服务，而非自行训练
- 建立提示版本管理系统
- 实施自动化评估流水线
- 建立成本监控和优化机制

### 流程层面

- 采用敏捷迭代开发方法
- 建立快速实验和验证文化
- 实施持续的红队测试
- 建立用户反馈收集和处理流程

## 知识检查

**问题**：在LLMOps中，以下哪项不属于五大核心评估指标？

1. 质量与伤害
2. 诚实度与延迟
3. 精确率与召回率

**答案**：3

**解析**：

LLMOps的五大核心指标是质量、伤害、诚实度、成本和延迟。精确率与召回率是传统MLOps中的评估指标，在LLMOps中被多维度的综合评估所取代。这是因为生成式AI的输出不是简单的分类结果，需要从多个维度评估其质量、安全性和依据性。
