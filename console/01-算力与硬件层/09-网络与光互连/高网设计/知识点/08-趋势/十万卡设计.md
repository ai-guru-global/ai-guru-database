# 十万卡设计

> 十万卡级集群里，电力与选址取代网络带宽成为第一约束，网络设计变量从"单集群最优"变为"超节点池化 × 多平面 × 协议可扩展性 × 光纤土建"的联合优化。

## 解决什么问题

从万卡到十万卡不是线性放大：光纤对数进入万级、电力进入万千瓦级、协议编址与故障率都被放大到必须前置设计的程度。本篇给出十万卡级集群的设计变量清单与数量级锚点，作为架构可行性评估的检查表。

## 核心原理

设计变量清单：
1. 多平面 + 超节点组合：十万卡≈NVL72×约 1,400 柜的池化规模，普遍思路是"超节点域内扛高频通信 + 多平面 scale-out 扛跨域"，每平面独立 spine 故障域；平面数与单平面规模在光纤成本与故障半径之间权衡。
2. 协议可扩展性：中兴 2026-02 白皮书提出，十万卡级集群互联协议需预留 GPU ID 标识位空间等可扩展性设计——编址、路由表项、集合通信域标识都要为规模上限留位，避免扩容时协议层返工。
3. 跨楼栋/跨园区光纤预算：东西向链路对应的光纤对数以万计（数量级估算，随收敛比与端口速率变化），园区光纤管道、桥架与光缆敷设成为土建级前置项；跨园区则进入 DCI 范畴（相干 400G/800G ZR 类）。
4. 电力与选址第一约束：十万卡 H100 级 GPU 集群 IT 负荷约 100 MW 量级，含冷却与损耗后园区负荷 120–150 MW 量级（行业经验口径，与机型/液冷方案强相关）；选址跟着电与水走，网络设计反而要适配地理分布。
5. 多作业拼用与拓扑调度：单一 100k 作业稀少，常态是多作业拼用——按拓扑分区分配、碎片管理、作业间隔离（QoS）与拓扑感知调度成为资源系统的核心能力。
6. 跨 DC 训练：Google 与 Meta 均有公开实践（Google 的跨 DC 训练调度、Meta 的跨园区 RDMA；细节待核实），前提是分层并行放置（跨 DC 只跑低频通信的维度）与容量冗余对冲链路抖动。
7. 失败率工程：按 λ_daily = N×AFR/365 推算，十万卡下服务器整机（12,500 台 × 5% AFR）日均 ~1.7 台，光模块（约 40 万只 × 1%）日均 ~11 只，合计硬件事件每小时级一起。checkpoint/自动隔离/续训不是可选项，而是与网络同级的顶层设计。

## 关键数字

| 变量 | 量级 | 口径 |
|---|---|---|
| 超节点池化规模 | NVL72 × ~1,400 柜 ≈ 100k GPU | 2024–2026 NVL72 口径 |
| IT 负荷 | ~100 MW；园区 120–150 MW | H100 级、含 PUE 口径（行业经验） |
| 东西向光纤对 | 万对级 | 数量级估算，随收敛比/速率变化 |
| GPU ID 等协议扩展设计 | 需预留标识位空间 | 中兴 2026-02 白皮书 |
| 硬件故障频率 | 约每小时 1–2 起 | 100k 卡 AFR 模型（行业经验口径） |
| 跨 DC 链路 | 相干 400G/800G ZR 类 DCI | 园区间互联通行方案 |

## 设计要点与权衡

- 电、网、楼三维联合设计：先定电力与建筑分期，再定网络平面与光纤路由；网络方案要给分期滚动建设留兼容缝（每期独立成域、可拼可拆）。
- 平面故障域隔离：单平面故障损失带宽不减连通，平面数（2/4/8）与单平面容量按业务可容忍的降级带宽选择。
- 拓扑调度与多作业拼用：十万卡的资源利用率依赖拓扑感知调度，"算力碎片 + 拓扑碎片"双维度回收；作业分级（大作业独占域、小作业填碎片）。
- 失败率工程前置：小时级故障频率下，checkpoint 频率、续训时长、备件池、自动隔离回池必须形成闭环，否则有效训练时间占比（goodput 口径）无法达标。
- 跨 DC 只做低频维度：跨 DC 训练的通信必须压缩到低频同步/参数面，带宽时延不对称需在并行策略层消化。

## 常见坑

- 按单集群最优设计，忽略分期滚动：第一期最优拓扑导致第二期无法拼入，二次布线成本巨大。
- 协议编址不留余量：GPU ID/路由表项/通信域标识在扩容时耗尽，协议层返工。
- 把跨 DC 当免费：时延与抖动跨园区是硬约束，盲目拉大作业跨 DC 比例直接拖垮步长。
- 只算卡不算电：机位好找、百 MW 级电力难落，选址延误是十万卡项目最大排期风险之一。
- 失败率工程后补：集群建成后再补自动隔离与续训，前期有效训练时间惨不忍睹。
