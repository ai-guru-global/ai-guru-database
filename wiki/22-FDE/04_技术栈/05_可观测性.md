# 可观测性

## FDE 的可观测性三支柱

```
Logs（日志）：发生了什么？
Metrics（指标）：系统状态如何？
Traces（链路）：一次请求经过了什么？
```

## 最小可行可观测性栈

| 组件 | 工具 | 作用 |
|---|---|---|
| 指标采集 | Prometheus + Node Exporter | CPU/内存/磁盘/网络 |
| 可视化 | Grafana | 仪表盘 |
| 日志采集 | Loki + Promtail | 应用日志聚合 |
| 链路追踪 | OpenTelemetry + Jaeger | 请求链路 |
| 告警 | Alertmanager → 企业微信/钉钉 | 异常通知 |

## 关键监控指标

```
AI 服务核心指标：
├── 请求量（QPS）
├── 延迟（P50/P95/P99）
├── 错误率（4xx/5xx）
├── Token 消耗量
├── 首 Token 延迟（TTFT）
└── 缓存命中率

基础设施指标：
├── CPU 使用率 >80% → 告警
├── 内存使用率 >90% → 告警
├── 磁盘使用率 >85% → 告警
├── GPU 显存使用率
└── 网络带宽

业务指标：
├── 日活用户（DAU）
├── 对话完成率
├── 用户满意度评分
└── 搜索无结果率
```

## FDE 的监控哲学

1. **先监控再优化**——不知道瓶颈在哪就别优化
2. **告警要可行动**——收到告警知道该做什么
3. **仪表盘要分受众**——技术看细节、业务看趋势、管理层看 ROI
4. **不要告警疲劳**——只告警真正需要人工干预的事
