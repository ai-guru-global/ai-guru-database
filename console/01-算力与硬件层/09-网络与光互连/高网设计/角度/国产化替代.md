# 国产化替代视角

> 一句话：跨机网络（交换机/光模块）国产化程度高，机内互联与 GPU 生态是短板——按「环节成熟度矩阵」逐环配对替代，而不是整栈一步到位。

## 核心问题清单

1. 哪些环节国产可选、哪些部分可替、哪些空白？
2. 千卡级国产 RoCE 集群的参考组合长什么样？
3. 生态碎片（每家卡一套通信库/工具链）怎么管理？
4. 可靠性与长稳数据不足的风险怎么对冲？
5. 替代节奏：哪些环节先替、哪些并行验证？

## 评估框架：可替代矩阵

| 环节 | 国产状态 | 代表与说明 |
|---|---|---|
| 交换机整机 | 可选 | 华为、新华三、锐捷的 400G/800G 盒式/框式已在智算中心规模部署 |
| 高端交换芯片 | 部分 | 51.2T 级国产自研芯片的规模商用进度（待核实）；整机走进口芯片 + 国产集成也是现实路径 |
| 光模块 | 强 | 旭创、新易盛等在 800G 全球份额领先；1.6T 跟进节奏（待核实） |
| 线缆/连接器 | 部分 | DAC/AEC 与高密连接器有国产供给；超高速连接器良率与产能（待核实） |
| 网卡 | 部分 | 400G RoCE 网卡有国产选项；800G PCIe 卡国产成熟度（待核实） |
| scale-up 互联 | 待核实 | 华为灵衢、摩尔线程夸娥 kUAE 超节点（2025）等路线的开放度与第三方适配进度（待核实） |
| 集合通信库 | 可选 | HCCL 等随卡提供，覆盖 NCCL 主路径；跨厂商互通（待核实） |
| GPU 本体 | 生态差距 | 单卡算力接近，差距在软件栈（编译器/profiler/算子覆盖）与大规模可靠性数据 |

### 替代组合参考：千卡国产 RoCE 集群

| 层 | 选型 | 备注 |
|---|---|---|
| 计算 | 128 台 × 8 国产卡 | HBM 容量/带宽先跑算例验证 |
| 机内 | PCIe 自组或国产超节点域 | 域大小按 TP/EP 跨域流量算 |
| 跨机 | 每卡 1×400G RoCE，两层 Clos 1:1 | 2048 口 > 1024 卡口，余量扩到 2k 卡 |
| 交换机 | 国产 400G 盒式（华为/新华三/锐捷） | NOS 与监控配套一并验证 |
| 模块/线缆 | 国产 400G + 柜内 DAC/AEC | 双供应商策略同采购与TCO篇 |
| 通信库 | 随卡 HCCL 类库 | 基线口径先立（对标 nccl-tests 指标）再迁 |
| 运维/存储 | 国产并行存储 + 国产运维栈 | 巡检/拨测/分工界面照网络运维篇执行 |

### 风险清单

1. 生态碎片：每家 GPU 配自己的通信库/驱动/算子集，混部集群互通成本高；卡型要收敛。
2. 工具链：profiler、算子覆盖、编译优化与 CUDA 生态的差距直接吃 MFU，验收必须按 MFU 而非峰值算力。
3. 可靠性数据不足：72h+ 长稳与 AFR 主要靠自建试点积累，备件率按保守口径上浮。
4. 供货与交期：国产高端模块/连接器同样有产能爬坡期，提前量口径同采购与TCO篇。
5. 规范与专利：UALink/UEC 的国内参与度与专利风险（待核实）。

## 关键指标与基线

| 指标 | 基线 | 口径 |
|---|---|---|
| 千卡 all_reduce busbw | ≥400G 线速 90% | 国产库对标 nccl-tests 口径 |
| MFU 验收 | 与同代进口卡的差距先量化再立项 | 训练侧口径 |
| 长稳 | 72h 无掉卡、无性能衰减 | 试点先行 |
| 国产化率 | 按环节加权（卡数/金额双口径） | 招标口径 |

## 常见误区

1. 整栈一步到位：跨机成熟、机内与生态不成熟，应分环节替代并保留对照环境。
2. 用峰值算力替代 MFU 验收：掩盖通信库与算子覆盖的差距。
3. 低估通信库绑定：换卡 = 换库 = 重跑全部基线，混部集群成本被系统性低估。
4. 只看单点性能不做长稳：国产件的 AFR 数据要自己攒，没有捷径。
