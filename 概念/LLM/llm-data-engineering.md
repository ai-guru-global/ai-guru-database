# LLM 数据工程 (LLM Data Engineering)

> 中文简称：LLM 数据工程

> 数据是 LLM 的燃料——同样的架构和算力，数据质量/数量/配比决定模型是「废铁」还是「SOTA」。

---

## 1. 定义

**LLM 数据工程**是围绕 LLM 训练全生命周期的数据管理实践，包括预训练数据清洗、SFT 数据构建、偏好数据标注、合成数据生成。

> LLaMA 3 用 15T 精选 token 达到 GPT-4 级性能，证明**数据质量 >> 数据数量**。

---

## 2. 数据流水线

| 阶段 | 规模 | 来源 | 关键技术 |
|------|------|------|----------|
| **预训练** | 1-15T tokens | 互联网/书籍/代码 | 去重、过滤、配比 |
| **SFT** | 10K-1M 条 | 人工标注/AI生成 | 质量>数量，覆盖度 |
| **RLHF/DPO** | 10K-1M 对 | 人类/AI偏好 | 一致性，去偏 |
| **合成数据** | 可变 | 教师模型蒸馏 | 多样性控制 |

---

## 3. 预训练数据处理

```
清洗流水线: 原始网页 → 文本提取 → 语言识别 → 基础过滤 → 去重 → 质量评分 → 输出
保留率: 通常仅 5-15%
```

---

## 4. SFT 数据方法

| 方法 | 规模 | 质量 | 代表 |
|------|------|------|------|
| 人工标注 | 10K-100K | 最高 | LLaMA 2 Chat |
| Self-Instruct | 100K+ | 中高 | Alpaca |
| Evol-Instruct | 100K+ | 中高 | WizardLM |
| 蒸馏 | 1M+ | 中 | Orca, Phi-2 |

---

## 微调数据集怎么造（大白话）

> **一句话理解**：微调数据 = 模型的"教材",质量 > 数量 > 多样性。1 万条精心写的高质量数据,吊打 10 万条网上爬的脏数据。

---

### 数据集的 4 种来源

| 来源 | 成本 | 质量 | 规模 | 适用 |
|------|------|------|------|------|
| **人工标注** | $1-10/条 | 最高 | 1K-100K | 高质量领域数据 |
| **Self-Instruct** | $0.001/条 | 中高 | 100K+ | 通用指令微调 |
| **蒸馏大模型** | $0.01/条 | 中高 | 100K-1M | 复刻 GPT-4 能力 |
| **用户日志** | $0 | 参差 | 大 | 真实场景适配 |

---

### SFT 数据集的标准结构

每条数据 = **指令 + 输入(可选) + 理想输出**

```json
{
  "instruction": "把下面这句话翻译成英文",
  "input": "今天天气真好",
  "output": "The weather is really nice today."
}
```

或者对话格式(Chat 模板):
```json
{
  "messages": [
    {"role": "system", "content": "你是一位专业翻译"},
    {"role": "user", "content": "把下面这句话翻译成英文:今天天气真好"},
    {"role": "assistant", "content": "The weather is really nice today."}
  ]
}
```

### 数据构造的 5 个核心原则

#### 1. **质量 > 数量**

LLaMA 3 用 15T 精选 token 达到 GPT-4 级性能——**数据精选 >> 数据堆量**。

实操 checklist:
- 答案必须**准确**(领域专家审核)
- 答案必须**清晰**(没有歧义)
- 答案必须**完整**(不偷懒、不省略)
- 答案必须**格式统一**(便于模型学习模式)

#### 2. **多样性覆盖**

| 维度 | 要覆盖什么 |
|------|----------|
| 任务类型 | 分类、生成、推理、对话、工具调用... |
| 难度 | 简单、中等、困难 |
| 领域 | 金融/医疗/法律/技术(按业务来) |
| 输入长度 | 短、中、长 |
| 边界场景 | 模糊问题、敏感问题、答不上来的 |

经验:100 条高质量数据覆盖 10 类任务,**比 1000 条单一任务数据**效果好。

#### 3. **不要污染测试集**

**数据泄漏 = 灾难**:
- 训练数据里**绝对不能出现**测试集的题目
- 否则模型只是"背答案",评估分数虚高
- 做法:严格分 train/val/test,**先切分再清洗**

#### 4. **去重 + 去脏**

```
原始数据 → 去重(完全重复 + 近似重复)→ 去脏(广告/低质/错误)→
过滤掉过长过短 → 敏感信息脱敏 → 标准化格式
```

经验:从 10 万条原始数据清洗出 1-3 万条高质量,**很常见**。

#### 5. **构造"对比样本"(DPO 用)**

如果做 DPO/RLHF,需要**偏好对**:
```json
{
  "prompt": "解释什么是量子纠缠",
  "chosen": "通俗版:两个粒子一旦纠缠,无论相隔多远... (好答案)",
  "rejected": "量子纠缠是物理学概念...(干巴、错误的答案)"
}
```

### 5 种主流数据构造方法详解

#### 1. 人工标注

**适用**:小批量、高质量、领域专业
**流程**:
```
写标注指南 → 培训标注员 → 试标 → 校准 → 正式标注 → 抽检 → 验收
```
**成本**:$1-10/条,周期 1-4 周

#### 2. Self-Instruct(自指令)

**适用**:大量通用指令数据
**流程**:
```
种子任务(100 条) → LLM 生成新任务 → LLM 生成答案 → 过滤低质 → 循环
```
**代表**:Alpaca(52K)、WizardLM
**风险**:会生成幻觉和重复,需要严格过滤

#### 3. Evol-Instruct(进化指令)

**适用**:增加数据复杂度
**核心思想**:用 LLM 把简单问题**变复杂**——加约束、加深度、加步骤。
**代表**:WizardLM(用 Evol-Instruct 扩到 250K)

#### 4. 蒸馏(从大模型学习)

**适用**:复刻 GPT-4 能力到开源小模型
**流程**:
```
GPT-4(教师) → 回答一批问题 → 用 GPT-4 的回答训练开源模型(学生)
```
**代表**:Orca、Phi-2、OpenHermes
**注意**:教师模型的偏见会被学生继承

#### 5. 用户反馈挖掘

**适用**:真实场景适配
**做法**:从产品日志里捞"用户改写过的答案"或"用户点赞的回答",作为微调数据
**优点**:免费、真实、贴合业务
**缺点**:噪声大,要清洗

---

### 数据集规模经验值

| 模型规模 | 微调数据量 | 训练 epoch |
|---------|-----------|-----------|
| 7B | 1K-50K 条 | 2-5 |
| 13B | 5K-100K 条 | 2-4 |
| 70B | 10K-200K 条 | 1-3 |

**黄金法则**:**数据越多,epoch 越少**——多了会过拟合。

---

### 数据集质量自检清单

发布/使用前过一遍:

- [ ] **准确性**:抽样 100 条人工核对,错误率 < 2%?
- [ ] **多样性**:覆盖了至少 5 类任务、3 个难度?
- [ ] **无泄漏**:测试集题目在训练集里搜不到?
- [ ] **去重**:没有完全重复或近似重复?
- [ ] **格式统一**:所有数据能用同一个模板加载?
- [ ] **敏感信息**:没有手机号/身份证/客户隐私?
- [ ] **答案长度**:不要全是 1 句话或全是长文?
- [ ] **风格一致**:不要一半口语一半论文?

## 2026 LLM 数据工程生态

| 特性/工具 | 说明 | 状态 |
|------|------|------|
| **合成数据** | LLM 生成高质量训练数据 | GA |

| **RLHF 数据** | 人类反馈数据收集平台 | GA |
| **数据飞轮** | 生产数据反哺训练闭环 | GA |
| **合规治理** | 数据版权/隐私合规检查 | GA |

## 生产最佳实践

1. **质量优先**：数据质量比数量重要，小规模高质量数据效果更佳
2. **去重必做**：训练数据必须去重，避免过拟合
3. **合成数据**：用强模型生成弱模型的训练数据
4. **合规审查**：训练数据来源必须合规，避免版权风险
5. **版本管理**：数据集版本化，确保可复现性
