## 一、类型学与边界（1–4）

**1. Agent 为什么需要记忆系统？**
**因为上下文窗口是请求级的，而用户和任务是跨会话的**——没有记忆，Agent 每次都从零开始，无法个性化、无法积累经验。

**2. 四类记忆和各自的载体？**
**工作记忆在上下文窗口、情景记忆在会话日志/向量库、语义记忆在向量库或知识图谱、程序记忆在技能与工具配置**——类比人脑的 RAM、日记、知识、肌肉记忆。

**3. 记忆和 RAG 什么关系？**
**同技术栈、不同对象**——RAG 检索静态文档知识，记忆检索「关于用户与 Agent 自身的动态事实」；长期记忆本质是「对自己的 RAG」，但多了写入决策与冲突消解两个 RAG 没有的问题。

**4. 上下文都 1M token 了，还要记忆吗？**
**要**——长上下文只替代窗口内的压缩摘要，跨会话持久化、按需检索的成本优势、显式的更新/删除语义，三样它都给不了；历史无限积累，窗口不会。

## 二、写入与检索（5–9）

**5. 记忆什么时候写？**
**三档并存：显式指令（用户说记住）、启发式规则（用户纠正/重复偏好）、LLM 判定（Mem0 式 ADD/UPDATE/DELETE/NOOP 四动作）**——成本递增、覆盖面递增，生产上三档组合。

**6. 写什么？**
**抽事实不存原文**——提炼第三人称原子事实（「用户用 zsh」）+ metadata（时间戳/来源/置信度）；原文只留会话日志供反思回溯。

**7. 记忆检索怎么排序？**
**加权融合：语义相似度 × 重要性 × 时间衰减**——典型配比 0.5/0.3/0.2，时间衰减用半衰期函数（如 0.5^(天数/7)）；纯相似度会把陈年噪音顶到前面。

**8. 新旧记忆冲突怎么处理？**
**四动作：ADD 新事实、UPDATE 覆盖旧值（留历史）、DELETE 失效事实、NOOP 语义重复**——两原则：时间新者胜、用户显式指令胜过模型推断。

**9. 反思（reflection）机制是什么？**
**LLM 读近期情景记忆，提炼跨会话有效的洞察存入语义层**——唯一能提升记忆质量的动作（其余只改变数量）；每条洞察须可回溯 ≥2 条情景记忆，防单次幻觉固化。

## 三、产品选型（10–14）

**10. Mem0 和 Zep 怎么选？**
**按「事实会不会变」分叉**——Mem0 是轻检索层（LLM-as-Judge + 向量，易运维）；Zep/Graphiti 是时序知识图谱（bi-temporal，内建事实演变追踪与时间推理）；用户事实频繁变化的场景选 Zep。

**11. Letta（MemGPT）解决什么问题？**
**长对话的 OS 式分层**——借鉴虚拟内存：核心上下文当 RAM、外部存储当硬盘，自动分页换入换出；单会话数万 token 的重度场景用它。

**12. Claude Memory Tool 的意义？**
**记忆从自建中间件变成平台原语**——file-based、client 维护、零服务依赖；省掉一层自研，代价是平台锁定与跨平台迁移成本。

**13. LangMem 什么时候用？**
**已 deep-dive LangGraph 生态时**——semantic/episodic/procedural 三类记忆与 LangGraph state 模型天然整合；框架未定则选框架无关的 Mem0/自建。

**14. 单用户本地部署（隐私优先）选什么？**
**Mem0 OSS + 本地向量库首选，file-based 自建是更轻替代**——全程数据不出机；Zep 图谱运维重量与单用户不匹配；Mem0 存的是文本事实，未来迁移兼容。

## 四、压缩与遗忘（15–17）

**15. 压缩、摘要、反思、遗忘的分工？**
**压缩救窗口（上下文内降 token）、摘要救历史（长历史变短总结）、反思救质量（情景提炼成语义洞察）、遗忘救容量（淘汰低价值）**——四者触发、产物、风险各不相同，混用是「越用越糊」的根因。

**16. 记忆遗忘有哪些策略？**
**四类：TTL 过期、评分淘汰（访问频率+显式权重+新近度+关联度加权）、冲突覆盖、合规删除**——淘汰先进归档缓冲层而非直接删，防误删用户重要事实。

**17. 记忆库膨胀怎么治理？**
**分层升降级 + 定期反思 + 评分淘汰三件套**——L2 短期层设 TTL、L3 长期层设评分线、反思把噪音提炼成少而准的语义事实；只加不过滤的写入是膨胀主因。

## 五、安全与多租户（18–20）

**18. 记忆系统有什么独有攻击面？**
**记忆注入（prompt injection 持久化）**——恶意内容被写入记忆后，会在未来所有会话持续生效；缓解：写入前内容过滤、记忆来源标注、敏感操作前人工确认。

**19. 记忆里的 PII 怎么管？**
**入口匿名化 + 出口权限过滤 + 被遗忘权删除**——存储前 PII 检测脱敏，检索时按权限过滤，用户主张删除时主库/快照/日志/缓存全链路清除。

**20. 多租户记忆怎么隔离？**
**user_id/tenant 级命名空间 + 检索层强制过滤 + 应用层二次校验**——记忆库必须把租户隔离做进元数据过滤（同 RAG 多租户），跨租户记忆共享只能走显式的「团队知识」通道。
