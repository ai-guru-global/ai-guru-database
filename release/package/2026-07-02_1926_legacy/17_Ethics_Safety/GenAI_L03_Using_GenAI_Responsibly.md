## 负责任 AI 原则

生成式 AI 的热潮前所未有。这种热潮吸引了许多新开发者、关注和资金涌入这一领域。虽然这对任何希望利用生成式 AI 构建产品和公司的个人来说是非常积极的，但我们也需要以负责任的态度继续前行。

### 六大核心原则

在整个课程中，我们将专注于构建我们的初创公司和 AI 教育产品。我们将使用以下**负责任 AI 的六大核心原则**：

| 原则 | 英文 | 含义 |
|------|------|------|
| 公平性 | Fairness | 确保 AI 系统没有偏见和歧视，公平平等地对待每个人 |
| 包容性 | Inclusiveness | 确保 AI 系统能够为所有人群提供服务，包括残障人士 |
| 可靠性/安全性 | Reliability & Safety | 确保 AI 系统在预期条件下可靠运行，在意外情况下安全失败 |
| 安全与隐私 | Security & Privacy | 保护用户数据和隐私，防止未经授权的访问 |
| 透明性 | Transparency | 让用户了解 AI 系统的工作方式和限制 |
| 问责制 | Accountability | 建立明确的责任机制，确保 AI 系统的开发和使用可追溯 |

### 为什么优先考虑负责任 AI

在构建产品时，采用以人为本的方法，时刻关注用户的最佳利益，通常会带来最佳结果。

生成式 AI 的独特之处在于它能够为用户生成有用的答案、信息、指导和内容。这可以在不需要太多手动步骤的情况下完成，从而产生令人印象深刻的结果。然而，如果没有适当的规划和策略，它也可能对用户、产品以及整个社会造成一些不良影响。

## 三大核心风险

### 风险一：幻觉（Hallucination）

"幻觉"是指当大型语言模型生成的内容**完全无意义**或**根据其他信息来源明显错误**时的情况。

**教育场景中的具体示例**：

假设我们为初创公司构建了一个功能，允许学生向模型提问历史问题。一名学生问了一个问题：

**学生提问**：`谁是泰坦尼克号的唯一幸存者？`

**模型回答**（幻觉示例）：

> 泰坦尼克号的唯一幸存者是维奥莱特·杰索普（Violet Jessop）。她是一位在泰坦尼克号沉没事件中幸存的女性...

**问题分析**：

这是一个非常自信且详尽的回答。不幸的是，它是错误的。即使进行最少量的研究，也会发现泰坦尼克号灾难中有**超过 700 名幸存者**，而不是只有一名。对于刚开始研究这一主题的学生来说，这个答案可能足够有说服力，以至于不会被质疑并被当作事实对待。

**幻觉的潜在危害**：
- 导致 AI 系统不可靠
- 损害我们初创公司的声誉和用户信任
- 在教育场景中，可能导致学生学习错误的知识
- 在医疗、法律等专业领域，幻觉可能造成严重后果

**幻觉随时间的变化**：

随着每一代大型语言模型的迭代，我们已经看到在减少幻觉方面的性能有所提高。即使有了这些改进，作为应用构建者和用户，我们仍需意识到这些局限性。幻觉不太可能被完全消除，我们需要设计系统来检测和管理它。

### 风险二：有害内容

除了错误信息，我们还需要注意另一种风险——模型可能生成有害内容。

**有害内容的定义和分类**：

| 类型 | 描述 | 示例 |
|------|------|------|
| 自残/伤害指导 | 提供自残或伤害某些群体的指示或鼓励 | 教唆自残行为的方法 |
| 仇恨言论 | 仇恨或贬低某些群体的内容 | 基于种族、性别、宗教的歧视性言论 |
| 暴力计划 | 指导任何类型的攻击或暴力行为 | 提供制作危险物品的步骤 |
| 非法行为 | 提供如何找到非法内容或实施非法行为的指示 | 教授网络攻击或欺诈的方法 |
| 性露骨内容 | 显示性露骨内容 | 不适合未成年人的内容 |

**教育场景中的风险**：

对于我们的初创公司，我们需要确保拥有合适的工具和策略，以防止学生看到此类内容。特别是在教育产品中，保护未成年用户免受有害内容的影响至关重要。

### 风险三：缺乏公平性

公平性被定义为"确保 AI 系统没有偏见和歧视，并公平平等地对待每个人"。

**在生成式 AI 中的表现**：

在生成式 AI 领域，我们希望确保模型输出不会强化对边缘化群体的排斥性世界观。这包括但不限于：

- **性别偏见**：模型可能默认使用特定性别的代词或描述
- **种族偏见**：模型可能对某些种族群体有不准确的刻板印象
- **文化偏见**：模型可能过度反映训练数据中占主导地位的文化观点
- **社会经济偏见**：模型可能对不同的经济背景做出不合理的假设

**影响**：

这些类型的输出不仅会破坏为用户构建积极产品体验的努力，还会对社会造成进一步的伤害。作为应用构建者，我们在使用生成式 AI 构建解决方案时，应始终考虑广泛且多样化的用户群体。

## 四步缓解框架

现在我们已经确定了负责任生成式 AI 的重要性，让我们来看看可以采取的四个步骤，以负责任的方式构建我们的 AI 解决方案。

### 第一步：测量潜在危害

在软件测试中，我们测试用户在应用上的预期操作。同样，测试用户最有可能使用的一组多样化的提示也是测量潜在危害的好方法。

**具体方法**：

1. **准备领域相关提示列表**：由于我们的初创公司正在构建一个教育产品，准备一份与教育相关的提示列表会很有帮助。这可以涵盖：
   - 某些学科（数学、历史、科学等）
   - 历史事实的查询
   - 关于学生生活的提示
   - 敏感话题的查询

2. **多样化测试**：确保提示列表涵盖不同年龄、背景、文化视角的用户可能提出的问题

3. **边界测试**：设计一些可能触发模型生成有害或不准确内容的边界案例

4. **记录和分类**：记录每个测试结果，按照危害类型进行分类（幻觉、有害内容、偏见等）

### 第二步：缓解潜在危害

这是四步框架中最关键的一步，我们可以从四个不同的层面来看：

#### 层面一：模型层面

**策略**：
- **选择合适的模型**：像 GPT-4 这样更大、更复杂的模型在应用于较小且更具体的用例时可能会带来更多有害内容的风险。选择与任务匹配的模型
- **微调模型**：使用你的训练数据进行微调可以减少有害内容的风险
- **评估模型版本**：不同版本的有害内容过滤能力可能不同

#### 层面二：安全系统

安全系统是模型服务平台上的一组工具和配置，用于帮助缓解危害。

**关键组件**：

| 组件 | 功能 | 示例 |
|------|------|------|
| 内容过滤系统 | 检测并过滤有害内容 | Azure OpenAI 服务中的内容过滤器 |
| 越狱检测 | 检测用户试图绕过安全限制的行为 | 识别提示注入攻击 |
| 活动监控 | 监控异常使用模式 | 检测来自机器人的大量请求 |
| 速率限制 | 防止滥用和过度使用 | API 调用频率限制 |

**Azure OpenAI 内容过滤系统**：

Azure OpenAI 服务内置了多层内容过滤系统，可以自动检测和处理以下类别的有害内容：
- 仇恨和公平性相关内容
- 性相关内容
- 暴力内容
- 自残相关内容

#### 层面三：元提示（Metaprompt）

元提示和基础信息是我们可以根据某些行为和信息来引导或限制模型的方法。

**方法**：

1. **系统消息**：使用系统输入来定义模型的某些限制。例如：
   ```
   你是一个教育助手。只回答与学习相关的问题。
   如果问题超出教育范畴，礼貌地告知用户你只能回答教育相关问题。
   ```

2. **基础信息**：提供更符合系统范围或领域的输出

3. **检索增强生成（RAG）**：使模型仅从一组可信来源中提取信息。这是控制信息来源的有效方法，可以减少模型编造内容的风险

**RAG 在负责任 AI 中的作用**：
- 限制模型的信息来源为可信数据
- 提供可追溯的引用和来源
- 减少幻觉的发生概率
- 确保输出的信息有据可查

#### 层面四：用户体验

最后一层是用户通过我们应用的界面直接与模型交互的方式。

**策略**：

1. **输入限制**：通过 UI/UX 设计限制用户向模型发送的输入类型
   - 使用预设的问题模板或建议
   - 对自由文本输入进行前端过滤
   - 提供明确的输入指引

2. **输出展示**：控制向用户显示的内容
   - 对模型输出进行后处理和过滤
   - 添加内容审核机制
   - 对敏感内容添加警告标签

3. **透明度**：在部署 AI 应用时，必须透明地说明
   - AI 应用可以做什么和不能做什么
   - 输出可能不完全准确
   - 用户应该独立验证重要信息

4. **反馈机制**：提供让用户报告问题输出的渠道
   - "报告问题"按钮
   - 用户满意度评分
   - 定期收集和分析用户反馈

### 第三步：评估模型

与大型语言模型合作可能具有挑战性，因为我们并不总是能够控制模型训练的数据。尽管如此，我们仍应始终评估模型的性能和输出。

**评估维度**：

| 维度 | 含义 | 测量方法 |
|------|------|----------|
| 准确性 | 输出内容的正确程度 | 与已知正确答案对比 |
| 相似性 | 输出与期望结果的一致程度 | 人工评审或自动化指标 |
| 基础性 | 输出是否有可靠的信息来源 | 检查引用和来源 |
| 相关性 | 输出与查询的相关程度 | 用户满意度调查 |

**评估的重要性**：

衡量模型输出的准确性、相似性、基础性和相关性仍然很重要。这有助于：
- 为利益相关者和用户提供透明度和信任
- 发现模型的弱点和改进方向
- 确保应用在持续迭代中保持或提升质量

### 第四步：运营负责任的生成式 AI 解决方案

围绕你的 AI 应用建立运营实践是最后阶段。

**关键运营实践**：

1. **跨部门协作**：与初创公司中的其他部门合作
   - 法律部门：确保符合所有法律法规
   - 安全部门：确保数据安全和隐私保护
   - 产品部门：平衡用户体验和安全性

2. **上线前准备**：
   - 制定详细的部署计划
   - 准备事件响应流程
   - 设计回滚方案，以防出现问题

3. **持续监控**：
   - 实时监控模型输出质量
   - 跟踪用户反馈和投诉
   - 定期审计系统安全性

4. **事件处理**：
   - 建立事件分级制度
   - 制定响应时间标准
   - 记录和总结每次事件的经验教训

## 工具与资源

虽然开发负责任 AI 解决方案的工作看起来很多，但这项工作是非常值得的。随着生成式 AI 领域的不断发展，帮助开发者高效地将责任融入工作流程的工具也将逐渐成熟。

### Azure AI 内容安全

[Azure AI 内容安全](https://learn.microsoft.com/azure/ai-services/content-safety/overview) 是一个重要的工具，可以通过 API 请求帮助检测有害内容和图像。

**主要功能**：
- 文本内容分析：检测仇恨言论、暴力、自残等多种有害内容
- 图像内容分析：识别不当图像
- 自定义类别：根据业务需求定义特定内容类别
- 多语言支持：支持多种语言的内容安全检测

**集成方式**：

```python
# Azure AI 内容安全 API 调用示例（概念性）
from azure.ai.contentsafety import ContentSafetyClient

# 创建客户端
client = ContentSafetyClient(endpoint="your_endpoint", credential=your_credential)

# 分析文本内容
result = client.analyze_text(
    text="需要分析的文本内容",
    categories=["Hate", "Violence", "SelfHarm", "Sexual"]
)

# 根据结果决定是否展示内容
for item in result.items:
    if item.severity > 0:
        print(f"检测到 {item.category} 类型的有害内容，严重程度: {item.severity}")
```

### 其他推荐工具和资源

- **Azure OpenAI 内容过滤**：内置在 Azure OpenAI 服务中，自动过滤有害内容
- **Prompt Shields**：检测和防止提示注入攻击
- **模型评估工具**：Azure AI Studio 提供的模型性能评估功能

## 知识检查

**问题**：为了确保负责任的人工智能使用，你需要关注哪些方面？

1. 答案是否正确
2. 防止有害使用，确保 AI 不会被用于犯罪目的
3. 确保 AI 没有偏见和歧视

**答案**：2 和 3 是正确的

**解析**：

负责任的人工智能不仅仅关注答案的正确性（尽管这也很重要），更重要的是关注如何减轻有害影响和偏见等问题。具体来说：
- 防止有害使用意味着确保 AI 系统不会被滥用于犯罪、伤害他人或传播有害内容
- 确保没有偏见和歧视意味着 AI 系统应该公平地对待所有用户，不因种族、性别、年龄等因素而区别对待
- 答案的正确性（选项 1）是重要的质量指标，但它不是"负责任 AI"的核心关注点
