# 系统集成

> **最后更新**：2026-08-03（补充向量库选型、MCP 标准化集成）

## FDE 集成的典型场景

政企客户的系统环境是"古董店+新零售"的混合体：有 20 年前的 Oracle 数据库，也有最新的微服务。FDE 必须能对接各种系统。

## 向量库选型（2025-2026）

| 库 | 类型 | 规模上限 | 适用场景 |
|---|---|---|---|
| **Milvus** | 分布式专用 | 十亿级+ | 大规模生产首选（30k+ Star，国内生态强） |
| **Qdrant** | Rust 专用、轻量 | 中大规模、单机低延迟 | 中等规模、性能敏感 |
| **pgvector** | PostgreSQL 扩展 | 小到中型（<千万） | **已有 PG 环境最务实**（政企常见） |
| **Chroma** | 嵌入式、轻量 | 小规模、原型 | 快速 POC |

> **benchmark 普遍结论**（来源：[Zilliz 对比](https://zilliz.com/comparison/milvus-vs-pgvector) · [Instaclustr](https://www.instaclustr.com/education/vector-database/pgvector-vs-milvus-5-key-differences-and-how-to-choose/)）：
> - 小规模（<千万）→ **pgvector 够用**，尤其客户已有 PostgreSQL
> - 千万-亿级 → **Milvus / Qdrant**
> - 十亿级+ → **Milvus**（分布式优势）

> **FDE 政企选型建议**：先用 pgvector 跑通（客户大概率已有 PG），数据量上来再迁 Milvus。

## MCP：标准化的集成新范式（2025-2026）

传统集成是逐个系统写定制 connector；**MCP（Model Context Protocol）** 把「Agent ↔ 工具/数据源」标准化，让客户内部系统（ERP/CRM/OA/数据库）能被任何兼容 Agent 统一调用。

```
旧模式（2024 前）：
  Agent → 定制 connector A → ERP
  Agent → 定制 connector B → CRM
  Agent → 定制 connector C → OA
  （每个系统都要单独写集成，维护成本高）

新模式（2025+）：
  Agent → MCP 协议 → ERP / CRM / OA / 数据库
  （一套协议对接所有系统，FDE 交付效率大幅提升）
```

> 详见 [Agent 协议栈](22-FDE/04_技术栈/07_Agent协议栈.md)。MCP 在私有化场景可完全离线运行，适合信创环境。

## 常见集成点

### 1. 身份认证集成

| 协议 | 客户环境 | FDE 方案 |
|---|---|---|
| LDAP | 内网 AD 域 | python-ldap 对接 |
| OAuth2/OIDC | 自建 SSO | Keycloak/OAuth2-proxy |
| SAML | 老系统 | pysaml2 对接 |
| CAS | 高校/政府 | flask-cas 对接 |

### 2. 数据源集成

```
结构化数据：
├── 关系数据库：PostgreSQL/MySQL/Oracle → SQLAlchemy
├── 国产数据库：达梦/人大金仓 → 专用驱动
├── 数据仓库：Hive/ClickHouse → 专用 connector
└── SaaS API：企业微信/钉钉/飞书 → REST API

非结构化数据：
├── 文件系统：NAS/对象存储 → MinIO/s3fs
├── 文档管理：SharePoint/Confluence → REST API
├── 邮件系统：Exchange/企业邮箱 → IMAP/EWS
└── 聊天记录：企业微信/钉钉 → 消息 API
```

### 3. 通知与协作集成

| 渠道 | 接口 | 用途 |
|---|---|---|
| 企业微信 | 群机器人 Webhook | 告警通知 |
| 钉钉 | 自定义机器人 | 审批通知 |
| 邮件 | SMTP | 定期报告 |
| 短信 | 阿里云/腾讯云 SMS API | 紧急告警 |

## 集成模式

### 模式 1：直连模式
```
AI 系统 → 直接调用客户系统 API
优点：实时性好
缺点：耦合度高，客户系统变更影响大
```

### 模式 2：中间层模式
```
AI 系统 → 数据中间层（ETL/CDC）→ 客户系统
优点：解耦，客户系统变更影响小
缺点：多一层维护
```

### 模式 3：事件驱动模式
```
AI 系统 ← 消息队列(Kafka/Pulsar) ← 客户系统
优点：异步、解耦、可扩展
缺点：复杂度高
```

## 集成铁律

1. **永远不要在生产环境直接改客户数据库**——用只读副本或 API
2. **集成之前先做数据采样**——避免全量同步带来的性能问题
3. **失败有降级**——集成挂了不能导致整个系统不可用
4. **日志可追溯**——每次集成调用记录请求/响应/耗时/状态
