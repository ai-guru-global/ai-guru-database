# Discovery（发现阶段）

## 目标

把"模糊的客户需求"转化为"清晰的项目定义"。这是 FDE 项目中**最重要的阶段**——方向错了，后面全错。

## 核心活动

### 1. 业务场景梳理

**四步提问法**：

```
Step 1: 现状
"你们现在怎么做这件事？"
→ 花 30 分钟看客户实际操作一遍

Step 2: 痛点  
"最痛苦的是什么环节？"
→ 追问 3 次"为什么"找到根因

Step 3: 期望
"如果有一个魔法工具，你希望它做什么？"
→ 不要限制想象力

Step 4: 约束
"有什么是不能做的/不能碰的？"
→ 安全红线、合规底线、预算上限
```

### 2. 利益相关方识别

```
权力/兴趣矩阵：

        高权力              低权力
高兴趣  【核心决策者】      【积极支持者】
        必须搞定            充分沟通
        ─────────────────
低兴趣  【潜在威胁者】      【路人】
        保持满意            定期通报
```

**必须搞清楚的问题**：
- 谁签合同/批预算？（经济决策者）
- 谁决定方案？（技术决策者）
- 谁每天用？（终端用户）
- 谁可能反对？为什么？

### 3. 成功指标定义

**SMART 原则落地**：

```
❌ 坏指标："提高工作效率"
✅ 好指标："客服人员处理一个工单的时间从 15 分钟降到 5 分钟"

❌ 坏指标："AI 要很准"
✅ 好指标："政策检索 top-5 准确率达到 85% 以上"

❌ 坏指标："系统要好用"
✅ 好指标："内测用户 NPS 评分达到 70 以上"
```

### 4. 数据与技术评估清单

```
□ 数据在哪？（数据库/文件系统/第三方API）
□ 数据量多少？（1000 条还是 1000 万条？）
□ 数据质量如何？（缺失率？格式统一吗？）
□ 数据有敏感信息吗？（需要脱敏吗？）
□ 客户 IT 环境？（OS/CPU/GPU/内存/网络）
□ 需要对接哪些现有系统？（SSO/ERP/CRM）
□ 客户团队技术能力？（能接手运维吗？）
```

### 5. 风险评估

| 风险类别 | 检查项 |
|---|---|
| 技术风险 | 客户环境支持我们的技术栈吗？ |
| 数据风险 | 数据质量和数量够支撑 AI 吗？ |
| 人员风险 | 关键对接人稳定吗？ |
| 合规风险 | 有没有没发现的合规要求？ |
| 商业风险 | 客户预算真的到位了吗？ |

## Discovery 阶段常见错误

1. **只听不问**：客户说什么就记什么，不追问根因
2. **过早承诺**：还没评估就说"这个能做"
3. **忽略反对者**：只和热心支持者聊，没发现潜在的阻碍
4. **跳过数据评估**：签了合同才发现数据根本不能用
5. **成功指标模糊**：项目结束时双方对"成功"的定义不一致
