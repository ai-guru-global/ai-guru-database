# 05 · SAIL SDK：PPU 软件栈全解

> 硬件参数决定能不能买，软件栈决定敢不敢用。官方名 **T-Head SAIL®**（阿里云页亦标 PPU SDK 2.2.0），2026-07-23 正式开源——国产自研 AI 芯片阵营第一个开放全栈的玩家。

## 命名与开源状态

- **命名口径**：官方全栈名 T-Head SAIL®；阿里云真武页（2026-11-06 检索）以「PPU SDK 2.2.0」指称同一软件栈；龙蜥社区渠道文（SegmentFault，2026-07）称「平头哥自研软件栈 T-Head SAIL® 正式开源」。三名同物，本库以 SAIL 为准。
- **开源状态**：**2026-07-23 正式开源**（龙蜥社区渠道文口径，🔍 一手锚点 developer.t-head.cn 下载中心待逐字核对）；**许可证未公开说明（❓ 挂账）**；未见公开 git 仓库——developer.t-head.cn 以「SDK 软件包、内核驱动、性能分析和调试工具」下载形式分发，是否逐字开放源码待核实。

## 五层技术栈（龙蜥渠道文口径，2026-07）

| 层 | 组件 | 说明 / 对标 |
|---|---|---|
| Driver 与 Runtime | PPU Driver（内核态 KMD + 用户态 UMD）+ PPU Runtime | 统一设备管理与内存管理接口 ↔ CUDA Driver/Runtime |
| 编程语言 | C/C++、Python 完整支持 | ↔ CUDA C++ / Python 前端 |
| 编译器 | Compiler + Debugger 两大组件，「构建完整的开发闭环」 | ↔ nvcc + cuda-gdb |
| 高性能库 | **六大数学库**：acBLAS / acDNN / acFFT / acRAND / acSOLVER / acSPARSE；编解码库 HGDEC / HGENC / HGJPEG / HGPP；集合通信 **PCCL 与 sailSHMEM**；acext 与 HGML | ↔ cuBLAS/cuDNN/cuFFT/cuRAND/cuSOLVER/cuSPARSE + NCCL |
| 开发者工具 | Asight Compute（算子级性能分析）、Asight Systems、PPU-SMI、PPU-DCGM | ↔ Nsight Compute/Systems + nvidia-smi + DCGM |

**组件口径注记**：集合通信库在阿里云页作「ACCL-P」、龙蜥文作「PCCL」——两名并存，可能为不同版本或同一库的演进命名（❓ 挂账，随版本核实）；acext 算子库两处口径一致；阿里云页另列 HolmesLLM 自研推理框架（↔ TensorRT-LLM），龙蜥五层文未单列——推断为库层之上的应用级框架（待核实）。

## 兼容面

- **框架**：龙蜥文原文「已全面适配 PyTorch、TensorFlow、vLLM、SGLang 等 **260 余个**主流训练与推理框架」（⚠️ 「260 余个」为官方口径未见清单）；阿里云页另列 Megatron / DeepSpeed / DeepEP 训练栈——训练钩 Megatron 系、推理钩 vLLM/SGLang 系的事实标准格局不变。
- **CUDA 兼容**：财新等媒体报道真武 PPU「与 CUDA 生态兼容」，wiki 内研究页称「SAIL 提供 CUDA 兼容层」；但官方页（aliyun.com/ppu，2026-11-06 检索）**通篇未提 CUDA**，只说编译器用法「与 GPU 类似、无缝切换」。三种可能：源码级迁移工具（类 HIPIFY）/ CUDA Graph 等 API 子集兼容 / 媒体对「易迁移」的误读——**兼容层级待核实（挂账）**，采购评估务必 POC 自有负载验证。
- **模型**：Qwen / LLaMA / DeepSeek / Kimi / GLM（官方页）；小米 MiMo-V2.5-Pro（1T 参数 / 1M 上下文）2026-04 完成 810E 适配并上架 PAI-Model Gallery（→ [08-模型生态绑定](08-模型生态绑定.md)）。
- **自动驾驶**：50+ 常见模型适配（感知/预测/端到端），PAI-TurboX 加速框架。

## OS 与生态位：龙蜥 AI Infra

SAIL 已基于龙蜥 ANCK（Anolis Cloud Kernel）内核完成**原生驱动适配**，覆盖 Anolis OS 7/8 与 Alinux 系列，并与龙蜥操作系统完成相互兼容性测试认证——这是 SAIL 第一个公开的 OS 生态位。含义（观点层）：国产 AI 芯片软件栈正在复制「国产 OS × 国产芯片」的捆绑打法，龙蜥（阿里主导）成为 PPU 的默认 OS 伙伴；对信创买家，这一认证本身就是采购理由。

## 「零代码修改」的真实边界（观点层）

框架层兼容承诺的是**主流路径零修改**。真实摩擦在三处：① 自定义 CUDA/C++ 算子需用 acext 重写或等价替换；② 调试与性能工具链的社区沉淀（Asight 系对标 Nsight 系但生态答案库需时间积累）；③ 依赖特定 CUDA 版本行为的第三方长尾库。**「零代码」对 80% 标准负载成立，剩余 20% 决定迁移的真实成本**——POC 必须测自有负载而非跑分（→ [06-软件路线对比](06-软件路线对比.md)）。
