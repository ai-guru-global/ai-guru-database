# 安全政策

AI News Database 团队非常重视用户的安全和隐私。由于本产品坚持「本地优先」原则，你的数据默认只存储在自己的设备上，这本身就大大降低了数据泄露的风险。

## 安全设计原则

1. **本地优先**：所有文章、阅读状态、笔记和配置默认存储在本地 SQLite 数据库中
2. **零遥测**：程序不会主动上传任何使用数据或崩溃报告到远程服务器
3. **API 密钥本地存储**：LLM 配置（`~/.ai-news-database/config.json`）仅存在于本地
4. **可选网络请求**：除文章采集和 LLM 调用外，程序不会进行其他网络通信

## 报告安全漏洞

如果你发现了安全漏洞，请通过以下方式向我们报告：

- **GitHub Security Advisories**: [创建私人安全建议](https://github.com/ai-guru-global/ai-guru-console/security/advisories/new)
- **电子邮件**: security@ai-news-database.dev（历史地址，维护者确认后更新）

请在报告中尽可能包含以下信息：

- 漏洞描述和影响范围
- 复现步骤
- 受影响的版本
- 可能的修复建议
- 是否需要公开披露的时间偏好

我们承诺：

- 在 **48 小时内** 确认收到报告
- 在 **7 天内** 提供初步评估
- 在修复完成后公开致谢报告者（除非报告者要求匿名）

## 已知限制

- **采集源安全性**：AI News Database 从第三方公开网站采集内容，无法保证这些网站 100% 安全。建议仅在可信网络环境下使用
- **LLM 服务商**：如果你配置了外部 LLM API，数据将通过 HTTPS 传输到该服务商。使用 Ollama 本地服务可以完全避免数据外传
- **本地文件权限**：`~/.ai-news-database/` 目录的权限取决于你的操作系统配置。建议确保该目录不对其他用户开放写入权限

## API Key 加密与机器迁移

LLM API Key 使用 AES-256-GCM 加密存储，加密密钥由本机特征（主机名 + 用户名 + 操作系统）派生。这意味着：

- **更换设备、修改主机名或用户名后，旧密文将无法解密**，这是预期行为（防止配置文件被直接拷走后泄露密钥）
- **迁移方法**：在旧设备上记录明文 API Key（从服务商控制台重新获取亦可），在新设备上重新配置 `~/.ai-news-database/config.json`，首次运行时会自动以新机器特征重新加密
- **解密失败的表现**：程序会提示 API Key 无效或未配置，此时重新填入明文 Key 即可，不会损坏其他数据（文章库与阅读状态不受影响）

## 浏览器扩展权限说明

扩展（v1.1.0+）仅申请 `localhost` / `127.0.0.1` 的 8080、8081 两个端口的访问权限，分别对应 Web 控制台与扩展 API 服务，不会访问其他本地端口或外部网站。
