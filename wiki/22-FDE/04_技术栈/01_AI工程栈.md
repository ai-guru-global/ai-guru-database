## FDE AI 技术栈全景

### 1. LLM 应用开发

| 层级 | 技术 | 推荐选型 |
|---|---|---|
| **模型调用** | API / 本地推理 | OpenAI API / Ollama / vLLM / SGLang |
| **编排框架** | Chain / Agent | LangChain / LlamaIndex / DSPy / Pydantic AI |
| **Prompt 管理** | 模板 / 版本管理 | LangSmith / Langfuse / 自建 Prompt 库 |
| **输出解析** | Structured Output | Pydantic / JSON Schema / Instructor |

**FDE 实战建议**：
- Dify 适合快速 POC（拖拽式搭建）
- LangChain/LangGraph 适合复杂定制（代码级控制）
- 自研框架适合规模化交付（可复用）

### 2. RAG 系统（2025-2026 主流平台对比）

| 平台 | 定位 | 强项 | 适用 |
|---|---|---|---|
| **Dify** | 企业级 LLM 应用全栈（BaaS+LLMOps） | 工作流+Agent+RAG 一体化、生态成熟（Apache 2.0 开源） | 私有化首选 |
| **Coze（扣子，字节）** | 零/低代码快速发 Bot | 上手最快、国内生态友好 | 快速 POC |
| **RAGFlow** | 开源 RAG 专项 | 复杂文档解析（PDF/表格/扫描件）最深，引用溯源 | 政企文档问答 |
| **FastGPT** | 开源知识库问答 | 工作流编排、国内社区活跃 | 中小项目 |

> **常见组合**：**RAGFlow（深度解析）+ Dify（编排发布）** —— 政企场景下 RAGFlow 负责把扫描件/复杂 PDF 解析干净，Dify 负责后续编排与发布。

> 来源：[火山引擎对比](https://developer.volcengine.com/articles/7501163741818257418) · [腾讯云对比](https://cloud.tencent.com/developer/article/2555423)

### 2.1 RAG 技术栈细节

```
文档摄入层
├── PDF 解析：PyMuPDF / Unstructured
├── 文档切分：RecursiveCharacterTextSplitter / Semantic Chunking
├── 元数据提取：自定义 Parser
└── 格式支持：PDF, DOCX, Markdown, HTML, 图片 OCR

向量化层
├── Embedding 模型：BGE / M3E / text2vec（中文）
├── 向量数据库：Milvus / ChromaDB / Qdrant
├── 索引策略：HNSW / IVF_FLAT
└── 维度选择：768 / 1024 / 1536

检索层
├── 混合检索：向量 + 关键词（BM25）
├── 重排序：BGE-Reranker / Cohere Rerank
├── 多路召回：多查询策略
└── 上下文压缩：LongContextReorder

生成层
├── Prompt 模板：System Prompt + Context + Query
├── 引用标注：来源溯源
├── 幻觉检测：Self-Check / NLI 验证
└── 流式输出：SSE / WebSocket
```

### 3. Agent 开发（2025-2026 框架对比）

| 框架 | 出品方 | 特点 | 最适场景 |
|---|---|---|---|
| **LangGraph** | LangChain | 图式编排，生产级细粒度控制最强 | 生产级多 Agent 系统（FDE 首选） |
| **AutoGen v0.4** | Microsoft（已分叉出 AG2） | 研究型对话式多 Agent | 研究、复杂对话 |
| **CrewAI** | CrewAI Inc. | 角色化、可读性强的多 Agent 工作流 | 快速搭角色分工的 Agent 团队 |
| **OpenAI Agents SDK** | OpenAI（2025.3.11 发布） | 最新，2026.4 加原生沙箱；将取代 Assistants API | OpenAI 生态、新项目 |
| **Google ADK** | Google | 与 A2A 协议深度集成 | Google Cloud 生态 |
| **Claude Agent SDK** | Anthropic | 与 MCP 深度集成 | Claude 生态 |
| **Pydantic AI** | Pydantic 团队 | 类型安全、Pythonic | 重视类型安全的生产项目 |

> ⚠️ **OpenAI Agents SDK 注意**：截至 2026 年缺原生 RAG/向量库支持，需自行集成。

**Agent 协议层（2025-2026 新增）**：详见 [Agent 协议栈](22-FDE/04_技术栈/07_Agent协议栈.md)。MCP / A2A / AG-UI 三层协议让 Agent 系统从「定制集成」走向「标准化组装」。

> 来源：[Langfuse 框架对比](https://langfuse.com/blog/2025-03-19-ai-agent-comparison) · [Composio 对比](https://composio.dev/content/openai-agents-sdk-vs-langgraph-vs-autogen-vs-crewai) · [Victor Dibia 对比](https://newsletter.victordibia.com/p/autogen-vs-crewai-vs-langgraph-vs)

| 组件 | 技术 | 说明 |
|---|---|---|
| **工具定义** | Function Calling / MCP | 工具标准化接口（2026 年 MCP 成事实标准） |
| **记忆系统** | 短期记忆 + 长期记忆 | 上下文管理 |
| **规划能力** | ReAct / Plan-and-Execute | 任务分解与执行 |
| **安全沙箱** | Docker / E2B / OpenAI 原生沙箱 | 代码执行隔离 |

### 4. 模型部署

| 引擎 | 特点 | 适用场景 |
|---|---|---|
| **Ollama** | 最简单，单机部署 | 开发测试 / 小规模 POC |
| **vLLM** | 高吞吐，PagedAttention | 生产级推理（GPU） |
| **llama.cpp** | CPU 推理，GGUF 量化 | 无 GPU 环境 |
| **Text Generation Inference** | HuggingFace 官方 | HF 生态集成 |
| **Triton Inference Server** | NVIDIA 官方 | 企业级多模型服务 |

### 5. 评估与可观测性（2025-2026 主流工具对比）

| 工具 | 特点 | 适用场景 |
|---|---|---|
| **LangSmith** | 与 LangChain/LangGraph 深度集成（LangChain 原生） | 已用 LangChain 生态 |
| **Langfuse** | 开源、可自托管、隐私敏感负载首选、厂商中立 | **政企私有化首选**（数据不出客户环境） |
| **Arize Phoenix** | 开源、源于传统 ML 可观测、漂移检测/eval 强 | 需要传统 ML 可观测能力 |

> **政企 FDE 选型建议**：优先 **Langfuse 自托管**——开源可控、数据不出客户环境，满足等保要求。

> 来源：[ZenML 对比](https://www.zenml.io/blog/langfuse-vs-phoenix) · [DigitalApplied 2026 对比](https://www.digitalapplied.com/blog/agent-observability-platforms-langsmith-langfuse-arize-2026)

| 评估维度 | 工具 | 指标 |
|---|---|---|
| **RAG 评估** | RAGAS / DeepEval | Faithfulness, Relevance, Precision |
| **Prompt 评估** | Promptfoo / Langfuse | 准确率、一致性 |
| **性能测试** | Locust / k6 | QPS、延迟、并发 |
| **安全测试** | Garak / 自定义 | 注入攻击、越狱 |

---

> **FDE 选型第一原则**：能在客户环境跑起来 > 技术先进性。不要因为选了"最好"的技术而导致交付失败。
