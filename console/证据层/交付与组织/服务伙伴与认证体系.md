# 服务伙伴与认证体系

> 交付能力一旦被写成证书，它买到的到底是什么：投标与分包资格、伙伴名录曝光、还是返点档位。本线索比较五套资格制度把"认证"绑在什么合同机制上——腾讯云 ADP FDE 认证、阿里云 AI 大模型生态计划（按调用量）、阿里云服务伙伴计划（按认证人员定级）、Salesforce 伙伴分级、ServiceNow 伙伴名录——并记录国内两家云厂商在 FDE 专项认证上的**缺位证据**。

## 概述

**分工声明：本条只处理资格与制度面**——认证由谁发、与什么合同权利绑定、能否被购买。FDE 的岗位史（Palantir 2005 年设立 Echo/Delta）、薪资公开口径、以及"自建团队 vs 认证外包两条互斥成本曲线"的论证，归 [[交付与组织/FDE前沿部署工程师]]，本条不重述、不引用其结论作为事实。

**已确认的一手节点是腾讯云 ADP 认证体系的调整。** 2026-08-17 腾讯云官方公告新增《腾讯云 ADP 前沿部署工程师（FDE）认证》，面向智能体前沿部署方向，与原 AI App Engineer 认证并行（[腾讯云国际站官方公告](https://intl.cloud.tencent.com/zh/announce/detail/101469) ✅）；2026-09-10 腾讯云对外称"行业首个 FDE 工程师认证"并**同步启动 FDE 合作伙伴招募**（[东南早报经腾讯新闻](https://view.inews.qq.com/a/20260910A08D0400)、[腾讯云 ADP 活动页](https://cloud.tencent.com/act/pro/openclaw-in-adp)），能力项覆盖场景理解、全生命周期交付与安全合规。认证与伙伴招募在同一天宣布，是本线索"认证即入场券"这一判断的唯一时点证据。

官方活动页（[cloud.tencent.com/act/pro/openclaw-in-adp](https://cloud.tencent.com/act/pro/openclaw-in-adp) ✅ 200／186,871 字节，活动时间 2026-09-11 至 2026-10-31）逐字给出该认证的定义：「前沿部署工程师（Forward Deployed Engineer）深入客户业务现场，负责将智能体从方案设计推进至上线运营，并对交付结果负责」，面向人群原文为「腾讯云合作伙伴的专业工程师与个人开发者」；三大能力中的**交付实施**明确列出考察场景——**金融、政务、制造、零售、医疗、教育**，即认证线与教育、金融等行业垂类线在同一页面上交叉（见 [[行业应用/AI教育]]、[[行业应用/AI金融]]）。⚠️ 该页参与四步的第一步是「注册开通（**新客购买套餐加赠 100 元 PU**）」，另有「赠 100 元 PU 额度（约 5000 万 token）」与年付 8.3 折 ⇒ **认证以消耗承诺为前提**，这是"入场券"判断的页面级依据。页面关键词实测：FDE 34／「前沿部署」6／ADP 67／「合作伙伴」6／**「交付工程师」0**。厂商「首推行业 FDE 工程师认证」的话术**不采信为"行业首个"**（无可比认证清单，见来源档案第四节防污染表）。

**但认证宣布后出现了购买路径缺位。** 2026-08-20 腾讯云开发者社区已有提问"为什么现在还没有 FDE 认证的购买入口"（[社区提问](https://cloud.tencent.com/developer/ask/2212707) ✅ 页面时间戳 **2026-08-20 08:41:03**，回答 0／关注 0／查看 473），公告（08-17）与提问（08-20）相隔**三天**。这条不是质量结论，而是一个可核验的顺序事实：**先有标准公告，后有兑付渠道**。提问正文逐字引用了 08-17 公告的三句（保留原有认证／新增 FDE 认证／并行运营），说明公告内容已被需求侧读到，缺的只是购买动作的落点。

**国内对照：阿里云与火山引擎未见 FDE 专项认证。** 阿里云「AI大模型销售与服务生态合作计划」（[partner.aliyun.com/program/aimsp](https://partner.aliyun.com/program/aimsp) ✅ 抓取于 2026-09-30）逐字列出的认证只有两项——**「阿里云AI大模型ACA/ACP认证」**与**「大模型服务专家认证 ASE-PTAM L3」**；同一页面列出的激励是**「百万调用奖」「五十万调用奖」「灵码专项」**，结算单位是调用量。页面全文**未出现"前沿部署 / FDE / 交付工程师"**字样。⚠️ 阿里云侧是**两个不同计划**，不可合并为"阿里云的伙伴制度"：[partner.aliyun.com/programs/service](https://partner.aliyun.com/programs/service) ✅（200／121,034 字节／去标签正文 13,697 字符）把「**阿里云的服务能力认证**」「**ACP/ACE 认证人员**」「服务案例数」「专职服务团队人数」四项同时写进 标准级／优选级／精英级／战略级 的等级条件（认证人员 —／5人+／10人+／15人+，服务案例 5+／10+／15+／20+，专职团队 5／10／20／50 人+；档位与列的对应关系由页面列序推定，页面未另作显式标注），权益清单 21 项含「认证服务伙伴授牌」「ACP/ACE 认证激励计划」「联合营销基金（MDF）」，服务伙伴定义原文为「具备阿里云产品或服务的交付能力，为客户设计、架构、搭建、迁移和管理其在阿里云上的工作负载和应用程序，包括MSP、服务供应商等」——这是国内侧唯一把**认证人数直接写成等级门槛**的公开页面；而 `program/aimsp` 按调用量结算。火山引擎侧三个入口的取证层级不同，不得并列：总入口 [partner.volcengine.com](https://partner.volcengine.com/) ✅ 已逐页读取（267,892 字节／去标签正文 3,232 字符），服务伙伴类目为「集成交付 · 授权服务」并注「敬请期待…敬请关注更多元化的交付生态合作模式」，名录等级标签为 领航级／铂金级／精英级／钻石级／金牌级但**页面未公布评定标准**，全页 **FDE 0 命中** ⇒ "缺 FDE 专项"在总入口的核对范围内成立，证据强度与阿里云 AIMSP 同级；另两个入口 [Partner-AI-Solution](https://www.volcengine.com/activity/Partner-AI-Solution)、[edu.volcengine.com](https://edu.volcengine.com/) 仍为 🔍（均 200，但可读正文分别只有 **176／17 字符**，其余是「You need to enable JavaScript to run this app」一类门禁原文），**不得与总入口并列为"已核对"**。⚠️ 两类缺位都属于**消极证据**：我们取到的是页面，不是缺席证明。

**三条制度线在同一季度出现**：把交付写成**法人**（OpenAI）、写成**等级门槛**（Salesforce/ServiceNow）、写成**可考认证 + 伙伴招募**（腾讯云）。阿里云写成两套并行口径：AI 生态计划按**调用量返**（交付能力不在结算单位里），通用服务伙伴计划把**认证人员数**直接写进等级门槛——同一家厂商同时示范了"认证无关结算"与"认证决定等级"两种可能。

## 分析

1. **"认证买到什么"有五个可核验的答案，且只有两个是公开可验证的。** Salesforce 的认证（badge）买的是**等级**，等级换曝光与资源——但本库只在第三方页面看到这条；ServiceNow 的专项认证买的是**名录里的可检索位置**；腾讯云的 FDE 认证与伙伴招募同日宣布，指向**入场券**，资格条款未公开，而活动页把"注册开通"与「新客购买套餐加赠 100 元 PU」写成第一步，即**认证与消耗承诺同框**；阿里云有两个计划：AI 生态计划（`program/aimsp`）买的是**调用量返点**（百万调用奖／五十万调用奖），交付资格不在结算条款里；通用服务伙伴计划（`programs/service`）买的是**等级**，且把「ACP/ACE 认证人员 5／10／15 人+」直接写进四档条件。五类机制中，本库能在页面上一眼验证绑定关系的是**阿里云服务伙伴计划与腾讯云活动页**两支（人数→等级、认证→购买套餐），其余三家的资格条款都在登录墙或销售合同之后。**因此"认证=渠道壁垒"这句话在本库里目前不可证实，只可证伪其中一支**（阿里云 AI 生态那支已被"按消耗返"证伪）。
2. **宣布与可购买之间的三天时滞，是判断认证性质的最低成本指标。** 08-17 公告、08-20 已有人问"在哪儿买不到"（且提问者逐字引用了公告三句，回答 0）。认证若首先是能力评测，购买入口与公告同期上线是最低工程要求；若首先是渠道策略，公告可以先于兑付体系存在。本线索用这条区分"标准"与"话术"，但**只对一个厂商的一次事件成立**，不外推。
3. **阿里云缺 FDE 专项认证的原因要分两个计划看，且都不是反应速度。** AI 生态计划（`aimsp`）的奖励按调用量发放，伙伴的收益函数是"带上更多消耗"而不是"交付更多项目"，因此增设交付类认证不改变厂商的结算结构、也就没有合同杠杆；通用服务伙伴计划（`programs/service`）**已经有认证门槛**（ACP/ACE 人数写进等级条件），它缺的不是"交付认证"这一类，而是"智能体现场交付"这一**科目**——同一家厂商的两套制度里，科目可以更新（腾讯在 6 月把乐享交付工程师的考核权重从产品概述转向需求分析与方案思路），也可以新增（8 月独立上线 FDE 认证），但阿里云侧两条路径均未出现 FDE 字样。这是一个**可证伪的结构判断**：若阿里云日后出现与交付认证绑定的返点或分包资格，说明它开始按项目而非按消耗结算渠道，本条判断即作废。
4. **法人化、等级化、认证化三种路线的差别是"谁对客户追责"，不是"谁交付得更好"。** OpenAI 把交付装进法人主体，客户对厂商追责；Salesforce/ServiceNow 把交付责任绑在伙伴等级与名录上，客户对伙伴追责、厂商对标准追责；腾讯云同时发认证与招伙伴，是第三种与第四种的混合。判断厂商意图，看它把**违约成本的落点**放在哪一侧——这比看认证名称与宣传口径信息量大。⚠️ 本条对 OpenAI 的部分依赖 ✗ 一手不可达的页面，只成立到"路线对照"层级。
5. **国内"缺位"类结论必须标注抓取层级，否则会变成假事实。** 本轮的三条层级差异本身就是教材：① 阿里云两个计划页均**逐页读取正文**后确认关键词 0 命中（最强消极证据）；② 火山引擎总入口已从"检索未见"升级为"**逐页核对未见**"（267,892 字节／正文 3,232 字符，FDE 0），但另两个子入口只有 176／17 字符可读、属 JavaScript 门禁，**不能与①②并列**；③ Salesforce 官方页由 🔍 升级为 ✅，**而其改革条款的证据层级并未因此上升**——正文可读取但没有那句话。缺位结论的强度取决于"读到多少"，也取决于"该说法本该出现在哪一页"；本条是方法论提醒，写进线索是为了防止后续追加时把弱证据写成强证据。
6. **下一步追踪信号：** ① 腾讯云 FDE 合作伙伴的资格条款是否公开（是否与分包、返点档位绑定，当前在登录墙后）；② 认证购买入口何时上线（对照 **08-20** 提问是否已被解决——提问页 回答 0／查看 473 是可复跑的进度指标）；③ Salesforce 收敛为两档后 badge 覆盖是否仍是等级门槛，收入门槛是否会披露（本轮已确认官方入口正文**不含**该条款，需等 Partner Academy／公告类页面而非 become-a-partner 页）；④ 火山引擎两个 JS 门禁子入口能否用可执行 JS 的抓取通道读到正文，以及「集成交付 · 授权服务」的**评定标准**是否公开；⑤ 是否出现**非厂商主体**（第三方评测机构、行业协会）对 FDE 能力的认证——若出现，认证的价值锚点将从"渠道入场券"转向"可跨厂商迁移的资质"；⑥ 阿里云 `programs/service` 的「服务能力认证」科目清单是否新增智能体／交付工程类条目（这是"认证人数→等级"这条链上唯一可能长出 FDE 的位置）。
