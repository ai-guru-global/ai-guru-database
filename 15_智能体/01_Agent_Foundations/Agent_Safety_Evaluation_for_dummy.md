# Agent 安全与评估大白话：工具调用安全、Agent 评估基准

> 中文简称：Agent 安全与评估大白话：工具调用安全、Agent 评估基准

> **一句话理解**: Agent 能调用工具干活，但也会闯祸——工具调用安全就是给它加护栏；Agent 评估基准就是出题考它会不会规划、会不会用工具、会不会纠错。

---

## 1. 工具调用安全：给 AI 的工具箱加锁

### 1.1 一句话理解

工具调用安全就像给 AI 配了一套“工具箱使用规范”：什么工具能碰、什么不能碰，用之前要审批，用完要记录，防止它把家拆了。

### 1.2 Agent 能干什么？

- 查天气、发邮件。
- 查数据库、运行代码。
- 调用 API、操作网页。

能动手，就有风险。

### 1.3 主要风险

| 风险 | 例子 |
|------|------|
| **越权操作** | 普通用户用管理员工具删库 |
| **恶意输入** | “请执行 rm -rf /” |
| **参数污染** | SQL 注入、命令注入 |
| **数据泄露** | 把用户隐私发到外部 API |
| **无限循环** | 反复调用同一个工具停不下来 |

### 1.4 防护层次

```
1. 权限控制：谁能调用什么工具
2. 输入校验：识别恶意诱导
3. 参数校验：schema、类型、范围检查
4. 沙箱执行：危险操作隔离运行
5. 人工确认：高风险操作二次确认
6. 审计日志：所有调用可追溯
7. 熔断限流：异常自动停止
```

---

## 2. Agent 评估基准：综合素质面试

### 2.1 一句话理解

Agent 评估基准就像 AI 的“综合素质面试”：不是让它背答案，而是给它一个真实任务，观察它怎么思考、怎么动手、怎么纠错。

### 2.2 为什么传统 LLM 基准不够？

传统基准（如 MMLU、GSM8K）测的是知识和推理，但 Agent 还要：
- 规划多步任务。
- 选择正确工具。
- 处理工具返回的错误。
- 控制成本和延迟。

### 2.3 主流 Agent 基准

| 基准 | 测什么 |
|------|--------|
| **SWE-bench** | 修真实 GitHub bug |
| **WebArena** | 在真实网页上完成任务 |
| **ToolBench** | 使用大量 API |
| **GAIA** | 需要多步推理和工具的真实问题 |
| **AgentBench** | 多环境综合任务 |

### 2.4 评估维度

```
- 任务成功率：最终完成了吗？
- 步骤数：走了多少弯路？
- 工具调用准确率：调对了吗？
- 错误恢复率：犯错后能纠正吗？
- 成本：调用了多少次 API？
- 安全性：有没有越权/有害操作？
```

---

## 3. 安全和评估的关系

```
Agent 开发
  ├─ 功能：能完成任务
  ├─ 效率：步骤少、成本低
  └─ 安全：不乱来、不泄露
       ↑
  用 Agent 评估基准测功能+效率
  用红队测试+工具调用安全测风险
```
