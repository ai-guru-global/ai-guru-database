# 智能体架构设计速查表

> Agent = LLM + Harness | **模型决定智能上限, Harness 决定工程下限**
> 详见 [[Agentic_AI_Complete_Guide]] | [[Multi_Agent_Systems_Guide]] | [[AgentOps_Production_Guide]] | [[Harness_Engineering_Complete_Guide]]

## 智能体认知层级 (L1-L5)

| 层级 | 定位 | 核心能力 | 人类类比 | 实现要素 | 何时使用 |
|------|------|---------|---------|---------|---------|
| **L1** | 辅助型 | Talk (对话) | 图书馆员 | RAG, Prompt Engineering | 知识库问答, FAQ |
| **L2** | 执行型 | Do (执行) | 实习生 | ReAct, Tool Use, CoT | **大多数企业应用应稳定在此** |
| **L3** | 自主型 | Learn (学习) | 工程师 | Vector DB, Reflexion, 记忆系统 | 需跨会话学习, 持续改进 |
| **L4** | 进化型 | Evolve (进化) | 科学家 | Self-Coding, APE, 自动提示词优化 | 自我改进系统 (慎用) |
| **L5** | 群体型 | Connect (连接) | 公司/社会 | Multi-Agent, SOP, A2A 协议 | 大规模协作, 社会模拟 |

> **设计启示**: L1 足够好 -> L2 是基石 -> L3 慎用 -> L4/L5 仍在研究阶段

## 推理技术对照表

| 技术 | 机制 | 复杂度 | 最佳场景 | 备注 |
|------|------|--------|---------|------|
| **CoT** (思维链) | 显式展示中间推理步骤 | 低 | 数学计算、逻辑推理 | "让我们一步步思考", T=0 |
| **Zero-shot CoT** | "Let's think step by step" 触发语 | 极低 | 通用简单任务 | 无需示例, 效果取决于模型规模 |
| **Self-Consistency** | 多路径采样 + 多数投票 | 中 | 高风险决策、数学 | T>0.5, n=5-20; 简单 3-5, 困难 10-20 |
| **ToT** (思维树) | 树状搜索 + BFS/DFS + 评分 | 高 | 复杂逻辑、规划、代码生成 | Token 消耗极大, 可回溯 |
| **GoT** (思维图) | 图状网络, 支持聚合与分支 | 极高 | 创意写作、多文档摘要 | 实现复杂, 调度难 |
| **ReAct** | 思考->行动->观察 循环 | 中 | 工具调用、探索性任务 | **Agent 标配**, 需 max_steps 护栏 |
| **Reflexion** | 失败->反思->总结->记忆注入 | 中 | 迭代改进、自我纠错 | 需评估者 + 反思者 |
| **Least-to-Most** | 由易到难顺序分解 | 低 | 组合泛化、多步数学 | 单路径, 不能回溯 |
| **Plan-and-Solve** | 先计划后求解 | 低 | 通用复杂任务 | 零样本友好, 计划质量决定上限 |

> **选型口诀**: 简单推理 -> CoT | 需探索 -> ToT | 需迭代 -> Reflexion | 大问题可分解 -> Decomposition | 需高可靠 -> Self-Consistency | 需工具 -> ReAct

## 记忆类型选择

| 记忆类型 | 定义 | Agent 映射 | 存储介质 | 延迟 | 容量 |
|---------|------|-----------|---------|------|------|
| **感觉记忆** | 即时感知输入 | 当前 Observation | 上下文窗口 | ~0ms | 极小 |
| **工作记忆** | 当前活跃信息 | 当前对话上下文 | LLM 上下文窗口 | ~0ms | 受窗口限制 |
| **短期记忆** | 会话级临时状态 | Session 摘要、中间结果 | 文件/数据库 | ~10ms | 数小时-数周 |
| **长期记忆** | 持久化知识 | 用户偏好、历史经验 | Vector DB / KG | ~100ms | 数月-数年 |
| **情景记忆** | 个人经历序列 | 对话日志, 交互历史 | Vector DB | ~100ms | 大 |
| **语义记忆** | 事实与世界知识 | 领域文档, 百科知识 | Knowledge Graph / RAG | ~100ms | 极大 |
| **程序记忆** | 执行任务的技能 | 工具定义, 代码解释器 | Function Schemas | ~0ms | 固定 |

> **斯坦福小镇检索打分**: `Score = alpha x Recency + beta x Importance + gamma x Relevance`
> **渐进式记忆 7 层**: L1 磁盘缓存 -> L2 微压缩 -> L3 Session -> L4 完整压缩 -> L5 自动提取 -> L6 "做梦" -> L7 子 Agent 通信

## 多 Agent 拓扑选择

| 拓扑 | 工作机制 | 复杂度 | 延迟 | 成本 | 适用场景 | 失败模式 |
|------|---------|--------|------|------|---------|---------|
| **顺序式** | A->B->C 线性传递 | 低 | 低 | 低 | 固定 SOP, 流水线 | 源头错误级联, 无反馈修正 |
| **层级式** | Supervisor 分派 + Worker 执行 | 中 | 中 | 中 | 动态路由, 复杂决策 | Supervisor 成瓶颈 |
| **联合协作** | 广播通信, 多轮讨论达成共识 | 高 | 高 | 高 | 创意生成, 头脑风暴 | 跑题、死循环争论 |
| **Peer-to-Peer** | 平等协商/辩论/投票 | 高 | 高 | 高 | 多视角碰撞, 探索性任务 | 发言顺序/仲裁难, 调试复杂 |
| **Orchestrator-Subagent** | 编排者动态分派, 子 Agent 执行 | 中 | 中 | 中-高 | **最主流**, 全局目标不漂移 | 编排者瓶颈, 拆解不好下游偏题 |
| **MoA (混合)** | 多模型并行提议 + 聚合融合 | 中 | 中 | 中 | 质量优先, 答案聚合 | 成本高, 编排复杂 |

> **选型原则**: "必须交付、可控回放、可审计" -> 先 Orchestrator-Subagent
> **系统性故障四类**: 协同饥饿(死锁) | 目标漂移(意图稀释) | 无限回文(标准不一致) | 责任推诿(边界不清)

## Agent 设计反模式检查清单

| # | 反模式 | 问题 | 修复方案 |
|---|--------|------|---------|
| 1 | **God Prompt** (万能提示词) | 所有工具+规则+历史塞一个大 Prompt, 推理链混乱 | 分层路由 + 职责隔离, 每 Agent 只带必需工具和上下文 |
| 2 | **长上下文当记忆** | 全量加载历史+知识库+文档, 检索精度下降 | 预算化上下文 + 分层记忆, 按需检索而非全量加载 |
| 3 | **暗码 (Dark Code)** | 决策链运行时生成、运行后消散, 无法审计 | 全链路追踪 (OTel), 强制 trace_id, 完整轨迹日志 |
| 4 | **忽视护栏** | 无 max_steps/成本预算/错误去重 -> 失控雪崩 | 必须配置 max_steps, token_budget, 连续重复检测, 成本熔断 |
| 5 | **过度工程** | 一开始堆叠多 Agent+复杂路由+全套可观测性 | 从单体 Agent + 简单护栏开始, 按需演进 |
| 6 | **负向指令优先** | 大量"不要做什么"导致负面启动效应 | 用正向表达: "请用..." 替代 "请不要..." |
| 7 | **缺乏退路** | 无"不知道"处理选项 -> 幻觉 | 提供逃生通道: `{"result": null, "reason": "未找到"}` |
| 8 | **单次调用超载** | 一个 Prompt 包含过多任务 | 使用提示词链分步处理 |

## 框架选型矩阵

| 框架 | 形态 | 核心优势 | 最佳场景 | 备注 |
|------|------|---------|---------|------|
| **LangChain / LangGraph** | 链式 -> 图编排 | 生态最完善, 可控性高, 集成广 | 企业级业务流 (审批/客服) | LCEL + 状态机 + 检查点 |
| **LlamaIndex** | 数据/RAG 驱动 | 索引/检索/权限隔离为一等公民 | 知识密集型任务 (法律/政策) | Workflows 支持图编排 |
| **AutoGen / AG2** | 多 Agent 协作 | 对话编排范式, 灵活 | 创意自动化, 多角色协作 | AG2 为社区主线 |
| **CrewAI** | 角色任务编排 | 角色定义清晰, SOP 流程化 | 团队模拟, 内容运营 | 稳定在 1.14.x |
| **OpenClaw** | 自驱型 Harness | 确定性工作流, Gateway 控制平面 | 自驱型长期任务 | SOUL.md + 三级权限 |
| **Dify / LangFlow** | 低代码平台 | 可视化拖拽, 零代码 | 快速原型, 非技术团队 | |
| **Microsoft Agent Framework** | 企业级 SDK | 身份/权限/审计/治理为核心 | 传统企业集成 | AutoGen 已进入维护模式 |

> **核心定律**: 智能体本质是 While 循环, 框架只是封装了循环里的脏活累活。理解底层 Prompt 设计、工具调用和记忆管理才是核心。

## Harness 四大核心子系统

| 子系统 | 职责 | 关键组件 |
|--------|------|---------|
| **运行时引擎** | Agent 心脏, 主循环维护 | 状态机管理, 消息编排, 异步执行, 超时中断 |
| **工具层** | 与真实世界连接点 | 注册/发现/调用/隔离执行/结果标准化 |
| **记忆子系统** | 学习和改进基础 | 工作记忆(窗口) + 短期(Session) + 长期(Vector DB) |
| **模型集成+输出治理** | LLM 交互管控 | 多供应商故障转移, 格式解析->自愈->语义验证->安全检查 |

> **Harness 实证**: OpenAI Codex 团队引入 Harness 层后准确率提升 30-40pp (零模型改进); LangChain 纯 Harness 改进 Terminal Bench 从 52.8% 到 66.5%

## Agent 提示词六大组件

| 组件 | 说明 | 设计要点 |
|------|------|---------|
| **身份定义** (Identity) | 角色、特质、工作风格 | 复合角色画像, 背景故事影响输出风格 |
| **能力描述** (Capabilities) | 能做/不能做 | 明确边界, 防止越权 |
| **约束规范** (Constraints) | 安全/交互/输出规范 | 硬约束标记 "绝不/不可协商" |
| **工具定义** (Tools) | JSON Schema 定义 | 名称自描述, 参数完整, enum 约束 |
| **输出格式** (Output Format) | 结构化、可解析 | JSON/XML/Markdown, 容错逃生通道 |
| **示例** (Examples) | Few-shot 示范 | 代表性 + 多样性 + 一致性, 2-3 个高质量示例 |

> **提示词缓存策略**: 静态内容前置 (系统指令/工具定义) -> 动态内容后置 (检索/对话/用户输入) -> 最大化缓存命中

## AgentOps 六种核心设计模式

| 模式 | 机制 | 可控性 | 适用场景 |
|------|------|--------|---------|
| **提示词链** | 固定顺序: A->B->C | 高 | 线性流水线, 每步可用不同模型 |
| **路由分发** | Router LLM 分类后分发 | 高 | 意图分类, 模型分层路由 |
| **并行执行** | 切片(独立子任务) / 投票(多次运行) | 中 | 安全/性能/风格同时检查; 减少幻觉 |
| **编排者-工作者** | 中心编排者动态分派 Worker | 中 | 子任务无法预知, 需动态生成 |
| **评估者-优化者** | Generator + 独立 Evaluator 循环 | 中-高 | 代码审查, 文案创作, 质量要求高 |
| **自主智能体** | 完整 ReAct 循环, 最大自主度 | 低 | 探索性任务, 需完善护栏和可观测性 |

> **静态编排 vs 自主编排**: 越接近自主越灵活但不可控; 越接近静态越稳定但泛化弱。实践中两者结合。

> **核心定律**: "中等模型 + 精心设计的流程" 远胜于 "顶级模型 + 混乱的架构"
