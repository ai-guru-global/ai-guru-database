# FDE 软技能与沟通

## 软技能的重要性

**技术让你进门，软技能让你留下**。FDE 在客户现场的 70% 时间在沟通，30% 在写代码。

## 核心软技能

### 1. 客户沟通

**听懂弦外之音**：

| 客户说 | 实际意思 | FDE 应对 |
|---|---|---|
| "我们考虑一下" | 不信任/有顾虑/没钱 | 主动了解顾虑 |
| "这个功能很简单" | 他们觉得应该很快 | 管理期望，解释复杂性 |
| "你们是专业的" | 把责任全推给你 | 明确协作边界 |
| "领导很重视" | 这是政治任务 | 帮对接人写汇报材料 |

**沟通金字塔**：

```
与高层沟通：讲战略、讲价值、讲结果（5 分钟）
与中层沟通：讲方案、讲计划、讲风险（30 分钟）
与执行层沟通：讲步骤、讲细节、讲操作（1 小时+）
```

### 2. 需求管理

**范围控制（Scope Control）**：

```
初始 scope
    ↓ 客户："顺便也做一下 XXX 吧？"
扩大 scope（scope creep）
    ↓
三种应对：
1. "这个需求很有价值，我们可以放在 Phase 2"（推迟）
2. "这个需要额外的时间和资源，我重新评估报价"（加钱）
3. "这个与我们达成的成功标准不完全一致"（婉拒）
```

**需求变更管理流程**：
1. 明确记录变更内容
2. 评估对时间/成本/风险的影响
3. 书面确认（邮件即可）
4. 更新项目计划

### 3. 政治敏感度

**政企客户的生存法则**：

- 不要在 A 领导面前批评 B 领导的决定
- 了解谁是"真正说了算的人"（通常不是 title 最高的）
- 帮对接人写汇报材料 = 帮他在内部成功 = 你的项目成功
- 永远不要绕过你的对接人直接找他的上级
- 负面消息私下说，正面成果公开说

### 4. 知识转移

**不只是交付系统，而是交付能力**：

| 阶段 | 内容 | 形式 |
|---|---|---|
| 交付前 | 系统架构和原理 | 技术培训（半天） |
| 交付中 | 运维操作 | 手把手教学 |
| 交付后 | 常见问题处理 | 运维手册 + FAQ |
| 持续 | 新功能/优化 | 定期回访培训 |

**知识转移的检验标准**：你离开后，客户团队能独立运维 2 周不出问题。

### 5. 期望管理

**FDE 期望管理三原则**：

1. **永远 low-ball, high-deliver**
   - 承诺 80 分，交付 95 分
   - 而不是承诺 100 分，交付 90 分

2. **坏消息第一时间说**
   - 延期、技术问题、资源不足 → 立即同步
   - 客户不怕问题，怕的是被蒙在鼓里

3. **管理成功定义**
   - 项目开始时就写清楚"什么叫成功"
   - 每月 review 是否还在正确的轨道上

## 软技能自评

| 等级 | 描述 | 标准 |
|---|---|---|
| L1 | 能清晰表达 | 客户能理解你在说什么 |
| L2 | 能管理期望 | 客户不会说"和说好的不一样" |
| L3 | 能影响决策 | 客户采纳你的建议 |
| L4 | 能成为可信顾问 | 客户做决策前会先问你 |

---

> **记住**：在客户现场，每个对话都是一次"交付"。你对待沟通的态度，就是客户对你专业能力的判断。
