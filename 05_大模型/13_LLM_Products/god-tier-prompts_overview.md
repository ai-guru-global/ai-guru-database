# God Tier Prompts 概览

> **一句话理解**: 高质量提示词集合与社区平台，提供经过社区验证的高效提示词模板，是提示词工程实践灵感的参考来源。

## 简介

God Tier Prompts 是一个社区驱动的提示词（Prompt）分享与投票平台，汇聚经过实际使用验证的高质量提示词模板。与纯理论教程不同，它强调**可复制、已验证**——每个提示词都附带使用场景、预期效果与社区评分，适合从入门到进阶的提示词工程学习者作为灵感库。

**官网**: [godtierprompts.com](https://www.godtierprompts.com/)

## 核心功能

| 功能 | 说明 |
|------|------|
| **提示词库** | 分类整理（写作/16_编程/分析/创意/营销等）的精选提示词 |
| **社区投票** | 类 Reddit 机制，社区票选最佳提示词，质量可筛选 |
| **模板化** | 可直接复制使用的提示词模板（含变量占位符） |
| **场景标签** | 每个提示词标注适用场景与模型（GPT/Claude/Gemini） |
| **效果展示** | 附带示例输入输出，所见即所得 |

## 价值与定位

```
提示词工程资源光谱：

  理论体系                    实践模板
  ┌──────────┬──────────┬──────────┐
  │ 论文/综述 │ 系统教程  │ 模板社区  │
  │ (CoT论文) │(本知识库) │(本工具)   │
  └──────────┴──────────┴──────────┘
  学原理      学方法      直接拿来用
```

God Tier Prompts 处于"实践模板"端——适合**快速获得可用提示词**，但若要理解原理（为什么这样写有效），应结合知识库的 [[05_大模型/Prompt_Engineering|提示词工程]] 系统学习。

## 使用建议

- **入门者**：浏览高分提示词，逆向学习优秀提示词的结构（角色设定→任务→约束→示例）
- **实践者**：直接复用模板，按需替换变量，快速落地
- **注意**：社区提示词的质量参差，高分≠适合你的场景，需自行测试验证

## 提示词模板示例

```markdown
# 角色
你是一位资深的 {domain} 专家，拥有 20 年经验。

# 任务
请分析以下 {input_type}，并提供：
1. 核心问题识别
2. 根因分析
3. 解决方案（按优先级排序）
4. 预防措施

# 约束
- 回答控制在 500 字以内
- 使用 Markdown 格式
- 每个方案附带成本估算

# 输入
{user_input}
```

## 2026 提示词工程趋势

| 趋势 | 说明 | 影响 |
|------|------|------|
| **系统提示词** | 从用户提示转向系统级设计 | 更稳定的输出 |
| **Context Engineering** | 上下文工程替代纯提示词 | 更精确的控制 |
| **自动优化** | DSPy/MIPRO 自动搜索最优提示 | 减少手工设计 |
| **多模态提示** | 图文音视频混合输入 | 更丰富的交互 |
| **Agent 提示** | 工具调用 + 规划提示 | 自主任务执行 |

## 生产最佳实践

1. **版本管理**：提示词纳入 Git 版本控制
2. **A/B 测试**：新提示词先小流量验证
3. **评估指标**：定义明确的输出质量指标
4. **模板化**：抽取可复用的提示词组件
5. **文档化**：记录每个提示词的设计意图和效果

## 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|------|
| 输出不稳定 | 提示词模糊 | 添加明确约束和示例 |
| 不遵循格式 | 缺乏格式指定 | 使用 JSON Schema 约束 |
| 幻觉严重 | 缺乏事实约束 | 添加 RAG + 事实核查 |
| 过长/过短 | 未指定长度 | 明确字数要求 |
| 忽略指令 | 指令冲突 | 简化并分层 |

## 总结

God Tier Prompts 是提示词工程的实践模板库，提供经过社区验证的高质量提示词。它是学习提示词设计模式、获取灵感的优质资源，但需结合系统学习才能掌握原理。2026 年，随着推理模型和 Agent 的普及，提示词工程正在向上下文工程和自动优化演进。

> 💡 提示词工程的核心：不是"写得好"，而是"设计得对"——理解模型的工作原理，才能设计出有效的提示词。在 2026 年，最好的提示词是那些能够引导模型自主思考和行动的提示词。
