## 什么是提示工程？

### 定义

**提示工程**是设计和优化文本输入（提示），以针对给定的应用目标和模型提供一致且高质量的响应（完成）的实践。

我们可以将其视为一个两步过程：

1. **设计**初始提示：为给定模型和目标创建初始的文本输入
2. **完善**提示：迭代地修改提示以提升响应质量

这必然是一个试错过程，需要用户的直觉和努力以获得最佳结果。

### 三个核心概念

要理解为什么提示工程如此重要，我们需要先理解三个概念：

#### 概念一：分词（Tokenization）—— 模型如何"看"提示

LLM 将提示视为 **token 序列**。不同模型（或模型版本）可以用不同方式对同一提示进行分词。由于 LLM 是对 token 进行训练（不是对原文本），分词方式直接影响生成响应的质量。

**分词示例**：

```
输入文本: "Hello, how are you today?"
     ↓ 分词器处理
Token: ["Hello", ",", " how", " are", " you", " today", "?"]
     ↓ 映射为索引
索引: [15496, 11, 703, 527, 499, 3432, 30]
```

**分词的关键特点**：
- 一个 token 可能是一个完整的词、一个词的一部分、或一个标点符号
- 空格和标点符号会影响分词结果
- 英文通常 1 个 token ≈ 4 个字符或 0.75 个单词
- 中文分词方式不同，一个汉字通常是 1-2 个 token
- 每个模型有最大 token 数限制（上下文窗口）

你可以使用 [OpenAI Tokenizer](https://platform.openai.com/tokenizer) 工具直观地了解分词过程。

#### 概念二：基础 LLM —— 基础模型如何"处理"提示

提示一经分词，基础 LLM 的主要功能是**预测序列中的下一个 token**。

**关键理解**：

由于 LLM 在海量文本数据集上训练，它们对 token 之间的统计关系具有良好把握，能有一定信心做出预测。但注意：

- 它们不理解提示或 token 中词语的**含义**
- 它们只是看到一个模式，可以用下一个预测来"完成"它
- 预测会持续进行，直到用户干预或达到预设条件

**示例**：

将 "Oh say can you see" 输入基础模型，它会立即补全接下来的歌词，因为训练数据中包含美国国歌。这展示了基本的**预测行为**，而非真正的"理解"。

#### 概念三：指令调优 LLM —— 模型如何"识别任务"

指令调优 LLM 是基于基础模型，使用带有明确指令的示例或输入/输出对进行微调的模型。

**RLHF 技术**：

这利用了"基于人类反馈的强化学习（RLHF）"等技术，使模型能够：
- **遵循指令**：理解并执行用户的明确要求
- **从反馈中学习**：根据人类反馈调整输出质量
- 生成更适合实际应用且更符合用户目标的响应

**对比演示**：

**基础模型提示**：

```
提示: "美国内战"
基础模型输出: "美国内战（1861-1865年）是美国历史上的一场重大冲突..."
（简单地继续补全相关文本）
```

**指令调优模型提示**：

```
系统消息: "为二年级学生总结你收到的内容。保持结果为一段文字，包含3-5个要点。"
提示: "美国内战"
指令调优模型输出: "美国内战是很久以前在美国发生的一场大战争。主要要点：
1. 战争发生在1861年到1865年之间
2. 北方和南方因为奴隶制等问题发生了争执
3. 亚伯拉罕·林肯是当时的总统
4. 战争最终以北方的胜利告终
5. 奴隶制被废除"
```

教育者现在可以直接在课堂幻灯片中使用此响应。

## 为什么我们需要提示工程？

既然我们了解了 LLM 如何处理提示，现在让我们谈谈为何需要提示工程。答案在于当前 LLM 存在诸多挑战：

### 挑战一：模型响应具有随机性

**相同提示**在不同模型或版本中可能生成不同响应。即使是**同一模型**，不同时间也可能产生不同结果。

**提示工程的作用**：通过提供更好的护栏来最小化这些差异。

### 挑战二：模型可能生成虚假响应

模型是用**大而有限**的数据集预训练，意味着它们对训练范围外的概念缺乏知识。因此，可能会产生不准确、虚构或与已知事实直接矛盾的结果。

**提示工程的作用**：帮助用户识别和减少此类虚假响应，例如通过要求 AI 提供引用或推理。

### 虚假响应的实验示例

想了解虚假响应是如何出现的？考虑以下提示：

**提示**：生成一份关于 2076 年火星战争的课程计划。

一次网络搜索显示，有关于火星战争的虚构记录（例如电视剧或书籍），但没有任何是发生在 2076 年的。常识也告诉我们，2076 年是在未来，因此无法与真实事件相关联。

**不同模型的响应**：

| 模型 | 响应特点 |
|------|----------|
| OpenAI Playground（GPT-35） | 生成了一个面向 8 年级学生的详细课程计划，包含学习目标、教学活动和评估方法 |
| Azure OpenAI Playground（GPT-35） | 假设是高中水平，生成了另一个版本的课程计划 |
| Hugging Face Chat（LLama-2） | 又一个不同风格的响应 |

如预期，每个模型都生成了可能让不了解情况的用户相信该事件是真实的回答。这就是虚假响应的典型表现——**看似合理但实际上完全虚构**。

### 挑战三：模型能力各异

较新型号或新一代模型功能更强大，但也带来费用和复杂性的独特变化与权衡。

**提示工程的作用**：帮助我们开发最佳实践和工作流，抽象差异并以可扩展、无缝的方式适应模型特定需求。

## 提示构建

### 基础提示

最基础的提示：一个只包含文本输入、无其他上下文的请求。

**示例**：

| 提示（输入） | 补全（输出） |
|-------------|-------------|
| Oh say can you see | 听起来你正在唱《星条旗永不落》，这是美国的国歌。完整歌词是…… |

这个例子展示了基本的预测行为——模型简单地补全最可能的后续文本。

### 复杂提示（Chat Completion API）

现在给基础提示增加上下文和指令。[Chat Completion API](https://learn.microsoft.com/azure/ai-services/openai/how-to/chatgpt) 让我们可以通过一组消息来构建复杂的提示：

```python
response = openai.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[
        # 系统消息：设置助手的行为或个性上下文
        {"role": "system", "content": "You are a helpful assistant."},
        # 用户输入
        {"role": "user", "content": "Who won the world series in 2020?"},
        # 助手的历史回应（提供对话上下文）
        {"role": "assistant", "content": "The Los Angeles Dodgers won the World Series in 2020."},
        # 用户的后续问题
        {"role": "user", "content": "Where was it played?"}
    ]
)
```

**消息角色说明**：

| 角色 | 用途 | 示例 |
|------|------|------|
| `system` | 设置助手的行为、个性和限制 | "你是一个教育助手，只回答学习相关问题" |
| `user` | 用户的输入和问题 | "2020 年世界大赛的冠军是谁？" |
| `assistant` | 模型的历史回应（提供对话上下文） | "2020 年世界大赛的冠军是洛杉矶道奇队" |

改变系统上下文对补全质量的影响可以和用户输入一样显著。

### 指令提示

在上述例子中，用户提示是一个简单的文本查询。对于**指令**提示，我们可以用该文本更详细地说明任务：

| 提示（输入） | 补全（输出） | 指令类型 |
|-------------|-------------|----------|
| 写一段关于内战的描述 | 返回一段简单的文字 | 简单 |
| 写一段关于内战的描述。提供关键日期和事件，并描述其意义 | 返回一段文字，随后附上关键事件日期及说明列表 | 复杂 |
| 用一段话描述内战。提供3条关键日期及其意义的要点。再提供3条关键历史人物及其贡献的要点。以JSON格式返回结果 | 返回更详细内容，以JSON格式呈现，便于复制粘贴验证 | 复杂，格式化 |

## 主要内容设计模式

借助**主要内容**设计模式，输入文本被分为两部分：

- **指令**（动作）：告诉模型要做什么
- **相关内容**（影响动作）：提供模型需要处理的实际内容

### 示例

**提示**：

```
木星是距离太阳第五颗行星，也是太阳系中最大的行星。它是一颗气体巨星，
质量约为太阳的千分之一，但却是太阳系其他所有行星质量总和的两倍半。
木星是夜空中用肉眼能见到的最亮天体之一，自有历史记载之前便为古代文明
所知。它以罗马神朱庇特命名。

请用两句简短的话总结以上内容。
```

**输出**：

```
木星是距离太阳第五的大行星，也是太阳系中最大的行星之一，夜空中最亮的
天体之一。它以罗马神朱庇特命名，是一颗质量相当于太阳系中其他行星总和
两倍半的气体巨星。
```

### 主要内容的三种驱动方式

#### 方式一：示例（Examples）

不是直接告诉模型做什么，而是给它该任务的样例，让它推断模式。

**零样本（Zero-shot）**：

| 提示（输入） | 补全（输出） |
|-------------|-------------|
| "The Sun is Shining"。翻译成西班牙语 | "El Sol está brillando" |

仅包含显式指令，不提供任何示例。

**一次样本（One-shot）**：

| 提示（输入） | 补全（输出） |
|-------------|-------------|
| "The Sun is Shining" => "El Sol está brillando"<br>"It's a Cold and Windy Day" => | "Es un día frío y ventoso" |

提供一个示例，模型从中推断任务。

**多样本（Few-shot）**：

| 提示（输入） | 补全（输出） |
|-------------|-------------|
| 该球员跑垒 => 棒球<br>该球员发 ace 球 => 网球<br>该球员击出六分球 => 板球<br>该球员扣篮得分 => | 篮球 |

提供多个示例，模型更准确地推断模式。

**关键洞察**：零样本提示需要显式指令，而一次样本和多样本提示中的指令是**隐含推断**出来的。更多示例帮助模型更准确推断，且无需额外指令。

#### 方式二：提示语（Cues）

通过给模型一个反映想要回复格式的开头片段，来"引导"它。模型据此"接招"，续写同样风格的内容。

| 提示语数量 | 提示 | 补全 |
|-----------|------|------|
| 0 | 木星是距离太阳第五颗行星...（长文本）<br>**请总结以上内容** | 木星是太阳系中最大的行星...（独立总结） |
| 1 | 木星是距离太阳第五颗行星...（长文本）<br>**总结如下**<br>我们了解到木星 | 是距离太阳的第五颗行星，也是太阳系中最大的行星...（续写式总结） |
| 2 | 木星是距离太阳第五颗行星...（长文本）<br>**总结如下**<br>我们了解到的三大事实： | 1. 木星是距离太阳第五颗行星...<br>2. 它是一颗气态巨行星...<br>3. 木星自古代以来就是肉眼可见... |

**提示语的效果**：提供开头片段后，模型会自然地续写，生成更符合期望格式的内容。这是一种非常自然和有效的提示方法。

#### 方式三：提示模板（Prompt Templates）

提示模板是一种**预定义的提示"配方"**，可以存储并根据需要重复使用，以推动更一致的大规模用户体验。

**简单形式**：像 OpenAI 的示例那样收集的提示示例，包含交互式提示组件（用户和系统消息）和 API 调用格式。

**复杂形式**：如 LangChain 的例子，包含**占位符**，可以用来自各种来源（用户输入、系统上下文、外部数据源等）的数据动态替换。

**LangChain 模板示例**：

```python
from langchain.prompts import PromptTemplate

# 创建带有占位符的模板
template = PromptTemplate(
    input_variables=["subject", "grade", "topic"],
    template="""
    你是一个教育助手。请为以下内容生成一个教案：
    学科：{subject}
    年级：{grade}
    主题：{topic}
    
    请包含：教学目标、重点难点、教学步骤和课后练习。
    """
)

# 使用实际数据填充模板
prompt = template.format(
    subject="数学",
    grade="初中二年级",
    topic="一元二次方程"
)
```

**模板的真正价值**：能够创建和发布针对垂直应用领域的**提示库**——提示模板经过优化以反映特定应用上下文或示例，使得响应更切合目标用户的需求。

**Prompts For Edu 示例**：[Prompts For Edu](https://github.com/microsoft/prompts-for-edu) 仓库是一个教育领域的提示库，重点覆盖课程规划、教学设计、学生辅导等关键目标。

## 次要内容（Supporting Content）

如果我们把提示构建看成包括一个指令（任务）和目标（主要内容），那么**次要内容**就像是我们提供的额外上下文，以某种方式影响输出。

**示例场景**：

假设有一个包含丰富元数据（名称、描述、级别、标签、讲师等）的课程目录：

- **指令**："总结 2023 年秋季课程目录"
- **主要内容**：给出几个所需输出的示例
- **次要内容**：标识 5 个最感兴趣的"标签"

这样，模型可以以示例展示的格式提供摘要——如果一个结果包含多个标签，则可以优先考虑次要内容中确定的 5 个标签。

**次要内容的常见形式**：
- 调优参数
- 格式化指令
- 主题分类
- 优先级排序
- 排除条件

## 提示工程最佳实践

### 心态（Mindset）

提示工程需要反复试验，要牢记以下三个大方向：

1. **领域理解很重要**：响应的准确性和相关性取决于应用或用户所处的领域。用你的直觉和领域专业知识来进一步定制技巧。例如，在系统提示中定义领域特定的人格，或在用户提示中使用领域特定的模板

2. **模型本身的理解也重要**：模型的实现会因训练数据集、提供的能力以及优化内容类型而异。了解你所用模型的优势和限制，并据此调整任务优先级

3. **迭代与验证同样重要**：使用提示工程工具和技巧"快速启动"提示构建，然后通过直觉和领域知识反复迭代验证结果。记录见解并创建一个知识库

### 技术最佳实践

以下是 OpenAI 和 Azure OpenAI 从业者推荐的通用最佳实践：

| 实践 | 原因 |
|------|------|
| 评估最新的模型 | 新一代模型会有更好的特性和质量，但也可能带来更高成本。评估影响后再决定是否迁移 |
| 分离指令和上下文 | 使用分隔符更清楚地区分指令、主要和次要内容，帮助模型更准确地分配权重 |
| 具体且清晰 | 提供更多关于期望上下文、结果、长度、格式、风格等的细节，提升响应质量和一致性 |
| 描述性强，使用示例 | 模型对"边做边讲"的方式响应更好。先用零样本指令，再用少样本以几个示例细化 |
| 用提示启动完成 | 给模型一些引导词和短语，促使它使用这些作为回答的起点 |
| 反复强调 | 有时需要对模型重复强调。主内容前后都给指示，或者同时用说明和提示语 |
| 顺序很重要 | 信息呈现顺序可能影响输出，尝试不同顺序找出最佳做法 |
| 给模型"退路" | 给模型设置一个兜底回应，如果无法完成任务则输出该回应，减少错误或虚假回答 |

**给模型"退路"的示例**：

```
请根据以下文本回答问题。如果你在文本中找不到答案，请回复：
"抱歉，根据提供的信息无法回答这个问题。"

文本：[内容]
问题：[问题]
```

### 注意事项

和任何最佳实践一样，具体效果可能因**模型、任务和领域不同而异**。把它们作为出发点，反复迭代找出最适合你的方案。随着新的模型和工具的出现，持续重新评估提示工程流程。

## 知识检查

**问题**：以下哪个是符合最佳实践的好提示？

1. 给我一张红色汽车的图像
2. 给我一张红色汽车的图像，汽车品牌是沃尔沃，型号是 XC90，停在悬崖边，夕阳西下
3. 给我一张红色汽车的图像，汽车品牌是沃尔沃，型号是 XC90

**答案**：2

**解析**：

选项 2 是最佳提示，因为它：
- 提供了"什么"的详情（红色汽车）
- 展开了具体细节（特定品牌沃尔沃和型号 XC90）
- 描述了整体环境（停在悬崖边，夕阳西下）

选项 3 次之，因为它也包含较多细节描述，但缺少环境描述。选项 1 最弱，因为它过于笼统，给模型的引导最少。
