# LLM 成本优化完全指南

> **一句话理解**: 降低 LLM 应用成本的系统性方法:模型路由、Prompt 缓存、量化、批处理、供应商选择等策略。

## LLM 成本构成

```
总成本 = 输入 token 费 + 输出 token 费 + 基础设施费
```

| 成本项 | 占比 | 优化空间 |
|--------|------|---------|
| API 调用费 | 60-80% | 高 |
| 基础设施 | 10-20% | 中 |
| 开发运维 | 10-20% | 低 |

## 优化策略

### 1. 模型路由 (Model Routing)
根据查询复杂度选择不同成本的模型:

```
简单查询(分类/提取) -> GPT-4o-mini ($0.15/1M)
中等查询(摘要/翻译) -> GPT-4o ($2.5/1M)
复杂查询(推理/创作) -> Claude Opus ($15/1M)
```

**节省比例**: 50-70%

### 2. Prompt 缓存
缓存重复的系统提示和上下文:

| 方案 | 节省比例 | 适用场景 |
|------|---------|---------|
| 前缀缓存 | 50-90% | 固定系统提示 |
| 语义缓存 | 30-60% | FAQ 类应用 |
| 结果缓存 | 90%+ | 确定性查询 |

### 3. Prompt 优化
减少不必要的 token:

| 技术 | 效果 |
|------|------|
| 精简系统提示 | 减少 20-50% 输入 token |
| 移除冗余上下文 | 减少 10-30% |
| 使用缩写/简写 | 减少 5-15% |

### 4. 批处理 (Batching)
OpenAI Batch API 享受 50% 折扣:

```python
# 非实时场景使用 Batch API
# - 数据标注
# - 内容分类
# - 批量翻译
# - 文档摘要
```

### 5. 量化与蒸馏
| 技术 | 效果 | 精度损失 |
|------|------|---------|
| 4-bit 量化 | 内存减少 75% | 1-3% |
| 模型蒸馏 | 成本减少 80% | 5-10% |
| 小模型替代 | 成本减少 90% | 10-20% |

### 6. 供应商选择
| 供应商 | 特点 | 价格区间 |
|--------|------|---------|
| OpenAI | 生态最完善 | 中高 |
| Anthropic | 代码理解强 | 中高 |
| Google | 长上下文优势 | 中 |
| Groq | 推理速度极快 | 低 |
| DeepSeek | 开源、性价比高 | 极低 |
| Together.ai | 开源模型托管 | 低 |

## 成本监控

```python
# 关键指标
- 每请求成本: token 数 x 单价
- 每用户月成本: 总成本 / 活跃用户数
- 缓存命中率: 缓存请求数 / 总请求数
- 模型分布: 各模型的请求占比
```

## 最佳实践

1. **建立成本基线**: 先测量当前成本,再优化
2. **模型路由优先**: 简单任务用小模型,效果最显著
3. **缓存必须开**: 前缀缓存几乎没有副作用
4. **定期审计**: 每月分析成本构成,找出优化点
5. **设置上限**: 防止异常请求导致成本飙升
