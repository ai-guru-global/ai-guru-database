## 2. 系统一：实时个性化推荐

### 2.1 生产架构

```
用户行为事件流 (点击/加购/购买)
  → 实时特征管道 (秒级更新用户短期兴趣)
  → 召回层: 多路召回 (协同过滤 + 向量 + 热销 + 新品)
  → 粗排: 轻量模型截断至 ~500
  → 精排: 深度模型 (多目标: CTR / CVR / GMV)
  → 重排: 多样性 + 业务规则 (库存/毛利/合规)
  → 曝光日志回流 → 模型小时级/天级更新
```

算法基础见 [[02_机器学习/10_Recommendation_Systems/Recommendation_Systems|推荐系统]]。2026 年的两个架构增量：

- **LLM 语义增强**：用 LLM 离线生成商品语义标签与"搭配理由"，解决冷启动与长尾商品无行为数据的问题；线上仍由轻量模型服务，LLM 不进实时链路
- **生成式陈列**：首页楼层标题、推荐理由文案由 LLM 按人群批量预生成并缓存，实测点击率提升 5-12%

### 2.2 延迟与新鲜度预算（行业基准）

| 环节 | 预算 | 说明 |
|------|------|------|
| 端到端推荐响应 | P99 < 150ms | 超时降级到缓存榜单 |
| 用户短期兴趣更新 | < 10s | 会话内行为需即时反映 |
| 精排模型更新 | 小时级 | 大促期间可到 15 分钟级 |
| 商品向量索引重建 | 天级增量 | 全量重建每周 |

## 3. 系统二：语义商品搜索

### 3.1 从关键词到混合检索

```
用户 Query ("适合露营的保温杯")
  → Query 理解: 纠错 / 类目预测 / 属性抽取
  → 混合召回:
      词法通道 (倒排索引, 精确匹配)
      语义通道 (向量检索, 意图匹配)
  → 融合重排 (RRF / 学习排序)
  → LLM 兜底: 零结果 Query 改写后二次检索
```

- Embedding 模型选型与微调见 [[14_RAG系统/02_Embeddings/Embedding_Models_Guide|Embedding 模型指南]]；电商领域必须用行为数据（点击/成交对）微调通用模型，否则语义通道对垂类词表（型号、规格、俗称）召回质量差
- **零结果率是核心北极星**：行业基准从纯词法的 8-15% 降到混合检索的 2-5%，零结果 Query 的挽回直接等于增量 GMV
- 导购问答型搜索（"送 60 岁父亲的礼物"）走 RAG + 商品库路线，架构见 [[14_RAG系统/01_RAG_Fundamentals/RAG_Fundamentals|RAG 基础]]

### 3.2 搜索质量评估分层

| 层级 | 方法 | 频率 |
|------|------|------|
| 离线 | 标注集 NDCG / Recall@K | 每次模型迭代 |
| 在线代理指标 | 零结果率 / 首屏点击率 / 改写率 | 实时看板 |
| 营收指标 | 搜索引导 GMV / UV 价值 | A/B 实验期 |

## 4. 系统三：需求预测与自动补货

### 4.1 架构

```
历史销量 + 价格/促销日历 + 天气/节假日 + 商圈事件
  → 特征仓库 (SKU × 门店 × 天 粒度)
  → 分层预测:
      头部 SKU: 深度时序/全局模型 (跨序列学习)
      长尾 SKU: 层级预测 + 类目聚合回摊
  → 概率输出 (分位数预测, 非单点)
  → 补货优化器 (服务水平 vs 库存成本的约束求解)
  → 人工例外审核 (仅异常单触发)
```

时序方法基础见 [[02_机器学习/09_Time_Series/Time_Series_Analysis|时间序列分析]]。关键工程认知：

- **分位数而非均值**：补货决策需要 P50/P90 分位数以平衡缺货与滞销；单点预测是新手最常见的方案性错误
- **促销是最大难点**：促销期误差可达平销期 3 倍，需独立的促销弹性模型
- **预测准确率不是目标**：立项指标应直接定为缺货率与库存周转，预测 MAPE 只是中间变量

### 4.2 行业效果基准

| 指标 | 实施前基线 | 成熟实施后 |
|------|-----------|-----------|
| 缺货率 | 5-8% | 2-4% |
| 库存周转天数 | 基线 | -10% ~ -20% |
| 生鲜损耗率 | 8-12% | 5-8% |
| 补货人工干预率 | 100% | <15%（例外管理制）|

## 5. 量化案例基准（2026 公开口径汇总）

| 场景 | 企业类型 | 关键数字 |
|------|----------|----------|
| 门店数字孪生运营 | 大型家居连锁（1750+ 门店）| 门店巡检与陈列合规自动化，运营决策周期从周级到天级 |
| 推荐系统重构 | 头部电商平台 | 推荐 GMV 占比 +6pct，长尾商品曝光 +25% |
| 混合语义搜索 | 垂类电商 | 零结果率 12% → 3.5%，搜索转化率 +9% |
| 需求预测补货 | 连锁商超 | 缺货率 -40%（相对），库存资金占用 -15% |
| AI 客服导购 | 跨境电商 | 人工客服工单 -55%，导购会话转化率为人工的 ~85% |

> ⚠️ 与 HR 行业不同，零售案例数字受大促周期影响极大：对外报告普遍取大促口径，内部立项应以平销期口径保守测算（约打 6-7 折）。

## 6. 用 A/B 实验守住 ROI 口径

零售 AI 的每一分收益都应经过在线实验验证，方法论见 [[09_测试/04_Online_Testing/AB_Testing_AI_Systems|AI 系统 A/B 测试]]。零售特有的三个陷阱：

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 大促污染 | 实验期撞上促销，效应无法归因 | 实验窗口避开大促，或用 CUPED 校正 |
| 溢出效应 | 推荐组的加购挤占搜索组的转化 | 按用户随机而非按流量；关注全站 GMV 而非单模块 |
| 新鲜感效应 | 新样式短期点击率虚高 | 实验期 ≥ 2 个完整购买周期，观察衰减曲线 |

## 7. 成本工程：零售 AI 的单位经济学

零售是低毛利行业，推理成本直接侵蚀 AI 项目 ROI：

- **LLM 离线化**：语义标签、文案、Query 改写词典尽量离线批量生成 + 缓存，线上实时调用 LLM 的场景压缩到导购对话等少数高价值链路
- **级联模型**：搜索/推荐用"小模型打底 + 大模型兜底"级联，大模型调用占比控制在 5-10%
- **峰值弹性**：大促流量可达日常 10 倍以上，推理集群需弹性扩缩与降级预案（缓存榜单兜底）
- 通用成本方法见 [[18_行业应用/01_Industry_Overview/AI_Production_Architecture_2026|AI 生产架构 2026]] 的成本章节

经验值：成熟电商的推荐+搜索 AI 基础设施成本应控制在其引导 GMV 的 0.3-0.8%，超过 1% 需触发架构复审。
