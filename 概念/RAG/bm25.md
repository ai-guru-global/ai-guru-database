# BM25

> **一句话理解**: BM25 是按「关键词在文档里出现多少次、在多少文档里出现过」来给文档打分的经典检索算法。

## 核心原理

### 基于 TF-IDF 的改进

BM25 是 TF-IDF 的改进版，增加了两个关键改进：
- **词频饱和**：词频增加时分数增长递减（而非线性增长）
- **文档长度归一化**：长文档不会因词多而天然占优

### 公式

```text
score(D, Q) = Σ IDF(q_i) × (f(q_i,D) × (k1+1)) / (f(q_i,D) + k1×(1-b+b×|D|/avgDL))

其中：
  f(q_i, D) = 词 q_i 在文档 D 中的词频
  |D|       = 文档长度
  avgDL     = 平均文档长度
  k1        = 词频饱和参数 (1.2-2.0)
  b         = 长度归一化参数 (0-1, 通常 0.75)
  IDF(q_i)  = log((N - n(q_i) + 0.5) / (n(q_i) + 0.5))
```

### 参数说明

| 参数 | 典型值 | 作用 |
|------|--------|------|
| **k1** | 1.2-2.0 | 控制词频饱和度，越大词频影响越大 |
| **b** | 0.75 | 控制文档长度影响，0=不考虑长度，1=完全归一化 |

## BM25 vs 向量检索

| 维度 | BM25 | 向量检索 |
|------|------|----------|
| 匹配方式 | 精确关键词匹配 | 语义相似度 |
| 优势 | 专有名词、精确查询 | 同义词、语义理解 |
| 劣势 | 不理解语义 | 可能丢失精确匹配 |
| 速度 | 极快（倒排索引） | 较快（ANN 索引） |
| 可解释性 | 强（知道哪个词匹配） | 弱（向量距离） |
| 典型引擎 | Elasticsearch, OpenSearch | Milvus, Qdrant, Pinecone |

## 在 RAG 中的角色

```
用户查询
    │
    ├──→ BM25 关键词召回 (Top-K₁)
    │         │
    │         └──→ 融合排序 (RRF) ──→ Top-K 结果 ──→ LLM 生成
    │         │
    └──→ 向量语义召回 (Top-K₂)
```

BM25 在混合检索中补充向量检索的不足：
- 精确产品名/型号查询（如 "RTX 4090"）
- 错误代码/异常名称（如 "NullPointerException"）
- 人名、地名等专有名词

## 实战示例

### Python (rank_bm25)

```python
from rank_bm25 import BM25Okapi
import jieba

# 中文分词
corpus = ["机器学习是人工智能的分支", "深度学习使用神经网络", "BM25是经典检索算法"]
tokenized_corpus = [list(jieba.cut(doc)) for doc in corpus]

bm25 = BM25Okapi(tokenized_corpus)

# 查询
query = "检索算法"
tokenized_query = list(jieba.cut(query))
scores = bm25.get_scores(tokenized_query)
# 返回: [0.0, 0.0, 0.69]  → 第三篇文档最相关
```

## 最佳实践

1. **与向量检索组合**：单独 BM25 不够，混合检索效果最佳
2. **中文分词**：使用 jieba/IK 分词器，而非按字切分
3. **参数调优**：k1=1.2, b=0.75 是通用起点
4. **停用词过滤**：移除"的"、"是"等无信息量词
5. **RRF 融合**：用 Reciprocal Rank Fusion 合并 BM25 和向量结果

## 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 中文检索差 | 未分词 | 配置 jieba/IK 分词器 |
| 召回率低 | 参数不当 | 调整 k1=1.2, b=0.75 |
| 与向量结果冲突 | 权重不当 | RRF 融合 + 权重调优 |
| 索引慢 | 数据量大 | 批量索引 + 异步 |
