# AI GURU 开源发布计划（2026-11）

> 制定：2026-11-02 · 范围：console 本体（不含 `wiki/GPU高网设计/`，该知识库另行规划）
> 一句话判断：**console 不以「产品」开源，以「数据 + 协议」开源。**

---

## 0. 结论先行

console 的护城河是 **69 节点骨架 + 证据层 + 六态核验纪律**，不是单页界面。社区会 fork 数据和工具，不会 fork 一个内容站。所以发布顺序必须是：

1. **数据层**（chain / clues / chronicle / verify）——先开放；
2. **站点层**（每节点可抓取页面 + sitemap + JSON-LD）——让人找得到；
3. **工作台层**（现有 console）——留作参考实现与本地优先模式。

对外叙事同步切换：**「不是又一个 AI 新闻站，而是一张可被引用、可被机器消费、可被社区修订的 AI 产业结构图。」**

---

## 1. 三个硬约束（为什么不能按产品发布）

| 约束 | 现状 | 后果 |
|---|---|---|
| 内容产品，不是代码产品 | 4.8MB 单页 + 2.97MB `data.js` | 开发者会看，不会参与 |
| 不可机器消费 | 数据锁在 JS 对象；路由是 `#/chain/...` 哈希 | 爬虫抓不到、Agent 读不了、无法二次开发 |
| 单点维护 | 48/48 次人为提交，bus factor = 1 | 社区先怀疑可持续性，再谈贡献 |

## 2. 切入角度

### 主角度：AI 行业的开源坐标系（Open Industry Graph）

> 不是又一个 AI 新闻站，而是一张可被引用、可被机器消费、可被社区修订的 AI 产业结构图。

支撑点：

- 69 节点 × 5 层 × 18 主题域是别人最难复制的部分——分类法比内容更难写；
- 每个节点有稳定坐标（`ai-guru:chain/L1/gpu`），天然适合作为引用单元；
- 六态核验（✅⚠️❓🔍✗E）是一套可公开的协议，不是自说自话；
- 2026 年最缺的是可被答案引擎引用的结构化行业事实，不是资讯。

### 副角度：证据优先的研究协议

把「官方一手源 + ≥2 家交叉印证 + 六态核验 + 修正留痕」独立成公开规范，吸引 researcher、记者、投研，也让 AI 生成内容的泛滥成为反向背书。

### 不选的角度

- 「最全的 AI 行业知识库」——不可验证，容易反噬；
- 「AI 新闻聚合」——红海，且与「不是新闻 console」自相矛盾；
- 「投资决策台」——受众窄、责任重、衰减最快；
- 「漂亮的单页工作台」——UI 不是社区。

---

## 3. 发布形态：三层

### 第 1 层：数据层（真正的开源物）

首发文件（本计划第一批交付）：

```
data/chain.json       五层产业链 + 节点 + 技术栈视图（稳定 uid）
data/topics.json      18 个主题域
data/clues.json       64 条线索（元数据 + 正文 + 分析）
data/chronicle.json   年度大事记
data/verify.json      六态待核实台账
data/models.json      模型登记册
data/players.json     玩家图谱
data/glossary.json    术语库
data/explain.json     节点六层解释 + 行业与企业版图
data/deep.json        节点深度拆解
data/index.json       版本 / asOf / 计数 / 许可证 / 引用格式
schema/*.json         JSON Schema
```

配套：

- **语义化版本**：`v2026.11`，每季度一个 release；
- **npm 包**：`ai-industry-graph`，三行代码加载数据（下一批）；
- **MCP server**：让 Agent 直接查节点、线索、核验状态（下一批）；
- **稳定 ID + 引用格式**：见根目录 `CITATION.md`。

### 第 2 层：站点层（让人找得到）

- 每个节点一个可抓取的静态 URL（不再只有哈希路由）；
- `sitemap.xml` + JSON-LD（`Dataset` / `DefinedTermSet`）+ OG 卡片；
- 保留现有单页工作台作为「本地优先 / 离线」模式；
- 首页 30 秒说清：是什么、为什么不同、怎么用、怎么贡献。

### 第 3 层：工作台层（参考实现）

现有 `console/` 不动，作为「这套数据能长成什么样」的参考实现。

### 渠道顺序

1. GitHub：数据仓 + console 仓互链；英文 README 先行；
2. Hacker News / Reddit：发「Open AI Industry Graph v0.1」+ 69 节点全景图；
3. 中文：即刻、V2EX、知乎、公众号（AI Infra / 算力 / 投研社群）；
4. Agent 生态：MCP server 提交到 MCP 目录、Claude/Cursor 社区；
5. 学术/媒体：给做 AI 产业研究的实验室和记者发「可引用数据集」邮件。

## 5. 贡献阶梯

| 级别 | 动作 | 门槛 | 对应入口 |
|---|---|---|---|
| L0 | 改错字 / 修链接 | 1 分钟 | Issue 模板 |
| L1 | 登记一条待核实 | 5 分钟 | 六态台账 |
| L2 | 给一条结论补来源 | 15 分钟 | `clues.json` / 来源档案 |
| L3 | 写一条线索时间线 | 1 小时 | `docs/线索模板.md` |
| L4 | 提议 / 新建一个节点 | 一次讨论 | `chain.json` |

## 6. 指标（不用 star）

- 被引用次数：周报、论文、AI 答案引擎引到节点页或 `chain.json`；
- 下游消费项目数：fork 后做衍生产品、或直接拉数据的仓库；
- 月活贡献者：按 L0–L4 分桶；
- 节点证据覆盖率：69 节点中非零且 90 天内有增量的比例；
- 待核实清偿率：六态队列里 ✅ / ✗ 结案比例。

---

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 数据衰减 | 版本号 + 季度复核 + `asOf` / 新鲜度徽标 |
| 「最全」反噬 | 对外只说「结构完整、证据可查」，缺口清单公开 |
| 单点维护 | 前 3 个月找到 2–3 位 co-maintainer；从「修过一个数字」的人里找 |
| 版权 | 厂商资料只用事实与自绘图表；不复制图 |
| 贡献质量 | JSON Schema + CI 校验 + 人工 review |
| 范围蔓延 | 对外承诺只覆盖「结构 + 证据」，不承诺「AI 的一切」 |
