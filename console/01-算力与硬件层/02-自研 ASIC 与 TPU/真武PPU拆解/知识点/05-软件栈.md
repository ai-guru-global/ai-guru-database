# 05 · PPU 软件栈：四件套与兼容面

> 硬件参数决定能不能买，软件栈决定敢不敢用。PPU 软件栈 = 自研四件套 + 框架层兼容面，官方口径「业务迁移零代码修改」。

## 自研四件套（官方页口径，2026-11-06 检索）

| 组件 | 角色 | 对标的业界组件 |
|---|---|---|
| PPU SDK（2.2.0） | 工具链总纲：编译器 + 开源加速库 + 驱动 | CUDA Toolkit / Neuron SDK |
| ACCL-P | 自研集合通信库 | NCCL / HCCL |
| acext | 算子库（PyTorch 扩展算子） | cuDNN/cuBLAS / CANN 算子库 |
| HolmesLLM | 自研推理框架 | TensorRT-LLM / vLLM |

工程接入面：pip 可装适配包 + 官方容器镜像 + ACS 标准 K8s 零改造接入；编译器用法官方称「与 GPU 类似，可无缝切换」（官方自述）。

## 框架与模型兼容面

- **框架**：Megatron / DeepSpeed / DeepEP / vLLM / SGLang——训练侧钩住 Megatron 系，推理侧钩住 vLLM/SGLang 系，恰好是当前事实标准的两大栈；
- **模型**：Qwen / LLaMA / DeepSeek / Kimi / GLM——覆盖主流开源阵营；训练场景含预训练与后训练（Finetune、Roll-out 强化学习集群），推理场景支持 PD 分离部署万亿参数 MoE、长上下文、int8/MoE 优化；
- **自动驾驶**：50+ 常见模型适配（感知/预测/端到端），PAI-TurboX 加速框架——说明平头哥在复用阿里云自动驾驶客户群（小鹏等）做垂直场景。

## 「零代码修改」的真实边界（观点层）

框架层兼容承诺的是**主流路径零修改**：标准 PyTorch 训练循环、标准 vLLM 服务化、已适配模型的推理。以下三类不在承诺内，迁移时的真实摩擦在这里：

1. **自定义算子**：CUDA/C++ 手写算子需要用 acext 重写或等价替换——AI 创业公司常用 trick 大多在这里；
2. **调试与性能工具链**：CUDA 生态二十年沉淀的 profiler/debugger/社区答案库，PPU 侧需要时间积累；
3. **长尾依赖**：依赖特定 CUDA 版本行为的第三方库（量化、通信、图优化类）。

判断：**「零代码」对 80% 的标准负载成立，剩余 20% 决定迁移的真实成本**——这也是选型 POC 必须测自有负载而非跑分的原因（→ [06-软件路线对比](06-软件路线对比.md)）。
