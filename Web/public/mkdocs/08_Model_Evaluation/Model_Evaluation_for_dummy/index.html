    模型评估 - 小白版

    一句话秒懂: 就像给学生打分,不能只看数学成绩,还要看语文、体育、品德——评估 AI 也需要多个维度的"成绩单"!

    你将学到什么

    • 你能够理解为什么需要多种评估指标(不只看准确率)
    • 你能够知道准确率、召回率、F1 值都是什么
    • 你能够了解 A/B 测试如何对比模型效果
    • 你能够掌握 LLM 的专属评估方法
    • 你能够明白离线评估和在线评估的区别

    为什么这个很重要?

    真实故事:99% 准确率的"废物"模型

    场景:医疗 AI 检测癌症

    模型A(看起来很厉害):

    准确率:99%! 🎉
→ 看起来超级棒!

实际情况:
- 测试集 1000 人:990 健康人,10 个癌症患者
- 模型策略:全部预测为"健康"
- 结果:990 个对,10 个错 → 准确率 99%

但是:
❌ 10 个癌症患者全部漏诊!
→ 这个模型完全没用!

    模型B(更有用):

    准确率:95%
召回率:90%(10个患者找到9个)
→ 虽然准确率低一点,但救了命!

    教训: 单看准确率不够,要看多个指标!

    核心概念

    1. 四大基础指标:考试的四种结果

    生活中的例子: 老师判卷,有四种情况:

    学生答案 vs 正确答案:

1. 学生答"对",真实也是"对" → ✓ 答对了!
2. 学生答"错",真实也是"错" → ✓ 答对了!
3. 学生答"对",真实是"错"    → ✗ 错误判断
4. 学生答"错",真实是"对"    → ✗ 漏掉正确答案

    AI 的混淆矩阵:

                   实际情况
             正例  负例
预测  正例    TP    FP
结果  负例    FN    TN

TP(True Positive):预测对,实际也对 ✓✓
TN(True Negative):预测错,实际也错 ✓✓
FP(False Positive):预测对,实际是错 ✗(误报)
FN(False Negative):预测错,实际是对 ✗(漏报)

    真实案例(垃圾邮件过滤):

    测试 100 封邮件:
- 70 封正常邮件,30 封垃圾邮件

模型预测结果:
TP = 25(正确识别 25 封垃圾邮件)
FP = 5(误把 5 封正常邮件当垃圾)
FN = 5(漏掉 5 封垃圾邮件)
TN = 65(正确识别 65 封正常邮件)

    简单来说: 这四个数字是评估的基础,所有其他指标都从这里算出来!

    记住这个: - FP(误报):把好人当坏人,冤枉了 - FN(漏报):把坏人当好人,放跑了

    2. 准确率:整体表现

    生活中的例子: 100 道题的考试,做对多少道?

    准确率 = 做对的题数 / 总题数

考了 90 分 = 90% 准确率

    AI 的准确率:

    准确率(Accuracy) = (TP + TN) / (TP + TN + FP + FN)

通俗版:
准确率 = 预测对的 / 总数

垃圾邮件例子:
准确率 = (25 + 65) / 100 = 90%

    优点: - ✅ 简单直观,一眼看懂

    缺点: - ❌ 数据不平衡时会误导!

    数据不平衡问题:

    场景:欺诈检测
- 9990 笔正常交易
- 10 笔欺诈交易

模型策略:全部预测"正常"
准确率 = 9990 / 10000 = 99.9%!

但是:
❌ 10 笔欺诈全漏掉!
→ 这个模型完全没用!

    简单来说: 准确率像"总分",但不平衡数据时会欺骗你!

    记住这个: 准确率高 ≠ 模型好!特别是正负样本数量差很大时。

    3. 召回率:找得全不全

    生活中的例子: 警察抓小偷,应该抓 10 个,实际抓了几个?

    召回率 = 实际抓到的小偷 / 应该抓的小偷

抓到 8 个 → 召回率 80%

    AI 的召回率:

    召回率(Recall) = TP / (TP + FN)

通俗版:
召回率 = 找到的正例 / 应该找的正例

垃圾邮件例子:
召回率 = 25 / (25 + 5) = 83.3%
→ 30 封垃圾邮件找到 25 封

    什么时候重视召回率? - 🏥 医疗诊断:宁可误诊,不能漏诊(漏掉癌症很危险!) - 🚨 欺诈检测:宁可误报,不能放过坏人 - 🔍 搜索引擎:宁可多返回,不能漏掉相关结果

    真实案例(癌症筛查):

    模型A:
召回率 95%(100个患者找到95个)
误诊率 10%(把一些健康人误判)
→ 救了 95 条命,值得!

模型B:
召回率 70%(100个患者找到70个)
误诊率 1%
→ 漏掉 30 个患者,危险!

    简单来说: 召回率衡量"不要放过坏人"的能力!

    记住这个: 高召回率 = 宁可错杀,不可放过!(适合高风险场景)

    4. 精确率:找得准不准

    生活中的例子: 警察抓了 10 个人,其中有几个真的是小偷?

    精确率 = 真小偷 / 抓到的人

10 个人里 8 个是小偷 → 精确率 80%

    AI 的精确率:

    精确率(Precision) = TP / (TP + FP)

通俗版:
精确率 = 预测对的正例 / 预测的所有正例

垃圾邮件例子:
精确率 = 25 / (25 + 5) = 83.3%
→ 预测 30 封垃圾邮件,25 封是对的

    什么时候重视精确率? - 📧 垃圾邮件过滤:不能把重要邮件当垃圾(误报很麻烦!) - ⚖️ 法律判决:宁可放过,不能冤枉好人 - 💰 推荐系统:推荐错了用户会不爽

    真实案例(邮件过滤):

    模型A:
精确率 99%(预测 100 封垃圾,99 封对)
召回率 60%
→ 几乎不误报,但漏掉一些垃圾邮件

模型B:
精确率 80%
召回率 95%
→ 找得全,但误报多(重要邮件进垃圾箱!)

    简单来说: 精确率衡量"不要冤枉好人"的能力!

    记住这个: 高精确率 = 宁可放过,不可错杀!(适合误报代价高的场景)

    5. F1 值:平衡木

    生活中的例子: 体操平衡木,既要速度快(召回率),又要不掉下来(精确率)

    F1 = 综合评分,平衡两者

单方面好不行:
- 只快不稳 → 会摔!
- 只稳不快 → 分数低!

    AI 的 F1 值:

    F1 = 2 × (精确率 × 召回率) / (精确率 + 召回率)

通俗版:
F1 = 精确率和召回率的平衡点

垃圾邮件例子:
精确率 = 83.3%
召回率 = 83.3%
F1 = 2 × (0.833 × 0.833) / (0.833 + 0.833) = 83.3%

    为什么用 F1?

    场景:对比两个模型

模型A:
精确率 95%,召回率 60%
→ 找得准但漏得多

模型B:
精确率 60%,召回率 95%
→ 找得全但误报多

哪个好?不好说!

用 F1 综合评估:
模型A F1 = 73.8%
模型B F1 = 73.8%
→ 综合表现一样!

    简单来说: F1 是精确率和召回率的"综合成绩",一个指标看整体!

    记住这个: F1 越高越好,但要看场景——有时宁可牺牲 F1 来提升召回率或精确率!

    6. A/B 测试:双胞胎对比实验

    生活中的例子: 超市测试两种促销方案:

    A 方案:买一送一(给一半顾客)
B 方案:7 折优惠(给另一半顾客)

一周后对比:
A 方案:销量提升 20%
B 方案:销量提升 15%
→ A 方案更好!全面推广 A 方案

    AI 的 A/B 测试:

    场景:推荐系统

模型A(旧版):推荐算法 v1
模型B(新版):推荐算法 v2

实验:
- 50% 用户看到 A 的推荐
- 50% 用户看到 B 的推荐

运行 7 天,对比:
- 点击率
- 购买转化率
- 用户停留时间

结果:
模型B 点击率提升 10% → 胜出!

    A/B 测试流程:

    1. 分流:随机分配用户到 A 组或 B 组
2. 运行:同时运行两个版本
3. 收集:记录所有关键指标
4. 分析:统计显著性检验
5. 决策:选择更好的版本全量上线

    注意事项: - ✅ 样本要足够大(至少几千用户) - ✅ 运行时间要够长(避免短期波动) - ✅ 随机分配(避免偏见)

    真实案例(Netflix):

    测试新推荐算法:
- A组(500万用户):旧算法
- B组(500万用户):新算法

观察 2 周:
- B组观看时长提升 8%
- B组新剧点击率提升 12%
→ 新算法胜出,全量上线!

    简单来说: A/B 测试就是让两个模型"同台竞技",用真实用户数据决胜负!

    记住这个: A/B 测试是"真金不怕火炼"——再好的离线指标,也要经过真实用户验证!

    图解理解

    混淆矩阵可视化

             实际情况
       癌症  健康
预测 癌症  90    5   ← 精确率 = 90/(90+5) = 94.7%
结果 健康  10   895
       ↑
    召回率 = 90/(90+10) = 90%

    准确率 vs 召回率 vs F1

    准确率:看整体
    做对的题
    ─────────
      总题数

召回率:看"不漏"
   找到的坏人
   ─────────
   应该找的坏人

精确率:看"不冤"
   真坏人
   ─────────
   抓到的人

F1:看平衡
   精确率和召回率的调和平均

    A/B 测试示意图

    用户流量
    │
    ├─ 50% → 模型A(旧版) → 记录指标A
    │
    └─ 50% → 模型B(新版) → 记录指标B

运行 2 周 → 对比 → 选胜者

    常见问题

    Q1: 什么时候用准确率,什么时候用 F1?

    A: 看数据平衡程度!

    数据平衡(正负样本差不多):

    例子:猫狗分类
- 5000 张猫照片
- 5000 张狗照片
→ 用准确率即可!

    数据不平衡(正负样本差很多):

    例子:欺诈检测
- 9990 笔正常交易
- 10 笔欺诈交易
→ 必须用 F1(或召回率/精确率)!

原因:
全预测"正常"也能 99.9% 准确率,
但完全没用!

    经验法则: - 正负样本比例 > 1:3 → 用 F1 - 正负样本比例 < 1:3 → 准确率可参考

    Q2: 如何选择召回率和精确率的权衡?

    A: 看错误的代价!

    误报代价高(FP 危害大):

    场景:推荐系统
误报:推荐了不喜欢的商品
→ 用户不爽,流失!
→ 提升精确率!

    漏报代价高(FN 危害大):

    场景:癌症筛查
漏报:患者没被检测出来
→ 可能丧命!
→ 提升召回率!

    权衡公式(F-beta):

    F2(更重视召回率) = 5 × P × R / (4P + R)
F0.5(更重视精确率) = 1.25 × P × R / (0.25P + R)

    决策树:

    错误代价对比
    ↓
误报更严重? → 提升精确率
    ↓ 否
漏报更严重? → 提升召回率
    ↓ 否
两者平衡 → 用 F1

    Q3: 离线评估和在线评估有什么区别?

    A: 一个是模拟考,一个是正式考!

    离线评估(上线前):

    用途:模拟测试
数据:历史数据集(固定)
速度:快(几分钟出结果)
成本:低(不影响用户)

例子:
在测试集上跑模型,算准确率

    在线评估(上线后):

    用途:真实环境测试
数据:实时用户数据
速度:慢(需观察几天/几周)
成本:高(可能影响用户体验)

例子:
A/B 测试,对比新旧模型

    关系:

    离线评估通过 → 进入在线评估 → 全量上线
离线评估不过 → 继续优化 ✗

    为什么都需要?

    离线高分 ≠ 在线效果好!

原因:
- 测试集可能不代表真实分布
- 用户行为实时变化
- 离线指标和业务指标不完全对应

真实案例:
离线准确率 95% 的模型,
在线点击率反而下降 5%!
→ 可能推荐太保守,用户觉得无聊

    Q4: LLM(大语言模型)如何评估?

    A: 比传统模型复杂得多!

    传统模型评估(分类/回归):

    有标准答案:
输入:猫的照片
正确答案:猫
模型输出:猫 ✓

→ 对比即可!

    LLM 评估(生成任务):

    没有唯一标准答案:
输入:"写一首关于秋天的诗"
正确答案:??? (无数种可能)
模型输出:[一首诗]

→ 如何评估好坏?

    LLM 评估方法:

    1. 自动化指标:

    BLEU:和参考答案的重叠度
ROUGE:和参考答案的召回率
Perplexity:困惑度(越低越好)

缺点:
不能真正衡量"质量"

    2. 人类评估:

    让人类打分:
- 相关性:是否回答了问题?
- 流畅性:语言是否自然?
- 准确性:信息是否正确?
- 有用性:是否对用户有帮助?

缺点:
成本高,速度慢

    3. LLM-as-Judge:

    用更强的 LLM 评估:
"请评价以下回答的质量(1-10分):
问题:{question}
回答:{answer}
评分依据:相关性、准确性、完整性"

优点:
便宜、快速、可扩展

    4. 基准测试:

    MMLU:综合知识测试(57个学科)
HumanEval:代码生成能力
MT-Bench:多轮对话能力
TruthfulQA:是否会胡编乱造

    真实案例(GPT-4 评估):

    OpenAI 的评估体系:
1. 自动化测试:MMLU、HumanEval 等
2. 人类评估:雇佣标注员打分
3. 红队测试:找漏洞和安全问题
4. A/B 测试:ChatGPT 用户反馈

    Q5: 如何设计好的 A/B 测试?

    A: 遵循科学实验原则!

    1. 样本量足够:

    太少:
100 个用户 → 偶然因素大,不可信

足够:
10000+ 用户 → 统计显著

    2. 随机分配:

    ❌ 错误:新用户用A,老用户用B
→ 两组本来就不同!

✅ 正确:完全随机分配
→ 确保两组"除了模型,其他都一样"

    3. 时间要够长:

    太短:
测试 1 天 → 可能赶上周末,不代表平时

足够:
测试 1-2 周 → 覆盖工作日+周末

    4. 单一变量:

    ❌ 同时改多个东西:
A:旧模型 + 旧UI
B:新模型 + 新UI
→ 不知道是模型好还是UI好

✅ 只改模型:
A:旧模型
B:新模型
→ 清楚是模型的功劳

    5. 监控副作用:

    不能只看主指标:
主指标:点击率提升 10% ✓

但是:
- 购买转化率下降 5% ✗
- 用户投诉增加 20% ✗
→ 综合判断,不能盲目上线!
