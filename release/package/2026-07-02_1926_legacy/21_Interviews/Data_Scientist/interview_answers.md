# Data Scientist 面试题实例答案

> 每个答案采用 **结论 → 展开 → 追问预判** 结构，适合面试场景直接参考。

---

## 统计理论

### Q1: 解释置信区间与 p-value 的区别，p < 0.05 意味着什么？

**结论**: p-value 衡量"假设成立时观察到当前或更极端结果的概率"，置信区间给出参数的可能范围。p < 0.05 只说明结果不太可能是随机噪声，不代表效果大小。

**展开**:
- **p-value**: P(数据 ≥ 观测值 | H₀ 为真)。p < 0.05 → 拒绝原假设，但可能犯 Type I Error (5% 概率)
- **置信区间**: 95% CI 表示重复抽样 100 次，约 95 次会包含真实参数。比 p-value 更有信息量
- **常见误区**: p < 0.05 ≠ "效果大"，p > 0.05 ≠ "没效果" (可能是样本量不够)
- **最佳实践**: 同时报告 p-value、置信区间和效应量 (Cohen's d / 相对提升%)

**追问预判**: "p-hacking 是什么？如何避免？"
→ 反复尝试不同分析直到 p < 0.05。解决: 预注册假设、Bonferroni 多重校正、控制 FDR。

### Q2: 相关性与因果性如何区分？在观测数据中如何推断因果？

**结论**: 相关性只说明变量共同变化，因果性需要排除混杂因素。观测数据中可用倾向得分匹配、DID、工具变量等因果推断方法。

**展开**:
- **经典案例**: 冰淇淋销量 ↑ 和溺水人数 ↑ 正相关，但冰淇淋不导致溺水 (共同原因: 温度)
- **因果推断方法**:
  - **RCT (A/B 测试)**: 随机分配 → 最强因果证据
  - **倾向得分匹配 (PSM)**: 模拟随机化，使处理组和对照组特征分布相似
  - **DID (双重差分)**: 比较处理前后的变化差异，控制时间趋势
  - **工具变量 (IV)**: 利用外生变量打破内生性 (如: 距离→入学率→收入)
- **实践建议**: 能做 A/B 测试优先做；不能做时，用多种方法交叉验证

**追问预判**: "什么时候 A/B 测试不可行？"
→ ①伦理限制 (测试涨价) ②样本太少 ③网络效应 (社交产品) ④长期效果 (需数月观察)

## 实验设计

### Q3: 设计一个完整的 A/B 测试流程？

**结论**: 五步走：假设定义 → 样本量估算 → 随机分流 → 实验运行 → 结果分析与决策。

**展开**:
- **Step 1 - 假设**: H₀ (无差异) vs H₁ (有差异)，定义核心指标 + 护栏指标
- **Step 2 - 样本量**: 需要 baseline 转化率、MDE (最小可检测效应)、α=0.05、Power=0.8
  - 公式: n = (Z_{1-α/2} + Z_{1-β})² × p(1-p) / δ²
- **Step 3 - 分流**: 用户级随机化 (非请求级)，检查 SRM
- **Step 4 - 运行**: 至少跑 1-2 周 (覆盖周中/周末差异)，不做 Peeking
- **Step 5 - 分析**: t-test / z-test → p-value + CI + 效应量 → 异质性分析 (按国家/设备/新老用户)

**追问预判**: "如果跑了两周还不显著怎么办？"
→ ①检查是否有 SRM 或数据质量问题 ②考虑 MDE 是否设置过高 ③延长实验或增加样本 ④接受"没有效果"的结论，不要 p-hacking。

### Q4: 什么是 SRM？如何检测和处理？

**结论**: SRM (Sample Ratio Mismatch) 是实际分流比例偏离预期比例，说明分流有问题，实验结论不可信。

**展开**:
- **检测方法**: 卡方检验 (χ²)，如预期 50:50 但实际 51:49 → χ² = (O-E)²/E 求和
- **常见原因**:
  - 分流 hash 不均匀 (bot/爬虫集中在某组)
  - 某组 crash/错误率高导致数据丢失
  - 分流逻辑 bug (如按 user_id % 2 但 user_id 分布不均)
- **处理方式**: ①先修复分流问题 ②重新运行实验 ③SRM 未解决前不解读实验结果

**追问预判**: "SRM 的 p-value 多少算有问题？"
→ 通常 p < 0.001 说明分流有显著问题，需排查。

## 业务分析

### Q5: 核心指标突然下降 10%，你的排查步骤？

**结论**: 四步定位法：核实数据 → 时间对齐 → 维度拆解 → 归因验证。

**展开**:
- **Step 1 - 核实数据**: 口径是否变更？数据源是否延迟/缺失？ETL 是否异常？
- **Step 2 - 时间对齐**: 下降时间点与什么变更吻合？(版本发布/运营活动/竞品动作/节假日)
- **Step 3 - 维度拆解**:
  - 按平台 (iOS/Android/Web) → 是否单端问题
  - 按国家/地区 → 是否局部问题
  - 按用户类型 (新/老) → 是否拉新问题
  - 按漏斗步骤 → 哪个环节掉得最多
- **Step 4 - 归因验证**: 形成假设 → 用数据验证 → 必要时发起实验确认因果

**追问预判**: "如果所有维度都在降，可能是什么？"
→ 可能是全局因素：大盘流量变化、季节性、竞品大促、宏观环境。看行业基准数据对比。

### Q6: 如何构建业务指标体系？

**结论**: 三层结构：北极星指标 (1 个) → 一级指标 (3-5 个) → 过程指标 (若干)，上下对齐，定期 Review。

**展开**:
- **北极星指标**: 最能反映业务核心价值的单一指标 (如: 周活跃用户数、GMV、DAU)
- **一级指标**: 拆解北极星 (如 GMV = 用户数 × 下单率 × 客单价)
- **过程指标**: 各环节转化率、功能使用率、错误率
- **护栏指标**: 不可退化的底线 (如: 页面加载时间、退款率)
- **治理原则**: 指标口径文档化 (数据字典)，统一计算逻辑，定期校准

**追问预判**: "如何衡量一个指标是否'好'？"
→ ①可行动 (Actionable) ②可比较 (Comparable over time) ③可理解 (Understandable) ④可审计 (Auditable)

## 机器学习应用

### Q7: Churn Prediction 的特征工程和模型选择？

**结论**: 核心是构建"用户行为变化"特征 (活跃度趋势、最近行为间隔)，模型选 XGBoost/LightGBM + 校准输出概率。

**展开**:
- **关键特征**:
  - RFM: Recency (最近一次活跃)、Frequency (活跃频率)、Monetary (付费金额)
  - 行为趋势: 最近 7 天 vs 前 7 天的活跃变化率
  - 产品使用: 核心功能使用深度、功能覆盖率
  - 支持交互: 投诉次数、客服对话情感分数
- **模型选择**: XGBoost (可解释 + 强基线) → 校准 (Platt Scaling / Isotonic Regression) → 输出流失概率
- **业务闭环**: 预测高风险用户 → 分层触达 (优惠/关怀/客服回访) → 追踪干预效果

**追问预判**: "Churn 的定义怎么定？"
→ 取决于业务: 订阅制 = 取消订阅；免费产品 = 连续 N 天未活跃。需要和产品/业务对齐。

## 行为面试

### Q8: 描述一个你用数据驱动业务决策的项目

**答案结构 (STAR)**:
- **Situation**: "公司核心产品的新用户 7 日留存率从 40% 下降到 32%"
- **Task**: "我被要求定位原因并提出改善方案"
- **Action**: "①Cohort 分析发现下降主要来自某渠道新用户 ②深入分析发现该渠道用户未触达核心功能 ③设计 A/B 测试：新用户引导流程增加核心功能体验 ④实验证明新引导提升留存 8pp"
- **Result**: "全量上线后月留存用户增加 15K，年化 LTV 提升 $2M"

### Q9: 如何向非技术人员解释一个统计结论？

**答案结构**:
- **避免**: "p-value = 0.03"、"95% CI"、"Cohen's d = 0.2"
- **使用**: "我们有 97% 的信心认为方案 A 比方案 B 好，预计提升转化率 2-5%"
- **可视化**: 用置信区间图代替数字表格，用 before/after 对比代替统计检验表
- **关注决策**: "基于数据，我建议选择方案 A，预期每月多带来 X 个付费用户"

# Data Scientist 面试题实例答案

## Q1: 相关性与因果性如何区分？
**答**：相关性反映变量共同变化，不代表因果。要建立因果关系需控制混杂因素，使用随机实验或因果推断方法（如倾向得分匹配）。在业务场景中，我会优先通过 A/B 测试验证结论。

## Q2: 如何设计一个 A/B 测试？
**答**：先定义核心指标与最小可检测效应，估算样本量与实验周期。确保随机分流与排除干预污染，并设置护栏指标。实验结束后进行显著性检验与异质性分析。

## Q3: 指标突然下降如何处理？
**答**：先核实口径与数据源是否变动，再按漏斗拆解定位影响环节。结合时间序列和分群分析排查外部因素，必要时回滚变更并发起专项实验验证。
