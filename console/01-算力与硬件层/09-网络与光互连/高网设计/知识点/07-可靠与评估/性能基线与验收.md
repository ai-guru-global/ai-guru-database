# 性能基线与验收

> 定义 algbw/busbw、bisection、小消息时延等可比指标，用"单跳→集合→端到端"逐层验收流程和 72h 长稳测试把网络验收从"能跑通"变成"可交付"。

## 解决什么问题

集群交付争议大多源于指标口径不清：测的是单向还是双向、算的是 algbw 还是 busbw、消息尺寸多大、跳过哪些层。本篇定义标准化指标与健康线，给出逐层验收流程与验收报告要点，让建设方、集成方、业务方在同一把尺子下签字。

## 核心原理

指标定义：
- algbw（算法带宽）= 消息量 S / 耗时 t，衡量集合算法本身的搬数速率；
- busbw（总线带宽）：把集合通信折算为"等效总线上每个节点都在收发"的口径，用于跨算法、跨规模比较。换算公式：
  - AllReduce：busbw = algbw × 2(n−1)/n（n=8 时 ×1.75，n=72 时 ×1.97，n→∞ 趋近 ×2）；
  - AllGather / ReduceScatter：busbw = algbw × (n−1)/n；
- bisection（对分带宽）：把网络对半划分后，跨分割面的聚合吞吐，衡量拓扑收敛能力；
- 小消息时延：64B 量级消息的端到端 RTT/单向时延，衡量控制面与同步类开销（交换机逐跳转发时延为百纳秒量级，具体芯片值待核实）。

## 关键数字

健康线（典型口径，具体合同值依代际与机型协商）：

| 指标 | 健康线 | 口径说明 |
|---|---|---|
| AllReduce busbw（大消息 256MiB–1GiB） | ≥ 单向链路峰值带宽的 80%–90% | nccl-tests，全拓扑、双平面取单平面满配 |
| 链路 FLR（帧丢失率） | < 1e-12 | 打流 48h 以上统计 |
| PFC 暂停占比 | < 0.1%（严苛要求 <0.01%） | 暂停时间/端口在线时间 |
| 端口 CRC | 验收期零增长 | 或按周增量个位数内（合同口径） |
| ECN 标记率 | 稳态 1e-6 量级 | 与拥塞控制参数联动解读 |
| 步长 P99/P50 | < 1.05–1.1 | 真实作业长稳口径 |

## 设计要点与权衡

逐层验收流程：

| 层 | 工具/手段 | 通过标准 |
|---|---|---|
| 物理层 | 光功率、CRC/FEC、链路训练速率 | 全端口达标，错误清零 |
| 单跳 | ib_write_bw 双向打满（逐端口矩阵） | 达线速 90% 以上（典型口径） |
| 全拓扑路径 | 跨 leaf/spine 组合打流、bisection 测试 | ECMP 分布均匀、无黑洞路径 |
| 集合层 | nccl-tests（机内 8 / 超节点 72 / 跨域 N） | busbw 达健康线 |
| 端到端 | 真实模型 MFU、步长 P99、checkpoint/续训演练 | 达业务约定值，故障注入后可恢复 |

验收报告模板要点：版本快照（GPU/网卡固件、驱动、NCCL、交换机 OS、拓扑导出）、环境记录（温度、供电、液冷参数）、各层基线数据及与历史基线的漂移对比、72h 长稳记录、遗留问题与豁免清单、复测触发条件（固件变更、扩容、故障率异常）。

## 常见坑

- 只测静态基准不测长稳：光模块温漂（机柜热点）、buffer/内存泄漏、路由振荡、固件垃圾回收类问题只在 72h 级稳定性测试中暴露，静态跑分全部通过不代表可交付。
- 基线不分消息尺寸：只报 1GiB 大消息，小消息时延与中等消息（EP all-to-all 主力区间）性能失察。
- 验收只看均值不看 P99：均值达标但 P99 抖动大，训练吞吐仍被尾延迟锁死。
- 用 synthetic 微基准代替真实作业：NCCL 拓扑文件与实际布线不一致时，微基准正常、真实作业走错拓扑。
- 口径不注明（双向/单双向叠加、busbw 与 algbw 混用）：交付双方各说各话，报告不可比。
