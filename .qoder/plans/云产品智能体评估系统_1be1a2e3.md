# 云产品智能体能力评估系统实施计划

## 背景

项目在 `07_AI_Engineering/12_Agent_Evaluation/` 已有丰富的评估文档（CAPER五维模型、排行榜模板、测试题库等），但缺少：

## Task 1: 创建评估框架Python源码目录结构

在 `07_AI_Engineering/12_Agent_Evaluation/` 下创建 `demo/` 目录：

```
demo/
├── README.md                    # 使用说明
├── requirements.txt             # Python依赖
├── config.yaml                  # 评估配置
├── run_evaluation.py            # 主入口脚本
├── evaluator/
│   ├── __init__.py
│   ├── core.py                  # 核心评估引擎
│   ├── metrics.py               # 指标计算（CAPER五维）
│   ├── scorer.py                # 评分聚合与排名
│   ├── llm_judge.py             # LLM-as-Judge评估器
│   └── safety_checker.py        # 安全性检测
├── plugins/
│   ├── __init__.py
│   ├── base.py                  # 插件基类
│   ├── aliyun_plugin.py         # 阿里云Agent适配器
│   └── openai_plugin.py         # OpenAI Agent适配器
├── datasets/
│   ├── cloud_knowledge_qa.json  # 云知识问答测试集
│   ├── task_completion.json     # 任务完成测试集
│   ├── safety_test.json         # 安全性测试集
│   └── interaction_quality.json # 交互质量测试集
└── results/
    └── sample_results.json      # 示例评估结果
```

核心设计：
- `evaluator/core.py`: EvaluationPipeline类，支持批量测试、并行评估、结果聚合
- `evaluator/metrics.py`: 实现CAPER五维指标（知识25% + 任务25% + 性价比20% + 交互15% + 安全15%）
- `plugins/base.py`: AgentPlugin抽象基类，定义evaluate()、call()接口，支持插件化扩展
- 所有代码包含模拟模式，无需真实API即可运行Demo

## Task 2: 实现评估框架核心代码

**文件**: `demo/evaluator/core.py`
- EvaluationPipeline: 加载配置 -> 加载数据集 -> 遍历Agent插件 -> 执行评估 -> 聚合分数
- 支持并行评估多个Agent
- 生成JSON格式结果报告

**文件**: `demo/evaluator/metrics.py`
- 知识问答准确率（精确匹配+语义相似度）
- 任务完成率（步骤正确性+最终结果）
- 性价比（延迟、Token消耗、成本）
- 交互质量（多轮连贯性、中文能力）
- 安全合规（毒性检测、偏见检测、注入防护）

**文件**: `demo/evaluator/scorer.py`
- CAPER加权评分
- 等级映射（S/A/B/C/D）
- 排名生成

**文件**: `demo/evaluator/llm_judge.py`
- LLM-as-Judge模板
- 模拟评估模式（用于Demo）

**文件**: `demo/evaluator/safety_checker.py`
- 提示注入检测
- 毒性评分
- 偏见检测

## Task 3: 创建测试数据集

4个JSON数据集文件，每个包含典型阿里云场景用例：

## 关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 评估框架语言 | Python | AI/ML生态标准，与opik等框架对齐 |
| 可视化图表 | 纯SVG雷达图 | 避免引入新依赖(recharts等)，保持轻量 |
| 数据格式 | JSON | 前后端通用，与现有dataService模式一致 |
| 排行榜数据 | 静态导入 | Demo阶段无需后端API，直接TypeScript数据 |
| 插件架构 | 抽象基类+注册模式 | 易扩展，新Agent只需实现Plugin接口 |
