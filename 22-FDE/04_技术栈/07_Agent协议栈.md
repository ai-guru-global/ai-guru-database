# Agent 协议栈：MCP / A2A / AG-UI

> **最后更新**：2026-08-03
> **核心认知**：这三个协议**不是竞争关系，而是互补关系**——分别解决 Agent 技术栈的不同层次问题。FDE 在 2026 年做多 Agent 系统部署，必须理解这三层。

---

## 一、三层协议全景

```
┌─────────────────────────────────────────────┐
│  展示层    AG-UI (CopilotKit)               │  Agent ↔ UI
│            流式 Agent 状态/事件到前端          │
├─────────────────────────────────────────────┤
│  Agent 间层  A2A (Google, 2025.04)           │  Agent ↔ Agent
│             多 Agent 协作、任务委派、动态发现   │
├─────────────────────────────────────────────┤
│  工具/数据层  MCP (Anthropic, 2024.11)        │  Agent ↔ 工具与数据源
│              标准化单 Agent 的工具调用          │
└─────────────────────────────────────────────┘
```

> 来源：[学术综述 arxiv 2505.02279](https://arxiv.org/html/2505.02279v1)

## 二、三个协议详解

### 1. MCP（Model Context Protocol）—— 工具/数据层

| 维度 | 内容 |
|---|---|
| **提出方** | Anthropic |
| **发布时间** | 2024 年 11 月 |
| **解决的问题** | 每个 LLM 接工具都要写定制集成；MCP 把「Agent ↔ 工具/数据源」标准化 |
| **连接对象** | 单个 Agent 与其可调用的工具、数据库、API |
| **典型用例** | 让 Claude/GPT 统一调用 GitHub、Slack、数据库、文件系统 |
| **类比** | 「AI 应用的 USB-C 接口」 |

**FDE 视角**：私有化部署时，MCP 让客户内部系统（ERP/CRM/OA）能被任何兼容 Agent 调用，**大幅降低集成成本**。

### 2. A2A（Agent-to-Agent）—— Agent 间层

| 维度 | 内容 |
|---|---|
| **提出方** | Google |
| **发布时间** | 2025 年 4 月 |
| **解决的问题** | 多个 Agent（可能来自不同框架/厂商）如何协作、委派任务、相互发现 |
| **连接对象** | Agent ↔ Agent |
| **典型用例** | 一个「规划 Agent」把子任务委派给多个「执行 Agent」，动态发现可用 Agent |
| **关键能力** | 任务委派、能力发现、跨框架互操作 |

**FDE 视角**：企业级 AI 系统往往是多 Agent 编排（采购 Agent + 财务 Agent + 审批 Agent）。A2A 让这些 Agent 即使基于不同框架也能协作。

### 3. AG-UI（Agent-User Interaction）—— 展示层

| 维度 | 内容 |
|---|---|
| **提出方** | CopilotKit |
| **解决的问题** | Agent 的中间状态、思考过程、工具调用如何实时流式呈现给前端用户 |
| **连接对象** | Agent ↔ UI（前端） |
| **典型用例** | 客户看到 Agent「正在检索知识库 → 找到 3 条相关文档 → 正在生成回答」的实时过程 |
| **关键能力** | 流式事件、状态同步、人机协作（human-in-the-loop） |

**FDE 视角**：政企客户**极度重视可解释性和过程透明**。AG-UI 让 Agent 的推理过程可见，是建立客户信任的关键。

## 三、对比矩阵

| 维度 | MCP | A2A | AG-UI |
|---|---|---|---|
| **层** | 工具/数据 | Agent 间 | 展示 |
| **连接** | Agent ↔ 工具 | Agent ↔ Agent | Agent ↔ UI |
| **提出方** | Anthropic | Google | CopilotKit |
| **发布** | 2024.11 | 2025.04 | 2025 |
| **核心价值** | 集成标准化 | 多 Agent 协作 | 过程透明化 |
| **是否竞争** | ❌ 互补 | ❌ 互补 | ❌ 互补 |

## 四、FDE 如何选用

### 决策树

```
你的 Agent 需要？
├── 调用外部工具/数据库/API？
│   └── ✅ 用 MCP（必选，2026 年事实标准）
│
├── 与其他 Agent 协作/委派任务？
│   └── ✅ 用 A2A（多 Agent 系统推荐）
│
└── 需要把推理过程展示给最终用户？
    └── ✅ 用 AG-UI（政企/金融场景强烈推荐）
```

### 典型组合

| 场景 | 推荐组合 |
|---|---|
| **单 Agent + 工具调用** | MCP |
| **多 Agent 编排（同框架）** | LangGraph + MCP（A2A 可选） |
| **多 Agent 编排（跨框架/跨厂商）** | A2A + MCP |
| **企业级 Agent（需透明度）** | A2A + MCP + AG-UI（全栈） |

### 信创/私有化注意

- MCP/A2A/AG-UI 均为开放协议，**可完全离线运行**，适合私有化
- 但需注意：部分参考实现依赖海外开源组件，FDE 需评估供应链合规性

## 五、与现有技术栈的关系

```
应用层：  Dify / Coze / 自研应用
          ─────────────────────
协议层：  AG-UI（展示）  A2A（Agent间）  MCP（工具）
          ─────────────────────
框架层：  LangGraph / AutoGen / CrewAI / OpenAI Agents SDK
          ─────────────────────
模型层：  GPT / Claude / Qwen / DeepSeek / 本地模型
```

> **关键认知**：协议层是 2025-2026 年的新增层。在此之前的 Agent 系统大多在框架层硬编码集成逻辑；协议层的出现让 Agent 系统从「定制集成」走向「标准化组装」，这正是 FDE 交付效率提升的关键。
