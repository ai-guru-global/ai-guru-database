# 计算通信重叠与MFU

> 网络好不好，最终只有一个判据：通信被计算藏住多少、MFU 被挤掉多少、步长抖不抖。

## 解决什么问题

标称带宽再高，通信只要暴露在关键路径上就直接加进步长。本篇定义三件事：overlap 的机制与边界、MFU 被通信挤压的定量关系、步长时间抖动的网络成因——它们构成训练性能验收中"网络侧"的全部责任边界。

## 核心原理

**overlap 机制**：
- 梯度分桶（bucketing）：反向中梯度不逐层同步，而是按桶（PyTorch DDP 默认 25 MB）凑齐即在独立通信流上异步发起 AllReduce，与后续层反向计算并行；桶大小决定"凑桶等待"与"通信次数"的折中。
- 反向中启动：DP 梯度通信天然可被后续反向掩盖；TP 的层内 AllReduce 与本层计算强依赖、不可重叠；PP 用调度把 P2P 藏进其他 micro-batch 的计算——1F1B、交织式 1F1B 是工程主流，ZB-1L（Zero-Bubble，2023）以修改调度进一步压小 bubble（定位：当前流水线调度的事实前沿之一）。
- 流水线 bubble：p 级流水、m 个 micro-batch，bubble 占比 ≈ (p−1)/(m+p−1)；每多一级跨机跳，P2P RTT 直接加进空泡。

**MFU 与挤压公式**：MFU = 实测 tokens/s × 6N ÷（卡数 × 峰值 FLOPS），N 为参数量，6N 是每 token 前反向 FLOPs 的常用近似（注意力项另计）。通信挤压：MFU ≈ MFU₀ × T_c / (T_c + T_exposed)，其中 MFU₀ 是无通信理论口径、T_c 是计算时间、T_exposed 是未被掩盖的通信时间。TP/EP 通信全额计入 T_exposed；DP 梯度通信只有超出计算窗口的部分计入。

**步长抖动（jitter）**：同步训练里集合通信是全局栅栏，最慢一条链路/一个节点定步长。网络侧成因按危害排序：物理层劣化（端口 flapping 降速、FEC 纠错上升、光模块误码）；拥塞（EP A2A 的 incast 瞬时打满队列）；PFC 暂停（无损反压误伤低优先级队列，队头阻塞 µs–ms 级）；路由变化与重传风暴。单步 P99 与 P50 的差值，基本等于网络最长一次"受害事件"的时长。

## 关键数字

| 项 | 典型值/公式 | 备注 |
|---|---|---|
| DDP 默认 bucket | 25 MB | 大集群常调至 100–400 MB |
| 流水线 bubble 占比 | (p−1)/(m+p−1) | p=8、m=64 时 ≈10% |
| MFU 定义 | tokens/s×6N ÷(卡数×峰值FLOPS) | 分母 6N 为近似 |
| 通信挤压 | MFU ≈ MFU₀×T_c/(T_c+T_exposed) | 只计暴露通信 |
| 跨机单跳 RTT | ~5–10 µs | 同机房 RoCE/IB |
| PFC 暂停时长量级 | µs–ms 级 | 视队列与门限（待核实具体平台参数） |
| 健康步长抖动 | P99/P50 < 1.05–1.1 | 经验值（待核实各厂基线） |
| 大模型稠密训练 MFU | 约 35–55% | 2024—2025 公开报告区间 |

## 设计要点与权衡

- 先测暴露通信再优化网络：用 profiler 把每步通信拆成"已重叠/暴露"两栏；网络优化只对暴露部分有效，其余该动框架与调度。
- bucket 与拓扑联动：跨机大 N 下小 bucket 把带宽项碎片化，先加大 bucket 再判断是否仍暴露。
- PP 跨机优先降 RTT：RTT 进入 bubble，比堆带宽更划算；相邻 stage 放低时延路径。
- 抖动治理顺序：先清物理层（降速/误码端口），再治 incast（拥塞控制、散列均衡），最后调 PFC 门限与队列映射。
- 验收口径：步长 P50/P99/P999 三档 + 长窗（≥12 h）连续跑；只看 P50 会漏掉分钟级慢节点事件。

## 常见坑

- 把 MFU 低全归咎网络：MFU₀ 本身受算子实现与显存带宽限制，先在单机小规模标定 MFU₀ 再外推归因。
- 用平均步长代替分位数：拥塞与 PFC 事件是低概率高伤害，均值完全掩盖。
- 忽视慢节点效应：一张降速网卡把全组 AllReduce 拖到它的水平；监控必须做到每端口粒度。
- overlap 调过头：bucket 过大导致反向结束仍有大块通信未发完（尾延迟），且显存峰值上升。
