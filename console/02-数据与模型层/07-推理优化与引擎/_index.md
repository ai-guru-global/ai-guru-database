# 推理优化与引擎

> vLLM/量化/KV cache 等系统工程，决定单位算力能服务多少用户。

## 拆解卡

- **价值来源**：决定单位算力能服务多少用户，是成本曲线的工程端。
- **护城河**：系统工程深度与硬件耦合优化。
- **瓶颈**：长上下文与高并发下的 KV 带宽墙。
- **领先指标**：推理引擎版本与吞吐基准；单 token 成本下降速率

## 六层速览

推理优化与引擎让同一张卡服务更多用户：吞吐、延迟和成本，全靠调度与内核优化；模型不变，工程能力决定毛利。

**打个比方**：像餐厅翻台率——菜（模型）不变，动线、预制和后厨调度决定一天能接待多少人；同样的厨房，翻台率差三倍就是三倍利润。

**拆开看**：五段链路：引擎（vLLM / SGLang / TensorRT-LLM）→ 批处理与调度 → 量化（FP8 / FP4）→ KV cache 管理与前缀缓存 → 多模型路由；显存带宽往往是真正的瓶颈。

**怎么运转**：开源引擎免费，托管服务按 token 收费；云厂商把推理优化内化为成本优势，单位 token 成本成为核心竞争力，也是价格战的底气。

**格局与博弈**：vLLM、SGLang 主导开源，英伟达 TensorRT-LLM 绑定自家硬件，Groq、Cerebras 用专用芯片抢低延迟场景；中国厂商做国产芯片适配与 PD 分离方案。

**边界与走向**：长上下文与高并发的 KV 带宽墙是主战场，投机解码与 PD 分离会持续提升吞吐；推理成本下降速度决定应用爆发速度，也决定哪些场景能跨过经济性阈值。

## 关键判断

推理是最大结构性增量，但独立推理云需在成本上持续领先（置信度 中高，展望 12–24 个月）——核心变量是单位 token 成本曲线与垂直整合；软件优化是第三方的主要护城河。

规模口径：推理云与引擎约 $300–500 亿（2025e），增速高于训练；Agent 调用放大单用户 token 消耗

## 二级细分

- **推理引擎（vLLM/SGLang）** — 调度、批处理与内核优化的主战场。
- **量化与压缩** — FP4/FP8 与 KV 压缩：精度换吞吐的性价比杠杆。
- **服务化与调度** — 多模型路由、弹性伸缩与冷启动治理。
