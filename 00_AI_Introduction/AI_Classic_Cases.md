## 案例1: AlphaGo vs 李世石 —— AI超越人类专家的里程碑

### 1.1 案例背景

```
时间: 2016年3月8日-15日
地点: 韩国首尔
事件: Google DeepMind的AlphaGo与围棋世界冠军李世石五番棋对决
结果: AlphaGo 4:1 击败李世石
历史意义: AI首次在完全信息博弈中击败人类世界冠军
```

### 1.2 围棋的复杂性

```
为什么围棋是AI的终极挑战?

复杂度对比:
┌─────────────────────────────────────────────────────────┐
│  游戏        状态空间复杂度        穷举可能性           │
├─────────────────────────────────────────────────────────┤
│  国际象棋     10^47               可暴力搜索            │
│  围棋         10^170              宇宙原子数仅10^80     │
│  宇宙原子数   10^80               对比参考              │
└─────────────────────────────────────────────────────────┘

围棋的难点:
├── 分支因子大: 平均每步250种选择(国际象棋35种)
├── 全局性: 局部决策影响全局，难以评估
├── 直觉性: 专业棋手依赖"棋感"，难以形式化
├── 传统AI局限: 规则启发式效果有限

人类观点 (2014年前):
├── "计算机在围棋上战胜人类还需要至少10年"
├── "围棋的直觉和创造力是计算机无法复制的"
└── "这是人类智慧的最后堡垒"
```

### 1.3 AlphaGo技术解析

```
AlphaGo系统架构:

┌─────────────────────────────────────────────────────────┐
│                    AlphaGo                              │
├─────────────────────────────────────────────────────────┤
│  策略网络 (Policy Network)                              │
│  ├── 13层CNN, 预测下一步走法                            │
│  ├── 训练数据: 3000万KGS棋局                            │
│  ├── 准确率: 57% (vs 之前最高44%)                       │
│  └── 作用: 快速缩小搜索空间                             │
├─────────────────────────────────────────────────────────┤
│  价值网络 (Value Network)                               │
│  ├── 评估当前局面胜率                                   │
│  ├── 替代蒙特卡洛模拟，速度提升1000倍                   │
│  └── 作用: 快速评估局面，无需走到底                     │
├─────────────────────────────────────────────────────────┤
│  蒙特卡洛树搜索 (MCTS)                                  │
│  ├── 选择性搜索最有希望的走法                           │
│  ├── 结合策略网络和价值网络                             │
│  └── 模拟未来对局，评估决策                             │
├─────────────────────────────────────────────────────────┤
│  快速走子 (Rollout Policy)                              │
│  ├── 简单线性策略，快速模拟对局                         │
│  └── 用于MCTS的叶节点扩展                               │
└─────────────────────────────────────────────────────────┘

训练过程:
第一阶段: 模仿学习
├── 输入: 人类职业棋手棋谱
├── 方法: 监督学习
├── 输出: 策略网络SL
└── 目标: 学会人类下棋模式

第二阶段: 强化学习
├── 对手: 历史版本的自己
├── 方法: 策略梯度 (REINFORCE)
├── 输出: 策略网络RL
└── 目标: 通过自我对弈提升

第三阶段: 价值网络训练
├── 数据: 策略网络自我对弈生成
├── 方法: 回归
├── 输出: 价值网络
└── 目标: 准确预测胜率

第四阶段: 整合搜索
├── 结合策略网络和价值网络
├── 使用MCTS选择最优走法
└── 实际对弈系统

计算资源:
├── 1202个CPU + 176个GPU
├── 训练时间: 数月
├── 分布式计算
└── 估值数亿美元
```

启示:

### 1.5 第四局: 李世石的"神之一手"

影响:

### 2.2 技术解析

```
ChatGPT背后的技术栈:

基础: GPT架构
├── Transformer解码器
├── 自回归语言建模
├── 预测下一个token
└── 1750亿参数(GPT-3)

关键创新: RLHF
┌─────────────────────────────────────────────────────────┐
│  RLHF (Reinforcement Learning from Human Feedback)      │
├─────────────────────────────────────────────────────────┤
│  Step 1: 监督微调 (SFT)                                 │
│  ├── 收集人类编写的对话数据                             │
│  ├── 监督学习微调GPT                                    │
│  └── 输出: SFT模型                                      │
├─────────────────────────────────────────────────────────┤
│  Step 2: 奖励模型训练                                   │
│  ├── 对同一提示的多个回答进行排序                       │
│  ├── 训练奖励模型预测人类偏好                           │
│  └── 输出: 奖励模型                                     │
├─────────────────────────────────────────────────────────┤
│  Step 3: 强化学习优化                                   │
│  ├── 使用PPO算法                                        │
│  ├── 奖励模型提供反馈                                   │
│  ├── KL散度约束防止偏离太远                             │
│  └── 输出: ChatGPT                                      │
└─────────────────────────────────────────────────────────┘

为什么RLHF有效?
├── 人类偏好复杂难形式化
├── 直接优化人类反馈比模仿更有效
├── 减少有害输出
├── 提高指令遵循能力

数据规模:
├── 预训练数据: 数千亿token
├── RLHF数据: 数万条比较
├── 标注成本: 数百万美元
└── 人力投入: 数百名标注员
```

## 案例3: ImageNet竞赛与深度学习革命

### 3.1 案例背景

```
ImageNet项目:
├── 发起: 李飞飞教授 (斯坦福大学)
├── 时间: 2009年发布
├── 规模: 1400万张图像，2万类别
├── 目标: 解决计算机视觉的数据瓶颈
└── 方法: 众包标注 (Amazon Mechanical Turk)

ImageNet大规模视觉识别挑战赛 (ILSVRC):
├── 开始: 2010年
├── 任务: 1000类图像分类
├── 评估: Top-5错误率
├── 影响: 计算机视觉的"世界杯"
└── 结束: 2017年(准确率已达98%)

2012年前的方法:
├── 手工设计特征 (SIFT, HOG)
├── 浅层机器学习 (SVM)
├── 每年进步: 1-2%
└── 2011年最佳错误率: 25.8%
```

### 3.2 AlexNet突破

```
2012年 ImageNet竞赛:

参赛团队: Alex Krizhevsky, Ilya Sutskever, Geoffrey Hinton
模型: AlexNet
结果: Top-5错误率 15.3% (第二名为26.2%)
优势: 10.9个百分点，史无前例

AlexNet架构创新:
┌─────────────────────────────────────────────────────────┐
│  AlexNet架构 (8层)                                      │
├─────────────────────────────────────────────────────────┤
│  卷积层1: 96个11×11卷积核, ReLU, Max Pooling, LRN      │
│  卷积层2: 256个5×5卷积核, ReLU, Max Pooling, LRN       │
│  卷积层3: 384个3×3卷积核, ReLU                         │
│  卷积层4: 384个3×3卷积核, ReLU                         │
│  卷积层5: 256个3×3卷积核, ReLU, Max Pooling            │
│  全连接6: 4096单元, ReLU, Dropout                      │
│  全连接7: 4096单元, ReLU, Dropout                      │
│  输出层: 1000类Softmax                                 │
└─────────────────────────────────────────────────────────┘

关键技术:
├── ReLU激活函数
│   ├── 解决梯度消失
│   ├── 训练速度快6倍
│   └── 现在成为标配
├── GPU训练
│   ├── 2块GTX 580
│   ├── 开启GPU计算时代
│   └── 现在AI研究离不开GPU
├── Dropout正则化
│   ├── 防止过拟合
│   └── 随机失活50%神经元
├── 数据增强
│   ├── 图像变换扩充数据
│   └── 提高泛化能力
├── 局部响应归一化 (LRN)
│   └── 增强泛化 (后续被Batch Norm取代)

训练细节:
├── 数据集: ImageNet 120万张
├── 硬件: 2块GTX 580 (3GB显存)
├── 时间: 5-6天
├── 参数: 6000万
└── 优化: SGD, 动量0.9

为什么成功?
├── 数据: ImageNet大规模数据
├── 算力: GPU并行计算
├── 算法: 深度CNN + ReLU + Dropout
└── 时机: 三要素齐备
```

### 3.3 后续演进

```
ImageNet竞赛后续 (2012-2017):

2013: ZFNet (14.8%)
├── 可视化CNN内部
├── 理解网络学到的特征
└── 指导架构设计

2014: VGGNet (7.3%)
├── 16-19层深度
├── 3×3小卷积核
├── 架构简单优雅
└── 成为后续标准

2014: GoogLeNet/Inception (6.7%)
├── 22层
├── Inception模块
├── 1×1卷积降维
└── 计算效率优化

2015: ResNet (3.6%)
├── 152层 (后达1000+层)
├── 残差连接
├── 解决深层网络训练难题
├── 超越人类表现 (5.1%)
└── 影响最深远的架构

2016: ResNeXt, DenseNet等 (<3%)
2017: Squeeze-and-Excitation (<2.5%)

里程碑:
2015年: ResNet首次超越人类Top-5准确率
├── 人类: 5.1%
├── ResNet: 3.6%
└── 计算机视觉进入超人类时代
```

## 案例 6: GPT 系列与规模法则 —— 量变引发质变

### 6.1 规模法则发现

```
Scaling Laws (规模法则):

OpenAI 2020年论文揭示:
├── 模型性能 ∝ 算力^0.73
├── 模型性能 ∝ 数据量^0.28
├── 模型性能 ∝ 参数量^0.07
└── 规律: 规模越大，性能越好(可预测)

关键洞察:
├── 性能提升可预测
├── 没有明显饱和点
├── 三个要素可互换
│   (10倍算力 ≈ 10倍数据 ≈ 10倍参数)
├── 持续扩展有效
└── 为大规模训练提供理论依据

实验验证 (GPT系列):
GPT-1 (2018): 1.17亿参数
├── 证明Transformer在NLP有效
├── 无监督预训练 + 有监督微调
└── 启示: 规模可以带来质的变化

GPT-2 (2019): 15亿参数
├── 生成能力惊人
├── 初版因"太危险"不敢发布完整版
├── 引发AI安全讨论
└── Zero-shot能力初现

GPT-3 (2020): 1750亿参数
├── 上下文学习(ICL)涌现
├── few-shot无需梯度更新
├── 广泛任务能力
├── API开放引发应用爆发
└── 证明规模法则的有效性

GPT-4 (2023): 估计1.7万亿参数(MoE)
├── 多模态能力
├── 推理能力大幅提升
├── 考试表现接近人类顶尖水平
└── 商业化成功
```

### 6.2 涌现现象

```
Emergent Abilities (涌现能力):

定义: 模型规模达到阈值后突然展现的新能力
├── 非线性增长
├── 难以预测
├── 量变引起质变

典型涌现能力:
├── 上下文学习 (In-context Learning)
│   └── 看几个例子就能学会任务
├── Chain-of-Thought推理
│   └── 分步思考解决复杂问题
├── 指令遵循 (Instruction Following)
│   └── 理解并执行自然语言指令
├── 多语言翻译
├── 代码生成
└── 世界知识问答

涌现能力示例:
┌─────────────────────────────────────────────────────────┐
│  模型规模        突然涌现的能力                          │
├─────────────────────────────────────────────────────────┤
│  10亿参数       基本语言理解                            │
│  100亿参数      简单推理、翻译                          │
│  1000亿参数     复杂推理、上下文学习、代码              │
│  10000亿参数    高级推理、多模态、接近人类水平          │
└─────────────────────────────────────────────────────────┘

争议:
├── 是否真正"涌现"还是平滑过渡?
├── 评估指标的离散性造成假象?
├── 斯坦福: 涌现可能是评估方式造成
└── 但不可否认规模带来质变
```
