# Designing Machine Learning Systems

> **一句话理解**: ML 系统设计领域的标杆之作，从工程师视角拆解真实 ML 系统的全生命周期，是 MLOps 与 ML 系统面试的必备参考书。

## 书籍概述

### 作者背景

**Chip Huyen** 是 ML 系统工程领域的权威实践者与教育者。她曾在 NVIDIA 主导大规模 ML 平台建设，在 Snorkel AI 负责企业级 ML 落地，并在斯坦福大学开设广受欢迎的课程 CS 329S: Machine Learning Systems Design。本书正是这门课程精华的结晶，凝聚了她对"如何把 ML 模型变成可靠的 ML 系统"的深刻洞察。本书出版后迅速成为 ML 系统设计的事实标准，也是大厂 ML 系统面试的核心参考。

### 本书定位

本书是 **ML 系统设计**领域的奠基之作：

- **不是**讲算法的书（不深入模型数学）
- **而是**讲"系统工程"——如何设计可靠、可扩展、可维护的 ML 系统
- 核心理念：ML 系统是**迭代式**的，不是一次性交付的

在知识库书籍谱系中：
- 本书是 [[ai-engineering-huyen]]（基础模型时代 AI 工程）的**前置与基础**
- 与 [[llms-in-production]]（LLM 生产化）形成"传统 ML → LLM"的进阶
- 是 ML 工程师从"调模型"进阶到"设计系统"的**必读**

## 核心内容

全书以**迭代式 ML 系统开发流程**组织，每章对应系统生命周期的一个环节。

### Part 1 — 基础认知

#### Ch 1: ML 系统概览

- **ML 系统 vs 传统软件**:
  - 传统软件：逻辑明确、确定性
  - ML 系统：数据驱动、概率性、持续演化
- **ML 系统的复杂性**:
  - 不只是模型，还有数据、特征、部署、监控的完整链路
  - "ML 代码只占整个 ML 系统的一小部分"（经典图示）
- **ML 系统的挑战**:
  - 数据依赖与质量
  - 配置复杂性
  - 持续维护成本
- **迭代式开发**: ML 系统需要持续迭代，而非一次性交付

#### Ch 2: 需求与框架

- **业务目标定义**:
  - 把业务问题转化为 ML 问题
  - 明确成功标准
- **需求类型**:
  - 功能性需求（模型要做什么）
  - 非功能性需求（延迟、吞吐、可靠性、成本）
- **约束条件**:
  - 技术约束（硬件、框架）
  - 业务约束（合规、隐私、预算）
- **ML 适用性判断**: 何时该用 ML，何时规则即可
- **需求文档化**: 清晰的需求是成功的前提

### Part 2 — 数据工程

#### Ch 3: 数据工程基础

- **数据模型**:
  - 结构化 vs 非结构化数据
  - 数据 Schema 设计
- **数据来源**:
  - 用户生成数据
  - 系统日志
  - 第三方数据
- **数据标注**:
  - 标注方法（人工、半自动、弱监督）
  - 标注质量控制
  - 标注成本管理
- **数据增强**: 扩充数据集的技术
- **数据版本控制**: 追踪数据变化

#### Ch 4: 特征工程与训练数据

- **特征工程**:
  - 特征提取与构造
  - 特征缩放与编码
  - 缺失值处理
- **特征存储（Feature Store）**:
  - 统一管理特征
  - 训练-推理特征一致性
- **类别不平衡**:
  - 问题识别
  - 处理策略（重采样、加权、合成）
- **数据分布**:
  - 训练集与生产数据的分布差异
  - 分布偏移的早期识别

### Part 3 — 模型开发与评估

#### Ch 5: 模型评估

- **离线评估指标**:
  - 分类：准确率、精确率、召回率、F1、AUC-ROC
  - 回归：MSE、MAE、R²
  - 排序：NDCG、MRR
- **指标选择**:
  - 与业务目标对齐
  - 多指标权衡
- **评估方法**:
  - 训练/验证/测试集划分
  - 交叉验证
- **基线模型**: 建立比较基准
- **评估的陷阱**: 数据泄露、过拟合验证集

#### Ch 6: 模型部署模式

- **部署模式**:
  - **批处理（Batch）**: 离线批量预测
  - **在线预测（Online）**: 实时响应
  - **边缘部署（Edge）**: 设备端推理
- **发布策略**:
  - **影子部署（Shadow）**: 新模型与生产并行，只对比不上线
  - **Canary 发布**: 渐进式小流量验证
  - **A/B 测试**: 对比新旧模型的业务效果
  - **蓝绿部署**: 快速切换与回滚
- **级联（Cascade）**: 多模型串联，逐步精细化
- **部署决策**: 按延迟、成本、风险选择策略

### Part 4 — 监控与持续学习

#### Ch 7: 监控与持续学习

- **监控维度**:
  - 系统监控（延迟、吞吐、错误率）
  - 模型监控（预测分布、质量指标）
- **数据漂移（Data Drift）**:
  - 输入数据分布变化
  - 检测方法（统计检验、分布对比）
- **概念漂移（Concept Drift）**:
  - 输入-输出关系变化
  - 模型性能下降
- **模型更新策略**:
  - 定期重训
  - 触发式重训（漂移检测触发）
  - 在线学习
- **监控告警**: 异常检测与响应

#### Ch 8: 数据分布偏移

- **偏移类型**:
  - 协变量偏移（Covariate Shift）
  - 标签偏移（Label Shift）
  - 概念偏移（Concept Shift）
- **偏移检测**:
  - 统计方法
  - 模型方法
- **应对策略**:
  - 重加权
  - 重训练
  - 域适应
- **真实案例**: 疫情导致的分布偏移

### Part 5 — MLOps 与基础设施

#### Ch 9: MLOps 与持续交付

- **MLOps 核心理念**:
  - ML 系统的持续交付
  - 自动化与可复现
- **CI/CD for ML**:
  - 持续集成（代码 + 数据 + 模型测试）
  - 持续部署（自动化发布）
- **实验管理**:
  - 实验跟踪
  - 模型版本控制
  - 模型注册中心
- **基础设施**:
  - 训练基础设施
  - 推理基础设施
- **团队协作**: ML 工程师、数据工程师、运维的协作

#### Ch 10: 隐式反馈与数据闭环

- **反馈类型**:
  - 显式反馈（用户评分、标注）
  - 隐式反馈（点击、停留、购买）
- **反馈循环**:
  - 用生产反馈改进模型
  - 数据飞轮
- **在线学习**:
  - 增量更新模型
  - 实时适应
- **反馈偏差**:
  - 选择偏差
  - 流行度偏差
- **数据闭环设计**: 构建持续改进的系统

## 关键概念与公式

### 分类评估指标

```
精确率 (Precision) = TP / (TP + FP)   # 预测为正中实际为正的比例
召回率 (Recall)    = TP / (TP + FN)   # 实际为正中被预测出的比例
F1 Score          = 2 × P × R / (P + R)  # 精确率与召回率的调和平均
AUC-ROC           = ROC 曲线下面积    # 整体分类能力
```

### 数据漂移检测

```
分布距离度量:
- KL 散度: D_KL(P || Q) = Σ P(x) log(P(x)/Q(x))
- JS 散度: 对称化的 KL
- PSI (Population Stability Index): 工业界常用
  PSI = Σ (P_i - Q_i) × ln(P_i/Q_i)
  PSI < 0.1: 无显著变化
  0.1-0.25: 中等变化
  > 0.25: 显著漂移
```

### 部署策略的风险对比

```
影子部署: 风险最低（不影响用户），但无法测真实业务效果
Canary:   风险可控（小流量），可测真实效果
A/B 测试: 风险中等，可量化业务影响
全量发布: 风险最高，但收益最快
```

### 类别不平衡处理

```
重采样:
- 过采样少数类 (如 SMOTE)
- 欠采样多数类
- 混合采样

加权损失: L = Σ w_i × loss(y_i, ŷ_i)
其中少数类权重 w 更大

评估: 避免用准确率, 改用 F1、AUC-PR
```

### 亮点

- **案例丰富**: 大量真实工业案例（Netflix、Spotify 等）
- **覆盖 MLOps 全景**: 数据、训练、部署、监控、迭代完整链路
- **面试友好**: ML 系统面试的事实标准参考
- **结构清晰**: 按系统生命周期组织，逻辑严谨
- **作者权威**: Chip Huyen 的工业与教学经验
- **迭代式思维**: 强调 ML 系统的持续演化

### 局限

- **成书于 LLM 爆发前**（2022）: 未深入 LLM 系统设计（需搭配 [[ai-engineering-huyen]]）
- **代码示例少**: 偏方法论，实操代码不多
- **偏传统 ML**: 03_深度学习/基础模型着墨较少
- **工具迭代**: 部分工具推荐可能过时

## ML 系统设计面试速查

本书是 ML 系统面试的事实标准参考。以下是面试核心要点：

### 系统设计题的解答框架

```
1. 澄清需求 (Clarify Requirements)
   - 业务目标是什么？成功指标？
   - 功能需求 + 非功能需求（延迟、吞吐、规模）
   - 约束条件（数据、合规、预算）

2. 数据设计 (Data Design)
   - 数据来源与采集
   - 标注策略
   - 特征工程 / 特征存储

3. 模型设计 (Model Design)
   - 模型选型与基线
   - 评估指标（与业务对齐）
   - 训练策略

4. 部署设计 (Deployment)
   - 部署模式（批/在线/边缘）
   - 发布策略（影子/Canary/A/B）

5. 监控设计 (Monitoring)
   - 系统监控 + 模型监控
   - 漂移检测
   - 更新策略
```

### 高频面试场景

| 场景 | 核心考点 | 本书章节 |
|------|----------|----------|
| 设计推荐系统 | 特征、排序、反馈循环 | Ch 4, 10 |

| 设计搜索排序 | 排序指标、A/B 测试 | Ch 5, 6 |

| 预测类系统（如 ETA） | 回归、漂移监控 | Ch 5, 7 |

### 面试常见陷阱

- **只谈模型不谈系统**: 面试官要的是端到端设计，不是算法细节
- **忽视非功能需求**: 延迟、成本、可维护性同样关键
- **不做权衡分析**: 要说明"为什么选 A 而非 B"
- **忽视监控与迭代**: ML 系统是持续演化的，不是一次性交付
- **数据问题一笔带过**: 数据质量往往是成败关键

**核心心法**: ML 系统面试考察的是**工程权衡能力**，而非背诵算法。本书提供的正是这种系统化、权衡式的思维框架。
