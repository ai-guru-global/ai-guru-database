# 网络运维视角

> 一句话：AI 集群网络的日常是「巡检分级 + 定时拨测 + 步骤化故障 SOP」，目标是让慢链路与配置漂移在训练任务发现之前被抓住。

## 核心问题清单

1. 日/周/月各巡检什么，处置阈值定多少？
2. 拨测矩阵怎么排（算子 × 规模 × 频率），怎么避开业务高峰？
3. 告警从定位到换件的标准动作是什么？慢链路怎么揪？
4. 固件、ECN/PFC 参数这类高危变更怎么灰度与回滚？
5. 备件率怎么定、RMA 怎么运营？
6. 运维与研发（平台/算法）的分工界面在哪？

## 评估框架

### 巡检分级表

| 频率 | 项目 | 口径/工具 | 处置阈值 |
|---|---|---|---|
| 日 | 端口 up/down、CRC/FEC 重传、光功率 | SNMP/gNMI 采入时序库 | CRC 日增量 >0 即建单 |
| 日 | 交换机温度/风扇/电源 | 告警平台 | 厂商阈值 |
| 日 | PFC pause 与 ECN 标记率突增 | RoCE 计数器 | 同比 3σ 突增告警 |
| 周 | 拨测矩阵（见下）、慢链路筛查 | 按 FEC 重传/光功率排序 top 口 | busbw < 基线 −5% |
| 周 | 链路利用率水位 | 流遥测 P99 | >70% 进扩容评估 |
| 月 | 固件/驱动版本一致性审计 | CMDB 对账 | 漂移即变更单 |
| 月 | 配置 diff、备件盘点与 RMA 时效 | 自动化对账 | 备件满足率 <98% 触发补货 |
| 季 | 故障注入/断网演练、续训切换 | 预演环境 | 演练失败进复盘 |

### 拨测体系与业务避让

1. 矩阵：nccl-tests 跑 all_reduce / all_gather / reduce_scatter × 规模 8/64/512/全量 × 大消息（≥256 MiB）；记录 busbw 均值与 P50/P99。
2. 频率：全量矩阵每周低峰窗口一次；8/64 卡小矩阵每日。
3. 业务避让：拨测走独立队列 + 空闲节点池；无法避让时降规模并在数据口径中标注。
4. 基线管理：硬件/固件变更后重建基线；历史基线入库可回溯，供性能篇对账。

### 故障 SOP（从告警到换件）

1. 接警定级：端口 down / 训练掉卡 / 性能劣化三类，映射影响面（单卡/单机/单 rail/全局）。
2. 快速隔离：定故障域（哪个平面、哪台 leaf、哪个 rail），必要时让调度避开该域。
3. 定位到件（先软后硬）：查计数器（CRC/FEC/pause）→ 查光功率与温度 → 复位端口观察 → 交叉换件验证（模块对调）。
4. 慢链路定位法：全网 busbw 掉但无 down 告警 → 按 rail 分组测 → 单 rail 掉 → 逐口打流（iperf3/RDMA 打流）→ 锁定到口 → 看该口 FEC 重传与收发光功率 → 换模块/线缆/光引擎验证。
5. 换件与验证：计数清零观察 + 局部拨测达标，才允许回业务。
6. 复盘：时间线、根因、备件消耗、SOP 增补条目。

### 变更管理（固件/ECN 参数灰度）

| 步骤 | 动作 | 门槛 |
|---|---|---|
| 1 | 变更单 + 影响面评估 + 回滚方案 | 缺一不批 |
| 2 | 实验环境/单台灰度 | 拨测达标 |
| 3 | 5% 灰度（单 spine/单平面），观察 ≥24h | busbw 与计数器无劣化 |
| 4 | 50% → 100% 推开 | 每步回归拨测 |
| 5 | 回滚条件预写（busbw 掉 >5% 或 CRC 增长） | 立即回滚并复盘 |

ECN/PFC 阈值属高危参数：单台设备的参数漂移可造成全网吞吐反噬，必须纳入月度配置 diff。

### 备件与 RMA、分工界面

1. 备件率：模块按装机量 2–3%、线缆 2%、交换机按 AFR × MTTR 折算（行业典型口径，待核实）；满足率目标 ≥98%。
2. RMA 运营：故障件 48h 内发出，按季度与供应商对账换新时效。
3. 分工界面：运维负责链路层到传输层 + 拨测执行与告警；研发（平台）负责 NCCL 参数、拓扑配置、调度避让；性能劣化联合定位——运维出网络证据，研发出通信侧证据。

## 关键指标与基线

| 指标 | 基线 | 口径 |
|---|---|---|
| 拨测 busbw 达成率 | ≥95% 的矩阵项 ≥ 基线 −5% | 周全量矩阵 |
| 网络类 MTTR | 小时级（备件 + SOP 到位） | 故障工单 |
| 备件满足率 | ≥98% | 月盘点 |
| 配置漂移检出 | 月检零遗留 | 自动化 diff |

## 常见误区

1. 只有 down 告警没有性能告警：慢链路不 down、只掉 busbw，必须靠拨测矩阵抓。
2. 拨测与业务抢资源：口径被污染，基线失真还误报。
3. 固件全网一把梭：问题爆发时没有对照组可回溯。
4. 备件一次性买断：不考虑 AFR 与扩容增量，第二年满足率下滑。
