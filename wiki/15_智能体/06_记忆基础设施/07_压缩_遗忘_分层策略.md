# 记忆压缩、遗忘与分层策略

> 中文简称：记忆压缩遗忘分层策略

> **一句话理解**: 记忆系统的卫生学——只写不清的记忆库，半年后检索返回的全是过时噪音；本页讲四个卫生动作（压缩/摘要/反思/遗忘）和 L1–L4 分层之间的升降级规则。

---

## 1. 四个动词辨析

| 动词 | 做什么 | 发生在哪 | 产物去向 | 触发时机 |
|------|--------|---------|---------|---------|
| **压缩**（Compaction） | 窗口内保信息降 token——去掉冗余、保结论 | L1 工作记忆（上下文内） | 还是上下文 | 窗口逼近上限 |
| **摘要**（Summarization） | 降粒度：长历史 → 短总结 | L1→L2 边界 | 短期记忆 / 会话摘要 | 会话结束或分段 |
| **反思**（Reflection） | 提炼：多条情景 → 少条语义洞察 | L2/L3→L4 | 语义记忆 | 每 N 轮 / 定时 |
| **遗忘**（Forgetting） | 淘汰：降权、归档、删除 | 全层 | 归档或消失 | 评分低于阈值 / TTL 到期 / 合规要求 |

一句话分工：**压缩救窗口，摘要救历史，反思救质量，遗忘救容量**。四者常被混为一谈，但触发条件、产物和风险完全不同——混用是记忆系统「越用越糊」的常见根因。

---

## 2. 分层升降级规则

对应 [[15_智能体/06_记忆基础设施/01_Agent_Memory_系统_2026|01 页]] 的 L1–L4 层级，每层有明确的**进入、停留、退出**条件：

| 层 | 进入 | 停留期 | 退出（升级 / 淘汰） |
|----|------|--------|---------------------|
| L1 工作记忆 | 检索注入 + 当前对话 | 单次请求 | 降级到 L2（重要片段）/ 随请求消失 |
| L2 短期记忆 | L1 降级 + 近期交互 | 24–48 小时（TTL） | 升级到 L3（反思提炼）/ TTL 过期删除 |
| L3 长期记忆 | 反思产物 + 高价值事实 | 永久（受评分约束） | 评分跌破阈值 → 归档；冲突 → 覆盖 |
| L4 语义记忆 | 反思整合 + 用户画像 | 账户生命周期 | 冲突覆盖（留历史）/ 合规删除 |

升降级的关键是**每层退出时不是丢弃而是分流**——L1 降级进 L2 的应该是「本轮未被用但可能有用」的片段，L2 反思进 L3 的应该是跨会话有效的洞察；分流规则写错，表现就是「重要的事第二天就忘、垃圾却永久留存」。

---

## 3. 重要性评分：遗忘的裁判

淘汰谁、留谁的量化依据（经验起点，需按场景调权）：

```text
score = 0.4 × 访问频率      # 被检索命中且实际注入上下文的次数
      + 0.3 × 显式权重      # 用户明确说「记住」/ 纠正过的记忆
      + 0.2 × 新近度        # 半衰期衰减：0.5^(天数/7)
      + 0.1 × 关联度        # 连接的其他记忆条数（知识网络度）
```

低于阈值（经验值 0.2–0.3）的记忆进入归档而非直接删除——**归档可恢复，删除不可恢复**，这个缓冲层能显著降低「误删用户重要事实」的事故率。

---

## 4. 遗忘四策略

| 策略 | 触发 | 实现 | 风险 |
|------|------|------|------|
| TTL 过期 | 时间到 | Redis TTL / 定时清理任务 | 长周期事实被误杀 → 关键层不设 TTL |
| 评分淘汰 | score < 阈值 | 定期批处理扫描 | 评分权重失衡 → 低频但重要的事实被淘汰（见 §3 显式权重项） |
| 冲突覆盖 | 新事实与旧记忆同主体 | UPDATE 旧条目，旧值留历史字段 | 未留历史则「何时变的」不可考 |
| 合规删除 | 用户行使被遗忘权 / 政策要求 | 按 user_id 级联删除 + 备份清理 | 备份与日志中的残留 → 需全链路删除方案 |

GDPR 场景提醒：用户主张删除时，只删主库不够——向量库快照、对话日志、缓存里的派生数据都要纳入删除范围（[[15_智能体/06_记忆基础设施/01_Agent_Memory_系统_2026|01 页 §5]] 的隐私机制对应此处）。

---

## 5. 反思实践：情景 → 语义

反思是唯一能「提升记忆质量」的动作（其余三个只改变数量），频率建议：

- **每 N 轮对话**（N=10–20）：轻量反思，提炼本轮模式；
- **每日/每周批处理**：重反思，把 L2/L3 的情景记忆整合成语义事实——实现可直接参考 [[15_智能体/06_记忆基础设施/01_Agent_Memory_系统_2026|01 页]] 的 `reflect()`（LLM 读近期记忆 → 生成洞察 → 存为长期记忆）与 [[概念/Agent/agent-memory-systems|概念卡]] 的 `consolidate()`（近期情景批量提取 pattern 更新语义层）。

反思产物的质量控制：每条洞察必须可回溯到 ≥2 条情景记忆（防止模型单次幻觉固化为「长期事实」——这是记忆污染的主要入口）。

## 6. 与长上下文的边界

「窗口已经 1M token 了，还需要记忆系统吗？」——长上下文替代的是**窗口内的压缩与摘要**（L1 管理变简单），替代不了：

| 维度 | 长上下文 | 记忆系统 |
|------|---------|---------|
| 跨会话 | ❌ 请求结束即逝 | ✅ 持久化 |
| 成本 | 每次全量计费，随历史线性增长 | 检索注入，按需付费 |
| 精度 | Lost in the Middle，越长越稀释 | 检索 + 重排，可聚焦 |
| 冲突 | 新旧版本并存于窗口，模型自行裁决 | 显式 UPDATE/DELETE 语义 |

完整辨析见 [[14_RAG系统/04_高级RAG/09_Long_上下文_vs_RAG_2026|Long 上下文 vs RAG 2026]]。工程结论：**窗口越长，L1 的压缩动作越可以省，但 L2–L4 的分层与遗忘越不可省**——历史会无限积累，窗口不会。

> 顺带一提：[[14_RAG系统/08_Deep_Research/02_架构拆解_四阶段流水线|Deep Research 的笔记外置（scratchpad）]] 就是同一套思想在研究循环里的应用——逐页抽取写笔记、原文用完即弃，本质是「L1 压缩 + L2 外置」的组合拳。
