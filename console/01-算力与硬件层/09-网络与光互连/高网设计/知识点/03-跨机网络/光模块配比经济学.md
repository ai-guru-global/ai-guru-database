# 光模块配比经济学：每 GPU 几只模块

> 两层 1:1 无阻塞 fat-tree 下每 GPU 约 4–4.5 只 800G 模块；过收敛与层数如何改变配比，以及万卡集群的网络 capex 结构。

## 解决什么问题

光模块是跨机网络 capex 最大单项（占比估算见下），采购量由拓扑与收敛比直接决定。把「每 GPU 需要几只模块」推导清楚，才能做网络预算、光模块招标量、以及「收敛比省下的钱 vs MFU 损失」的权衡。

## 核心原理

**两层 1:1 无阻塞的推导**。假设：leaf-spine 两层、每 GPU 1×800G NIC、无阻塞（leaf 上行带宽 = 下行带宽）、全 800G 光链路、单平面无冗余：

1. NIC 侧 1 只 + leaf 下行端口 1 只（同一根链路两端各一只）；
2. 1:1 无阻塞 → 每 GPU 对应 1 条 800G leaf-spine 上行链路，两端各 1 只 → 再 +2；
3. 合计 4 只 800G/GPU；计入带外/管理、少量备件与不对称余量后行业口径约 4–4.5 只/GPU。

**三层 1:1**：多一层 spine-super-spine 链路（两端各 1 只）→ 纯链路推导为 6 只/GPU；行业研报常见口径 ≈8–9 只/GPU，差额来自叠加存储网、双平面/冗余设计、备件与 10–20% 余量等假设（数量级估算，待核实），引用时必须带上假设。

**过收敛的削减**（两层）：收敛比 k:1 时上行链路降为 1/k：
- 2:1 → 1（NIC）+1（leaf 下行）+2×0.5（上行两端）= 3 只/GPU；
- 4:1 → 1+1+2×0.25 = 2.5 只/GPU。

**柜内铜与超节点的削减**：NVL72 类 scale-up 域把 72 卡收敛在柜内铜背板（无光模块），柜间互联若保持 1:1 则每卡配比不变、但柜间做过收敛更容易落地；leaf 下联改 DAC/AEC 可同步削减 NIC 侧与 leaf 侧模块。

## 关键数字

| 拓扑/收敛比 | 每 GPU 800G 模块数 | 口径说明 |
| --- | --- | --- |
| 两层 1:1 | ≈4–4.5 | 4 为纯链路推导，4.5 含管理/备件余量 |
| 两层 2:1 | ≈3 | 推导值 |
| 两层 4:1 | ≈2.5 | 推导值 |
| 三层 1:1 | ≈6（纯推导）～8–9（行业口径） | 8–9 含存储/冗余/备件假设（估算，待核实） |

行业通行口径汇总：**GPU : 800G 光模块 ≈ 1:2.5 ~ 1:4.5，取决于收敛比**；三层无阻塞与带冗余设计向 1:6 以上走。

| 万卡集群网络 capex 结构 | 占比（数量级估算） |
| --- | --- |
| 网络设备占集群总 capex | ~10–20%（研报口径，待核实） |
| 其中：光模块 | ~50–60%（待核实） |
| 其中：交换机 | ~25–35%（待核实） |
| 其中：线缆/布线/其他 | ~10–15%（待核实） |

量级示例：万卡两层 1:1 需 4–4.5 万只 800G 模块；按 2025 年 800G 均价数百美元量级（价格口径待核实）粗算，仅模块即数千万美元量级（估算）。

## 设计要点与权衡

- 先定收敛比再谈配比：训练集群（AllReduce 占比高）通常两层 1:1 或 2:1；推理与数据并行为主可 4:1。收敛省下的模块/交换机钱要与 MFU 损失一起算总账。
- 模块数 = 链路数 × 2：任何「每 GPU 一只」的说法都漏算了交换机侧端点，预算按两端算。
- 采购分层锁价：DR8 与 2×FR4 用量比例随拓扑层数变化，分批交付要按层配比下单，避免 spine 长距规格缺货。
- 换代叠加效应：GPU 带宽每代翻倍（400G→800G/卡），即使配比不变，模块总量与功耗随卡数×速率双升；1.6T 世代引用配比时注意「按 800G 折算」的口径统一。
- 备件率要进 BOM：现场按部署量留 5–10% 备件（行业常见口径，待核实），万卡即数千只。

## 常见坑

- 用 1:2.5 的口径套 1:1 的设计：研报口径不标假设，预算差近一倍。
- 三层设计按两层配比下单，spine-super-spine 层模块缺口在建网后期才暴露。
- 只算计算网漏掉存储网模块，存储平面同样两端计数。
- 把柜内铜替代的节省重复计算（NVL72 柜内本就无光模块，不能在跨机配比上再扣一次）。
- 忽略光模块年降价格曲线（幅度口径待核实），分批采购不做价格重谈。
