# Hallucination (幻觉)

## 定义

幻觉（Hallucination）是大语言模型生成的内容与事实不符、缺乏依据或逻辑矛盾的现象。模型输出的文本看似流畅自信，但无法溯源到训练数据或输入上下文中的真实信息。NIST AI 600-1 将其称为"虚构"（Confabulation），是 LLM 系统最核心的可靠性挑战之一。

## 核心机制

### 幻觉的成因

幻觉的根源在于 LLM 的技术特性：

1. **概率性生成**：模型基于 Token 概率分布采样，而非事实检索——它"预测"最可能的下一个词，而非"查找"正确答案
2. **训练数据噪声**：训练集中的错误、过时信息和矛盾被内化到模型权重中
3. **知识截止**：模型不知道训练数据截止后发生的事件，但可能自信地"编造"
4. **注意力偏差**：长上下文中模型可能过度关注某些信息而忽略关键约束
5. **参数记忆的固有局限**：固化在权重中的知识是统计压缩的结果，非精确存储

### 幻觉的分类

| 类型 | 描述 | 示例 |
|------|------|------|
| **事实性幻觉** | 生成不存在的事实 | 编造不存在的论文引用、虚构人物履历 |
| **忠实度幻觉** | 偏离输入内容 | 摘要中添加原文没有的信息 |
| **逻辑幻觉** | 推理链中的错误 | 数学计算中间步骤出错导致结论错误 |
| **工具调用幻觉** | 生成无效的函数参数 | 编造不存在的 API 端点、虚构文件路径 |

### 智能体系统中的放大效应

幻觉与工具执行的耦合是独特且危险的风险：

- **幻觉生成无效参数**：生成不存在的 API 端点、错误的函数签名、虚构的文件路径
- **幻觉驱动意外操作**：删除错误的文件（路径幻觉）、向错误地址发送邮件、修改错误的数据库记录
- **级联放大**：一个步骤的幻觉输出被下游当作可信输入继续放大——"系统继续'正常运行'却在错误方向上稳定放大"

### 检测方法

1. **RAG 溯源验证**：检查生成内容是否能追溯到检索到的文档，幻觉率 = 无法溯源的事实比例
2. **交叉验证**：多文档印证、多模型对比，结果不一致时标记可疑
3. **结构化输出校验**：验证工具调用参数是否在合理范围内（工具是否存在、参数值是否合法）
4. **置信度评估**：低置信度触发重试或人工审批
5. **LLM-as-Judge**：用独立模型审查输出的一致性和事实性

### 缓解策略

- **RAG 接地（Grounding）**：用检索到的真实文档锚定生成，强制引用来源
- **输出验证门控**：格式解析 -> 自愈修复 -> 语义验证 -> 安全检查四步防御
- **Constitutional Classifiers**：利用模型内部激活模式识别可疑输出
- **参数验证**：工具执行前严格校验格式、范围和合理性
- **操作前确认**：不可逆操作在执行前向用户明确展示目标
- **拒答机制**：当检索证据不足时，明确告知"无法找到相关信息"而非编造

## 关键设计决策

- **RAG 优于参数记忆**：对于需要准确性的场景，始终优先使用外部检索而非依赖模型权重中的知识
- **宁可遗漏不要错引**：准确性 > 完整性——CitationAgent 的设计原则
- **分层压缩保护关键约束**：压缩上下文时关键约束放入"不可压缩层"，防止约束丢失导致幻觉
- **记忆系统的目标函数**：多数系统默认优化语义相似度，但真正需要优化的是更新正确性、时间正确性和冲突消解
