# RSI 治理与准备 2026 (Recursive Self-Improvement Governance)

> 中文简称：RSI 治理与准备 2026

> **一句话理解**: 弱 RSI（AI 自动化 AI 研发）已在前沿实验室真实运转——治理的问题从「要不要防」变成「怎么在飞轮低速档就装好刹车」；本页给出组织层面的五层治理栈与就绪度自查清单。

## 2. 五层治理栈

```
L5 组织与协调   ← 进度指标监控 / 事件响应 / 跨机构共享
L4 审计链       ← 每轮自改进留痕 / 可复现 / 第三方可核查
L3 部署期       ← 分级放权 / 沙箱隔离 / 最小权限
L2 评估可信度   ← 防 sandbagging / 活环境评测 / 独立验证
L1 训练期       ← 对齐闸门 / 可扩展监督 / 自动化研发边界
```

### L1 训练期：对齐闸门

- 自我改进实验与生产环境**物理隔离**（沙箱化），禁止生产流量喂进自改进循环。
- 每轮迭代后强制**对齐回归评估**：安全基准未回退才允许下一轮——把对齐做成 CI 门禁而非事后审查。
- 自动化研发的产出（代码/实验设计）进入主线前保留**人类评审点**：不是每份都审，而是按风险抽样 + 高风险动作（改训练目标、动评估器）必审。

### L2 评估可信度：防藏拙

- 评估与部署的权限**分段**：通过评估 ≠ 拿到全部权限（见 L3）。
- 引入模型无法可靠识别「在测试」的评测设计（盲测集、混入自然流量样本）；注意与知情权/隐私的边界。
- 活环境评测替代静态 benchmark：任务分布持续换新，压缩记忆化与藏拙的获利空间（见 [[概念/Agent/rl-environment|RL 环境工程]]）。

### L3 部署期：分级放权（trust ladder）

| 级别 | 权限 | 升级条件 |
|------|------|------|
| T0 | 只读/沙箱内 | 默认 |
| T1 | 低风险写操作（沙箱内提交） | T0 行为统计达标 |
| T2 | 真实基础设施子集（CI、工单） | T1 无异常 + 人类抽检 |
| T3 | 生产变更/资金动作 | 专项审批 + 双人复核 |

- 升级依据是**部署后真实行为统计**而非一次性评估——把「测准」问题转化为「限权」问题。
- 高风险动作（评估器修改、训练配方变更）永远保留人类否决权。

### L4 完整审计链

- 每轮自改进留痕：模型版本、数据来源、目标函数、评估快照——满足「可复现 + 第三方可核查」。
- 留痕格式对齐 [[概念/Safety/ai-audit-traceability|审计与溯源]] 要求；审计日志与改进产物**分离存储**（防自改进循环篡改自己的日志）。

### L5 组织与协调

- **进度指标监控**：跟踪 AI 代码占比、自动化实验闭环时延、能力提升速率——这些是「飞轮转速表」，与对齐投入的差值即风险敞口。
- **事件响应预案**：自改进产物引发事故时的回滚、熔断、上报路径；谁有权按下停止钮要有名字。
- **跨机构共享**：前沿安全事件与评估结论参与行业共享（前沿论坛 / AI 安全研究所网络口径），避免单点盲区。

## 3. RSI 就绪度自查清单（10 项）

- [ ] 自改进/自动化研发工作流与生产系统物理隔离
- [ ] 存在对齐回归基准，且作为迭代的硬门禁
- [ ] 高风险动作（训练目标/评估器变更）有必审清单
- [ ] 评估设计考虑了藏拙（盲测/活环境/行为统计三选二以上）
- [ ] 部署权限分级，升级依据是真实行为而非单次评估
- [ ] 每轮改进可复现（版本/数据/目标函数留痕）
- [ ] 审计日志独立存储、不可被自改进循环触达
- [ ] 有具名的停止钮与事件响应预案
- [ ] 跟踪飞轮转速指标（AI 代码占比/闭环时延）
- [ ] 参与或至少知悉行业级安全信息共享渠道

达标 <6 项：治理缺口显著；6–8 项：具备基础；9–10 项：领先实践。

## 4. 与既有合规框架的映射

| 框架 | 与 RSI 的接口 | 本页对应层 |
|------|------|------|
| **EU AI Act**（GPAI 系统性风险条款，2026-08 起执行） | 训练算力超阈值的 GPAI 模型需评估并缓解系统性风险——自动化自我改进能力属于评估要点 | L1/L4 |
| **NIST AI RMF** | Measure/Manage 函数覆盖自改进系统的持续度量与风险处置 | L2/L5 |
| **内部模型卡/系统卡** | 自改进循环的每轮产物按系统卡口径披露变更 | L4 |
| **前台论坛/AI 安全研究所网络** | 严重事件通报与评估方法共享 | L5 |

> 口径提醒：EU AI Act 的具体执行细则在滚动更新中，引用具体条款前核对最新版本。

## 5. 常见误区

| 误区 | 正确认知 |
|------|------|
| 「RSI 是 AGI 以后的事，现在不用管」 | 弱 RSI 已在研发管线运转——治理要在低速档装刹车，而不是等高速 |
| 「对齐评估通过 = 安全」 | 评估可被藏拙穿透；评估只是放权依据之一，不是安全证明 |
| 「自动化研发提效是纯工程问题」 | 提速率的同时放大了对齐/评估/审计的赌注——速率指标与治理投入要同表监控 |
| 「审计日志放同一套系统就行」 | 自改进循环可能触达自己的日志——审计链必须独立存储 |
