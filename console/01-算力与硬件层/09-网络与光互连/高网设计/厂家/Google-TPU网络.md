# Google TPU 网络 × GPU 高网

> 自建超大规模网络的极致实践者：ICI 直连 Torus + OCS 光路交换重构拓扑，配合自研 TPU 与 Jupiter DCN，是商用体系之外「另一条技术路线的存在证明」。

## 在 GPU 高网中的角色

- 不外卖任何网络设备，但其论文与公开披露持续为全行业设定想象空间：OCS 进生产网络、Torus 拓扑跑超大模型、光/机架配比优化均为其先例。
- 以「自研 TPU + 自研拓扑 + 外采芯片」垂直整合：定制交换芯片来自 Broadcom、光 DSP 涉及 Marvell 等（公开报道口径，细节待核实），绕开 NVIDIA 体系完成大规模训练。
- 其存在本身构成对 NVIDIA 的战略制衡：证明专用互联路线在 TCO 上可与商用体系竞争（估计口径）。
- 采购杠杆：以超大规模买家身份深度影响供应商（Broadcom 定制交换、Marvell DSP、光模块厂）的技术路线（公开报道口径）。

## 技术路线与取舍

- 专用拓扑优于通用 Clos（在其负载画像下）：ICI 直连 Torus 省去大规模 Spine 的交换跳数与收敛比问题；代价是拓扑固定，必须与拓扑感知调度深度耦合。
- OCS 的两个收益：按负载重构拓扑（训练/推理复用同一批光路资源），以及把空闲链路的光路调走省电（论文口径）。
- 超节点化路径：pod 从 v4 的 4096 到 Ironwood 的 9216 芯片，等价于把 scale-up 域做到近万芯，直接改变集合通信的 Ring/Tree 切分方式。
- 商业上不外卖：网络能力是自研 TPU 体系的一部分，对外只以 Cloud TPU 服务形态交付。
- OCS 与 CPO 的区别：OCS 是纤级光路交换（无光电转换、速率透明），CPO 是光电合封缩短电通道；Google 靠前者省电省模块，产业界靠后者缩距提速。
- 双网结构：即便有 ICI 专用网，DCN 仍走以太网 Clos 演进——「专用+通用」双网在超大规模是稳定形态。
- 训练/推理共用同一批 ICI 与光路资产，拓扑随负载重配，是 OCS 商业逻辑的核心。

## 竞争与对标

- 对 NVIDIA 体系：另一条技术路线的存在证明——自研加速器 + 专用拓扑 + OCS，绕开 NVLink/IB 锁定。
- 对以太网统一阵营：Torus+OCS 与 UEC 的「以太网统一」是两条路线；但 DCN 侧 Jupiter 仍是以太网 fabric 演进，两线在其内部并存。
- 对国内实践：Torus+OCS 论文是国内自研训练集群的重要参考系（观察口径）。
- 披露的连锁反应：其论文倒逼其他超大规模公开更多网络实践（Meta 的 fabric 论文即对照样本）。
