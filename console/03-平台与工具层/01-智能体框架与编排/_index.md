# 智能体框架与编排

> Agent 的开发框架与多智能体编排层，应用复杂度的承载者。

## 拆解卡

- **价值来源**：应用复杂度的承载层：谁定框架，谁定分发。
- **护城河**：开发者心智与运行时事实标准。
- **瓶颈**：框架过剩、生产级可靠性工程尚未收敛。
- **领先指标**：框架采用率消长（star/生产案例）；标准化收敛事件（合并或淘汰）

## 六层速览

智能体框架与编排让模型「会做事」：把工具调用、记忆、多步规划和多智能体协作组织成可运行的系统；模型提供智力，框架提供纪律。

**打个比方**：像给一个聪明但只会聊天的实习生配上工作流、工具箱和检查清单，它才能独立完成任务；清单越细、检查点越多，失误越少，但速度越慢。

**拆开看**：五层结构：工具调用（function calling）→ 状态与记忆（会话、长期记忆）→ 规划与反思（拆任务、自我检查）→ 多智能体编排（分工、交接）→ 可观测与评测；可靠性来自重试、约束与人工兜底。

**怎么运转**：开源框架免费换生态，托管平台按调用或席位收费，企业版按部署与并发收费；框架之争本质是开发者入口之争——谁被默认选中，谁就掌握分发与后续变现。

**格局与博弈**：LangGraph、CrewAI、AutoGen 主导开源，OpenAI 与 Anthropic 用官方 SDK 收编开发者，Dify、Coze 做低代码平台，云厂商捆绑销售；MCP 与 A2A 让框架之间开始互通，也在削弱单框架锁定。

**边界与走向**：框架会向「运行时 + 协议」收敛：能力差异被标准抹平，竞争转向可靠性、可观测与治理；生产级能力（回滚、权限、成本控制）才是分水岭，demo 级的编排很快会变成免费功能。

## 关键判断

编排层战略价值高但独立框架变现困难；企业套件与可观测层更稳，模型厂垂直整合是最大变量（置信度 中，展望 12–24 个月）——核心变量是企业生产部署节奏与模型厂是否吞并编排入口；评估该节点应以「生产部署数」而非「GitHub star」为锚。

规模口径：全球 agent 平台与编排工具约 $30–60 亿（2025e），2030 年可达 $200–400 亿

## 二级细分

- **编排框架** — LangGraph 类：图与状态机的开发范式
- **多智能体协作** — 分工、交接与共享记忆
- **低代码工作流** — Dify/Coze：把编排交给业务人员
