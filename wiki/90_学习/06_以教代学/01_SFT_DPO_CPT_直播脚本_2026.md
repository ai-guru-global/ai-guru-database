# SFT、DPO、CPT 直播脚本 (Learn-by-Teaching Live Script)

> 中文简称：SFT DPO CPT 直播脚本

> **一句话理解**: 把模型调教比作应届生成长——CPT 是读研补知识、SFT 是岗前培训教格式、DPO 是导师复盘调品味，这份脚本让你照着讲 45 分钟就能把三件事讲透。

---

## 0. 使用说明与播前准备

**定位**：45 分钟单人直播脚本 ｜ **受众**：对大模型应用感兴趣、但没系统训练过模型的开发者/产品同学 ｜ **方法**：以教代学（费曼学习法）——备教、直播、自检三步闭环。

**主线类比**（全程不换，降低认知负担）：把基座模型比作一个"读过很多书但没上过班的应届生"。

| **训练方法** | **类比** | **一句话本质** |
|------|------|------|
| **CPT 持续预训练** | 送他去读行业研究生，狂读专业书 | 补**知识** |
| **SFT 监督微调** | 岗前培训：看例题 + 标准答案 | 教**格式** |
| **DPO 直接偏好优化** | 上岗后导师拿好/坏案例复盘 | 调**品味** |

> 讲者备忘：三个词的记忆钩子——"**CPT 补知识，SFT 教格式，DPO 调品味**"，直播中至少重复 3 次。

**播前准备清单**（开播前 30 分钟）：

- [ ] 云平台控制台已登录、切到**北京地域**（DPO/CPT 往往只在北京地域开放，演示时别翻车）
- [ ] 三份样例数据摆在桌面：SFT 的 jsonl（instruction/output）、DPO 的 jsonl（chosen/rejected）、CPT 的领域语料 txt
- [ ] 幻灯片按下面各幕的 [幻灯片] 提示备齐
- [ ] 把"费曼自检表"（附录 B）打印出来放旁边——这是"以教代学"的真正作业

## 2. 第一幕 · 开场（0:00–3:00）

**[幻灯片 1]** 标题页 + 一个问题："同一个开源模型，为什么别人家的会像老中医一样说话，你家的在胡说八道？"

**口播稿**：

> 大家好，今天这期直播有点特殊——我是来"以教代学"的。费曼说过，检验自己是不是真懂一个概念，就看你能不能把它讲明白。所以我逼自己备了这期课，把模型训练里出场率最高的三个词：**SFT、DPO、CPT**，一次讲透。
>
> 开头先问大家一个问题：同一个开源基座模型，为什么有的团队做出来的助手，问医疗像老中医、问法律像老律师，你直接问却一本正经地胡说八道？模型没换，换的只是"教法"。今天讲的三个词，就是三种教法。
>
> 先打个弹幕互动：**自己亲手微调过模型的扣 1，没微调过但想学的扣 0。** 好，看到比例了，那今天我就按"扣 0 的也能听懂"的标准来讲。

**[互动]** 扣 1 / 扣 0 热身，顺便校准讲解深度。

## 3. 第二幕 · 全景定位（3:00–8:00）

**[幻灯片 2]** 模型生命周期流水线图：

```text
预训练（读完互联网，会续写）
   ↓
CPT 持续预训练（补领域知识）
   ↓
SFT 监督微调（教对话格式）
   ↓
DPO 偏好对齐（调回答品味）
```

**口播稿**：

> 先给一张全景图，不然三个词是散的。基座模型预训练完，你可以理解成一个**读过互联网上几乎所有公开书、但一天班都没上过的应届生**——你问他任何话，他的本能是"续写"，而不是"回答你"。
>
> 要把这个应届生变成合格员工，一般走三步：
> 第一步，如果他要进医疗、法律、金融这种专业行当，先送他去**读行业研究生**，狂读专业书——这就是 **CPT，持续预训练**，补的是知识；
> 第二步，**岗前培训**，给他看一千道例题和标准答案，教他"别人提问，你要这样答"——这就是 **SFT，监督微调**，教的是格式；
> 第三步，上岗之后**导师复盘**，拿两份回答对比："这份比那份好，以后往这个风格靠"——这就是 **DPO，直接偏好优化**，调的是品味。
>
> 注意，我现在是按"一个应届生的成长顺序"讲的。但今天直播我会**倒着讲**：先讲大家最熟的 SFT，再讲 DPO，最后讲 CPT。为什么倒着？因为顺着问题讲更好懂——每讲一个，你都会发现上一个的局限，下一个就是来补位的。最后我们再回到这张图，把顺序拧回来，那时候你会有一种"通了"的感觉。

**[讲者防坑]** 这一幕只铺类比，不碰任何公式。公式留到 DPO 段选讲。

## 4. 第三幕 · SFT 监督微调（8:00–18:00）

**[幻灯片 3]** 定义卡：**SFT** = Supervised Fine-Tuning，**监督微调**（指令微调）｜数据 =（指令，标准答案）｜推荐量：**上千条**

**口播稿**：

> 第一个概念，SFT，监督微调，也常叫指令微调。
>
> 基座模型只会续写，你输入"今天天气"，他可能接"预报显示多云"，也可能接一篇新闻。SFT 干的事特别朴素：**给它看成对的例题和标准答案**。数据长这样——一条指令、配一条理想回答：

```json
{ "instruction": "把这句话翻译成英文：今天天气不错",
  "output": "The weather is nice today." }
```

> 训练目标就是最经典的交叉熵：让模型照着标准答案学。几千条看下来，模型就明白了："哦，人类提问的时候，我要这样结构化地回答。"
>
> 所以 SFT 的类比是**岗前培训看例题**——它教的是"答题格式和指令跟随"，不是新知识。这一点是今天第一个关键认知，大家弹幕帮我刷一遍：**SFT 教格式，不教知识。**
>
> 数据量上，平台实践（比如阿里云百炼）推荐**上千条**起步。但记住行业里的共识：**一千条高质量数据，胜过一万条噪声数据**。SFT 阶段数据质量是命门，格式错一条，模型就学坏一个习惯。
>
> 什么时候该上 SFT？三个信号：模型听不懂你的指令格式；回答结构总不对；你要它稳定输出 JSON、稳定调用工具，它时灵时不灵。反过来，如果你的问题是"模型根本不知道你们公司的产品手册"——别用 SFT 硬塞，那是后面 CPT 或者 RAG 的活儿。

**[幻灯片 4]** SFT 适用/不适用对照表（适用：指令格式、输出结构、工具调用格式；不适用：注入大量新知识、频繁更新的事实）。

**[互动 · 场景题 1]** 出第一道弹幕题：

> 来，现学现卖。场景一：某银行要让模型**按"您好，尊敬的客户……"的标准话术格式**回答业务问题。该用哪个？弹幕刷起来。
> ——对，**SFT**。这是格式问题，例题教得会。

**[讲者防坑]**

- 别把 LoRA 和 SFT 混为一谈：SFT 是"教什么"，LoRA 是"怎么省钱地教"，两者是正交的。被问到时一句话带过。
- "微调 vs RAG" 必被问，答案：**风格格式用微调，易变知识用 RAG**，可以组合。

## 5. 第四幕 · DPO 直接偏好优化（18:00–28:00）

**[幻灯片 5]** 定义卡：**DPO** = Direct Preference Optimization，**直接偏好优化**｜数据 =（问题，更好的回答，更差的回答）｜推荐量：**上百条**

**口播稿**：

> SFT 教完格式，你会发现新问题：**格式都对，但就是"不好用"**。要么语气生硬，要么啰嗦，要么爱瞎编。这种"哪个更好"的问题，标准答案给不了你——因为同一个问题，合理回答有一百种。
>
> 这就轮到 DPO，直接偏好优化。它的数据不是例题，是**对比案例**：一个问题，配一个更好的回答 chosen、一个更差的回答 rejected：

```json
{ "prompt": "如何学习编程？",
  "chosen": "建议从 Python 入门，先掌握语法，再用小项目练习。",
  "rejected": "编程很简单，看两天就会了。" }
```

> 类比就是**导师复盘**：导师不给你背评分标准，直接拿两份答卷拍在你面前——"这份比那份好，自己体会"。
>
> DPO 在学术上的高光点是：在它之前，主流做法是 RLHF——先训练一个奖励模型当"打分器"，再用强化学习 PPO 去优化，流程三阶段、同时跑四个模型，又贵又不稳。DPO 的作者从数学上证明了：**这个打分器可以不用单独训**，偏好对可以直接折算成损失函数，一步到位。所以它只要两个模型、一个阶段，训练稳定得像监督学习。效果上接近 RLHF，某些任务还能反超。
>
> 数据量上，DPO 是三者里最省的，**上百条**就能见效——因为"哪个好哪个差"的偏好信号信息密度极高。但注意：条数可以少，**chosen 和 rejected 之间的差距必须"可辨别"**，两条差不多的回答凑成一对，等于给模型喂噪声。
>
> 最后一个关键认知，帮我刷弹幕：**DPO 解决"哪个更好"，不解决"什么是对"**。模型连答都不会答的时候，你给它做偏好对齐是空中楼阁——所以 DPO 几乎永远排在 SFT 后面。

**[幻灯片 6]** RLHF vs DPO 对照表：

| **维度** | **RLHF (PPO)** | **DPO** |
|------|-----------|-----|
| 流程 | 3 阶段（SFT→奖励模型→PPO） | 1 阶段直接优化 |
| 同时跑的模型 | 4 个 | 2 个 |
| 稳定性 | 不稳定（RL 固有） | 稳定（监督式） |
| 适用 | 资源充足追极致 | 资源有限求稳求快 |

**[互动 · 场景题 2]**

> 场景二：客服机器人回答都正确，但**语气太冲、还爱说教**，想让它友好简洁。用哪个？
> ——**DPO**。这是品味问题，对比案例调得过来。

**[讲者防坑]**

- 不要说"DPO 比 RLHF 好"。准确说法：**DPO 是更简单稳定的替代路线；追上限的大厂仍用 PPO 甚至 GRPO（DeepSeek-R1 用的就是 GRPO）**。
- 被问"还有别的吗"可以加分一句：KTO 只要"好/坏"二元反馈、ORPO 把 SFT 和偏好合成一阶段——点到即止，显深度不跑题。

## 6. 第五幕 · CPT 持续预训练（28:00–36:00）

**[幻灯片 7]** 定义卡：**CPT** = Continued Pre-training，**持续预训练**｜数据 = 领域语料｜推荐量：**5000 万 Token**

**口播稿**：

> 现在我们把最"重"的一个留到了最后。前面 SFT 和 DPO 都假设一件事：**模型底子懂行，只是不会答、答得不够好**。但如果模型连你们行业的术语都认不全呢？你问一个放射科医生才懂的概念，它一脸茫然——这时候例题和复盘都救不了它，它缺的是知识本身。
>
> 这就是 CPT，持续预训练：**在基座模型已有的权重上，拿领域语料继续做预训练**——还是下一个词预测那套，只不过语料换成医疗论文、法律文书、金融研报。类比回到开头：**送应届生去读行业研究生**，不是看例题，是整图书馆地读。
>
> 大家注意数据量这一栏，这是今天最容易讲错、也最值得讲的地方：SFT 上千**条**，DPO 上百**条**，CPT 是 **5000 万 Token**。单位都不一样！为什么差两个数量级？因为学的东西不一样：SFT 学"行为格式"，少量高质量示范就够；CPT 学"领域的知识分布和语言习惯"，覆盖面不够，模型就只学了个皮毛。
>
> CPT 有两个必讲的坑。第一个，**灾难性遗忘**：读专业书读太猛，会把通用能力忘掉，所以工程上一定要**混入一定比例的通用数据一起训**，学习率也要比预训练小。第二个，**顺序**：CPT 必须在 SFT、DPO 之前做——你先把它教成会答题的客服，再往回灌知识，格式会被冲垮。
>
> 什么时候值得上 CPT？三个信号：模型读不懂你的领域术语；行业语料是封闭的、RAG 检索也补不齐语感；你要做长上下文、新语言这类"底座级"扩展。反之，如果只是"模型不知道上周发布的新产品"——那是 RAG 的活儿，别动 CPT。

**[互动 · 场景题 3]**

> 场景三：医院要让模型**真正读懂影像报告里的专业术语**，而不是靠猜。用哪个？
> ——**CPT**。这是知识问题，得回去读书。

**[讲者防坑]** CPT 的 C 是 Continued/Continual，中文"持续预训练"或"继续预训练"都对，但**不要说成"重新预训练"**——它是在已有权重上继续，成本远低于从头预训练，这正是它的价值。

## 7. 第六幕 · 对比选型与顺序反转（36:00–42:00）

**[幻灯片 8]** 平台实践对照表（以阿里云百炼为例）：

| **训练方法** | **用途** | **推荐数据量** | **站点可用性** |
|------|------|------|------|
| SFT | 监督微调（指令微调） | 上千条 | 全部站点 |
| DPO | 直接偏好优化（偏好对齐） | 上百条 | 北京地域 |
| CPT | 持续预训练（领域知识） | 5000 万 Token | 北京地域 |

**口播稿**：

> 三个概念讲完了，上对比表。这张表大家截图保存，它是平台实践的口径：SFT 最通用、所有站点都有；DPO 和 CPT 因为算力形态更重，目前只在北京地域开放——真要在云上动手，先看清地域，这是实战里真实会踩的坑。
>
> 然后给大家一棵**三问决策树**，以后任何需求进来，按顺序问：
> 第一问，模型**懂不懂行**？不懂术语、缺领域知识 → CPT；
> 第二问，模型**会不会答**？不懂指令、格式乱 → SFT；
> 第三问，模型**答得好不好**？内容对但风格差 → DPO。
>
> 最后，兑现开头的承诺——把顺序拧回来。我今天为了好懂，按 SFT、DPO、CPT 讲；但**真实工程的执行顺序是反的：CPT → SFT → DPO**。先补知识，再教格式，最后调品味。学习顺序和施工顺序相反，这本身就是今天最好的一个记忆点。
>
> 当然，大多数团队不需要三步全做：**没有领域知识缺口，就 SFT 起步；格式对了还不满意，再叠 DPO。** 按需取用，别过度训练。

**[互动 · 综合题]** 把三道场景题连起来快速复盘，让弹幕一次性刷答案（SFT/DPO/CPT），检查留存。

## 附录 A · 观众问答弹药库（被问到时直接答）

| **观众可能问** | **答案要点** |
|------|------|
| SFT 和 RAG 怎么选？ | 风格/格式/能力塑形用 SFT；频繁更新的事实知识用 RAG；两者可组合。 |
| DPO 是不是比 RLHF 好？ | 不是"更好"，是"更简单稳定"。追上限仍用 PPO/GRPO，求稳求快用 DPO。 |
| 为什么 CPT 要 5000 万 Token，SFT 只要上千条？ | 学的东西不同：CPT 学知识分布，要覆盖面；SFT 学行为格式，要质量。单位都不同，别直接比数字。 |
| DPO 能不能放在 SFT 前面？ | 一般不能。DPO 前提是模型已会答，只调偏好；顺序乱了等于空中楼阁。 |
| 微调后模型"忘了"通用能力怎么办？ | 灾难性遗忘，CPT 尤其明显。混入通用数据回放 + 更小学习率缓解。 |
| LoRA 和这三个是什么关系？ | LoRA/QLoRA 是"怎么省钱地教"（工程实现），SFT/DPO/CPT 是"教什么"（训练目标），正交可组合，如 QLoRA+SFT→QLoRA+DPO 是个人主流路径。 |
