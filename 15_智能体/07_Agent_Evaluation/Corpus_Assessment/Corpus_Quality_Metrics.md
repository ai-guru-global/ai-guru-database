# 语料库质量指标体系

> 中文简称：语料库质量指标体系

> 量化评估语料库质量的完整指标体系，从准确性、完整性、一致性、时效性四个角度全面衡量

## 指标总览

```
语料库质量指标体系
├── 准确性指标（Accuracy）
│   ├── 事实准确率
│   ├── 代码可执行率
│   ├── 数值精确度
│   └── 术语规范性
├── 完整性指标（Completeness）
│   ├── 知识点覆盖度
│   ├── 步骤完整度
│   ├── 前置条件标注
│   └── 异常处理覆盖
├── 一致性指标（Consistency）
│   ├── 术语一致性
│   ├── 版本一致性
│   ├── 跨文档一致性
│   └── 中英文对齐度
├── 时效性指标（Timeliness）
│   ├── 版本同步延迟
│   ├── 新功能覆盖速度
│   ├── 废弃信息清理
│   └── 链接有效性
└── 效用指标（Utility）
    ├── 可检索性
    ├── 可理解性
    ├── 可操作性
    └── 可验证性
```

---

## 一、准确性指标

### 1.1 事实准确率（Factual Accuracy Rate）

```
定义：Agent 回答中事实性信息的正确比例

计算方法：
  事实准确率 = 正确事实陈述数 / 总事实陈述数 × 100%

评估方法：
  - 从 Agent 回答中抽取事实性声明
  - 与官方文档/权威来源交叉验证
  - 标记正确、部分正确、错误、无法验证

评分标准：
  ≥95%  → 满分（10分）
  90-94% → 9分
  85-89% → 8分
  80-84% → 7分
  75-79% → 6分
  70-74% → 5分
  <70%  → 不及格
```

### 1.2 代码可执行率（Code Executability Rate）

```
定义：Agent 生成的代码/命令可以直接执行成功的比例

计算方法：
  代码可执行率 = 可执行代码数 / 总代码样本数 × 100%

测试范围：
  - CLI 命令（aws/az/gcloud/aliyun）
  - API 调用代码（Python/Java/Go/Node.js SDK）
  - IaC 代码（Terraform/CloudFormation/Pulumi）
  - 配置文件（YAML/JSON）
  - Shell 脚本

评分标准：
  ≥90%  → 满分（10分）
  80-89% → 8分
  70-79% → 6分
  60-69% → 4分
  <60%  → 不及格
```

### 1.3 数值精确度（Numerical Precision）

```
定义：Agent 回答中数值信息的准确程度

测试类型：
  - 定价信息（实例价格、存储费用、网络费用）
  - 规格参数（CPU、内存、带宽、IOPS）
  - 限制值（配额、速率限制、超时值）
  - 版本号和日期

评分标准：
  完全正确 → 10分
  量级正确但具体值偏差 → 5分
  明显错误 → 0分
```

### 1.4 术语规范性（Terminology Compliance）

```
定义：Agent 使用的技术术语是否规范和一致

评估内容：
  - 产品名称准确性（如 ECS vs EC2 vs VM）
  - 参数名称准确性（如 InstanceType vs instance_type）
  - 技术术语一致性（同一概念用词统一）
  - 版本号规范性（如 v2 vs V2 vs version 2）
```

## 二、完整性指标

### 2.1 知识点覆盖度（Knowledge Point Coverage）

```
定义：语料库对关键知识点的覆盖比例

评估方法：
  1. 建立知识图谱（产品 → 服务 → 功能 → 知识点）
  2. 标注每个知识点的必要语料
  3. 检测语料库中是否包含对应内容
  4. 计算覆盖比例

知识图谱示例（AWS EC2）：
  EC2
  ├── 实例类型
  │   ├── 通用型（M7, T4g）
  │   ├── 计算优化型（C7)
  │   ├── 内存优化型（R7, X2）
  │   ├── 存储优化型（I4, D3）
  │   ├── GPU 加速型（P5, G6）
  │   └── Graviton（ARM）
  ├── 网络
  │   ├── VPC 配置
  │   ├── 安全组
  │   ├── ENI
  │   └── Elastic IP
  ├── 存储
  │   ├── EBS 类型
  │   ├── Instance Store
  │   └── EFS 挂载
  └── 生命周期
      ├── 启动模板
      ├── Spot 实例
      ├── Auto Scaling
      └── 实例状态转换
```

### 2.2 步骤完整度（Step Completeness）

```
定义：Agent 给出的操作步骤是否完整，无遗漏

评估方法：
  - 收集 50 个需要多步骤操作的场景
  - 对比 Agent 给出的步骤与官方推荐步骤
  - 计算步骤覆盖比例

评分标准：
  步骤完整无遗漏 → 10分
  关键步骤完整，细节有遗漏 → 7分
  有步骤遗漏但可完成 → 4分
  关键步骤缺失导致无法完成 → 0分
```

### 2.3 前置条件标注（Prerequisite Coverage）

```
定义：Agent 是否提醒必要的前置条件和注意事项

检查内容：
  - 权限要求
  - 依赖服务/资源
  - 版本要求
  - 区域限制
  - 费用提醒
```

### 2.4 异常处理覆盖（Error Handling Coverage）

```
定义：语料库对常见错误和异常情况的处理覆盖

评估：
  - 常见错误码的覆盖率
  - 错误原因分析的准确性
  - 解决方案的可行性
  - 降级方案的完整性
```

## 三、一致性指标

### 3.1 术语一致性（Terminology Consistency）

```
同一概念在所有回答中的用词一致性

检测方法：
  1. 建立术语映射表
  2. 抽取 Agent 所有回答中的术语
  3. 检查同一概念是否使用统一术语
  4. 计算一致性比率

示例：
  ✅ 一致：始终使用"安全组"描述 Security Group
  ❌ 不一致：混用"安全组"和"防火墙规则"
```

### 3.2 版本一致性（Version Consistency）

```
Agent 回答中引用的版本信息是否自洽

检测内容：
  - 同一功能在不同对话中引用的版本是否一致
  - 推荐的 API 版本是否统一
  - 弃用提示是否一致
```

### 3.3 跨文档一致性（Cross-document Consistency）

```
不同来源的语料是否一致

检测内容：
  - 官方文档与 API 文档的一致性
  - 不同语言版本文档的一致性
  - 文档与实际行为的一致性
```

### 3.4 中英文对齐度（Bilingual Alignment）

```
中英文技术内容的对应一致性

评估内容：
  - 技术术语翻译一致性
  - 功能描述一致性
  - 参数说明一致性
  - 代码示例一致性
```

## 四、时效性指标

### 4.1 版本同步延迟（Version Sync Latency）

```
定义：产品发布新版本后语料库更新的时间延迟

测量方法：
  - 记录产品重要版本发布日期
  - 测试 Agent 对新版本的了解程度
  - 计算延迟天数

评分标准：
  ≤3天   → 满分
  ≤7天   → 8分
  ≤14天  → 6分
  ≤30天  → 4分
  >30天  → 2分
  完全未知 → 0分
```

### 4.2 新功能覆盖速度（New Feature Coverage Speed）

```
新发布功能被语料库覆盖的速度和程度

测试方法：
  - 选取最近 6 个月发布的 10 个新功能
  - 测试 Agent 对每个新功能的了解程度
  - 按发布时间计算覆盖速度曲线
```

### 4.3 废弃信息清理（Deprecation Cleanup）

```
已废弃功能/参数是否被正确标注和替换

测试内容：
  - 10 个已废弃的 API/功能
  - Agent 是否告知已废弃
  - Agent 是否提供替代方案
```

### 4.4 链接有效性（Link Validity）

```
Agent 回答中提供的链接是否有效

检查内容：
  - 官方文档链接有效性
  - API 参考链接有效性
  - 下载链接有效性
  - 错误码参考链接有效性
```

## 五、效用指标

### 5.1 可检索性（Findability）

```
Agent 能否快速定位到相关信息

评估：
  - 问题理解准确率
  - 相关信息检索精度
  - 答案定位速度
```

### 5.2 可理解性（Comprehensibility）

```
Agent 回答的清晰度和可读性

评估：
  - 结构清晰度（分段、列表、代码块）
  - 技术深度适当性
  - 表述准确性
  - 示例充分性
```

### 5.3 可操作性（Actionability）

```
Agent 给出的建议是否可直接执行

评估：
  - 操作步骤明确性
  - 代码/命令可执行性
  - 预期结果描述
  - 回滚方案提供
```

### 5.4 可验证性（Verifiability）

```
Agent 回答的信息是否可被验证

评估：
  - 提供参考链接的比例
  - 引用来源的权威性
  - 信息可交叉验证性
```

## 综合质量评分

### 评分公式

```
质量总分 = Σ(Wi × Si)

其中：
  Wi = 各指标权重
  Si = 各指标得分（0-10）

权重分配：
  准确性（35%）：事实准确率(10%) + 代码可执行率(10%) + 数值精确度(8%) + 术语规范性(7%)
  完整性（25%）：知识点覆盖度(10%) + 步骤完整度(7%) + 前置条件(4%) + 异常处理(4%)
  一致性（15%）：术语一致性(5%) + 版本一致性(4%) + 跨文档一致性(3%) + 双语对齐(3%)
  时效性（15%）：版本同步(5%) + 新功能覆盖(4%) + 废弃清理(3%) + 链接有效(3%)
  效用性（10%）：可检索(3%) + 可理解(3%) + 可操作(2%) + 可验证(2%)
```

### 质量等级

| 总分 | 等级 | 描述 |
|:----:|:----:|------|
| 90-100 | S | 语料库质量卓越，可作为标杆 |
| 80-89 | A | 质量优秀，满足高标准要求 |
| 70-79 | B | 质量良好，有改进空间 |
| 60-69 | C | 质量一般，需系统提升 |
| <60 | D | 质量不足，需重点建设 |

## 数据采集方法

### 自动化采集

| 方法 | 适用指标 | 频率 |
|------|----------|------|
| API 回归测试 | 代码可执行率 | 每周 |
| 链接检测爬虫 | 链接有效性 | 每月 |
| 术语扫描器 | 术语一致性 | 每月 |
| 版本对比工具 | 版本同步延迟 | 每周 |
| LLM-as-Judge | 事实准确率 | 每季度 |

### 人工采集

| 方法 | 适用指标 | 频率 |
|------|----------|------|
| 专家评审 | 知识点覆盖度 | 每季度 |
| 用户体验调研 | 可理解性 | 每季度 |
| 实操验证 | 步骤完整度 | 每月 |
| 双语专家审核 | 中英文对齐度 | 每季度 |
