# FDE 团队架构设计

## 概述

FDE 团队的架构设计直接影响交付效率、客户满意度和团队稳定性。不同阶段的 FDE 组织需要不同的架构模型。本文档提供从 3 人初创到 30 人规模化的团队架构演进方案。

---

## 二、各阶段详细设计

### 2.1 阶段 1：创始团队（3-5 人）—— 验证期

**适用场景**：公司初创，前 3-5 个项目，验证商业模型

| 角色 | 人数 | 职责 | 能力要求 |
|------|------|------|---------|
| **Founding FDE** | 1 | 全能交付 + 客户关系 + 商务 | 全栈工程 + 行业知识 + 商务能力 |
| **Senior FDE** | 1-2 | 项目交付主力 | 5年+工程经验，独立交付能力 |
| **自由人（可选）** | 1 | 补充技术/商务/运营短板 | 按需配置（平台/售前/财务） |

**核心原则**：
- Founding FDE 必须是"超级个体"——能独立完成从获客到交付的全流程
- 前 3 个项目创始人亲自交付，建立方法论和信用
- 此阶段不设纯管理岗，每个人都是战斗人员
- 招聘优先级：**工程能力 > 行业经验 > 学历背景**

**典型成本结构**（月）：
| 项目 | 金额 |
|------|------|
| 人力成本 | 15-25 万（3 人） |
| 办公/差旅 | 3-5 万 |
| 工具/云服务 | 1-2 万 |
| **合计** | **20-32 万** |
| **月营收目标** | **50-80 万**（2-3 个项目） |

---

### 2.2 阶段 2：成长期（6-15 人）—— 规模化初期

**适用场景**：模式验证后快速扩张，同时进行 5-8 个项目

| 角色 | 人数 | 职责 | 关键能力 |
|------|------|------|---------|
| **FDE Lead** | 1 | 团队管理 + 项目质量把控 + 方法论建设 | 管理能力 + 资深 FDE 经验 |
| **Senior FDE** | 2-3 | 负责中大型项目（100 万+），带新人 | 独立主导项目 + 指导能力 |
| **Junior FDE** | 4-6 | 负责小型项目或协助大型项目 | 基础工程能力 + 学习意愿 |
| **平台工程师** | 1-2 | 公共组件开发、工具链维护、内部提效 | 全栈 + 平台思维 |
| **售前/解决方案** | 1 | 售前支持、投标、方案撰写 | 商务 + 技术双重能力 |

**关键架构决策**：

1. **行业分组 vs 技术分组**
   - **推荐**：行业分组（政企组、金融组、其他行业组）
   - 理由：行业知识积累是 FDE 的核心壁垒

2. **"师徒制"配置**
   - 1 Senior FDE 带 2-3 Junior FDE
   - Senior 对 Junior 的项目质量负连带责任
   - 定期轮换师徒配对，避免知识孤岛

3. **平台团队的定位**
   - 不做产品，做"交付加速器"
   - 从项目中抽象公共组件（RAG 框架、部署脚本、监控面板）
   - KPI：组件复用率、交付周期缩短比例

**典型成本结构**（月）：
| 项目 | 金额 |
|------|------|
| 人力成本 | 50-80 万（10 人） |
| 办公/差旅 | 8-15 万 |
| 工具/云服务 | 3-5 万 |
| **合计** | **60-100 万** |
| **月营收目标** | **150-250 万**（6-8 个项目） |

---

### 2.3 阶段 3：规模化（16-30 人）—— 组织化运营

**适用场景**：多行业覆盖、多地交付、品牌建设

| 角色 | 人数 | 职责 |
|------|------|------|
| **FDE Director** | 1 | 战略规划 + 团队建设 + 大客户关系 |
| **Team Lead（行业/区域）** | 2-3 | 各自管理 5-8 人团队 |
| **Senior FDE** | 4-6 | 复杂项目交付 + 方法论输出 |
| **Junior FDE** | 6-10 | 标准化项目交付 |
| **平台/中台团队** | 2-4 | 技术平台 + 知识库 + 培训体系 |
| **售前/商务** | 2-3 | 销售支持 + 客户关系管理 |
| **运营/PMO** | 1-2 | 项目管理、资源调度、数据运营 |

**组织架构图**：
```
                  ┌──────────────┐
                  │ FDE Director │
                  └──────┬───────┘
           ┌─────────────┼─────────────┐
     ┌─────┴─────┐ ┌─────┴─────┐ ┌─────┴─────┐
     │ 行业组 A   │ │ 行业组 B   │ │ 行业组 C   │
     │ (政企)     │ │ (金融)     │ │ (医疗/教育)│
     │ TL + 5-8人 │ │ TL + 4-6人 │ │ TL + 3-5人 │
     └───────────┘ └───────────┘ └───────────┘
           ┌─────────────┼─────────────┐
     ┌─────┴─────┐ ┌─────┴─────┐ ┌─────┴─────┐
     │ 平台/中台  │ │ 售前/商务  │ │ 运营/PMO  │
     │ 2-4 人     │ │ 2-3 人     │ │ 1-2 人     │
     └───────────┘ └───────────┘ └───────────┘
```

**关键制度设计**：

1. **内部定价（Transfer Pricing）**
   - 售前团队引荐项目 → 行业团队交付
   - 内部结算机制避免"谁的功劳"
   - 平台团队按组件使用率计费

2. **知识管理**
   - 每个项目结束强制产出：项目复盘 + 可复用组件 + 行业洞察
   - 双周跨组分享：行业组互相学习
   - 知识贡献纳入绩效考核

3. **职业发展双通道**
   - 管理线：Junior FDE → Senior FDE → Team Lead → Director
   - 专家线：Junior FDE → Senior FDE → Principal FDE → Fellow

## 三、核心角色能力画像

### 3.1 Founding FDE（创始人级别）

```
技术能力：★★★★★  业务能力：★★★★★  领导力：★★★★☆
薪资区间：80-150 万/年（+ 股权）
核心要求：
- 能从 0 到 1 交付一个 300 万+ 的政企 AI 项目
- 能独立拿单、独立交付、独立收款
- 具备行业判断力（知道什么能做、什么不能做）
典型来源：大厂 FDE Lead / 资深解决方案架构师 / 连续创业者
```

### 3.2 Senior FDE（骨干级别）

```
技术能力：★★★★★  业务能力：★★★★☆  领导力：★★★☆☆
薪资区间：50-80 万/年
核心要求：
- 5 年+全栈开发经验 + 2 年+ AI 相关经验
- 独立交付过至少 2 个 100 万+ 项目
- 能带 2-3 个 Junior FDE
- 出差/驻场意愿（项目期间 50%+ 时间在客户现场）
典型来源：大厂 T 型工程师 / 创业公司技术负责人
```

### 3.3 Junior FDE（培养级别）

```
技术能力：★★★☆☆  业务能力：★★☆☆☆  学习能力：★★★★★
薪资区间：20-35 万/年
核心要求：
- 2 年+ 开发经验，至少精通一个技术栈（前端/后端/AI）
- 强烈的好奇心和学习意愿
- 愿意出差/驻场
- 有 AI/LLM/RAG 项目经验加分
典型来源：优秀应届生 / 转型的传统 IT 工程师 / 培训机构输出
```

### 3.4 平台工程师

```
技术能力：★★★★★  产品思维：★★★★☆  协作能力：★★★★☆
薪资区间：40-60 万/年
核心要求：
- 从 FDE 交付中抽象公共能力，建设内部平台
- 维护交付工具链（部署脚本、监控面板、RAG 框架）
- KPI：组件复用率 >60%、交付周期缩短 >30%
典型来源：全栈工程师 / 平台工程背景
```

## 四、团队文化建设

### 4.1 FDE 团队的核心价值观

| 价值观 | 含义 | 行为体现 |
|--------|------|---------|
| **客户成功第一** | 交付的价值标准是客户是否真正用起来了 | 不接受"已交付未使用"的项目 |
| **创造而非执行** | FDE 不是照章办事的实施工程师 | 主动提出更好的方案，挑战客户的需求 |
| **知识共享** | 一个人的经验变成所有人的能力 | 项目复盘、技术分享、文档化 |
| **长期主义** | 宁可丢单也不做烂项目 | 项目筛选有底线，保护团队声誉 |

### 4.2 团队建设活动

- **每月 FDE Day**：全体 FDE 回公司（不在客户现场），分享+复盘+团建
- **项目庆祝仪式**：每个项目上线时，全团队庆祝（增强成就感）
- **失败分享会**：不讲成功的项目，只讲踩过的坑（建立心理安全感）

## 五、关键绩效指标

### 团队级 KPI

| 指标 | 阶段 1 | 阶段 2 | 阶段 3 |
|------|--------|--------|--------|
| 项目按期交付率 | >80% | >85% | >90% |
| 客户满意度（NPS） | >50 | >60 | >70 |
| 人均营收（万/年） | >80 | >100 | >120 |
| 项目利润率 | >30% | >35% | >40% |

### 个人级 OKR 示例

```
Senior FDE Q3 OKR：
O: 高质量交付金融行业标杆项目
  KR1: 项目按期上线，客户 NPS > 60
  KR2: 沉淀 3 个可复用金融行业组件
  KR3: 带教的 2 名 Junior FDE 能独立承担小型项目
```
