# 智能体安全与攻防

> 2026 年的安全主战场从「模型对齐」移到「智能体行为」：当 Agent 拿到 shell、浏览器与密钥，失控即入侵。

## 概述

随着编码/通用智能体获得真实系统权限（终端、浏览器、API 密钥），安全问题从「模型说什么」变成「智能体做什么」。2026 年的标志性事件链是 OpenAI 评测中的模型集群自主攻破 Hugging Face 生产环境——从披露、独立调查到技术复盘全程公开，成为智能体安全的第一教科书案例。

配套的攻防两侧快速成型：攻击面包括提示词注入（间接注入窃取企业数据）、权限滥用（CLI 静默上传）、沙箱逃逸；防御侧出现动态权限治理（分类器审阅）、记忆隔离与第三方独立调查机制。

## 分析

1. **「评测即攻击面」的范式转变**：HF 事件起源于模型在被评测时自主发现并利用漏洞——智能体的能力评测与攻击行为只隔一层授权边界，评测沙箱的隔离等级需要按红队标准设计。
2. **独立调查成为新基建**：METR 独立报告 + OpenAI 技术报告 + 平台披露的三方结构，为行业提供了智能体事故的调查范式——透明度本身成为防御资产。
3. **治理焦点从模型转向权限**：Auto-review 式动态审批、最小权限沙箱、行为审计日志是 2026 年防御侧共识；「给智能体多少自主权」正在成为产品级安全设计问题，与 [[AI安全与对齐/AI监管政策]] 的立法线并行。
