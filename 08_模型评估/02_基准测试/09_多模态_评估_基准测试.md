# 多模态评测基准深度解析

> 中文简称：多模态评测基准深度解析

## 一句话理解

多模态评测不是"看图回答对不对"那么简单，而是**要区分模型是真的理解了图像内容，还是只记住了训练数据中的图文配对**——这需要在推理、细粒度理解和幻觉检测三个维度上设置越来越难的陷阱。

---

## 一、评测维度分类

```
多模态评测
├── 图像理解 (Image Understanding)
│   ├── 描述生成 (Captioning)
│   ├── 视觉问答 (VQA)
│   ├── 指代表达 (Referring Expression)
│   └── 视觉推理 (Visual Reasoning)
├── 文档理解 (Document Understanding)
│   ├── 图表问答 (Chart QA)
│   ├── 文档问答 (Doc QA)
│   ├── 信息抽取 (Information Extraction)
│   └── 表格理解 (Table Understanding)
├── 视频理解 (Video Understanding)
│   ├── 动作识别 (Action Recognition)
│   ├── 时序问答 (Temporal QA)
│   ├── 视频描述 (Video Captioning)
│   └── 因果推理 (Causal Reasoning)
├── 跨模态推理 (Cross-modal Reasoning)
│   ├── 图像-文本检索 (Image-Text Retrieval)
│   ├── 视觉蕴含 (Visual Entailment)
│   └── 多模态常识 (Multimodal Commonsense)
└── 幻觉检测 (Hallucination Detection)
    ├── 对象幻觉 (Object Hallucination)
    ├── 属性幻觉 (Attribute Hallucination)
    └── 关系幻觉 (Relation Hallucination)
```

## 二、图像理解评测

### 2.1 视觉问答 (Visual Question Answering, VQA)

**核心任务**: 给定图像和问题，生成正确答案。

**主流基准**:

| 基准 | 规模 | 问题类型 | 难度 | 关键挑战 |
|---|---|---|---|---|
| VQAv2 | 1.1M Q-A | 开放式 | 中 | 需要细粒度视觉理解 |
| GQA | 22M Q-A | 结构化 | 高 | 需要组合推理、场景图理解 |
| OK-VQA | 14K Q-A | 知识型 | 高 | 需要外部知识（不仅是图像内容） |
| A-OKVQA | 25K Q-A | 知识+推理 | 极高 | 需要常识推理 |
| VizWiz | 31K Q-A | 盲人提问 | 高 | 真实用户提问，噪声大 |

**GQA 的层次化难度设计**:
```
简单: "图中有什么颜色的车？" → 单属性查询
中等: "穿红衣服的人在车的左边还是右边？" → 关系推理
困难: "如果把车开走，图中还剩几个人？" → 反事实推理
```

**OK-VQA 的知识要求示例**:
```
图像: 一张网球比赛照片
问题: "这个运动员用的拍子是哪个国家的品牌？"

正确答案: "法国" (Babolat 是法国品牌)
所需知识: 网球品牌知识（不在图像中）
```

### 2.2 视觉推理与数学 (MathVista / MMStar)

**MathVista**: 数学问题 + 视觉输入

```
图像: 一个几何图形
问题: "求阴影部分的面积" 或 "证明这两个三角形全等"

能力要求:
1. 识别几何元素（点、线、角、圆）
2. 理解几何关系（垂直、平行、相切）
3. 执行数学推理（面积公式、三角函数）
4. 生成可验证的解题步骤
```

**MMStar (Multi-modal Multi-step Reasoning)**:
- 专门测试多步推理能力
- 每个问题需要 3-5 个推理步骤
- 包含陷阱选项（看似合理但逻辑错误）

### 2.3 幻觉检测基准

**POPE (Polling-based Object Probing Evaluation)**:
```
方法: 询问模型图像中是否存在某个对象

正例: "图中有一只狗吗？" (图像确实有狗) → 期望回答 "是"
负例: "图中有一只猫吗？" (图像没有猫) → 期望回答 "否"

 trick questions:
"图中有一头大象吗？" (图像是在室内客厅)
→ 考察模型是否知道"客厅不可能有大象"
```

**MMHal-Bench**:
- 12 个幻觉类别（对象、属性、数量、位置、关系等）
- 每个类别 50-100 个测试样本
- 同时评估检测率和误报率

**CHAIR (Caption Hallucination Assessment with Image Relevance)**:
```
方法: 生成描述，检查描述中的每个名词是否在图像中出现

模型描述: "一只猫坐在沙发上，旁边有一台电视"
图像内容: [猫] [沙发] [桌子] [窗户]

幻觉检测:
- "电视" 不在图像中 → 幻觉！
- "猫" 和 "沙发" 在图像中 → 正确

CHAIR 分数 = 幻觉名词数 / 总名词数
```

## 三、文档理解评测

### 3.1 图表问答 (Chart QA)

**ChartQA 基准**:
```
图像: 各种类型的图表（柱状图、折线图、饼图、雷达图）
问题类型:
  - 数据查找: "2020年的销售额是多少？"
  - 比较: "哪一年的增长最快？"
  - 计算: "平均增长率是多少？"
  - 趋势: "销售额是上升还是下降趋势？"
  - 推理: "如果保持当前趋势，2025年会达到多少？"
```

**关键难点**:
- **OCR 误差**: 图表中的数字识别错误会连锁影响所有后续推理
- **视觉推理**: 需要理解坐标轴、图例、颜色编码
- **计算精度**: 模型经常算错百分比变化

**PlotQA**: 更难的图表基准
- 问题需要多步推理
- 包含需要跨图表比较的问题

### 3.2 文档问答 (DocVQA / InfographicVQA)

**DocVQA**: 扫描文档理解
```
图像: 发票、表格、合同、表格、申请表
问题: "发票的总金额是多少？" "合同签署日期是什么？"

挑战:
- 文档布局复杂（表格、印章、手写批注）
- 信息分布在多个区域
- 需要理解文档类型（发票 vs 合同有不同的字段）
```

**InfographicVQA**: 信息图理解
```
图像: 复杂的信息图（多栏、图文混排、箭头连接）
问题: "根据图中所示，哪个步骤是导致失败的关键？"

挑战:
- 非线性阅读顺序
- 视觉元素（箭头、颜色、图标）承载语义
- 需要整合分散的信息片段
```

### 3.3 表格理解 (Table QA)

**WikiTableQuestions / TabFact**:
```
表格: 维基百科中的结构化表格
问题: "哪些国家的人口超过 1 亿且 GDP 增长率超过 5%？"

能力要求:
1. 定位相关列
2. 理解条件逻辑（AND/OR）
3. 数值比较
4. 多行聚合
```

## 四、视频理解评测

### 4.1 动作识别与时序定位

**ActivityNet**:
```
任务: 在未剪辑的长视频中定位和分类动作

输入: 10 分钟的视频（包含多个动作片段）
输出: 
  - 动作类别: "做饭"、"跑步"、"打电话"
  - 时间定位: "做饭"发生在 00:02:15 - 00:05:30

评估指标: mAP @ tIoU (temporal Intersection over Union)
```

**EPIC-KITCHENS**: 第一人称视频理解
```
任务: 理解烹饪过程中的动作序列

问题: "主角在切洋葱之前做了什么？"
答案需要: 回溯时序，找到 "切洋葱" 事件，识别前一个动作
```

### 4.2 视频问答

**NExT-QA ( causal reasoning)**:
```
问题类型:
- 因果: "为什么主角会摔倒？"
- 时序: "摔倒之前发生了什么？"
- 计数: "视频中有几个人帮忙？"

关键: 不能只看单帧，必须理解事件的前因后果
```

**Ego4D**:
```
任务: 第一人称视角的长期目标理解

问题: "这个人想做什么？"（观察他拿起了锅、打开了火、倒了油）
预测: "他想要做饭"

需要: 理解动作序列的目标和意图
```

## 五、跨模态推理评测

### 5.1 视觉蕴含 (Visual Entailment, SNLI-VE)

```
图像: 一个人在雨中打伞
假设 1: "天气晴朗" → 矛盾 (contradiction)
假设 2: "有人在户外" → 蕴含 (entailment)
假设 3: "这个人要去上班" → 中性 (neutral，无法从图像推断)

评估: 三分类准确率
```

### 5.2 多模态常识推理 (VCR)

**Visual Commonsense Reasoning**:
```
图像: 一个男孩在生日派对上哭泣
问题: "他为什么哭？"

选项:
A. 因为他收到了太多礼物
B. 因为他的气球飞走了
C. 因为他很高兴
D. 因为他吃了太多蛋糕

正确答案: B

需要: 视觉理解 + 常识推理 + 情感理解
```

## 六、评测方法论

### 6.1 指标选择

| 任务 | 推荐指标 | 原因 |
|---|---|---|
| 分类/选择 | Accuracy, F1 | 明确的对错 |
| 生成描述 | CIDEr, SPICE, METEOR | 评估语义质量 |
| 定位 | mAP @ IoU | 需要精确的位置 |
| 开放式 QA | Exact Match / LLM-as-a-Judge | 答案形式多样 |
| 幻觉检测 | Precision/Recall of hallucination | 误报和漏报都重要 |

**为什么不推荐 BLEU/ROUGE 用于 VQA？**
- BLEU 基于 n-gram 匹配，对同义词敏感
- "狗" 和 "犬" 在 BLEU 中算错误，但语义正确
- 推荐 CIDEr（基于 TF-IDF 的 n-gram 匹配）或 SPICE（基于场景图）

### 6.2 LLM-as-a-Judge 在多模态中的应用

```python
def multimodal_llm_judge(image, question, model_answer, ground_truth):
    # 用更强的多模态模型（如 GPT-4V）作为裁判
    
    prompt = f"""
    图像: [image]
    问题: {question}
    参考答案: {ground_truth}
    模型回答: {model_answer}
    
    请判断模型回答是否正确。评分标准:
    - 5分: 完全正确，包含所有关键信息
    - 4分: 基本正确，有 minor 遗漏
    - 3分: 部分正确，有关键错误
    - 2分:  mostly 错误
    - 1分: 完全错误或幻觉
    
    先解释理由，再给出分数。
    """
    
    return gpt4v(prompt)
```

**优势**:
- 可以处理开放式答案
- 能理解语义等价（"狗" = "犬"）
- 可以检测幻觉

**风险**:
- 裁判模型自身的偏见和幻觉
- 成本高昂（每个样本需要一次 API 调用）
- 可能偏好"更长、更流畅"的答案

### 6.3 对抗性评测

**MMBench 的陷阱设计**:
```
问题: "图中红色的物体是什么？"

陷阱 1: 图中没有红色物体 → 测试模型是否编造
陷阱 2: 有多个红色物体 → 测试模型是否全部列出
陷阱 3: 红色物体是背景的一部分 → 测试模型是否能区分前景/背景
```

**MMMU 的大学级问题**:
```
学科: 大学物理 / 化学 / 生物 / 数学 / 工程
难度: 需要专业知识 + 视觉理解 + 多步推理

示例 (物理):
图像: 一个光学实验装置图
问题: "如果波长从 600nm 改为 400nm，干涉条纹间距会如何变化？"

正确答案: 间距变小（因为 Δx = λL/d）
```

## 七、前沿趋势

### 7.1 统一评测框架

当前多模态评测是碎片化的——每个基准只测一个方面。

**趋势**: 向 "通用多模态智能" 评测发展
- **MMBench-Dev**: 覆盖 20+ 能力维度
- **MMStar**: 专注最难的推理问题
- **SEED-Bench**: 包含 19K 人工标注的多选问题

### 7.2 动态难度评测

**问题**: 静态基准容易被模型"刷分"（过拟合到测试集）。

**解决方案**:
- **自适应测试**: 根据模型表现动态调整问题难度
- **对抗生成**: 用另一个模型生成专门针对当前模型弱点的问题
- **人类在环**: 持续收集人类认为"有挑战性"的新问题

### 7.3 评测与实际应用的 Gap

| 评测场景 | 真实应用场景 | Gap |
|---|---|---|
| 清晰的高质量图像 | 手机拍摄的模糊、低光图像 | 鲁棒性 |
| 标准问题 | 用户的口语化、模糊提问 | 理解意图 |
| 单轮问答 | 多轮对话中的上下文理解 | 持续推理 |
| 静态图像 | 实时视频流 | 时序理解 |
