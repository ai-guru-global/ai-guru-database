# 语料库覆盖度评估框架

> 系统化评估各云产品智能体背后语料库/知识库的完备性、准确性和时效性

## 概述

语料库覆盖度评估是 Agent 测评的关键环节。一个 Agent 的表现上限由其语料库质量决定——即使模型推理能力再强，缺乏必要的知识也无法给出正确答案。本框架建立了一套系统化的语料库评估方法，帮助：

1. **定位知识盲区**：精确定位哪些领域的知识缺失
2. **量化覆盖水平**：用标准化指标衡量语料完备程度
3. **指导语料补充**：基于差距分析提供语料优化建议
4. **验证改进效果**：追踪语料补充后的 Agent 表现提升

## 评估维度

### 四维覆盖度模型（COVR）

```
┌───────────────────────────────────────────────────────────────────┐
│                    COVR 四维覆盖度模型                              │
├───────────────────────────────────────────────────────────────────┤
│                                                                    │
│   C - 内容覆盖度（Coverage）                                       │
│   ├── 产品文档覆盖：官方文档的覆盖比例                              │
│   ├── API 参考覆盖：API 文档的完整度                                │
│   ├── 最佳实践覆盖：推荐方案和 Pattern 的丰富度                    │
│   └── 故障案例覆盖：已知问题和解决方案的覆盖度                      │
│                                                                    │
│   O - 场景覆盖度（Operational）                                    │
│   ├── 部署场景：从单机到分布式的各种部署模式                        │
│   ├── 运维场景：监控、告警、故障排查、容量规划                      │
│   ├── 安全场景：权限、加密、审计、合规                              │
│   └── 成本场景：选型、优化、预留、FinOps                            │
│                                                                    │
│   V - 版本时效性（Version & Vitality）                             │
│   ├── 版本同步度：与最新产品版本的同步程度                          │
│   ├── 变更追踪：API 变更、功能上下线的及时性                        │
│   ├── 新功能覆盖：新发布功能的语料纳入速度                          │
│   └── 废弃标记：已废弃功能/API 的标注和替代指引                     │
│                                                                    │
│   R - 语言质量度（Representation）                                 │
│   ├── 中文质量：中文技术术语的准确性和一致性                        │
│   ├── 英文质量：英文技术内容的理解深度                              │
│   ├── 双语对齐：中英文内容的对应一致性                              │
│   └── 代码示例：可执行的代码片段质量和多样性                        │
│                                                                    │
└───────────────────────────────────────────────────────────────────┘
```

## 评估方法

### 方法一：基准题库探测法

通过精心设计的基准题库，反向探测语料库覆盖情况。

```
探测流程：
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  题目库       │ ──→ │  Agent 回答   │ ──→ │  答案分析     │
│  (350题/产品) │     │              │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
                                                  │
                                                  ▼
                         ┌──────────────────────────────────────┐
                         │  分类统计：                           │
                         │  ✅ 正确 → 语料覆盖良好               │
                         │  ❌ 错误 → 语料可能有误/不完整        │
                         │  ⚠️ 模糊 → 语料不充分                │
                         │  🚫 无法回答 → 语料缺失               │
                         │  🔄 过时 → 语料未更新                 │
                         └──────────────────────────────────────┘
```

#### 题目分类矩阵

| 产品服务 | 入门 | 进阶 | 专家 | 前沿 | 合计 |
|----------|:----:|:----:|:----:|:----:|:----:|
| 计算（ECS/EC2/VM） | 10 | 8 | 5 | 2 | 25 |
| 存储（OSS/S3/Blob） | 10 | 8 | 5 | 2 | 25 |
| 网络（VPC/VNet） | 10 | 8 | 5 | 2 | 25 |
| 数据库（RDS/Aurora） | 10 | 8 | 5 | 2 | 25 |
| 容器（ACK/EKS/AKS） | 8 | 8 | 4 | 2 | 22 |
| 安全（IAM/WAF） | 8 | 6 | 4 | 2 | 20 |
| 监控（CloudMonitor） | 6 | 6 | 4 | 2 | 18 |
| AI/ML 平台 | 8 | 6 | 4 | 2 | 20 |
| Serverless | 6 | 6 | 4 | 2 | 18 |
| 成本管理 | 6 | 4 | 2 | 2 | 14 |
| **合计** | **82** | **68** | **42** | **20** | **212** |

### 方法二：文档交叉比对法

将 Agent 回答与官方文档逐条比对。

```
步骤：
1. 选取官方文档 100 个知识点
2. 对每个知识点生成 1 个问题
3. 收集 Agent 回答
4. 与官方文档进行语义比对
5. 分类统计覆盖情况
```

| 比对结果 | 定义 | 占比目标 |
|----------|------|:--------:|
| 完全匹配 | 回答与文档内容一致 | >80% |
| 部分匹配 | 回答覆盖部分内容 | <15% |
| 补充信息 | 回答超出文档范围（需验证） | <5% |
| 矛盾信息 | 回答与文档矛盾 | <1% |
| 缺失 | 无法回答文档中的知识点 | <5% |

### 方法三：版本追踪测试法

专门测试语料库对产品版本变更的追踪能力。

```
版本追踪测试：
├── 测试最新发布功能（发布 1 周内）
├── 测试近期 API 变更（3 个月内）
├── 测试已废弃功能/参数
├── 测试新区域/新可用区
└── 测试新定价/新实例类型
```

| 时效性等级 | 定义 | 测试题目数 |
|:----------:|------|:----------:|
| 实时 | 发布 1 周内的新功能 | 5 |
| 近期 | 1-3 个月内的变更 | 10 |
| 稳定 | 3-12 个月的特性 | 10 |
| 历史 | 已存在 1 年以上的成熟功能 | 10 |

### 方法四：双语质量评估法

```
双语测试矩阵：
┌─────────────┬──────────────────────┐
│ 测试类型     │ 描述                  │
├─────────────┼──────────────────────┤
│ 中文→中文    │ 中文提问，中文回答     │
│ 英文→中文    │ 英文提问，中文回答     │
│ 中文→英文    │ 中文提问，英文回答     │
│ 英文→英文    │ 英文提问，英文回答     │
│ 混合         │ 中英混合技术文档理解   │
└─────────────┴──────────────────────┘
每类 10 题，共 50 题
```

## 评分标准

### 覆盖度评分公式

```
覆盖度总分 = W_c × C + W_o × O + W_v × V + W_r × R

其中：
  C = 内容覆盖度（0-100）
  O = 场景覆盖度（0-100）
  V = 版本时效性（0-100）
  R = 语言质量度（0-100）
  
  W_c = 0.35（内容覆盖度权重）
  W_o = 0.30（场景覆盖度权重）
  W_v = 0.20（版本时效性权重）
  W_r = 0.15（语言质量度权重）
```

### 覆盖度等级

| 分数 | 等级 | 说明 | 建议 |
|:----:|:----:|------|------|
| 90-100 | A | 语料库完备，覆盖全面 | 维护为主 |
| 80-89 | B+ | 大部分覆盖，有少量盲区 | 针对性补充 |
| 70-79 | B | 基本覆盖，有明显不足 | 系统性补强 |
| 60-69 | C | 覆盖不足，影响 Agent 表现 | 重点建设 |
| <60 | D | 严重缺失 | 全面重建 |

### 各维度评分细则

#### C - 内容覆盖度评分

| 子维度 | 权重 | 评分方法 |
|--------|:----:|----------|
| 产品文档覆盖 | 30% | 抽样 50 个知识点，计算正确回答比例 |
| API 参考覆盖 | 25% | 抽样 30 个 API，测试参数/用法回答质量 |
| 最佳实践覆盖 | 25% | 测试 20 个最佳实践场景的回答质量 |
| 故障案例覆盖 | 20% | 测试 20 个故障排查场景的回答质量 |

#### O - 场景覆盖度评分

| 子维度 | 权重 | 评分方法 |
|--------|:----:|----------|
| 部署场景 | 25% | 测试 5 种部署模式的方案建议质量 |
| 运维场景 | 25% | 测试 5 个运维场景的操作指引质量 |
| 安全场景 | 25% | 测试 5 个安全场景的合规建议质量 |
| 成本场景 | 25% | 测试 5 个成本优化场景的建议质量 |

#### V - 版本时效性评分

| 子维度 | 权重 | 评分方法 |
|--------|:----:|----------|
| 版本同步度 | 30% | 测试 10 个最新版本特性 |
| 变更追踪 | 25% | 测试 5 个近期 API 变更 |
| 新功能覆盖 | 25% | 测试 5 个新发布功能 |
| 废弃标记 | 20% | 测试 5 个已废弃功能/参数 |

#### R - 语言质量度评分

| 子维度 | 权重 | 评分方法 |
|--------|:----:|----------|
| 中文质量 | 30% | 术语准确性、表达流畅度 |
| 英文质量 | 30% | 英文内容理解深度 |
| 双语对齐 | 20% | 中英文内容一致性 |
| 代码示例 | 20% | 代码可执行性、多样性 |

## 语料库与 Agent 表现关联分析

### 关联分析方法

```
分析步骤：
1. 计算各产品语料库 COVR 得分
2. 计算各产品 Agent CAPER 得分
3. 进行相关性分析
4. 识别关键差距点
5. 建立改进优先级矩阵
```

### 差距定位矩阵

```
                    语料库覆盖度
                    高          低
              ┌──────────┬──────────┐
         高   │  优秀     │  模型强   │
Agent    │  维持现状 │  语料是瓶颈│
表现     ├──────────┼──────────┤
         低   │  需优化   │  全面改进   │
              │  模型/推理 │  基础建设   │
              └──────────┴──────────┘
```

### 改进优先级

| 优先级 | 条件 | 行动 |
|:------:|------|------|
| P0 | 语料缺失导致关键功能无法回答 | 立即补充语料 |
| P1 | 语料不充分导致回答模糊 | 2 周内补充 |
| P2 | 语料过时导致回答不准确 | 1 月内更新 |
| P3 | 语料冗余影响回答效率 | 优化整理 |
| P4 | 语料质量可提升 | 持续优化 |
