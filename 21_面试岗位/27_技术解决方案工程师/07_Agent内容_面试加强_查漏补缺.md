## 1. 缺口一：Agent 架构范式对比

面试官问"你做的 Agent 是什么架构"时，要能先给**范式坐标**再讲自己的选择。

| 范式 | 机制 | 优点 | 缺点 | 适用 | 代表 |
|------|------|------|------|------|------|
| **ReAct** | Thought→Action→Observation 循环 | 简单、每步可见 | 长任务易丢目标、循环打转 | 中短任务、工具调用 | LangChain Agent、你的运维智能体 |
| **Plan-and-Execute** | 先出计划再逐步执行 | 长任务稳、可审阅计划 | 计划赶不上变化，需重规划机制 | 多步骤生产流程 | LangGraph Plan nodes |
| **Multi-Agent（hub-spoke）** | 主 Agent 路由到专职子 Agent | 复杂度分治、爆炸半径隔离 | 路由错误、消息传递成本 | 技能边界清晰的场景 | **你的运维智能体**、CrewAI |
| **状态机/工作流型** | 用图/状态机固化流程 | 可靠性最高、可测试 | 灵活性差 | 流程确定的业务 | Dify、扣子、Airflow 式编排 |

**答题要点（用自己的架构收尾）**：

> "我的运维智能体选 hub-spoke 多智能体：工单入口是 hub 做意图路由，分场景技能是 spoke——高频问题再用分支判断树走确定性路径。这是在'灵活 ReAct'和'死板工作流'之间取的平衡：**长尾用 LLM 灵活性，高频用确定性可靠性**。"

- [ ] 四种范式各 30 秒讲清
- [ ] "你的架构属于哪种、为什么选它"1 分钟版

## 2. 缺口二：Harness 工程深入（JD 点名必考）

### 2.1 核心公式与定义

```text
Agent = LLM + Harness
```

**Harness（马具）**：LLM 与真实执行环境之间的系统工程框架——标准化消息协议、分层权限、执行可见性、错误处理，使 LLM 在**受控约束**下安全可靠地感知、执行、学习。一句话：**模型决定思维上限，Harness 决定下限和能不能落地**。

### 2.2 五大子系统（必须背全）

| 子系统 | 职责 | 缺了会怎样 | 你项目里的对应物 |
|--------|------|-----------|-----------------|
| **1 工具层** | 工具注册/选择/调用/结果解析 | LLM 幻觉工具、调用格式错 | 蒸馏出的技能 = 受限工具集 |
| **2 执行循环** | 消息协议、终止条件、迭代上限 | 死循环烧钱、永不收尾 | hub-spoke 路由循环 + 分支树 |
| **3 护栏（Guardrails）** | 输入输出过滤、权限分级、沙箱执行 | 越权操作、数据泄露 | 脱敏 + 客户数据隔离 + 沙箱 |
| **4 记忆与状态** | 会话内/跨会话状态、检索注入 | 每轮从零开始、答非所问 | LM Wiki 知识沉淀 |
| **5 评测与可观测** | Trace、指标、回归、在线监控 | 无法证明 POC 成功、退化不可见 | 场景覆盖率 80% 度量 |

### 2.3 答题套路（必练）

> **"你做的 Agent 的 Harness 长什么样？"** —— 用上表第 4 列把自己的项目映射到五大子系统，1.5 分钟讲完。这正是招聘方要的"**上层方法论 + 下层工程化**"结构。

- [ ] 五大子系统脱稿
- [ ] 自己项目映射表 1 分钟版

## 3. 缺口三：Agent 推理场景与模型侧

JD 第 3 条要求"了解主流 AI/Agent 推理场景"——面试官会问：**Agent 推理和普通聊天推理有什么不同？**

| 维度 | 普通聊天推理 | Agent 推理 |
|------|-------------|-----------|
| **输出形态** | 自由文本 | **结构化 tool_calls**（JSON schema 强约束） |
| **上下文** | 单轮为主 | 超长累积：系统提示 + 工具定义 + 历史轨迹 + 检索结果 |
| **交互模式** | 一问一答 | **多轮串行**：一次任务 5–50 次模型调用，延迟累乘 |
| **关键指标** | 吞吐、TTFT | **工具调用准确率**、首步延迟、轮次成本、任务成功率 |
| **推理优化** | batch 吞吐 | 前缀缓存（system prompt + 工具定义命中）→ 降 TTFT 与成本 |
| **失败模式** | 答错 | 循环打转、错误工具、参数幻觉 → 要靠 Harness 兜底 |

**必备知识点**：

- **Function Calling / 结构化输出**：模型微调过的"协议能力"；schema 约束 + 重试 + 校验三层保底。
- **前缀缓存（Prefix Cache）**：Agent 每轮都带相同 system + tools 前缀，命中缓存可显著降 TTFT 和 token 成本——**这正是你 AISTack"保证缓存命中率"的原理，联动讲**。
- **长上下文 vs RAG**：上下文窗口再大也不能全塞（注意力稀释 + 成本），检索注入是主流。
- **并发特性**：Agent 任务内部串行、任务之间并发 → 推理服务要扛**并发小请求**而非单一大流量。

**自测题**：

- [ ] "Agent 调工具失败了模型会怎样？你怎么兜底？"（答：格式校验+重试+降级到人/确定性路径，联系你的分支判断树）
- [ ] "为什么 Agent 场景前缀缓存特别重要？"（5 轮调用 × 相同前缀，命中率直接乘 5 倍节省）

**深挖材料**：[Agent Engineering 高级面试问答](../26_高级面试问答/05_Agent_Engineering_高级面试问答.md)、[概念/function-calling](../../概念/Agent/function-calling.md)

## 4. 缺口四：记忆与上下文管理

JD 第 2 条点名方案要组合"**上下文管理**"——这块要能画出分层图。

```text
┌─ 上下文窗口（单次调用装得下的）─────────────┐
│  System Prompt（身份+规则）                  │
│  工具定义（前缀缓存友好，放最前）             │
│  检索注入（RAG 结果 / LM Wiki 片段）          │
│  会话历史（滑动窗口 / 摘要压缩）              │
└──────────────────────────────────────────┘
        ↑ 按需注入
┌─ 记忆层（窗口装不下的）────────────────────┐
│  短期：会话状态、中间结果（状态管理）          │
│  长期：向量库 + 知识图谱（跨会话偏好/经验）    │
│  沉淀：LM Wiki / 技能库（蒸馏固化）           │
└──────────────────────────────────────────┘
```

**三个高频问答**：

| 问题 | 答题要点 |
|------|---------|
| 上下文超了怎么办？ | 四招：滑动窗口截断 → 历史摘要压缩 → 检索式注入（只取相关片段）→ 外置记忆（写回长期层）。按顺序组合用 |
| 记忆和 RAG 什么区别？ | RAG 解决"**不知道**"（知识注入），记忆解决"**不记得**"（状态与经验延续）；你的方案两者都用了：代码检索 = RAG，LM Wiki = 沉淀记忆 |
| 为什么工具定义放 prompt 最前面？ | 前缀缓存命中要求**逐字节相同的前缀**；放最前使所有请求共享同一缓存段 |

- [ ] 分层图手绘 1 遍
- [ ] 三个问答脱稿

## 5. 缺口五：Agent 安全与沙箱的衔接

安全是把"Agent 知识"和"沙箱卖点"**焊在一起**的关键章节——面试官大概率顺着安全往下问沙箱。

### 5.1 威胁分层 → 对应防线

| 威胁层 | 具体威胁 | 防线 | 归属 |
|--------|---------|------|------|
| **输入层** | Prompt Injection（网页/文档里藏指令）、间接注入 | 输入过滤、不可信内容标记、权限最小化 | Harness 护栏 |
| **模型层** | 幻觉工具调用、参数注入 | schema 校验、白名单工具、敏感操作人审 | Harness 护栏 |
| **执行层** | 恶意代码删库、越权访问、数据串扰 | **沙箱隔离 + 配额 + 网络策略** | **沙箱（我方产品）** |
| **数据层** | 多租户数据泄露 | 脱敏 + 租户边界（你的项目实践） | 方案设计 |

### 5.2 金句串联（面试直接用）

> "Agent 安全是**分层防御**：应用层靠 Harness 护栏管'说什么、调什么'，执行层靠沙箱管'跑在哪、能不能越界'——**Prompt Injection 防不住 100%，所以执行层的沙箱隔离是最后也是最硬的一道防线**。这就是为什么我说沙箱是 Agent 刚需。"

- [ ] 威胁分层表看熟，能反向问"你们客户遇到过注入类事故吗"
- [ ] 金句脱稿

## 6. 缺口六：Agent 评测

POC 要给客户看成功指标——**"怎么证明你的 Agent 是好的"**必被问到。

| 评测维度 | 指标 | 你项目中的实践 |
|---------|------|---------------|
| **任务级** | 成功完成率（端到端） | 场景覆盖率 80% |
| **输出级** | 直推无需修改率（质量分） | >40% 直推率 |
| **轨迹级** | 工具调用正确率、步数效率、循环率 | 分支判断树压循环 |
| **安全级** | 越权率、泄露率、注入拦截率 | 脱敏 + 隔离验证 |
| **成本级** | 单任务 token 成本、时延 P95 | 缓存命中优化 |

**三段答题逻辑**：

1. **难在哪**：输出非唯一（同一任务多种合法答案）、轨迹长、环境动态 → 传统准确率不够用。
2. **怎么做**：黄金集（Golden Set）离线回归 + LLM-as-a-Judge 抽样 + 在线业务指标（直推率）三层结合。
3. **我怎么做**：黄金工单集回归 + 覆盖率/直推率双指标 —— **这就是我给客户 POC 定指标的方法**。

- [ ] 三层评测逻辑脱稿
- [ ] "给客户 POC 定什么指标"用自己口径讲 1 分钟

## 7. 缺口七：业界生态与竞品地图

JD 第 4 条"主动探索业界 AI 新技术"——准备一张**四行地图**，面试口述 2 分钟：

| 层 | 代表 | 一句话定位 |
|----|------|-----------|
| **框架/编排** | LangGraph、CrewAI、OpenAI Agents SDK、AgentScope（你用的）、ADK | 写 Agent 的代码骨架 |
| **协议** | **MCP**（工具接入标准）、A2A（Agent 互操作） | 连接的"普通话"——MCP 已成事实标准，值得展开 1 分钟 |
| **平台/产品** | 扣子（Coze）、Dify、Claude Code、Manus | 低代码/成品 Agent |
| **Infra（本团队象限）** | E2B、Modal、Daytona + **阿里云沙箱** | Agent 运行时与隔离——**卖点所在** |

**收尾金句**：

> "框架层卷得很厉害、会持续洗牌，但**无论上层用什么框架，底层都要一个安全的运行时**——我们做 Agent Infra 就是押注这个不变量。"

**补充热点（面试前刷新）**：AI Coding Agent（Claude Code/Cursor）、Computer-Use、多智能体协议进展——**面试前一天搜一次最新动态**。

| 类别 | 例证 | 一句话讲法 |
