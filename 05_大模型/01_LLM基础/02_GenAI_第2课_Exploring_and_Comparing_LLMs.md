- 理解基础模型与下游模型之间的区别

## LLM 的分类维度概述

LLM 可以根据其**架构**、**训练数据**和**使用场景**进行多种分类。了解这些差异将帮助我们为特定场景选择适合的模型，并了解如何测试、迭代和提高性能。

LLM 模型种类繁多，选择哪种模型取决于多个因素：

- **使用目的**：文本生成、图像生成、音频处理等
- **数据类型**：你的应用处理什么类型的数据
- **预算**：不同模型的成本差异很大
- **延迟要求**：实时应用需要低延迟的模型
- **数据隐私**：某些场景需要本地部署模型

## 按输出类型分类

根据你希望模型生成的输出类型，可以选择不同类型的模型：

### 音频和语音识别模型

对于音频和语音识别用途，**Whisper** 类型的模型是一个很好的选择。

**Whisper 模型特点**：
- 通用性强，专注于语音识别任务
- 基于多样化的音频数据进行训练
- 可以执行多语言语音识别
- 支持语音翻译和语音活动检测

**适用场景**：语音转文字、会议记录、字幕生成、多语言翻译

### 图像生成模型

对于图像生成，**DALL-E** 和 **Midjourney** 是两个非常知名的选择。

**DALL-E**（由 Azure OpenAI 提供）：
- 根据文本描述生成图像
- 支持图像编辑和变体生成
- DALL-E 3 是最新版本，提供更高的图像质量和更好的文本理解

**Midjourney**：
- 以艺术风格的图像生成著称
- 通过 Discord 界面使用
- 在创意设计领域广受欢迎

**Stable Diffusion**：
- 开源的图像生成模型
- 可以本地部署
- 支持多种自定义和微调

### 文本生成模型

大多数 LLM 都经过文本生成训练，你可以选择从 **GPT-3.5** 到 **GPT-4** 的多种模型。

**模型对比**：

| 模型 | 特点 | 适用场景 |
|------|------|----------|
| GPT-3.5 | 成本较低，速度快 | 通用文本生成、简单问答 |
| GPT-4 | 更强的推理能力，准确性更高 | 复杂推理、代码生成、专业内容 |
| GPT-4 Turbo | GPT-4 的优化版本 | 需要平衡质量和成本 |

建议使用 [Azure OpenAI Playground](https://oai.azure.com/portal/playground) 评估哪些模型在能力和成本方面最适合你的需求。

### 多模态模型

如果你需要同时处理输入和输出中的多种数据类型，可以考虑多模态模型：

- **GPT-4 Turbo with Vision**：将自然语言处理与视觉理解结合起来
- **GPT-4o**：OpenAI 最新发布的多模态模型，能够通过多模态界面进行交互
- 可以同时理解和生成文本、图像等多种格式的内容

## 基础模型与下游模型

### 什么是基础模型？

"基础模型"（Foundation Model）这一术语由斯坦福研究人员在 2021 年提出，定义为符合以下标准的 AI 模型：

1. **使用无监督学习或自监督学习进行训练**：即它们基于未标注的多模态数据进行训练，不需要人工注释或标注数据来完成训练过程
2. **非常大的模型**：基于非常深的神经网络，训练了数十亿个参数
3. **作为其他模型的"基础"**：它们可以作为其他模型的起点，通过微调来构建其他专用模型

**基础模型的核心价值**：

基础模型的核心理念是"一次训练，多次使用"。通过在海量数据上进行昂贵的预训练，获得一个具有广泛能力的模型，然后可以相对低成本地微调到各种特定任务。

### 基础模型到专用模型的转化

以 ChatGPT 为例说明这个转化过程：

1. **基础模型**：OpenAI 首先训练了 GPT-3.5 作为基础模型，它具有通用的文本生成能力
2. **特定数据微调**：使用特定的聊天对话数据对 GPT-3.5 进行微调
3. **专用模型**：微调后的模型在对话场景（如聊天机器人）中表现更加出色
4. **产品化**：最终形成了 ChatGPT 产品

**这个过程的类比**：

想象基础模型就像一个拥有广泛知识通才。通过微调，我们让它成为某个领域的专家——就像一个通才医生经过专科培训成为心脏外科医生。

## 开源模型与专有模型

### 开源模型

开源模型是公开提供给公众使用的模型，任何人都可以使用和修改。

**特点**：
- 由创建它们的公司或研究社区提供
- 可以被检查、修改和定制
- 通常不针对生产使用优化，性能可能不如专有模型
- 资金可能有限，可能无法长期维护或更新

**流行的开源模型**：

| 模型 | 开发者 | 特点 |
|------|--------|------|
| Alpaca | 斯坦福 CRFM | 基于 LLaMA 微调的指令遵循模型 |
| Bloom | BigScience | 多语言开源模型 |
| LLaMA | Meta | 高性能开源模型系列，支持多种规模 |
| Mistral | Mistral AI | 高效的开源模型，性能接近专有模型 |

### 专有模型

专有模型是由公司拥有的模型，未向公众开放。

**特点**：
- 通常针对生产使用进行了优化
- 无法被检查、修改或定制
- 可能需要订阅或支付费用
- 用户无法控制训练数据，需要信任模型所有者确保数据隐私和负责任的 AI 使用

**流行的专有模型**：

| 模型 | 开发者 | 特点 |
|------|--------|------|
| GPT 系列 | OpenAI | 行业领先的语言模型 |
| Claude | Anthropic | 注重安全性和有用性 |
| Gemini | Google | Google 的多模态 AI 模型 |

### 如何选择？

选择开源还是专有模型，需要考虑以下因素：

| 考虑因素 | 选择开源 | 选择专有 |
|----------|----------|----------|
| 成本预算 | 有限预算，愿意自行承担计算成本 | 有预算用于 API 调用费用 |
| 数据隐私 | 需要完全控制数据，必须本地运行 | 可以接受数据发送到云端 |
| 定制需求 | 需要深度定制和修改模型 | 使用标准功能即可 |
| 技术能力 | 有团队可以部署和维护模型 | 希望即用型服务 |
| 性能要求 | 可以接受稍低的性能 | 需要最佳性能 |

## 按生成输出分类

### 嵌入模型

嵌入（Embedding）模型可以将文本转换为数值形式，称为**嵌入向量**。嵌入向量是输入文本的数值表示，使机器更容易理解单词或句子之间的关系。

**嵌入模型的主要用途**：
- 作为其他模型的输入（如分类模型或聚类模型）
- 语义搜索和相似度计算
- 迁移学习：模型为一个有大量数据的替代任务构建，然后模型权重（嵌入）被重新用于其他下游任务

**示例**：OpenAI Embeddings 模型可以将文本转换为高维向量，用于语义搜索、文本分类等任务。

### 图像生成模型

图像生成模型是生成图像的模型，通常用于：
- 图像编辑和合成
- 图像翻译
- 图像修复（Inpainting）
- 超分辨率和上色

这些模型通常基于大型图像数据集（如 LAION-5B）进行训练。示例包括 DALL-E-3 和 Stable Diffusion。

### 文本和代码生成模型

文本和代码生成模型是最常见的 LLM 类型：
- **文本生成**：通常基于大型文本数据集（如 BookCorpus）训练，用于文本摘要、翻译和问答
- **代码生成**：如 CodeParrot，通常基于大型代码数据集（如 GitHub）训练，用于生成新代码或修复现有代码中的错误

## 编码器-解码器架构分类

为了理解 LLM 的不同架构类型，我们可以用一个类比来说明。

### 类比说明

假设你的经理给你布置了一项任务，为学生编写一个测验。你有两位同事：

**同事 A（内容创建者）—— 类似仅解码器模型**：
- 他们可以查看主题和已有内容
- 然后根据这些内容编写课程
- 非常擅长编写引人入胜且信息丰富的内容
- 但不太擅长理解主题和学习目标
- **代表模型**：GPT 系列模型（如 GPT-3）

**同事 B（审核者）—— 类似仅编码器模型**：
- 他们查看编写的课程和答案
- 注意它们之间的关系并理解上下文
- 但不擅长生成新内容
- **代表模型**：BERT

**同事 C（全能型）—— 类似编码器-解码器模型**：
- 既能创建又能审核测验
- 兼具理解和生成能力
- **代表模型**：BART、T5

### 三种架构对比

| 架构类型 | 代表模型 | 擅长 | 不擅长 | 典型应用 |
|----------|----------|------|--------|----------|
| 仅编码器 | BERT | 理解上下文、文本分类 | 生成文本 | 文本分类、情感分析、命名实体识别 |
| 仅解码器 | GPT 系列 | 生成连贯文本 | 理解复杂上下文关系 | 文本生成、对话、代码生成 |
| 编码器-解码器 | BART、T5 | 同时理解和生成 | 训练成本高 | 翻译、摘要、文本转换 |

## 服务与模型的区别

理解"服务"和"模型"之间的区别对于正确部署和使用 AI 至关重要。

### 模型（Model）

模型是神经网络本身，包括参数、权重等。它是一个静态的计算图，需要输入数据才能产生输出。

**特点**：
- 允许公司在本地运行
- 需要购买计算设备
- 需要构建扩展结构
- 需要购买许可证或使用开源模型
- 例如 LLaMA 可以使用，但需要足够的计算能力

### 服务（Service）

服务是由云服务提供商提供的产品，通常是模型、数据和其他组件的组合。模型是服务的核心组件。

**特点**：
- 通常针对生产使用进行了优化
- 更易于使用，通过图形用户界面操作
- 可能需要订阅或按使用量付费
- 利用服务所有者的设备和资源
- 示例：Azure OpenAI Service

**Azure OpenAI Service 详解**：
- 提供**按使用量付费**的计划，用户根据使用服务的多少按比例收费
- 在模型功能之上提供**企业级安全性**和**负责任的 AI 框架**
- 提供 REST API 和 SDK，方便集成到各种应用中
- 支持内容过滤和安全机制

## 在 Azure AI Studio 上测试和迭代模型

一旦确定了适合场景的候选模型，下一步就是在实际数据和工作负载上测试这些模型。这是一个通过实验和测量完成的迭代过程。

### Azure AI Studio 概览

[Azure AI Studio](https://ai.azure.com/) 是一个云平台，专为开发者设计，用于构建生成式 AI 应用并管理整个开发生命周期。它将所有 Azure AI 服务整合到一个便捷的图形用户界面中。

### 模型目录

Azure AI Studio 的模型目录使用户能够：

1. **发现模型**：在目录中找到感兴趣的基础模型，无论是专有模型还是开源模型。可以按任务、许可证或名称进行筛选。模型被组织到不同的集合中（如 Azure OpenAI 集合、Hugging Face 集合等）

2. **查看模型卡**：每张模型卡包含关于预期用途和训练数据的详细描述、代码示例以及内部评估库的评估结果

3. **基准测试**：通过模型基准测试面板比较行业内可用的模型和数据集的基准测试，评估哪个模型最符合业务场景

4. **微调模型**：利用 Azure AI Studio 的实验和跟踪功能，在自定义训练数据上微调模型，提高模型在特定工作负载中的性能

5. **部署模型**：将原始预训练模型或微调版本部署到远程实时推理端点（托管计算）或无服务器 API 端点（按需付费），使应用程序可以使用

**注意**：目录中的所有模型目前并不都支持微调和/或按需付费部署。请查看模型卡以了解模型的功能和限制。

## 提升 LLM 结果的方法

企业可以采用多种方法从 LLM 中获得所需的结果。在生产环境中部署 LLM 时，可以选择不同类型的模型，这些模型具有不同的训练程度、复杂性、成本和质量。

### 方法一：带上下文的提示工程

**核心思想**：在提示时提供足够的上下文，以确保获得所需的响应。

**零样本学习（Zero-shot）**：

即使只用一个简短的提示调用模型，它也能完成通用自然语言任务。例如，直接要求模型完成一个句子或回答一个问题。

**一次样本学习（One-shot）**：

在提示中包含一个示例，帮助模型理解期望的输出格式。

**少样本学习（Few-shot）**：

在提示中包含多个示例，使模型更准确地理解任务要求。

**适用场景**：
- 快速原型验证
- 预算有限的场景
- 不需要特定领域知识的通用任务

**优点**：最具成本效益的方法，无需额外训练
**缺点**：对于复杂的特定领域任务可能不够准确

### 方法二：检索增强生成（RAG）

**核心思想**：通过文档片段形式的外部数据增强提示，同时考虑提示长度限制。

**RAG 的工作原理**：

1. 用户提交查询
2. 系统从预定义数据源中检索相关文档片段（通常通过向量数据库如 Azure Vector Search）
3. 将检索到的相关信息作为上下文添加到用户提示中
4. LLM 基于增强后的提示生成回答

**RAG 解决的问题**：
- LLM 只能使用训练数据中的信息，无法获取训练后发生的事实
- 无法访问非公开信息（如公司内部数据）
- 通过外部数据源增强，减少幻觉风险

**适用场景**：
- 企业没有足够的数据、时间或资源来微调 LLM
- 需要提高特定工作负载的性能
- 需要减少幻觉（虚构内容的风险）
- 需要引用和追溯信息来源

### 方法三：微调模型

**核心思想**：利用迁移学习，在自有数据上进一步训练模型，使其更加精确并满足特定需求。

**微调过程**：

1. 准备训练示例：每个示例包含一个输入（提示）和对应的输出（完成）
2. 选择基础模型作为起点
3. 在训练数据上更新模型权重和偏差
4. 评估微调后的模型性能

**适用场景**：
- 需要使用能力较弱的微调模型（如嵌入模型），实现更具成本效益的解决方案
- 延迟要求高，无法使用很长的提示
- 拥有大量高质量数据和真实标签
- 有资源能够随时间推移保持数据更新

**与其他方法的对比**：

与少样本学习和 RAG 不同，微调会生成一个新的模型，并更新权重和偏差。

### 方法四：从零训练模型

**核心思想**：完全从头开始训练一个 LLM。

**注意**：这是最困难和最复杂的方法，需要：
- 大量数据
- 专业资源
- 适当的计算能力
- 长时间的训练周期

只有在企业拥有特定领域的用例和大量领域相关数据的情况下，才应考虑这种选项。

### 方法对比总结

| 方法 | 成本 | 效果 | 数据需求 | 适用场景 |
|------|------|------|----------|----------|
| 提示工程 | 低 | 中 | 无 | 快速原型、通用任务 |
| RAG | 中 | 较高 | 文档数据 | 需要引用来源、企业知识库 |
| 微调 | 高 | 高 | 标注数据 | 特定领域、低延迟需求 |
| 从零训练 | 极高 | 最高 | 海量数据 | 极端专业化场景 |

## 知识检查

**问题**：什么是提高 LLM 完成结果的好方法？

1. 带上下文的提示工程
2. RAG（检索增强生成）
3. 微调模型

**答案**：3

**解析**：如果你有时间、资源和高质量数据，微调是保持模型最新的更好选择。微调后的模型在特定任务上的性能通常优于其他方法。然而，如果你希望改进结果但缺乏时间和资源，首先考虑 RAG 可能更值得。RAG 不需要重新训练模型，只需提供相关的上下文数据即可显著提升结果质量。
