# Agent 可观测与评测 (Agent Observability & Evaluation)

> 中文简称：可观测与评测

> **一句话理解**: Agent 是非确定性系统——同一个输入每次跑法都不同，所以"看监控、追问题、做复盘"（JD 原话）的前提是先把每一次执行记录成可回放的轨迹。

---

## 1. Agent 可观测的特殊性（先讲差异再讲方案）

| 传统服务 | Agent 系统 |
|---------|-----------|
| 输出确定，回归测试可复现 | 同输入不同输出，需评测集+统计口径 |
| 调用链固定 | 轨迹动态：模型↔工具↔子 Agent 多跳嵌套 |
| 失败=异常/超时 | 失败=异常 **或"成功地做错事"**（幻觉、跑偏） |
| 成本是基础设施 | 每次调用都是真金白银的 token |

- 结论：Agent 可观测 = 传统 Trace 之上加一层 **语义层**（这一步是模型调用还是工具调用？花了多少 token？为什么失败？）。

---

## 2. 三支柱在 Agent 场景的落法

### 2.1 Trace（任务轨迹回放）

- 结构：一次会话 = 一条 trace，内嵌层级 span——**agent step → LLM call（模型/版本/token 数）→ tool call（工具名/参数/结果/耗时/成败）→ 子 Agent trace**；
- 关键能力：**轨迹回放**（一步步重看 Agent 当时看到了什么、决定做什么）——排障时比日志高效一个量级；
- 标准：OpenTelemetry 的 GenAI 语义约定（gen_ai.* 属性）正在统一字段口径，平台选型时优先兼容。

### 2.2 Metrics（JD 点名的四个度量）

| 指标 | 口径 | 平台动作 |
|------|------|---------|
| 任务成功率 | 按任务类型/租户分桶，区分"完成"与"完成且正确" | 失败归因看板 |
| 延迟 | 首 token、每步间隔、端到端 p50/p95 | 分位线告警而非均值 |
| 稳定性 | 崩溃率、重试率、死循环检出率 | 循环检测（同工具连续 N 次相似调用） |
| 成本 | token 成本 + 工具/沙箱计算成本 per 会话 | 预算配额与降级 |

### 2.3 Logs

- 结构化日志与 trace 用同一 trace-id 串联；工具执行的 stdout/stderr、沙箱事件（创建/回收/逃逸尝试）单独成流。

- 工具参照：[[11_模型运维/08_可观测性/17_Langfuse_LangSmith_对比|Langfuse vs LangSmith 对比]]、[[11_模型运维/08_可观测性/01_AI_可观测性_深入分析|AI 可观测性深入分析]]。

## 3. 失败原因分类学（"追问题"的方法论）

| 失败类 | 典型表现 | 诊断信号 | 平台对策 |
|--------|---------|---------|---------|
| 工具失败 | 超时、报错、返回空 | tool span 错误率 | 重试/降级/工具熔断 |
| 模型幻觉 | 编造事实、引用不存在内容 | 轨迹里无对应证据的断言 | RAG 增强、评测拦截 |
| 循环/跑偏 | 反复调用同一工具、目标漂移 | 步数超阈值、相似动作聚类 | 步数上限、反思节点、换 Checkpoint 回退 |
| 上下文溢出 | 截断、遗忘早期约束 | token 水位、遗忘型错误 | 压缩/外置 Memory |
| 环境故障 | 沙箱 OOM、网络被断 | 沙箱事件日志 | 池化重建、资源限额调优 |

- 面试表述："**先分类、再归因、后专项**——把失败聚成类，每类有 owner 和对策，成功率提升才有抓手。"

---

## 4. 评测体系（离线 + 在线）

- **离线评测**：评测集（任务+评判标准）+ 执行器 + 打分器（规则/LLM-as-judge/人工抽检）；每次改模型/prompt/工具版本，跑回归评测防退化；
- **在线评测**：生产流量抽样审计、用户反馈闭环（赞/踩/返工率）、A/B 灰度对比；
- **轨迹级评测**：不只看最终对错，评分中间步骤（该调的工具调了没、参数对不对）——这是 Agent 评测区别于普通 LLM 评测的关键；
- 深入：[[15_智能体/07_Agent评估/01_Agent_评估_指南|Agent 评估指南]]。

---

## 5. SRE 方法落地（要求 3"可观测性/SRE"）

- SLI/SLO：把"会话成功率 ≥ 95%""p95 端到端延迟 ≤ X"写成 SLO，配**错误预算**决定发版节奏；
- 告警分级：预算烧穿（趋势）≠ 单点错误（噪音），只对"用户可感知"的指标呼；
- 无责复盘：每次事故产出"失败分类 + 追踪缺口"两条输入，反哺可观测建设。

---

## 6. 高频面试题速练

1. **"接手一个成功率 70% 的 Agent 平台，第一步做什么？"** —— 先建轨迹追踪与失败分类（没有归因就没有优化），把 30% 失败聚成 Top3 类，再按类对症（工具失败→熔断重试；跑偏→上限+回退），每类措施用评测集验证。
2. **"怎么衡量一次改动有没有让 Agent 变好？"** —— 离线回归评测集 + 线上 A/B（成功率/延迟/成本三线同看），防止单指标优化伤害其他指标。
3. **"LLM 调用的延迟优化空间在哪？"** —— 路由分层（小模型干简单步）、并行工具调用、流式提前返回、KV 缓存命中（prompt 前缀稳定）、 speculation（略讲）——注意区分模型侧与平台侧手段。
