# ML 系统设计 (ML Systems Design)

> 中文简称：ML 系统设计

## 1. ML 系统 vs 传统软件系统

### 1.1 核心差异

```
传统软件: 代码 + 数据 → 答案 (确定性)
ML 系统:  代码 + 数据 → 模型 → 预测 (概率性)

ML 系统特有挑战:
- 数据依赖: 模型质量 = 数据质量
- 反馈循环: 预测影响未来数据
- 分布漂移: 生产数据 ≠ 训练数据
- 评估困难: 离线指标 ≠ 在线效果
- 版本管理: 数据/特征/模型/代码四维版本
```

### 1.2 ML 系统架构全景

├─────────────────────────────────────────────────────────┤

## 2. 特征存储 (Feature Store)

### 2.1 为什么需要特征存储？

```
问题:
- 训练和推理使用不同代码计算特征 → 训练-服务偏差
- 多个团队重复计算相同特征 → 资源浪费
- 特征计算逻辑分散 → 难以维护和复用
- 实时特征 vs 离线特征不一致

解决: 统一的特征存储
- 单一事实来源 (Single Source of Truth)
- 训练/推理共享特征定义
- 离线 (批量) + 在线 (实时) 双模式
```

### 2.2 特征存储架构

```python
# 特征存储核心组件:
# 1. 特征定义 (Feature Definition)
# 2. 离线存储 (Offline Store) — 训练用
# 3. 在线存储 (Online Store) — 推理用
# 4. 特征注册 (Feature Registry) — 元数据
# 5. 数据管道 (Pipeline) — 计算和同步

# Feast 示例 (开源特征存储):
from feast import FeatureStore, Entity, FeatureView, Field
from feast.types import Float32, String
from datetime import timedelta

# 定义实体
user = Entity(name="user_id", join_keys=["user_id"])

# 定义特征视图
user_features = FeatureView(
    name="user_activity",
    entities=[user],
    ttl=timedelta(days=7),
    schema=[
        Field(name="click_count_7d", dtype=Float32),
        Field(name="avg_session_time", dtype=Float32),
        Field(name="last_purchase_category", dtype=String),
    ],
    source=batch_source,  # 离线数据源
)

# 训练时: 获取历史特征 (point-in-time correct)
training_df = store.get_historical_features(
    entity_df=training_entities,
    features=["user_activity:click_count_7d"]
).to_df()

# 推理时: 获取最新特征 (低延迟)
online_features = store.get_online_features(
    features=["user_activity:click_count_7d"],
    entity_rows=[{"user_id": "user_123"}]
).to_dict()
```

## 4. AB 测试框架

### 4.1 ML 系统的 AB 测试

```python
# ML AB 测试 vs 传统 AB 测试:
# - 需要更大样本量 (模型效果差异小)
# - 需要考虑网络效应 (推荐系统)
# - 需要长期指标 (用户留存)
# - 需要分层实验 (避免流量冲突)

class MLExperiment:
    """ML 系统 AB 测试框架"""
    
    def __init__(self, name, traffic_split=0.5):
        self.name = name
        self.traffic_split = traffic_split
        self.metrics = {
            'primary': None,      # 主要指标
            'guardrail': [],      # 护栏指标 (不能恶化)
            'secondary': [],      # 次要指标
        }
    
    def assign_group(self, user_id):
        """确定性分组 (同一用户始终在同一组)"""
        import hashlib
        hash_val = int(hashlib.md5(
            f"{self.name}:{user_id}".encode()
        ).hexdigest(), 16)
        return 'treatment' if (hash_val % 1000) / 1000 < self.traffic_split else 'control'
    
    def check_significance(self, control_metric, treatment_metric, alpha=0.05):
        """统计显著性检验"""
        from scipy import stats
        t_stat, p_value = stats.ttest_ind(control_metric, treatment_metric)
        return {
            'p_value': p_value,
            'significant': p_value < alpha,
            'lift': (treatment_metric.mean() - control_metric.mean()) / control_metric.mean()
        }
```

## 5. 数据管道设计

### 5.1 训练数据管道

```
原始数据 → 清洗 → 特征工程 → 采样 → 训练集
    │                                    │
    ▼                                    ▼
数据质量检查                        数据版本快照
(缺失/异常/重复)                    (DVC/LakeFS)

关键原则:
1. 可复现: 相同输入 → 相同输出
2. 时间正确: 不使用未来数据 (point-in-time)
3. 幂等性: 重复执行结果一致
4. 监控: 数据质量指标持续追踪
```

### 5.2 推理数据管道

```
请求到达 → 特征获取 → 模型推理 → 后处理 → 响应
    │           │          │          │
    ▼           ▼          ▼          ▼
  日志      特征存储   模型服务    业务规则
  记录      (低延迟)   (GPU/CPU)   (过滤/排序)

延迟预算 (推荐系统示例):
- 总预算: 100ms
- 特征获取: 20ms (Redis)
- 模型推理: 50ms (GPU batch)
- 后处理: 10ms
- 网络: 20ms
```

## 6. 模型服务架构

### 6.1 服务模式

| 模式 | 延迟 | 适用场景 | 示例 |
|------|------|----------|------|
| 实时推理 | <100ms | 推荐/搜索/广告 | 在线服务 |
| 近实时 | 100ms-1s | 风控/审核 | 流式处理 |
| 批量推理 | 分钟-小时 | 报表/离线分析 | Spark/批处理 |
| 边缘推理 | <10ms | IoT/手机 | 端侧模型 |

# 模型服务关键设计:

class ModelServer:
    def predict(self, request):
        try:
            # 主模型
            return self.primary_model.predict(request)
        except TimeoutError:
            # 降级: 使用轻量模型

## 7. 监控与可观测性

### 7.1 ML 监控维度

| 维度 | 指标 | 告警阈值 |
|------|------|----------|
| 数据质量 | 缺失率/异常率/分布偏移 | >5% 偏移 |
| 特征质量 | 特征覆盖率/值域/相关性 | 覆盖率 <95% |
| 模型性能 | 准确率/AUC/延迟 | 下降 >2% |
| 预测分布 | 预测值分布/置信度分布 | KL 散度 >0.1 |
| 系统健康 | QPS/延迟/错误率/GPU 利用率 | P99 >200ms |
| 业务指标 | 转化率/收入/用户满意度 | 下降 >1% |

### 7.2 数据漂移监控

```python
from scipy import stats

class DriftMonitor:
    """监控特征/预测分布漂移"""
    
    def __init__(self, reference_stats, threshold=0.05):
        self.reference = reference_stats
        self.threshold = threshold
    
    def check(self, current_data):
        alerts = []
        for feature, ref_dist in self.reference.items():
            current_dist = current_data[feature]
            
            # KS 检验
            ks_stat, p_value = stats.ks_2samp(ref_dist, current_dist)
            if p_value < self.threshold:
                alerts.append({
                    'feature': feature,
                    'ks_stat': ks_stat,
                    'p_value': p_value,
                    'severity': 'high' if p_value < 0.01 else 'medium'
                })
        
        return alerts
```

### 8.1 ML 系统设计步骤

```
1. 问题定义 (2min)

   - 关键特征设计
   - 实时 vs 离线特征
   - 特征存储方案

4. 模型选择 (3min)
   - 基线模型
   - 候选模型
   - 训练策略

5. 服务架构 (3min)
   - 推理服务设计
   - 延迟优化

6. 评估与监控 (3min)
   - 离线评估
   - 在线 AB 测试
   - 监控与告警

7. 迭代优化 (2min)
   - 反馈循环
   - 持续改进
   - 扩展性考虑
```
