## 1. 趋势：2026 为什么是黄金窗口

### 1.1 三个核心驱动

| 驱动 | 数据 | 含义 |
|---|---|---|
| **信创政策** | 2027 年央国企关键系统替代率 70%+ | 不做信创 = 不合规 |
| **数据合规** | 《数据安全法》《个保法》要求数据本地化 | 上公有云 = 违法风险 |
| **国产 LLM** | DeepSeek V3 = GPT-4 水平 | 技术不再有短板 |

### 1.2 央国企 AI 预算

- **2024 年**：央国企 AI 投入同比增长 **+85%**（信通院）
- **2025 年**：100+ 央企已设立"AI 专项预算"
- **2026 年**：预算集中释放期（**5 年内最佳窗口**）

### 1.3 私有化 vs 公有云的关键差异

| 维度 | 公有云 API | 私有化部署 |
|---|---|---|
| 数据位置 | 云厂商服务器 | **客户机房** |
| 启动速度 | 1 天 | 4-12 周 |
| 单次成本 | 低 | 高（首期） |
| 长期成本 | 高（持续付费） | 低（边际成本） |
| 定制化 | 弱 | **强** |
| 合规性 | 受限 | **满足等保三级** |
| 适合场景 | 互联网/中小企业 | **政企/金融/医疗** |

## 2. 决策：什么时候必须私有化

### 2.1 三个核心判断标准

✅ **必须私有化**（满足任一）：

1. **数据敏感**：客户/员工/财务/医疗数据
2. **合规要求**：等保三级、信创目录、行业监管
3. **定制需求**：要深度对接内部系统

❌ **不需要私有化**（满足全部）：

1. 数据不敏感（公开信息）
2. 无合规要求
3. 通用功能即可满足

### 2.2 决策树

```
开始
  │
  ├─ 数据敏感？
  │   ├─ 是 → 私有化 ✅
  │   └─ 否 ↓
  │
  ├─ 合规要求？
  │   ├─ 是 → 私有化 ✅
  │   └─ 否 ↓
  │
  ├─ 深度定制？
  │   ├─ 是 → 私有化 ✅
  │   └─ 否 ↓
  │
  └─ 公有云 API 即可
```

### 2.3 真实的"半私有化"形态

很多客户实际是"混合模式"：
- **核心数据**（客户信息、财务）：私有化
- **通用功能**（写作、翻译）：公有云 API
- **不敏感文档**：公有云 + RAG

> **最佳实践**：**80% 私有化 + 20% 公有云**，既安全又灵活。

## 3. 架构：典型部署方案

### 3.1 标准架构图

```
┌──────────────────────────────────────────────┐
│ 用户层：浏览器 / 桌面 / 移动端 / 飞书 / 钉钉   │
└──────────────────────────────────────────────┘
                    ↓ HTTPS
┌──────────────────────────────────────────────┐
│ 接入层：Nginx + API Gateway + WAF            │
└──────────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────┐
│ 应用层：Open WebUI（前端 + 业务逻辑）          │
│ - 用户/权限管理                               │
│ - 对话/工作区/插件                            │
│ - RAG 引擎（文档解析 + 向量化）                │
│ - 审计日志 / 数据脱敏                          │
└──────────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────┐
│ AI 层：LLM 推理服务（Ollama / vLLM）          │
│ - DeepSeek V3 70B（主力模型）                │
│ - Qwen3 72B（多语言 / 备选）                 │
│ - GLM4（中文强）                             │
│ - Embedding：BGE-M3 / M3E                   │
└──────────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────┐
│ 数据层：                                      │
│ - 文档库：MinIO / NAS（原始文件）              │
│ - 向量库：ChromaDB / Milvus                  │
│ - 关系库：PostgreSQL（用户/对话/权限）         │
│ - 缓存：Redis                                │
└──────────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────────┐

└──────────────────────────────────────────────┘
```

## 4. 选型：模型 / 硬件 / 软件栈

### 4.1 LLM 选型

| 模型 | 优势 | 劣势 | 适用场景 |
|---|---|---|---|
| **DeepSeek V3 70B** | 性能强 / 开源 / 价格低 | 英文略弱 | 通用首选 |
| **Qwen3 72B** | 多语言 / 阿里系生态 | 中文略弱于 GLM | 国际化场景 |
| **GLM4** | 中文强 / 智谱生态 | 商业授权 | 中文政企 |
| **豆包** | 字节系 / 多模态强 | 私有化部署难 | 多模态场景 |

**推荐组合**：
- **主力**：DeepSeek V3 70B
- **备选**：Qwen3 72B / GLM4
- **Embedding**：BGE-M3

### 4.2 硬件选型

**预算敏感**：
- 1×A100 80G（试点）—— 30 万
- 4×A100 80G（标准）—— 100 万

**信创要求**：
- 4×昇腾 910B（标准）—— 80-120 万
- 8×昇腾 910B（集群）—— 200 万

**顶级配置**：
- 8×H100（大型）—— 300 万
- 16×H100（超大型）—— 600 万+

### 4.3 软件栈选型

| 层级 | 推荐 | 备选 |
|---|---|---|
| 推理框架 | **Ollama** | vLLM / TGI |
| 前端 | **Open WebUI** | 自研 |
| 向量库 | **ChromaDB** (<100w) | Milvus (>100w) |
| 关系库 | **PostgreSQL** | OceanBase |
| 文档解析 | **PaddleOCR** + 自研 | Unstructured |
| 监控 | **Prometheus + Grafana** | 夜莺 |
| 鉴权 | **Keycloak** | Authing |

> **核心原则**：**80% 用成熟开源 + 20% 自研定制**。

用户使用
    ↓

    ↓

## 8. 误区：10 个常见踩坑

### ❌ 1. 模型越大越好
- **真相**：70B 模型在 90% 场景已够用
- **建议**：先 70B，不够再上 200B+

### ❌ 2. 一步到位买顶级配置
- **真相**：先试点验证场景，再扩规模
- **建议**：先 1 卡 → 4 卡 → 8 卡渐进

### ❌ 3. 用 ChatGPT 同款 Prompt
- **真相**：政企场景需要专业 Prompt
- **建议**：领域知识 + 业务术语 + Few-shot

### ❌ 4. 完全离线才能安全
- **真相**：混合模式（核心本地 + 通用云端）更优
- **建议**：分级分类，敏感数据本地化

### ❌ 5. RAG 解决一切
- **真相**：复杂推理仍需微调
- **建议**：RAG + SFT 双管齐下

### ❌ 6. 忽视文档解析质量
- **真相**：政企文档复杂（PDF 扫描件、表格、图表）
- **建议**：专业 OCR + 版面分析

### ❌ 7. 等保通过就完事
- **真相**：等保是底线，不是全部
- **建议**：数据分级 + 访问审计 + 行为分析

### ❌ 8. 自己训练模型
- **真相**：90% 场景开源模型已够用
- **建议**：能微调就别预训练

### ❌ 9. 忽视用户培训
- **真相**：用户不会用 = 项目失败
- **建议**：分角色培训 + 提示词大赛

### ❌ 10. 没有数据飞轮设计
- **真相**：上线只是开始
- **建议**：从 Day 1 设计反馈机制
