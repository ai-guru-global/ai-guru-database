# AI 应用实战：从提示词到智能体的入门指南

> 中文简称：AI 应用实战：从提示词到智能体的入门指南

> **一句话理解**: 学了原理之后，普通人最该掌握的是"怎么用好 AI"——管理 AI 就是管理学：用 BROKE 框架（背景+角色+目标+关键结果+例子）下指令、用少样本/思维链/指定格式做约束、用上下文工程注入知识、用 ReAct 智能体把"聊天"升级为"办事"。

> 本文聚焦零基础视角的应用与提示词入门。工具完整目录见 [[AI_Tools_Practical_Guide]]，提示词深度技术见 [[Prompt_Engineering]]、[[Context_Engineering_Guide]]。

## 1. 主流 AI 工具速览（初学者版）

对普通人来说，不需要通过编程使用 AI，主流工具大多像聊天软件：你发一句话（提示词），它回一段话/一张图/一段代码。把它们用好，你就像拥有了一个由不同专长助手组成的私人顾问团。

### 1.1 三大国际工具

| 工具 | 出身 | 初学者认知要点 |
| :--- | :--- | :--- |
| **ChatGPT** | OpenAI | AI 时代的开启者，全能型助手，产品生态与工具链完整 |
| **Claude** | Anthropic | 写作与长文处理表现稳定，风格相对稳健 |
| **Gemini** | Google | 多模态能力强，与 Google Workspace/搜索整合紧密 |

### 1.2 国产工具的本土优势

国产 AI 在中文理解、本土落地、性价比上表现突出，且数据不出境（合规安全）。除了"不用翻墙"，还有独特优势：懂中文梗、懂中国国情（写公文/请假条/小红书文案味道更正）、合规安全。

| 工具 | 定位 | 最擅长 |
| :--- | :--- | :--- |
| **阿里通义千问 Qwen** | 开源之王 | 极强的中文写作能力（非常通顺）+ 图片识别（Qwen-VL）国内顶尖 |
| **DeepSeek** | 极客之光 | 通用 V3 + 推理 R1，在数学/代码/逻辑推理口碑好，性价比常被认为高 |
| **Kimi（月之暗面）** | 长文专家 | 能读很长的材料（几十份财报/合同/论文不晕） |
| **百度文心** | 知识型 | 连接知识图谱和搜索，事实性中国历史/百科较准 |
| **字节豆包** | C 端路线 | 语音交互好，AI 角色（陪聊/英语陪练）日活高 |

> **组合建议**：用 DeepSeek 写代码，用 Kimi 读报告，用通义写宣发文案——按场景组合而非"只用一个"。完整工具生态见 [[AI_Tools_Practical_Guide]]。

## 2. 提示词工程入门：BROKE 黄金框架

### 2.1 为什么 CEO 的指令最有效？

很多人用 AI 像用百度，只输几个关键字："日本市场调研"。这好比路过员工工位丢一句"做个调研"就走了——员工（AI）绝对一脸懵逼，做出来的东西肯定不行。大老板下指令通常非常清晰，因为潜意识里用了 **BROKE 模型**。

### 2.2 BROKE 拆解

| 字母 | 含义 | 作用 | 示例（CEO 口吻） |
| :--- | :--- | :--- | :--- |
| **B**ackground | 背景 | 前因后果，给 AI 喂料 | "咱们公司下个季度要进军日本市场..." |
| **R**ole | 角色 | 指定人设，激活特定知识库 | "你作为咱们的首席市场官..." |
| **O**bjectives | 目标 | 要干什么 | "你要给我出一份市场调研报告..." |
| **K**ey Result | 关键结果 | 交付标准 | "分析竞品价格策略，用数据说话，给我 3 个可行定价建议，做成 PPT 大纲" |
| **E**xamples | 例子（可选） | 打个样 | "风格参考去年做的北美市场报告" |

> **刻在脑子里的模板**：[背景] 我最近... / [角色] 请你扮演... / [目标] 帮我做... / [关键结果] 要求风格...格式...字数...

按这个框架系统输入，AI 在复杂任务上的 **一次命中率、回答结构可读性与最终可控性** 将得到可观测的显著提升。

### 2.3 BROKE 为什么管用？背后的科学

大模型本质在算一个条件概率："给定你说的这段话，下一个字最可能是什么？"提示词不是"命令"，而是 **条件信号**——它改变了模型"要翻哪本书"的方向：

- **加角色**（"你是资深工程师"）= 告诉 AI"在专家文献那堆书里找答案"，输出自然严谨专业。
- **加背景** = 让 AI 先翻到"相关章节"，而非全书翻一遍。
- **加示例** = 给 AI 一份"样板"，让它知道交付物长什么样。

> BROKE 是一套"调台"工具箱：每加一个元素，就把"全宇宙的可能回答"缩窄到你真正想要的那个角落。

### 2.4 提示词的失效边界（重要）

> 提示词工程不是魔法。如果任务涉及 **实时外部数据**（今天某只股票价格）、**精确复杂计算**（大数相乘）、**严格的流程约束**（多重条件语句），无论运用多少高级修辞，单凭 BROKE 仍无法阻止 AI 产生严重"幻觉"。这些情况请立刻转向 **工具调用（Function Calling）** 或 **检索增强生成（RAG）** 等硬性工程手段。

深度提示词技术见 [[Prompt_Engineering]]、[[Context_Engineering_Guide]]。

## 3. 常用提示词模式：三个"咒语"

### 3.1 少样本提示（Few-Shot）：照猫画虎

有时很难用语言描述清楚你要什么 **风格**（"赛博朋克且带点忧伤的文字"）。最简单的办法是 **直接给例子**：

```
请模仿下面的例子，把成语翻译成 Emoji。
例子1：对牛弹琴 -> 🧑🏼🎸🐄
例子2：画蛇添足 -> 🐍🦵❌
任务：拔苗助长 -> ?
```

AI 看了例子瞬间 get 到你的点。这招在数据清洗、风格模仿时极其好用。

### 3.2 链式思考（Chain of Thought）：逼它把题算对

问 AI 复杂数学题或逻辑题，直接问答案它经常瞎蒙。加上一句咒语：

> **"请一步一步地思考（Let's think step by step）。"**

这就像老师让学生写"解题步骤"并检查中间过程，错误更容易被及时发现。在不少推理任务里这类指令通常会让答案更稳定，但不保证每次都更好，仍需结果核验。思维链进阶见 [[AI_Reasoning_Models_Guide]]。

### 3.3 指定格式：不要让它乱发挥

从今天起养成好习惯：**永远告诉 AI 你要的输出格式**。

| 场景 | 咒语 |
| :--- | :--- |
| 做对比 | "用 Markdown 表格输出" |
| 程序员 | "用 JSON 格式" |
| 做总结 | "用 1, 2, 3 清单体" |
| 复制粘贴 | "用代码块" |

> 管理新员工也是这样：给模板（Few-Shot）→ 让他把逻辑讲一遍（CoT）→ 规定汇报格式（Format）。**管理 AI，其实就是管理学。**

## 4. 上下文工程：从"这一次提问"到"整个背景"

### 4.1 同样的问题，不同的上下文，完全不同的答案

问"推荐一部电影"，AI 给《肖申克的救赎》之类普通回答。但如果你告诉 AI：我是医生每天很疲惫、喜欢烧脑片、不喜欢暴力、最近看了《盗梦空间》、只有 3 小时——AI 给出的推荐就完全不同（《心灵捕手》《时间规划局》）。**提示词只是"推荐一部电影"，但上下文完全不同，答案也不同。**

> **上下文（Context）= AI 做决定时能看到的所有信息**：系统提示、用户信息、之前的对话记录、相关文档/知识库、任务说明、当前这句话。当前这一句话其实占比很小，AI 真正看重的是整个背景信息。

### 4.2 上下文的三个层次

| 层次 | 内容 | 实现方式 | 效果 |
| :--- | :--- | :--- | :--- |
| **第一层：对话上下文** | 之前的对话记录 | 所有 AI 工具都支持 | AI 理解"再乘以 2"的"再"指上一结果 |
| **第二层：知识库上下文** | 公司手册等私有知识 | RAG（向量数据库 + 检索） | 答案从"不知道/瞎说"变成"精确回答" |
| **第三层：系统集成上下文** | 实时访问外部系统 | MCP（Model Context Protocol） | AI 从"知道"变成"能看到"实时信息 |

### 4.3 提示词工程 vs 上下文工程

| 维度 | 提示词工程 | 上下文工程 |
| :--- | :--- | :--- |
| 优化对象 | 这一次提问 | 整个对话背景 |
| 技巧 | 使用更好的词 | 注入知识库/工具 |
| 学习曲线 | 容易 | 中等 |
| 可扩展性 | 有上限 | 受窗口、成本、检索质量限制 |
| 适用 | 快速问答 | 专业系统、知识密集型任务 |

> **关键洞察**：上下文 > 提示词。在知识密集型任务里，仅优化提示词通常不够。详见 [[Context_Engineering_Guide]]、[[Context_Engineering_Patterns]]。

## 5. AI 实战应用场景：10 个锦囊

> 这里没有"展示 AI 的能力"，只有"解决你的问题"。把这一节当作"AI 场景字典"，遇到什么事翻到那页，复制提示词，解决问题。

### 5.1 五大维度

| 维度 | 典型场景 |
| :--- | :--- |
| **职场提效**（24 小时私人助理） | 写周报、会议纪要整理、邮件润色 |
| **学习导师**（因材施教的私教） | 英语口语陪练、考试复习规划、论文辅导 |
| **编程辅助**（不懂代码也能开发） | Excel 公式生成、自动化脚本、简单网页制作 |
| **生活助手**（把琐事交给 AI） | 旅行规划、食谱生成、情感咨询 |
| **非技术行业** | 文学新闻、法律、医疗、教育、金融 |

### 5.2 非技术行业的深度反思

AI 不是只有程序员能用。每一行都在悄悄用 AI 重新定义工作方式，但每个应用都伴随深刻的伦理与就业反思：

| 行业 | AI 在做什么 | 深层问题 |
| :--- | :--- | :--- |
| **文学与新闻** | 虚拟编辑（草稿/润色/标题）、翻译民主化、新闻自动化（美联社 2014 起每季产出约 3700 篇财报） | 创意工作的"前期痛苦"被跳过，可能失去深度思考机会；多媒体用同一 AI 导致内容多样性消失 |
| **法律** | 合同审查（从 2-3 小时到秒速）、案例检索、文书生成 | AI 可能编造案例号（严重伦理问题）；判断权责任必须在律师手里 |
| **医疗** | 辅助诊断（影像模式比对）、药物研发（AlphaFold）、病程预测 | 对"极罕见病例"会"非常自信但完全错误"；模型概率 ≠ 确定事实 |
| **教育** | 个性化学习路径、智能批改、AI 辅导 | 过度个性化损害同伴学习；AI 批改主观题肤浅，可能用机器学习训练人类思想 |
| **金融** | 风控反欺诈、量化交易、智能客服/投顾 | 决策黑箱（用户不知为何被拒）；算法同质化加剧市场波动；AI 建议亏钱谁负责？ |

> **三波冲击**：第一波落重复性工作（翻译、批改、初筛、数据整理）；第二波落需要判断力和创意的工作（医生、律师、编辑、设计师）；第三波落"最人性的东西"（同理心、伦理判断、创意突破、领导力）——目前 AI 还搞不定，但"目前"是关键词。

详见 [[AI_Ethics_And_Future_For_Beginners]]。

## 6. AI 智能体：从"聊天"到"办事"

### 6.1 智能体 vs 聊天机器人

目前的 Chatbot 有两个大问题：(1) **幻觉**——不知道的瞎编，无法调用工具验证；(2) **行动力缺失**——只能输出文字，无法改变现实世界。**智能体（Agent）** 尝试缓解这两个问题：通过接入工具和反馈闭环，让系统不只输出文字，也能查证信息、执行受控动作。

> 智能体 = 能够 **规划任务、调用工具、观察结果、根据反馈调整行为** 的 AI 系统。它具备四个关键特征：感知、规划、行动、记忆。

**现实案例（旅行规划）**：你说"帮我订下周去三亚的机票和酒店，预算 5000"。

- 普通 Chatbot："你可以去携程或去哪儿网看看..."
- 智能体：(1) 调日历 API 确认日期 → (2) 调天气 API 查天气 → (3) 调机票 API 发现直飞 3200/转机 1800 → (4) 调酒店 API 列亚龙湾选项 → (5) 按预算选转机+三星酒店 → (6) 反馈"已找到方案，总价 4800，需要我下单吗？"

> **关键差异**：智能体不只是给建议，而是 **在授权边界内调用工具、比较选项，并把高风险决策交给人确认**。完整介绍见 [[Microsoft_AI_Agents_L01_Intro]]、[[Agentic_Design_Patterns_AndrewNg]]。

### 6.2 ReAct 模式：思考—行动—观察

ReAct（Reasoning + Acting）是智能体最经典的思考模式：每一步行动前先推理（Thought），行动（Action）后再观察结果（Observation），三者形成循环直到得出最终答案。

```
任务："周杰伦现在的年龄是多少？他的年龄乘以 2 是多少？"

智能体（ReAct）的做法：
1. 思考：需要先查出生日期，再根据今天日期计算
2. 行动：调用搜索工具 Search("周杰伦 出生日期")
3. 观察：出生于 1979 年 1 月 18 日
4. 思考：现在需要当前日期
5. 行动：调用系统时间 GetTime()
6. 观察：2026-02-13
7. 思考：已过生日，年龄 47
8. 行动：调用计算器 Calculate(47 * 2)
9. 观察：94
10. 最终回答：47 岁，乘以 2 是 94
```

> 智能体不靠"猜"，它靠"查"和"算"。规划能力包括 **任务分解**（把大任务拆成子任务）和 **反思（Reflection）**（做错了根据报错提出修正方案再试）。详见 [[Hello_Agents_L06_Frameworks_AutoGen_LangGraph]]。

### 6.3 多智能体协作

一个诸葛亮不如三个臭皮匠。组建智能体团队（如软件开发）：产品经理智能体写需求→架构师智能体设计结构→工程师智能体写代码→测试智能体找 Bug 扔回工程师。用户只需说"帮我写个贪吃蛇游戏"，几个智能体在后台互相协作交付可运行的游戏。**MetaGPT**、**AutoGen** 是这种多智能体框架的代表。

### 6.4 智能体安全：从"能跑"到"可上线"

很多 Demo 看起来很惊艳，但离真实业务上线还差至关重要的 **工程化与安全加固**。当企业基于 **MCP** 等标准协议把内部系统大批量接入智能体后，攻击面会指数级增加（黑客可能在网页藏恶意指令，诱骗智能体调用工具执行删库——"链式工具利用"）。工业级部署必须满足三大基线：

| 基线 | 内容 |
| :--- | :--- |
| **1. 评测体系（Evals）** | 端到端测试集，评测成功率、平均耗时、Token 成本；注入对抗性测试（Red-teaming）验证是否被越狱骗走权限 |
| **2. 行动边界（Guardrails）** | 工具沙盒化与最小权限（API 密钥只给只读）；高危动作（转账、写库、发公开邮件、执行系统命令）必须 Human-in-the-loop 二次批准 |
| **3. 审计与可观测性** | 像监控微服务一样监控智能体，记录时间戳、Trace ID、意图识别、完整输入输出参数、原始 API 响应耗时，精准回放"案发现场" |

> 没有这三件套，智能体很容易停留在"演示可用、生产翻车"的隐患阶段。详见 [[Agent_Safety_Evaluation_for_dummy]]、[[Microsoft_AI_Agents_L06_Trustworthy_Agents]]。

## 7. 给初学者的行动建议

1. **拒绝"一句话提示词"**：把 BROKE 模板刻在脑子里，复杂任务一次命中率显著提升。
2. **永远指定输出格式**：表格/JSON/清单体/代码块——这一招省下大量返工。
3. **失效边界要清醒**：实时数据、精确计算、流程约束 → 立刻转 RAG/工具调用，别指望提示词修辞。
4. **从聊天升级到办事**：当你发现"光输出文字不够"，就到了引入智能体（ReAct + 工具 + 审批）的时候。
5. **按场景组合工具**：没有一个工具是全能的，按"写代码/读长文/写文案"组合国产与国际工具。
