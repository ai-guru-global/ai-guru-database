# EU AI Act / 欧盟 AI 法案

> 中文简称：EU AI Act / 欧盟 AI 法案实施

> **一句话理解**:EU AI Act 是全球首部综合性 AI 法规——按风险分级管理(不可接受 / 高 / 有限 / 极小),通用 AI 模型(GPAI)有透明度义务,高风险 AI 需通过 CE 认证、风险管理、数据治理、人工监督,违规最高罚 7% 全球营收。是 2025-2026 企业 AI 落地必过的"合规关"。

---

## 一、EU AI Act 时间线

| 阶段 | 时间 | 内容 |
|---|---|---|
| **生效** | 2024-08-01 | 正式法律生效 |
| **禁止类条款** | 2025-02-02 | 不可接受风险类 |
| **GPAI 规则** | 2025-08-02 | 通用 AI 模型规则 |
| **完整义务** | 2026-08-02 | 高风险 AI 全部义务 |
| **完整适用** | 2027-08-02 | 全部条款适用 |

## 三、风险分级详解

### 3.1 不可接受风险(禁止)

- 操纵行为(潜意识)
- 剥削脆弱群体
- 社交评分
- 实时远程生物识别(警察)

### 3.2 高风险(严格监管)

- 关键基础设施
- 教育 / 就业
- 执法
- 医疗
- 边境管理
- 司法
- 民主进程
- **AI 在产品中**(玩具 / 医疗器械 / 玩具)

### 3.3 有限风险(透明度)

- **聊天机器人**:必须告知是 AI
- **深度伪造**:必须标注
- **情感识别**:必须告知
- **生物分类**:必须告知

### 3.4 极小风险(无约束)

- 垃圾邮件过滤
- 推荐系统
- 游戏 AI
- 库存管理

## 四、通用 AI 模型(GPAI)义务

### 4.1 所有 GPAI

- **技术文档**
- **下游使用说明**
- **欧盟版权法合规**(训练数据透明)

### 4.2 系统性风险 GPAI(> 10^25 FLOPs 训练)

- **模型评估 / 红色团队**
- **系统性风险评估**
- **事故报告**
- **网络安全保护**
- **能源效率报告**

### 4.3 被指定的 GPAI

- GPT-4 / GPT-5
- Claude 3.7 / Opus 4.5
- Gemini 2.0 / 2.5
- Llama 3 / 4
- Mistral Large 2 / 3
- Qwen 2.5 / 3
- DeepSeek V3 / R1

---

## 五、高风险 AI 义务

### 5.1 完整义务

1. **风险管理系统**(全生命周期)
2. **数据治理**(训练 / 验证 / 测试数据)
3. **技术文档**(Annex IV)
4. **事件日志**(自动 / 可追溯)
5. **透明度**(向部署者提供)
6. **人工监督**(有意义、有效)
7. **准确性 / 鲁棒性 / 网络安全**
8. **质量管理系统(QMS)**
9. **CE 标记**(认证合规)
10. **EU 数据库注册**
11. **事故报告**(严重事件)

### 5.2 实施流程

```
风险评估 → 数据治理 → 模型设计 → 训练
   ↓
技术文档
   ↓
CE 认证(公告机构)
   ↓
EU 数据库注册
   ↓
上市 / 部署
   ↓
持续监测
   ↓
事件报告
```

## 六、处罚

| 违规类型 | 处罚 |
|---|---|
| 禁止类(不可接受风险) | 最高 €35M 或 7% 全球营收 |
| 高风险义务违反 | 最高 €15M 或 3% 全球营收 |
| 错误信息 | 最高 €7.5M 或 1% 全球营收 |
| GPAI 义务违反 | 最高 €15M 或 3% 全球营收 |

**以高者为准**

## 七、合规实施指南

### 7.1 风险评估

```python
def assess_risk(ai_system):
    if ai_system in PROHIBITED_USE_CASES:
        return "UNACCEPTABLE"  # 禁止
    if ai_system in HIGH_RISK_USE_CASES:
        return "HIGH"  # 高风险,完整义务
    if ai_system in TRANSPARENCY_OBLIGATIONS:
        return "LIMITED"  # 有限,透明度义务
    return "MINIMAL"  # 极小
```

### 7.2 透明度要求

```python
def transparency_compliance(ai_system):
    if ai_system.is_chatbot:
        # 必须告知用户是 AI
        return "I am an AI assistant."
    if ai_system.generates_content:
        # 必须标注
        return mark_as_ai_generated(content)
    if ai_system.emotion_recognition:
        # 必须告知
        return "This system analyzes emotions."
```

## 八、对企业的影响

### 8.1 立即行动(2024-2025)

1. **AI 资产清单**:所有 AI 系统登记
2. **风险分类**:每系统按 4 类评估
3. **透明度**:ChatBot / Deepfake 等立即合规
4. **文档化**:技术文档、QMS 准备

### 8.2 中期(2025-2026)

1. **高风险 AI 认证**:CE 标记流程
2. **GPAI 报告**:OpenAI / Anthropic / Google 已开始
3. **供应商管理**:上游 GPAI 提供商合规
4. **员工培训**:AI 合规官 / Responsible AI 团队

### 8.3 长期(2026-2027)

1. **持续合规**:QMS 持续运行
2. **国际对接**:EU AI Act 与 US EO 14110 / 中国生成式 AI 法规协调
3. **监管沙盒**:在 EU 测试新 AI

## 十、生产最佳实践

1. **建立 AI Governance 委员会**:跨部门合规。
2. **风险评估自动化**:CI/CD 集成风险检测。
3. **GPAI 供应商审计**:OpenAI / Anthropic 合规状态检查。
4. **文档自动化**:技术文档 / 数据治理自动生成。
5. **透明度 UI 设计**:ChatBot 默认显示"我是 AI"。
6. **事故响应流程**:24-72 小时报告。
7. **Red Team 评估**:高风险 AI 必做。
8. **QMS 认证**:ISO/IEC 42001 准备。
9. **员工培训**:每年 AI 合规培训。
10. **国际合规团队**:EU + US + China 三地。
