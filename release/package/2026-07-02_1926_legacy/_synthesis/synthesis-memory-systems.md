# AI 系统记忆体系全景：从 KV Cache 到长期知识图谱

> **核心洞察**：记忆不是一个组件，而是一个从纳秒级 KV Cache 到永久知识图谱的连续谱系。不同层级的记忆在延迟、容量、精度、成本上有本质不同的权衡。真正优秀的 AI 系统不是记住一切，而是**在正确的时刻回忆正确的信息**。

---

## 1. 记忆的五层连续谱系

```
延迟: 纳秒 ──────────────────────────────────────────→ 秒/分钟
容量: 极小 ──────────────────────────────────────────→ 无限
持久: 瞬时 ──────────────────────────────────────────→ 永久

┌────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│  KV    │  │ 对话历史  │  │ 工作记忆  │  │ 长期记忆  │  │ 知识图谱  │
│ Cache  │→ │ Session  │→ │ Agent    │→ │ Vector DB│→ │ Graph    │
│        │  │ History  │  │ Working  │  │ Memory   │  │ Memory   │
│推理层   │  │ 会话层    │  │ 智能体层  │  │ 持久层    │  │ 关系层    │
└────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘
  GPU 显存     Redis/内存     文件系统      向量数据库     图数据库
```

## 2. 第一层：KV Cache（推理层记忆）

### 核心机制

参见 [[LLM_Inference_Deep_Dive#2.1]]。

**原理**：因果掩码保证历史 Token 的 K/V 不受未来影响，只需计算一次后缓存复用。每步新增 Token 只需：计算新 Q/K/V → 追加缓存 → Q 与全部缓存 K 计算注意力 → 加权求和缓存 V。

**显存公式**：`KV 缓存 = 2 × B × L × H_kv × d_h × t × bytes`

| 模型 | KV 头数 | 4096 Token FP16 缓存 |
|------|---------|---------------------|
| Llama 2-70B (GQA) | 8 | ~1.25 GiB |
| 同参数 MHA | 64 | ~10 GiB |

### 关键优化

| 技术 | 压缩比 | 说明 |
|------|--------|------|
| **GQA** | 缓存减至 1/8 | KV 表征存在大量冗余 |
| **MLA (DeepSeek)** | 再压缩 5-7x | 576 维 vs 全维度 32768 |
| **前缀缓存** | 跨请求复用 | 共享系统提示词的 KV 缓存 |

### 前缀缓存的上下文排列策略

将不变内容放前部（缓存命中），变化内容放末尾（缓存未命中）。缓存命中价格通常仅为常规输入的 10%（Anthropic）。参见 [[Context_Engineering_Guide#7.2]]。

## 3. 第二层：对话历史（会话层记忆）

### 核心特征

- **生命周期**：单次会话（Session），超时或显式结束时销毁/持久化
- **存储介质**：Redis 等内存数据库，以 Session ID 为键隔离
- **注入方式**：先进先出（FIFO）或滑动窗口

### 管理策略

参见 [[Context_Engineering_Patterns#3.4]]。

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| **滑动窗口** | 保留最近 N 轮对话 | 简单问答 (2-5轮)、复杂任务 (5-10轮) |
| **Token 预算** | 按 Token 数设定上限 | 成本控制敏感场景 |
| **重要性采样** | 按分数优先丢弃低分消息 | 长对话管理 |
| **递进式摘要** | 近期原文、中期摘要、远期高度压缩 | 超长对话 |

### 递进式摘要模型

```
最近 3 轮：保留原文
4-10 轮：简短摘要
10 轮以前：高度压缩的会话检查点
```

## 4. 第三层：工作记忆（智能体层记忆）

### 核心特征

Agent 在多步执行中维持任务状态的记忆，类似人类的工作记忆。

参见 [[Agentic_AI_Complete_Guide#4]]、[[Context_Engineering_Patterns#1.2]]。

### 认知科学映射

| 人类记忆 | AI Agent 映射 | 存储介质 |
|---------|-------------|---------|
| 工作记忆 | 当前对话上下文窗口 | LLM 上下文 |
| 情景记忆 | 对话日志、交互历史 | Vector DB |
| 语义记忆 | 领域文档、百科知识 | Knowledge Graph / RAG |
| 程序记忆 | 工具、代码解释器 | Function Schemas |
| 反思记忆 | 优化后的 Prompt、SOP | 提示词库 / 元数据 |

### MemGPT 操作系统隐喻

参见 [[Context_Engineering_Patterns#1.4]]。

- 上下文窗口 = 主内存
- 外部存储 = 磁盘
- 显式分页：系统在"主存"和"磁盘"之间主动交换数据
- 中断机制：上下文占满时触发"内存管理中断"

## 5. 第四层：长期记忆（持久层记忆）

### 核心特征

跨会话持久化的知识，支持语义检索。

### 三大实现方案对比

| 方案 | 存储 | 检索方式 | 优势 | 劣势 |
|------|------|---------|------|------|
| **向量数据库** | 嵌入向量 | 语义相似度 | 快速、可扩展 | 不擅长关系推理 |
| **知识图谱** | 实体+关系 | 图遍历 | 关系推理强 | 构建成本高 |
| **混合方案** | 向量+图 | 双路检索融合 | 取长补短 | 系统复杂度高 |

参见 [[Context_Engineering_Patterns#2]]、[[Context_Engineering_Patterns#6]]。

### 向量数据库选型

参见 [[Agentic_AI_Complete_Guide#4.3]]、[[Harness_Core_Subsystems#3.4]]。

| 向量库 | 适用规模 | 特点 |
|--------|---------|------|
| **Chroma** | 原型开发 | 轻量、易上手 |
| **Pinecone** | 生产无运维 | 全托管、免运维 |
| **Weaviate** | 自托管+混合搜索 | 多模态、GraphQL |
| **Milvus** | 超大规模 (亿级) | 高性能分布式 |
| **Qdrant** | 中小规模高性能 | Rust 实现、K8s |
| **Hnswlib** | <1M 向量 | 纯内存索引 |
| **pgvector** | <5M | 深度 SQL 集成 |

### 记忆检索打分

斯坦福小镇模型：`Score = α × Recency + β × Importance + γ × Relevance`

参见 [[Agentic_AI_Complete_Guide#4.1]]。

### 记忆更新策略

参见 [[Context_Engineering_Patterns#1.7]]。

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| **追加式** | 新信息不断追加 | 日志、历史记录 |
| **覆盖式** | 新信息替换旧信息 | 状态信息、配置 |
| **合并式** | 新旧信息智能合并 | 知识累积 |
| **淘汰式** | 按规则删除旧信息 | 容量管理 |

> **关键洞察**：记忆系统的效果上限往往不取决于检索算法的优劣，而取决于**目标函数是否准确**。多数系统默认优化语义相似度，但长期记忆真正需要优化的是更新正确性、时间正确性和冲突消解。

## 6. 第五层：知识图谱（关系层记忆）

### 何时需要图结构

参见 [[Context_Engineering_Patterns#6]]、[[Agentic_AI_Complete_Guide#4.5]]。

当系统需要稳定回答"谁在什么时候与谁发生了什么关系"时：
- 对实体间关系的表达（向量检索不天然表达"A 是 B 的子公司"）
- 多跳查询（"找出所有投资了 AI 公司的 PE 基金合伙人"）
- 跨多文档的关系推理

### Graph RAG 架构

```
用户查询 → 实体提取 → 图谱检索 → 子图提取 → 上下文构建 → LLM 生成
```

### 记忆脑图（Memory Mind Map）

参见 [[Context_Engineering_Patterns#6.3]]。

全量构建知识图谱成本高昂且脆弱。工程实践中更具价值的演进形态是**轻量化图结构**：
- 介于松散分块与重度图谱之间
- 通过 **Chain of Memory** 工程模式：系统自觉过滤通识内容，仅保留对当前业务场景具有差异化价值的要点
- 形成以根节点（Root Node）和主题节点（Topic Node）为核心的轻型脑图网络

## 7. 三大系统的记忆实现对比

### 7.1 Claude Code：7 层递进式记忆架构

参见 Claude Code Deep Dive、[[Claude_Agent_Architecture#4.4]]。

| 层 | 名称 | 职责 | 成本 |
|----|------|------|------|
| 1 | 工具结果存储 | 超阈值持久化到磁盘，仅留 ~2KB 预览 | 几乎无 |
| 2 | 微型压缩 | 时间清理 + 缓存微压缩 + API 级管理 | 几乎无 |
| 3 | 会话记忆 | 结构化笔记（目标、状态、学习），零额外 API | 零 |
| 4 | 完整压缩 | 紧急机制，分支 Agent 生成摘要 | 中 |
| 5 | 自动记忆提取 | 任务结束提取到 MEMORY.md | 中 |
| 6 | 梦想机制 | 跨会话记忆整合（研究预览） | 高 |
| 7 | 跨 Agent 通信 | 分支 Agent，Haiku 生成进度快照 | 中 |

**设计哲学**：前 3 层几乎零成本，渐进式增加投入。MEMORY.md 前 200 行或 25KB 自动加载，超出部分需主动检索。

### 7.2 OpenClaw：MEMORY.md + 每日日志

参见 [[OpenClaw_Complete_Guide#6.3]]、[[OpenClaw_Internals#2]]。

**双层记忆结构**：
- **长期记忆**（`MEMORY.md`）：持久化偏好、决策、经验
- **每日日志**（`memory/YYYY-MM-DD.md`）：阶段性进展、当天细节

**写入规则**：只记录**稳定**（跨会话复用）、**可追溯**（来自工具回执）、**可纠错**的事实。

**检索机制**：`memory_search`（混合搜索：BM25 + 向量相似度，400 token/分块）+ `memory_get`（精确读取特定行）。

**上下文四层信息源**：

| 层级 | 来源 | 预算占比 | 裁剪优先级 |
|------|------|---------|-----------|
| 系统身份 | AGENTS.md / SOUL.md / TOOLS.md | 10-15% | 不可牺牲 |
| 工作区知识 | MEMORY.md / 检索结果 | 5-10% | 较后裁剪 |
| 对话历史 | 用户消息与助手回复 | 75-85% | 按时间裁剪 |
| 工具回执 | 工具调用原始返回 | - | 最先被裁剪 |

### 7.3 Harness：autoDream 记忆整合管道

参见 [[Harness_Core_Subsystems#3.2]]。

**三门触发机制**（满足至少一个即激活）：
1. 时间门槛（24 小时未整合）
2. 会话计数门槛（5 个新会话）
3. 显式触发（用户或系统主动调用）

**四阶段整合管道**：

```
Orient（分析目标）→ Gather（提取事实）→ Consolidate（合并记忆）→ Prune（删除过期）
```

### 7.4 三者对比总结

| 维度 | Claude Code 7层 | OpenClaw 双层 | Harness 3层 |
|------|----------------|--------------|------------|
| **触发精度** | 七层独立阈值 | 写入规则驱动 | 三门机制 |
| **压缩策略** | 渐进微压缩→完整压缩 | 手动整理 | 统一 autoDream |
| **存储媒介** | 分散式 | 集中式文件 | 集中式 |
| **成本结构** | 前 3 层几乎无成本 | 几乎无成本 | 整合时一次性较高 |
| **跨会话恢复** | 预构建摘要注入 | MEMORY.md 加载 | 向量搜索 |

## 8. 记忆生命周期：写入 → 检索 → 巩固 → 遗忘

### 8.1 写入（Write）

参见 [[Context_Engineering_Guide#4.1]]。

| 写入方式 | 说明 | 适用场景 |
|---------|------|---------|
| 显式保存 | 用户明确要求记住 | 偏好、关键事实 |
| 重要性判断 | 自动识别 (Reflection 机制) | 任务成果、异常事件 |
| 摘要压缩 | 提取关键内容存储 | 长对话、长任务 |
| 工具回执 | 结构化结果写入 | 检索结果、执行日志 |

### 8.2 检索（Retrieve）

参见 [[Context_Engineering_Patterns#1.6]]。

| 检索方式 | 说明 | 优势 |
|---------|------|------|
| 语义相似度 | 向量余弦相似度排序 | "以前遇到过类似问题吗" |
| 时间相关性 | 最近 N 条记录 | "刚才发生了什么" |
| 重要性评分 | LLM 对每条记忆评分 | "我对花生过敏"(10) vs "我想吃披萨"(2) |
| 混合检索 | 先时间窗口缩候选集，再语义排序 | 最常用 |

### 8.3 巩固（Consolidate）

参见 [[Harness_Core_Subsystems#3.2]]。

定期回顾和整合已有记忆：去重、更新、合并冲突信息。autoDream 管道的 Consolidate 阶段执行此功能。

### 8.4 遗忘（Forget）

参见 [[Context_Engineering_Patterns#1.6]]。

| 遗忘机制 | 说明 |
|---------|------|
| **遗忘曲线** | 模拟人类遗忘：`Weight_t = Weight_0 × e^(-λt)` |
| **使用频率 (LRU)** | 不常用的记忆优先淘汰 |
| **TTL 过期** | 临时偏好设过期策略（如 24 小时） |
| **相似度去重** | 相似度 > 0.95 的记忆合并 |
| **相关性过滤** | 相关性 < 0.6 的记忆淘汰 |

## 9. 核心权衡矩阵

| 维度 | 低延迟端 | 高容量端 | 工程建议 |
|------|---------|---------|---------|
| **延迟 vs 容量** | KV Cache (纳秒级) | 知识图谱 (秒级) | 分层缓存，热数据快取 |
| **精度 vs 召回** | 精确匹配 (高精度) | 语义检索 (高召回) | 混合检索 + 重排序 |
| **成本 vs 质量** | 截断 (零成本) | LLM 摘要 (高质量) | 渐进式压缩，先低成本后高成本 |
| **持久性 vs 灵活性** | 参数记忆 (不可改) | 外部记忆 (易更新) | RAG + 微调混合策略 |

## 10. 记忆安全

参见 [[Agent_RAG_Security#1.5]]。

记忆系统面临的安全威胁：

| 威胁 | 说明 | 防御 |
|------|------|------|
| **短期记忆污染** | 注入恶意上下文影响后续决策 | 输入验证、上下文隔离 |
| **长期记忆污染** | 恶意信息被存入长期记忆 | 来源标注、TTL、写入门控 |
| **记忆泄露** | 一个用户的记忆被检索给另一个用户 | 行级权限隔离、多租户过滤 |
| **指令升级** | 外部数据中的指令性文本被当作系统指令 | 指令/事实分离、数据标记 |

**记忆治理要点**：
- 每条记忆保留来源、写入时间、置信度
- 来自网页/邮件/工具的文本默认视为数据，不升级为系统指令
- 涉及凭据、PII、安全例外的记忆写入需触发审批
- 多租户场景必须在检索前按租户/项目/权限过滤
