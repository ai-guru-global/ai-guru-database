# 06 · 软件路线对比：框架层钩住为什么是唯一解

> 新 AI 芯片要被用起来，只有三条软件路线。PPU 选了第三条——本文论证为什么这是当下唯一理性选择，以及它的代价。

## 三条路线

| 路线 | 代表 | 优势 | 代价 | 有谁走成过 |
|---|---|---|---|---|
| ① CUDA 兼容 | 海光 DCU（类 CUDA/HIP）；PPU「CUDA 兼容层」为媒体口径、层级待核实 | 生态继承成本最低 | 法律灰区 + 兼容层级越高工程地狱越深（二进制级无人做成） | 海光（境内市场） |
| ② 自建 DSL/运行时 | 华为 CANN、Google XLA | 生态自主、可深度优化 | 用户迁移摩擦大、从零建生态 | Google（有 20 年 + TPU 梯队）；华为（政企市场买单） |
| ③ 框架层钩住 | **PPU（主线）**、AWS Neuron SDK | PyTorch/vLLM 事实标准直接继承，迁移成本最小 | 上游演进受制于人；壁垒可复制 | AWS Trainium（已规模化） |

## PPU 的选择与位置

PPU 主线走 ③：不造 DSL，在 PyTorch/Megatron/vLLM/SGLang 的设备适配层做 hook。**CUDA 口径注意**：官方页（2026-11-06 检索）通篇未提 CUDA，只说编译器用法「与 GPU 类似、无缝切换」；财新等媒体报道「与 CUDA 生态兼容」，wiki 内研究页称 SAIL 提供 CUDA 兼容层——**若兼容层属实，PPU 实为 ③ 为主 + ① 源码级迁移工具为辅的混合路线**（类 HIPIFY 定位），兼容层级（源码迁移工具 / API 子集 / 二进制）待一手核实（挂账）。选择的理性在时间窗口：PyTorch + vLLM 已是事实标准，绕开 = 让用户重学一套栈。

**2026-07-23 的第二阶段：SAIL 开源**（→ [05-软件栈](05-软件栈.md)）。把 Driver/Runtime/编译器/高性能库/工具五层开放——国产自研 AI 芯片阵营第一个开放全栈的玩家。战略含义（观点层）：

1. **对内**：开源是 OS 生态收编工具——SAIL 已与龙蜥 ANCK 原生互认，「国产 OS × 国产芯片」捆绑成型，信创市场入场券；
2. **对外**：开源降低第三方（模型 lab、集成商、二线云）接入成本的边际——每个基于 SAIL 的适配都是免费的生态扩张；
3. **对壁垒**：开源进一步放弃软件栈封闭护城河——PPU 的软件壁垒从「栈本身」转移到「硬件 × 超节点 × 生态运营」的组合，这是主动选择：软件栈之战的胜负手是**装机量与开发者习惯**，不是授权费。

对照：CUDA 封闭三十年、华为 CANN 未开源、AWS Neuron SDK 封闭——PPU 用开源换生态速度，是弱势方对抗生态霸主的经典打法（Android 对 iOS 同构）。

## 与昇腾的结构性差异（及各自的买家）

- **昇腾 CANN（路线②）**：全栈自建 = 生态自主但迁移昂贵；买家是政企与信创市场——那里「自主可控」本身就是采购理由，迁移成本可被预算消化；
- **PPU（路线③）**：框架租借 + 全栈开源 = 迁移便宜但生态不完全自主；买家是已经在 PyTorch/vLLM 上的互联网公司与模型公司——他们要的是「换硬件不换代码」。

两类买家几乎不重叠：**PPU 与昇腾是分层市场而非同一战壕**（→ [09-国产竞争格局](09-国产竞争格局.md)）。这也解释了 M890 Day0 适配的是 Kimi（大模型公司）而不是政企方案。

## 代价：护城河最薄的一层

框架适配是可复制的工程工作（竞品也能钩 vLLM），SAIL 开源后连栈本身都可复制。PPU 软件壁垒必须长在三处深度上：acext 算子覆盖度与性能、PCCL/ACCL-P 在超节点拓扑上的通信效率、HolmesLLM 对 Qwen 系模型的调度优化——**开源开放的是「能跑」，壁垒在「跑得最好」**：同一份开源代码上，性能调优深度与超节点工程仍只在平头哥手里（→ [12-展望与领先指标](12-展望与领先指标.md)）。
