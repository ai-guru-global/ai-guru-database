# 集群架构师视角

> 一句话：把「训练什么模型」逐层翻译成 scale-up 域大小、拓扑形态、器件清单与软件参数，并用逐层基线证明这套设计在目标规模下成立。

## 核心问题清单

1. 通信矩阵：目标模型 + 并行策略下，跨机流量由 AllReduce、AllGather 还是 All-to-All 主导？单条消息多大、每步多少次、可重叠比例多少？
2. 分层：scale-up 域做多大（NVLink 整柜 / 自组超节点 / 只到机内 8 卡）？跨域流量占比多少？
3. 拓扑：两层还是三层？单平面、双平面还是多小平面？rail 数取多少？
4. 器件：交换芯片代际、光模块速率、铜/光配比按什么公式定？
5. 软件：NCCL 参数、无损三件套、自适应路由按什么基线调？
6. 验证：逐层基线怎么定、长稳门槛是什么、多快能证明设计不成立？

## 评估框架：六阶段端到端 checklist

| 阶段 | 输入 | 输出 | 关键决策点 |
|---|---|---|---|
| ①需求 | 模型结构（参数量/序列长/MoE）、目标卡数 | 通信矩阵：算子类型 × 消息大小 × 频次 × 可重叠性 | TP/EP 是否出 scale-up 域；DP 主导则收敛比可讨论 |
| ②分层 | 通信矩阵、卡型（域内互联形态） | scale-up 域大小、跨域流量比例、scale-out 收敛比 | 万卡级 1:1 起步（工程惯例口径）；域内带宽要覆盖 TP/EP 流量 |
| ③拓扑 | GPU 总数、每卡网卡数、交换机端口数 | leaf/spine/core 层数与台数、平面切分、rail 映射 | 64 口两层 1:1 约 2048 卡口封顶（算术见下）；更大规模三层或多小平面 |
| ④器件 | 拓扑端口表 | 交换机/光模块/网卡/线缆清单与数量 | 51.2T=64×800G、102.4T（Tomahawk 6，2025）=128×800G 或 64×1.6T；模块数按配比公式 |
| ⑤软件 | 拓扑与器件清单 | NCCL 版本与参数、ECN/PFC 阈值、AR 开关 | IB 走 SHARP；RoCE 三件套逐跳验证后才上业务 |
| ⑥验证 | 软硬件配置 | 逐层基线（单机/单跳/全网 busbw）+ 72h 长稳报告 | busbw 达基线 −5% 内、慢链路筛查零遗留 |

两层容量算术（rail-optimized、1:1、每卡 1 口）：64 口交换机 leaf 取 32 下 32 上 → 64 台 leaf × 32 台 spine，单平面 64×32=2048 卡口；万卡必须三层，或双平面/多小平面（阿里 HPN 双平面 15k GPU，SIGCOMM 2024）。

### 决策树（文字版）

1. 有 NVLink 整柜或超节点 → TP/EP 封在域内，scale-out 只算 DP/PP 流量 → 网卡可降配、收敛比可放松。
2. 无机内大域 → 跨机流量翻倍 → 每卡 ≥1×400G、收敛比 1:1。
3. 卡数 ≤2k → 两层单平面，rail 数 = 每卡网卡数。
4. 2k < 卡数 ≤15k → 三层，或双平面/多小平面（故障域与运维分区更小）。
5. 卡数 >15k → 多小平面 + 拓扑感知调度是设计前提，不是事后优化。
6. 团队无以太无损经验且能接受锁定 → IB；要开放/白盒/国产 → RoCE；UEC 1.0（2025-06 发布）生态成熟前只做预研，商用规模（待核实）。

## 关键指标与基线

| 指标 | 口径 | 参考基线 | 锚点 |
|---|---|---|---|
| 单机 NVLink AllReduce busbw | nccl-tests，NVL8，大消息 | ≈480 GB/s（H100 代） | 公开 nccl-tests 常见实测 |
| scale-up 域带宽/卡 | 单向 | H100 900 GB/s；Rubin NVLink 6 3.6 TB/s | NVIDIA 2026-01 CES（已核实） |
| 跨机 AllReduce busbw | 全规模，大消息 | ≥网卡线速 90%（400G → 45+ GB/s/卡） | nccl-tests 实测口径 |
| MFU | dense 模型、含通信 | 万卡级 55% 可达成 | 字节 MegaScale 55.2%（NSDI 2024，12288 卡） |
| 长稳门槛 | 72h 全规模训练 | 无掉卡、busbw 波动 <5%、CRC 零增长 | 工程惯例口径 |

## 常见误区（常见架构错误清单）

1. 拿通用数据中心网络直接套：收敛比 3:1 起步、ECMP 默认哈希、无 PFC/ECN 设计，AllReduce 直接打崩。
2. scale-up 域大小拍脑袋：没量化 TP/EP 跨域流量就上小域，事后跨域通信每步暴露。
3. 两层硬扛万卡：第三层临时加上，模块用量、时延、故障域全部超标。
4. 器件代际错配：51.2T 芯片配 1.6T 模块（端口数浪费），或 400G 模块配 102.4T 芯片（芯片能力闲置）。
5. 无损参数照抄别家模板：ECN 阈值与缓冲不匹配自家交换机，拥塞反噬吞吐。
6. 只跑一次 nccl-tests 就验收：没有长稳、没有慢链路筛查、没有配置漂移防护。
