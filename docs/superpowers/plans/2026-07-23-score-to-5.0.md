# 知识库补满 5.0 实现计划

> **For agentic workers:** 本计划用并行 subagent 执行。每个 agent 负责一个章节块，产出后由主控抽查质量门禁。所有步骤 checkbox 跟踪。

**Goal:** 将知识库综合评分从 4.8 提升至 5.0，所有低于满分的章节与维度补齐（纯增量，不删减）。

**Architecture:** 按章节独立性分发 6 个并行 agent；每个 agent 遵循统一的满分文档标准（深度页 450-650行/题库5件套/index导航规范）产文；主控负责质量门禁与收尾。

**Tech Stack:** Markdown + Obsidian wikilinks；项目 frontmatter 规范。

**参考样本（满分标准）:**
- 人物专题: `业界观点/Mark_Zuckerberg/Zuckerberg_AI_Pivot_2026.md` (565行)
- 题库套件: `面试岗位/Machine_Learning_Engineer/` (5文件)
- 导航index: `运维/Observability/index.md` (232行)

## 通用文档标准（所有 agent 必须遵守）

### frontmatter 模板
```yaml
---
title: "标题"
category: "xx-chapter"
tags: ["tag1", "tag2"]
summary: "**一句话概括**: 核心要点。"
created: "2026-07-23"
updated: "2026-07-23"
tier: core  # 或 supporting
aliases: ["别名"]
sources: []
---
```

### 质量门禁（每篇必过）
- 深度内容页: 450-650 行；含 ≥3 表格；≥7 wikilinks；无占位符
- 题库: 每文件 200+ 行；30+ 题
- index导航: 200+ 行；含文件导航表 + 子目录 + 知识体系表
- 中文撰写；wikilink 用 `[[目录/文件名|显示名]]` 格式

## 核心术语速查

| 术语 | 含义 | 关联概念 |
|------|------|----------|
| Loss Function | 衡量预测与真实值差距 | 交叉熵/MSE/对比损失 |
| Gradient Descent | 沿负梯度方向更新参数 | SGD/Adam/学习率 |
| Overfitting | 模型在训练集过好但泛化差 | 正则化/Dropout/早停 |
| Batch Size | 每次更新的样本数 | 收敛速度/显存/噪声 |
| Epoch | 完整遍历训练集一次 | 训练轮次/早停 |
| Fine-tuning | 在预训练模型上继续训练 | 迁移学习/LoRA/全量 |
| Inference | 模型前向传播产生输出 | 延迟/吞吐/量化 |
| Token | 文本处理的最小单元 | BPE/SentencePiece |
