## 3. 核心技术架构

### 3.1 Yi 基础架构参数

| 参数 | Yi-6B | Yi-9B | Yi-34B |
|------|-------|-------|--------|
| 参数量 | 6B | 9B | 34B |
| 层数 | 32 | 48 | 60 |
| 隐藏维度 | 4096 | 5120 | 7168 |
| 注意力头数 | 32 | 40 | 56 |
| KV 头数 | 4 (GQA) | 8 (GQA) | 8 (GQA) |
| FFN 维度 | 11008 | 13824 | 20480 |
| 词表大小 | 64000 | 64000 | 64000 |
| 上下文长度 | 4096 | 4096 | 4096 |
| 训练数据 | 3T tokens | 3T tokens | 3T tokens |
| 位置编码 | RoPE | RoPE | RoPE |
| 激活函数 | SwiGLU | SwiGLU | SwiGLU |
| Norm | RMSNorm | RMSNorm | RMSNorm |

### 3.2 关键架构选择

```
Yi 架构设计决策:
════════════════════════════════════════════════════════════════════

  1. GQA (Grouped Query Attention):
     ────────────────────────────────────────
     Yi-34B: 56 个查询头 → 8 个 KV 头
     压缩比: 7:1
     好处: KV Cache 减少 87%，推理加速显著

  2. 词表策略:
     ────────────────────────────────────────
     64K 词表 (SentencePiece BPE)
     • 平衡中英文效率
     • 不追求超大词表（如 Baichuan2 的 125K）
     • 训练效率与推理速度的折中

  3. 训练数据策略:
     ────────────────────────────────────────
     3T tokens 高质量数据
     • 英文占比: ~60%
     • 中文占比: ~30%
     • 代码占比: ~10%
     • 严格去重与质量过滤
```

### 3.3 GQA 深度解析

```
标准 MHA vs GQA (Yi):
════════════════════════════════════════════════════════════════════

  标准多头注意力 (MHA):
  Q: [q1, q2, q3, q4, q5, q6, q7, q8]
  K: [k1, k2, k3, k4, k5, k6, k7, k8]  ← 每个头独立 KV
  V: [v1, v2, v3, v4, v5, v6, v7, v8]

  GQA (Grouped Query Attention):
  Q: [q1, q2, q3, q4, q5, q6, q7, q8]
  K: [k1, k1, k2, k2, k3, k3, k4, k4]  ← 共享 KV
  V: [v1, v1, v2, v2, v3, v3, v4, v4]

  Yi-34B 具体配置:
  56 Query Heads → 8 KV Heads
  每 7 个 Query Head 共享 1 组 KV
  KV Cache: (56-8)/56 = 85.7% 减少
```

## 4. Yi-34B 架构深度解析

### 4.1 为什么 Yi-34B 令人瞩目

Yi-34B 在 2023 年 9 月发布时，多项 Benchmark 超越 Llama-2-70B，成为当时最强开源模型之一。

```
Yi-34B 的关键数字:
════════════════════════════════════════════════════════════════════

  参数量:         34B (仅为 Llama-2-70B 的一半)
  训练数据:       3T tokens
  训练算力:       ~3,000 GPU-days (A100)
  Benchmark:      多项超越 Llama-2-70B
  许可证:         Apache 2.0 (最宽松)
  词表:           64K
  上下文:         4K → 16K → 200K (渐进扩展)
```

### 4.2 训练方法论

```
Yi-34B 训练流程:
════════════════════════════════════════════════════════════════════

  Phase 1: 数据准备 (3 个月)
  ┌──────────────────────────────────────────┐
  │ • 3T tokens 网页数据爬取                  │
  │ • 语言检测与分类                          │
  │ • 去重 (MinHash + exact dedup)            │
  │ • 质量过滤 (分类器打分)                   │
  │ • 有害内容过滤                            │
  └──────────────────────────────────────────┘

  Phase 2: 预训练 (2 个月)
  ┌──────────────────────────────────────────┐
  │ • 3D 并行: 数据 + 模型 + 流水线            │
  │ • 批量大小: 4M tokens                     │
  │ • 学习率: 峰值 3e-4 → 余弦衰减            │
  │ • 训练 3T tokens (约 1 epoch)             │
  │ • 硬件: ~1,000 A100 GPUs                  │
  └──────────────────────────────────────────┘

  Phase 3: 对齐 (2 周)
  ┌──────────────────────────────────────────┐
  │ • SFT: 10K+ 高质量指令数据                │
  │ • DPO: 偏好对齐                          │
  │ • 人类反馈收集与质量标注                   │
  └──────────────────────────────────────────┘
```

### 4.3 长上下文扩展

```
Yi-34B 上下文扩展路线:
════════════════════════════════════════════════════════════════════

  4K (初始)
  ├── 原始预训练上下文
  └── 满足大多数基础任务

  16K (RoPE 缩放)
  ├── NTK-Aware 插值
  ├── 短程微调 (~100 步)
  └── 不损失短上下文性能

  200K (Yi-34B-200K)
  ├── 持续预训练 + 长数据
  ├── 梯度检查点优化
  └── 长文档理解、代码库分析
```

## 5. Yi-Lightning 推理优化

### 5.1 架构特色

Yi-Lightning 是零一万物的推理优化模型，主打极速推理。

```
Yi-Lightning 设计目标:
════════════════════════════════════════════════════════════════════

  速度:  首字延迟 < 100ms (业内最快)
  质量:  保留 Yi-34B 90%+ 能力
  成本:  推理成本降低 5-10 倍
  用途:  实时对话、高频调用场景
```

### 5.2 推理优化技术

| 技术 | 描述 | 效果 |
|------|------|------|
| 模型蒸馏 | 从 Yi-34B 蒸馏到更小模型 | 保留 90% 性能 |
| 量化感知训练 | INT8/INT4 量化 | 速度提升 2-4x |
| 知识浓缩 | 结构化知识转移 | 减少参数但不减能力 |
| 推理优化 | KV Cache 优化 + Speculative Decoding | 延迟降低 50%+ |

### 5.3 性能对比

```

════════════════════════════════════════════════════════════════════

  ────────────────────────────────────────────────────────────
  首字延迟          < 100ms         ~300ms         ~200ms
  生成速度          150+ tok/s      ~40 tok/s      ~80 tok/s
```

### 11.2 零一万物的优势与挑战

**优势：**
- Apache 2.0 许可证: 最宽松的开源协议，商业友好
- 参数效率: Yi-34B 以一半参数达到 70B 级性能
- 国际化: 英文能力在国产模型中领先
- 李开复影响力: 品牌知名度与行业影响力
- Yi-Coder: 编程专用模型有差异化

**挑战：**
- 2025 年战略调整，重心转向应用层
- 模型迭代速度不如 Qwen、DeepSeek
- 社区活跃度下降
- MoE 架构探索不足
- 多模态能力落后于 Qwen-VL
