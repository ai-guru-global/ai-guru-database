# Agent Harness 工程直播脚本 (Learn-by-Teaching Live Script)

> 中文简称：Agent Harness 直播脚本

> **一句话理解**: 模型是马，Harness 是马具——马具不让马更强壮，但能把马的力量可靠地变成有用的工作；这份脚本让你 45 分钟讲透"模型之外的一切工程"。

---

## 0. 使用说明与播前准备

**定位**：45 分钟单人直播脚本 ｜ **受众**：写过 Prompt、玩过 Agent Demo，但还没把 Agent 送进生产的开发者 ｜ **方法**：以教代学（费曼学习法）——备教、直播、自检三步闭环。

**主线类比**（全程不换）：**模型是马，Harness 是马具**（缰绳、鞍座、胸带、眼罩）。马具不给马增加力量，它干三件事：**引导方向**、**分散风险**、**标准化协作**。

**记忆钩子**（直播中至少重复 3 次）：

1. 一个公式：**Agent = Model + Harness**，"如果你不是 Model，你就是 Harness"
2. 一个类比：**模型是马，Harness 是马具**
3. 一个结论：**模型决定思维上限，Harness 决定工程下限**

**播前准备清单**（开播前 30 分钟）：

- [ ] 打开你正在用的编程助手（Claude Code / Qoder / Cursor 任一），第六幕要现场解剖它
- [ ] 幻灯片按各幕 [幻灯片] 提示备齐，重点页：五层解剖图、实证数据页
- [ ] 费曼自检表（附录 B）打印放手边

## 2. 第一幕 · 开场（0:00–3:00）

**[幻灯片 1]** 标题页 + 一个问题："同一个模型，为什么在别人手里是生产级 Agent，在你手里是 Demo 玩具？"

**口播稿**：

> 大家好，欢迎来到"以教代学"系列第二期。上期我们讲了 SFT、DPO、CPT，怎么**教**模型；这期讲一个更贴近工程的话题：模型教好了，为什么你做的 Agent 还是跑不进生产？因为差的那一层叫 **Harness**。
>
> 先给大家一个画面：同一匹烈马，没套马具，它跑得再快也只是在草原上乱窜；套上缰绳、鞍座、胸带，它的力量才变成拉车、耕地的**有用的工作**。模型就是那匹马，Harness 就是那套马具。
>
> 弹幕互动：**自己从头写过 Agent 的扣 1，只调过 Prompt 的扣 2。** 好，今天这期就是帮扣 2 的同学跨过那条线——从"调 Prompt"到"做工程"。

**[互动]** 扣 1 / 扣 2 热身，校准听众画像。

## 3. 第二幕 · 定义与边界（3:00–10:00）

**[幻灯片 2]** 核心公式图：Agent = Model（智能）+ Harness（工程系统）。

**口播稿**：

> 先给定义。Harness 这个词本义就是马具，2025 年到 2026 年被 LangChain 的《The Anatomy of an Agent Harness》和 OpenAI 的工程博客带火。定义只有一句：**Agent = Model + Harness，模型之外的一切都是 Harness**——System Prompt、工具、沙箱、编排逻辑、状态管理、验证回路，全包。
>
> 业内有句更狠的话，帮我刷弹幕：**"如果你不是 Model，你就是 Harness。"** 一个 Agent 系统里，除了模型推理那一下，其余每一行代码都是 Harness。
>
> 为什么必须有 Harness？因为裸模型有四件"不能"：**不能**记住跨会话的状态、**不能**执行代码和访问文件、**不能**获取实时知识、**不能**安装依赖搭环境。裸模型只能接收文本、输出文本。Harness 就是把这些能力补上，把"会说话的大脑"变成"能干活的人"。
>
> 然后讲边界，这是最容易被问倒的地方。Harness **做**什么？工具集成、权限授权、执行跟踪验证、状态管理、可观测和审计。Harness **不做**什么？推理和决策是模型的活儿，工具的实际执行是工具自己的活儿，模型训练、业务逻辑定义也都不归它管。**马具不替马思考，也不替马跑步，它只管把力量导向正确的方向。**

**[幻灯片 3]** 职责边界对照表（做/不做两栏）。

**[讲者防坑]**

- 别把 Harness 翻译成"测试 Harness"。测试领域的 test harness 是同名老概念，Agent 语境下的 Harness 指"模型外部的完整运行系统"。
- 别说"Harness 和模型对立"。Harness 既**弥补模型缺陷**，也**放大模型智能**；模型越强，Harness 可以越薄，但不会消失——就像 Prompt Engineering 到今天也没消失。

## 4. 第三幕 · 五层解剖（10:00–22:00）

**[幻灯片 4]** 五层解剖图（上下文/编排/执行/钩子/观测）。

**口播稿**：

> 定义讲完，拆开看。Harness 内部一般分五层，我按马具一一对应，大家记起来就快了。
>
> **第一层，上下文层**——组装模型每一步看到什么：System Prompt、记忆、Skills、工具描述。马具里它是**眼罩和缰绳**：决定马往哪看、听什么指令。上期讲过的 Context Engineering，整个就是这一层的学问。
>
> **第二层，编排层**——决定怎么干：模型路由、子 Agent 派生、Handoff。它是**骑手的路线规划**：走哪条路、什么时候换马。简单任务路由便宜模型，复杂任务上贵模型，这一层直接管钱包。
>
> **第三层，执行层**——安全地执行：沙箱、Bash、文件系统、浏览器。它是**鞍座和挽具**，把马力真正变成拉车的功。这里有一个反直觉的设计原则，等下方法论幕会展开：**与其给 Agent 预定义一千个工具，不如给它一台计算机**——文件系统加 Bash，让它自己写代码解决新问题。
>
> **第四层，钩子层**——防止跑偏：上下文压缩、工具输出裁剪、确定性拦截、中断续写。它是**刹车和急停绳**：关键瞬间**确定性**干预，不跟模型商量。记住这个词：确定性。安全这种事，不能靠模型"自觉"。
>
> **第五层，观测层**——监控一切：Traces、Metrics、成本追踪、告警、审计日志。它是**仪表盘加黑匣子**：出事能复盘，没出事能算账。
>
> 五层连起来念一遍，帮我刷弹幕：**上下文管看什么，编排管怎么干，执行管做出来，钩子管别跑偏，观测管算得清。**

**[互动 · 场景题 1]**

> 场景一：Agent 跑了五十步，上下文溢出，回答质量断崖下跌。该哪层出手？
> ——**钩子层**：上下文压缩、输出裁剪，就是干这个的。

**[互动 · 场景题 2]**

> 场景二：Agent 差点执行 `rm -rf`，没人拦。最后一道防线该在哪层？
> ——**钩子层**做确定性拦截，**执行层**做沙箱隔离兜底。双保险，任何一层都不该信模型的"自觉"。

**[讲者防坑]** 五层是教学模型，不同文献切法不同（有的按"四大子系统"切：工具执行/状态记忆/安全权限/观测）。被问到时说"切法不同，覆盖的职责相同"，不纠缠名词。

## 5. 第四幕 · 实证价值：为什么 Harness 比模型更值得投（22:00–31:00）

**[幻灯片 5]** 实证数据页（四组数据大字呈现）。

**口播稿**：

> 这一幕是全场最重要的十分钟。因为很多人本能地觉得"效果不好 = 模型不行"，而 2026 年的实证数据反复打脸这个直觉。
>
> 第一组，OpenAI Codex 团队：给系统引入 Harness 层——语法验证、类型检查、结果验证——准确率提升 **30 到 40 个百分点**。没有任何模型改进，纯系统工程。
>
> 第二组，Bölük 的 Hashline 实验：把"完整文本编辑"的工具接口改成"行级哈希引用"，16 个模型**一致**提升，其中 Grok Code Fast 1 从 6.7% 涨到 68.3%，约 10 倍。注意，改的不是模型，是**工具的接口设计**。
>
> 第三组，LangChain Deep Agents：模型不变，纯 Harness 改进，Terminal-Bench 2.0 从 52.8% 到 66.5%，全球排名从 30 名开外进前 5。
>
> 第四组，Anthropic 的反向验证：固定模型、只改基础设施配置，成功率漂移 6 个百分点。所以他们给了一句行业判词，帮我刷弹幕：**排行榜上低于 3pp 的差距，很可能反映的是 Harness 配置差异，而不是模型能力。**
>
> 再用一道小学数学解释为什么。一个任务 100 步，每步成功率 90%，硬串联是 0.9 的 100 次方，约等于 0——这就是裸模型跑长任务必崩的数学原因。但 Harness 加上"验证 + 重试 3 次"，每步有效成功率变成 1 减 0.1 的 4 次方 = 99.99%，再串 100 步约等于 99%。**同一个 90 分的模型，有没有 Harness，是 0 分和 99 分的区别。**
>
> 所以结论句再刷一遍：**模型决定思维上限，Harness 决定工程下限。** 模型准确率到 85% 以后，投系统工程的 ROI 高于继续卷模型。

**[讲者防坑]** 数据引用要带出处（OpenAI Codex / Bölük Hashline / LangChain / Anthropic），别裸报数字；被问"这些实验场景是否通用"时承认：编码类任务证据最硬，开放任务证据还在积累。

## 6. 第五幕 · 建设方法论与反模式（31:00–39:00）

**[幻灯片 6]** "何时必须建正式 Harness" 清单 + 六原则。

**口播稿**：

> 那是不是做个 Agent 就要上全套 Harness？不是。先给判断标准，满足任一条，就别再靠人工试用，该建正式 Harness 了：**会调外部工具和 API**；**任务是多步链路**；**要进生产流程**；**失败代价高**；**版本迭代频繁**；**要做选型采购**。反过来，一次性 Demo，一个脚本跑通就行，别过度工程。
>
> 要建的时候，六条原则：
> 一，**文件系统是最基础的原语**——工作区、增量卸载、协作表面、版本控制，全靠它；
> 二，**给 Agent 一台计算机，而不是一千个工具**——Bash 加代码执行是通用工具，新问题让它自己写脚本；
> 三，**安全放钩子层，做确定性拦截**——权限最小化，每次调用带 trace_id；
> 四，**验证回路是可靠性之母**——验证加重试，把 90% 的单步变成 99.99%；
> 五，**状态要持久化**——会话状态落文件落库，检查点支持中断恢复；
> 六，**观测先行**——没有 Traces 和成本追踪，不许上生产。
>
> 再点四个反模式，都是真金白银踩出来的：**把一切塞进 Prompt**（该分层，静态模块和动态模块分开，还能吃提示词缓存）；**靠模型自觉保安全**（自觉不可审计，钩子才可靠）；**无检查点裸奔长任务**（崩了从头来，成本翻倍）；**没有观测上生产**（烧了多少钱、错在哪，一问三不知）。
>
> 最后澄清一个高频混淆：**Harness 和 Agent Skills 什么关系？** Harness 是操作系统，Skills 是注入上下文层的"专业知识包"。Harness 管怎么运行、怎么约束，Skills 管特定任务怎么做。两者协同，别混为一谈。

**[互动 · 场景题 3]**

> 场景三：老板问你"这个 Agent 上个月烧了多少 Token、错在哪一步"，你答不上来。缺哪层？
> ——**观测层**。所以原则六说：观测先行，没有黑匣子不许上路。

## 7. 第六幕 · 现场解剖（39:00–42:00）

**[幻灯片 7]** 空白五层表，现场填空。

**口播稿**：

> 最后一幕，现场解剖。打开你正在用的编程助手——Claude Code、Qoder、Cursor 都行——我们一起把它的五层找出来。
> 它的 AGENTS.md、系统提示、记忆系统，是**上下文层**；它的技能包 Skills，是注入上下文层的知识包；它派生子代理、路由模型，是**编排层**；它的沙箱、文件工具、终端，是**执行层**；它的 pre-commit 钩子、上下文压缩、输出裁剪，是**钩子层**；它的成本追踪、会话日志，是**观测层**。
> 看，你每天用的工具，就是一个活生生的 Harness。**下次你骂 Agent 笨的时候，先看看是马不行，还是马具没套好。**

**[互动]** 让弹幕刷自己工具里"最像钩子层"的一个功能，挑两条点评。

## 8. 第七幕 · 收尾（42:00–45:00）

**[幻灯片 8]** 一页总结：公式 + 马具图 + 五层口诀 + 3pp 法则。

**口播稿**：

> 收尾，三句话压缩全场：
> 一，**Agent = Model + Harness**，模型之外的一切都是 Harness；
> 二，**模型是马，Harness 是马具**——上下文管看什么、编排管怎么干、执行管做出来、钩子管别跑偏、观测管算得清；
> 三，**模型决定上限，Harness 决定下限**——低于 3pp 的榜单差距，先怀疑 Harness 再怀疑模型。
>
> 以教代学的惯例：下播后我做费曼自检（附录 B），卡壳的条目就是下期开场补课素材。下期预告：我们把**钩子层**单独拎出来讲一期——Hooks 与生命周期控制。感谢大家，下播。

## 附录 A · 观众问答弹药库（被问到时直接答）

| **观众可能问** | **答案要点** |
|------|------|
| Harness 和 Agent 框架（LangGraph 等）什么关系？ | 框架是建 Harness 的工具，Harness 是概念边界；用框架不等于 Harness 设计得好。 |
| 模型越来越强，Harness 会消失吗？ | 不会。Harness 既补缺陷也放大智能；类比 Prompt Engineering 至今未消失，只是形态演化。 |
| Prompt / Context / Harness 三者谁替代谁？ | 递进包含，非替代：Harness 包含 Context Engineering，Context 包含 Prompt。 |
| 小 Demo 也要五层全建吗？ | 不要。按"何时必须建"六条标准判断，一次性任务过度工程是反模式。 |
| 安全和能力冲突怎么办？ | 安全放钩子层做确定性拦截，能力留给模型；最小权限 + 审计日志，不靠模型自觉。 |
| 怎么证明我的 Harness 改好了？ | 固定模型做对照实验（Anthropic 法）：只改 Harness 跑同一组任务，看成功率漂移；<3pp 的差异要警惕是配置噪声。 |
