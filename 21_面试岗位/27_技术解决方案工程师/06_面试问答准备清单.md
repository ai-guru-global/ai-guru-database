# 正式面试问答准备清单 (Interview Q&A Checklist)

> 中文简称：面试问答准备清单

> **一句话理解**: 把面试可能被问到的问题按 8 组拆开，每题给出答题要点和自检框——答完一题勾一格，全勾满就是准备完成。

---

## 使用方法

1. 每题先**脱稿讲一遍**，再对照"答题要点"补漏。
2. 标记 ⭐ 的是**高概率必考题**（来自招聘方沟通中的明确信号）。
3. 答题总原则（招聘方口径）：**上层讲方法论，下层讲工程化与隔离，自然引出沙箱需求**。

---

## 第 1 组：自我介绍与转岗动机

### 1.1 ⭐ 请做个自我介绍（3 分钟版）

**要点**：SDK/AISTack 二线专家工单（llm、sg、lang、vllm）→ 运维智能体建设（80% 覆盖率、>40% 直推）→ 个人实践（AgentUp 开源、数字人）→ 求职动机一句话收尾。

- [ ] 3 分钟版脱稿 ≤3 遍通过

### 1.2 ⭐ 为什么选择这个岗位？（招聘方明确提示：深圳还有其他方向机会）

**要点**（三段式，详见 05 文档第 5 章）：
1. 地理：大团队在杭州，仅我一人在深圳 → 本地团队协作融入最优；
2. 职业发展：走技术深钻路线，本岗位是"客户场景 × Agent Infra × 产品迭代"交点；
3. 兴趣：运维智能体、AgentUp、数字人都是自发的 Agent 实践，与"沙箱是刚需"判断一致。

- [ ] 三段式讲熟，避免只答"离家近"

### 1.3 为什么想转岗 / 离开现在团队？

**要点**：正向表述——不是逃离，是选择；现团队整体在杭州，异地协作限制发挥，深圳团队能让我把 Agent 实践经验直接复用到新业务。

- [ ] 不吐槽现团队/老板

### 1.4 你的职业规划是什么？

**要点**：沟通中已答过——继续走技术路线，不追求快速晋升，把技术做深、多做优质案例。保持口径一致。

- [ ] 与沟通记录口径一致

---

## 第 2 组：技术案例深挖（四层结构）

### 2.1 ⭐ 讲一个你最有挑战的技术案例

**要点**：按"问题 → 表现 → 解决手段 → 底层原理"四层；首选**运维智能体**（见 05 文档案例 1）。

- [ ] 四层齐全，3 分钟版脱稿
- [ ] hub-spoke 架构图能手绘

### 2.2 ⭐ 运维智能体追问链（招聘方已听过一遍，会往深处问）

| 追问 | 答题要点 |
|------|---------|
| 为什么蒸馏成技能而不是直接塞代码库？ | 上下文预算 vs 信噪比；检索命中率；技能化便于复用与评测 |
| hub-spoke 为什么优于单体 Agent？ | 路由降复杂度、技能隔离爆炸半径、独立迭代 |
| 分支判断树解决什么问题？ | 高频问题走确定性路径保可靠性，LLM 只兜长尾 |
| 场景覆盖率 80% 怎么算的？ | 准备统计口径：场景总数/命中数定义 |
| >40% 直推怎么保证质量？ | 脱敏 + 隔离 + 人工确认机制 |
| 数据怎么隔离的？ | 脱敏流程 + 客户数据边界，讲清具体机制 |
| 本地五六十个仓库怎么检索？ | 全量检索方案、索引更新频率 |

- [ ] 每个追问写出 3 句以内的答案

### 2.3 讲一个 vLLM/SGLang/LLM 工单排查案例

**要点**：按 05 文档案例 2 骨架写好 2 个，落到 KV cache / PagedAttention / 并行通信 / 批调度等机制层。

- [ ] 2 个案例各 3 分钟版

### 2.4 AISTack 是什么？你做了什么？

**要点**：轻量方案让用户快速跑 PPU；整合 SG + vLLM；预配置最佳实践命令保证缓存命中率与首 token 响应；薄 UI + 厚预设 = 降低决策成本。

- [ ] 能展开"前缀缓存为什么能降 TTFT"

### 2.5 AgentUp / 双飞卷是什么？为什么开源？

**要点**：把私有 Agent 蒸馏实践抽象成通用开源方案（代码蒸馏生成技能和知识库）→ 展现抽象能力与自驱力。准备 GitHub 链接与 star 情况。

- [ ] 链接/demo 备好，讲清与运维智能体的方法论同源

### 2.6 数字人项目怎么落地的？

**要点**：个人爱好 → 接入 IM 做私域运营 → 业务闭环闭环（获客/留存），证明"AI 能力包装成付费场景"的产品感觉。

- [ ] 一句话讲清商业模式

---

## 第 3 组：Agent 知识（四维逻辑链）

### 3.1 ⭐ 用四个维度讲 Agent（招聘方布置的作业）

**要点**：行业趋势 → 组件原理 → 落地实践 → 底层资源 → 收束到"Agent Infra + 沙箱"（见 05 文档第 2 章）。

- [ ] 2 分钟版脱稿 ×3 遍通过

### 3.2 ⭐ 90% Agent 项目会废弃，你怎么看？

**要点**：判断标准是"能否解决生产问题或办公提效预期"；收敛为办公提效 + 生产集成两类；活下来的 10% 成为核心生产力。（沟通中双方已达成一致，保持口径）

- [ ] 能举出收敛两类的实例各 1 个

### 3.3 Agent 的核心组件有哪些？

**要点**：模型推理（vLLM/SG）、Harness（工具/循环/护栏/评测）、沙箱（执行隔离）、存储、观测、上下文管理——对应 JD 中"云沙箱组合安全、存储、观测、上下文管理"。

- [ ] 每个组件能讲 1 句原理 + 1 句在方案中的角色

### 3.4 给没有云启平台的客户，怎么讲 Agent 部署、运行与隔离？（招聘方点名）

**要点**：三步——① 部署：算力选型 + 推理服务搭建；② 运行：Harness 工程（工具接入、循环控制、评测回归）；③ 隔离：每会话沙箱 + 数据脱敏 + 网络策略。没有托管平台时这三层都要客户自建，**顺势引出我方方案价值**。

- [ ] 三步各写 3 句话

### 3.5 什么是 Harness 工程？（JD 原文要求）

**要点**：Agent 的"驾驶舱工程"——工具管理、执行循环、护栏、状态与记忆、评测与可观测；好 Harness 决定 Agent 从 Demo 到生产的转化率。

- [ ] 能用一个实际项目的 Harness 拆解说明

---

## 第 4 组：沙箱专项（核心售卖产品）

### 4.1 ⭐ 沙箱解决什么问题？

**要点**：三价值——数据安全隔离（客户最关心）、资源隔离、生命周期管理；Agent 执行不可信代码是根因。（金句口径见 03 文档）

- [ ] 30 秒版 + 2 分钟版各讲熟

### 4.2 ⭐ 容器为什么不够？必须上沙箱？

**要点**：namespace/cgroup 共享内核 → 内核漏洞可逃逸（runc CVE 类）；多租户场景容器只是兜底不是隔离边界。

- [ ] 能说出至少 1 个真实逃逸漏洞类型

### 4.3 ⭐ 对比开源沙箱方案，我方优势在哪？（招聘方明确要求）

**要点**：9 维度选型框架（隔离/启动/密度/快照/FS/网络/GPU/K8s/生态）+ 四段式话术（场景切入→开源拼装成本→我方优势→引导提问），见 04 文档第 3、4 章。

- [ ] 核实 "GV 方案 / Cube CloudBoss" 准确项目名
- [ ] gVisor vs Firecracker vs Kata 各 30 秒讲清
- [ ] 3 分钟宣讲脚本脱稿 ×3 遍

### 4.4 客户说"我们就用 Docker 跑，为什么要买沙箱"？

**要点**：Docker 适合单租户内网；多用户在线 Agent 场景 = 逃逸风险 + noisy neighbor + 合规审计 → 给一个"风险场景故事"（用户 A 读到用户 B 数据）再引方案。

- [ ] 风险场景故事写好

### 4.5 沙箱冷启动慢怎么优化？

**要点**：预热池、镜像懒加载、快照恢复、内存页共享——连接到"Agent 会话要毫秒级创建"的业务诉求。

- [ ] 每个手段一句话机制

### 4.6 GPU Agent 沙箱的难点？

**要点**：设备直通 vs GPU 虚拟化（vGPU/MIG）、显存配额、调度排队、成本分摊——顺势讲我方算力优势。

- [ ] MIG 与 vGPU 区别一句话

## 第 5 组：弹性计算产品与云架构

### 5.1 ECS / 容器（ACK）/ 云沙箱三者怎么协同？（JD 产品线）

**要点**：ECS = 底座算力；ACK = 容器编排与生态；沙箱 = 面向 Agent 会话的隔离执行层——同一客户方案里三层如何叠。

- [ ] 画一张三层协同图

### 5.2 设计一个高可用/高扩展的云架构（JD 要求）

**要点**：多 AZ、无状态服务 + 弹性伸缩、负载均衡、数据层复制、故障演练——准备一个 5 分钟白板模板。

- [ ] 白板模板画 1 遍

### 5.3 我方 vs AWS/GCP/Azure 的 Agent 基础设施差异？

**要点**：准备 1 张对比表（沙箱产品、推理生态、国内合规、价格），**不确定的参数标注"待核实"**，面试时诚实说会后补。

- [ ] 对比表做完，存疑处标注

### 5.4 你了解阿里云哪些弹性计算产品？

**要点**：面试前过一遍官网产品页：ECS 实例族、ACK、沙箱相关产品。**列出不认识的产品名，面前列清。**

- [ ] 产品清单过一遍

---

## 第 6 组：方案设计与售前场景题

### 6.1 ⭐ 客户要做客服 Agent，你怎么出方案？（场景演练）

**要点**：四段式——需求挖掘（并发/数据/合规）→ 架构（推理 + Harness + 沙箱 + 观测）→ POC 范围与指标 → 商务（算力 + 沙箱打包）。**每一步都要问客户问题，而不是直接给答案。**

- [ ] 5 分钟方案宣讲 ×2 遍

### 6.2 POC 怎么推动到生产转化？（JD 核心 KPI）

**要点**：POC 前定成功指标 → 过程中周报可见 → 失败项给修复计划 → 生产化清单（安全/监控/SLA/成本）→ 用数据说服管理层。

- [ ] 准备一个"POC 指标怎么定"的例子

### 6.3 怎么影响客户的不同团队（基础设施/工程/算法）？（JD 第 5 条）

**要点**：三类人三种语言——基础设施讲隔离与成本、工程讲集成与运维、算法讲模型效果与迭代；用同一份方案的三个切面。

- [ ] 每类人 2 句话切入

### 6.4 从客户诉求中怎么抽象出产品需求？（JD 第 4 条）

**要点**：用自己例子——工单高频问题 → 抽象成"技能蒸馏"能力需求 → 推动产品化；讲清信息收集→模式归类→需求描述→产研对齐链路。

- [ ] 一个真实抽象案例写好

---

## 第 7 组：行为面与软技能

### 7.1 ⭐ 讲一次跨团队协作解决复杂问题

**要点**：STAR；突出"快速协调所需资源，推动复杂技术问题定位"（JD 第 6 条原文）。

- [ ] STAR 四段各 2 句

### 7.2 讲一次抗压/救火经历

**要点**：线上故障或工单爆炸场景，重点在情绪稳定 + 拆解步骤 + 复盘机制。

- [ ] 准备 1 个带数据的结果（恢复时长/影响面）

### 7.3 你的优缺点？

**要点**：优点=自驱与动手（用开源项目佐证）；缺点=给真实但不致命的，并说明改进动作。

- [ ] 缺点有改进证据

### 7.4 能接受出差吗？（JD 明确写了出差频率）

**要点**：直接爽快答应，可补充"客户现场是方案落地的一部分"。

- [ ] 不犹豫

### 7.5 最近在学什么新技术？（自驱力/好奇心，JD 第 7 条）

**要点**：沙箱技术（正在补）、Agent Infra 新趋势、某开源项目动手实践——与面试准备本身联动。

- [ ] 准备 2 个具体学习动作和产出

## 第 8 组：反问环节（准备 3–5 个）

建议按"业务 → 团队 → 成长"梯度：

- [ ] 团队今年沙箱增长目标里，新同学最能贡献的切入点是什么？
- [ ] 团队里做得最好的 Solution 是什么样子？（问成功标准）
- [ ] Agent Infra 方案目前客户落地最大的卡点是哪个环节？
- [ ] 转岗后前 3 个月的期望是什么？
- [ ] 后续流程与时间线（面试后多久有反馈）？

**避免**：第一轮就问加班/薪资（留给 HR 轮）。
