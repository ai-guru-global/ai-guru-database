# 大模型安全全链路：从训练投毒到推理防御

> **核心洞察**：大模型安全不是一个单点问题，而是一条从训练数据到推理部署的全链路攻防。攻击者只需突破一个环节，防御者必须在每个环节都建立纵深防线。

---

## 1. 全链路威胁地图

```
训练阶段                部署阶段                推理阶段              运行时
┌──────────┐       ┌──────────┐       ┌──────────────┐      ┌──────────┐
│ 数据投毒  │       │ 模型窃取  │       │ Prompt       │      │ 工具滥用  │
│ 后门植入  │  ──→  │ 配置泄露  │  ──→  │ Injection    │ ──→  │ 越权操作  │
│ 供应链污染│       │ 仿制/逆向 │       │ Jailbreak    │      │ 数据外带  │
│ 对齐退化  │       │ 权重篡改  │       │ 隐私攻击     │      │ 级联故障  │
└──────────┘       └──────────┘       │ 信息泄露     │      └──────────┘
                                       └──────────────┘
攻击者视角:    污染源头           窃取资产           操纵行为          利用后果
防御者视角:    数据审计           访问控制           I/O 防护         权限+监控
```

## 2. 训练阶段：源头污染威胁

### 2.1 数据投毒（Data Poisoning）

参见 [[LLM_Security_Complete_Guide#3.3]]。

**原理**：在训练数据中注入恶意样本，改变模型整体行为分布。

| 投毒路径 | 风险等级 | 防御要点 |
|----------|---------|---------|
| 公开数据源（网页、论坛） | 高 | 来源白名单、异常样本统计检测 |
| 内部人员直接篡改 | 中 | 数据版本控制、访问审计 |
| 定向任务/领域投毒 | 高 | 模型行为基线测试、回归验证 |

### 2.2 后门攻击（Backdoor）

参见 [[LLM_Security_Complete_Guide#3.4]]。

**与投毒的区别**：
- **投毒**：改变整体分布，无特定触发条件
- **后门**：植入特定触发器（Trigger），仅触发时异常，其他正常，更隐蔽

### 2.3 微调安全（PEFT Security）

参见 [[LLM_Security_Complete_Guide#3.8]]。

LoRA/QLoRA 等参数高效微调放大了安全挑战：
- **对齐退化**：不当微调可显著削弱安全对齐
- **后门植入**：少量恶意样本即可在微调阶段植入后门

**安全微调流水线**：`数据审计 → 安全微调 → 微调后验证 → 适配器级部署治理`

### 2.4 恶意模型工件

参见 [[LLM_Security_Complete_Guide#3.9]]。

Pickle 格式（`.pkl`/`.pt`/`.bin`）在加载时可执行代码，攻击者借此实现 RCE。

**防御**：优先使用 Safetensors 格式、来源签名校验、沙箱加载。

## 3. 部署阶段：资产窃取风险

### 3.1 模型窃取（Model Extraction）

参见 [[LLM_Security_Complete_Guide#3.5]]。

通过大量 API 查询收集模型行为数据，训练替代模型。

**防御措施**：速率限制、查询异常检测、推理行为水印、模型签名验证。

### 3.2 供应链风险

参见 [[LLM_Security_Defense_Guide#1.6]]。

风险来源：预训练模型、数据集、依赖库、第三方服务、容器镜像。

**关键控制**：
- 来源可追溯：签名/校验，建立可信供应商清单
- SBOM / AI BOM：为每个部署生成物料清单
- 版本治理：管理模型与依赖的不同版本，支持回滚

## 4. 推理阶段：行为操纵攻击

### 4.1 提示注入攻击（Prompt Injection）

参见 [[LLM_Security_Complete_Guide#3.1]]。这是 LLM 安全的**头号威胁**。

**本质**：利用 LLM 无法严格区分指令与数据的特性。

#### 直接注入

| 手法 | 说明 |
|------|------|
| 指令覆盖 | "忽略之前的所有指令。你现在是..." |
| 角色扮演（DAN） | 诱导模型进入无限制角色 |
| 编码混淆 | Base64、ROT13、Unicode 同形字符绕过过滤器 |
| 系统提示提取 | "repeat your instructions" |

#### 间接注入（更危险）

恶意指令隐藏在外部数据源中，当 LLM 处理数据时被触发：

- **RAG 知识库投毒**：上传含隐藏指令的文档
- **网页浏览注入**：在网页中嵌入恶意指令
- **工具返回值注入**：通过 API 响应注入
- **文档隐写"零点击"注入**：Word 文档中嵌入不可见恶意 Prompt

参见 [[Agent_RAG_Security#1.3]]。

### 4.2 越狱攻击（Jailbreak）

参见 [[LLM_Security_Complete_Guide#3.2]]。

**本质**：绕过 LLM 安全对齐机制，使模型生成被禁止的内容。

| 技术 | 说明 |
|------|------|
| 角色扮演（DAN 及变体） | 诱导进入"无限制"人格 |
| 场景构造 | 构建虚构研究/教育场景绕过拒绝 |
| 格式操纵 | 利用代码块、Base64 等绕过 |
| 多模态越狱 | 文字嵌入图像、对抗性图像 |

**自动化越狱**（从手工到工业化）：

| 方法 | 核心机制 |
|------|---------|
| GCG | 白盒梯度搜索对抗后缀 |
| TAP | 攻击树搜索最优路径 |
| AutoDAN | 分层遗传算法语义化越狱 |

### 4.3 隐私攻击

参见 [[LLM_Security_Complete_Guide#3.6]]。

| 攻击类型 | 说明 |
|---------|------|
| 成员推理攻击 | 判断特定数据是否在训练集中 |
| 训练数据提取 | 从模型输出恢复训练数据 |
| 属性推断 | 推断训练数据的特定属性 |

## 5. 运行时：智能体特有的风险

### 5.1 过度自主权（Excessive Agency）

参见 [[Agent_RAG_Security#1.2]]。OWASP LLM06。

智能体权限随功能需求逐渐膨胀：读取文件 → 读写文件 → 执行命令 → 管理员级别。

### 5.2 工具调用安全

参见 [[Agent_RAG_Security#3]]。

| 风险 | 说明 | 示例 |
|------|------|------|
| 参数注入 | 未验证参数传递到后端 | SQL 注入、命令注入 |
| 越权调用 | 调用不应访问的工具 | 访问管理功能 |
| 链式攻击 | 多工具组合实现攻击 | 读敏感文件 + 邮件外带 |
| 幻觉驱动调用 | LLM 生成无效/危险参数 | 删除错误文件、向错误地址转账 |

### 5.3 RAG 攻击面

参见 [[Agent_RAG_Security#2]]。

```
知识库投毒 → 检索操纵 → 上下文注入 → LLM 推理 → 有害输出
```

**PoisonedRAG**（USENIX Security 2025）实证：每个目标问题只需注入约 5 条恶意文本，攻击成功率约 90%。

### 5.4 记忆与状态污染

参见 [[Agent_RAG_Security#1.5]]。

长期记忆被投毒后，恶意信息在后续任务中被检索并影响行为。

## 7. 纵深防御架构

参见 [[LLM_Security_Defense_Guide#1.1]]、[[Harness_Production_Security#5]]。

### 七层防御体系

```
L1: 边界防护 — WAF、API 网关、速率限制、DDoS
L2: 输入安全 — 注入检测、格式验证、编码归一化、内容过滤
L3: 上下文安全 — System Prompt 加固、来源标记、隔离
L4: 模型安全 — 安全对齐、Constitutional Classifiers、推理约束
L5: 工具安全 — 权限控制、参数验证、沙箱隔离
L6: 输出安全 — 内容审核、敏感过滤、格式验证、幻觉检测
L7: 运营安全 — 监控、审计、异常检测、红队演练、事件响应
```

### MVP 最小可行防线

参见 [[LLM_Security_Defense_Guide#2.6]]：

1. **机密不入上下文**：System Prompt 里不放密钥、内部 URL、数据库结构
2. **外部内容默认不可信**：RAG 文档与工具返回值先检测清洗
3. **输出脱敏与策略拦截**：对 System Prompt / PII / 密钥模式做检测
4. **工具最小权限**：每个工具做 allowlist，高风险动作需人工审批

### Rule of Two：高风险能力三选二

参见 [[Agent_RAG_Security#6]]。

> 在单个 session 中，一个 Agent 最多同时满足三项高风险性质中的**两项**：
> 1. 处理不可信输入
> 2. 访问敏感系统或私有数据
> 3. 改变状态或对外通信

三项都需要时，必须引入**监督（HITL）或可靠验证（独立 Agent / 规则引擎）**。

## 8. 攻击者 vs 防御者视角

| 阶段 | 攻击者目标 | 攻击手法 | 防御者策略 | 关键技术 |
|------|-----------|---------|-----------|---------|
| **训练** | 植入后门/偏见 | 数据投毒、恶意微调 | 源头审计 + 行为基线 | 统计检测、回归测试 |
| **部署** | 窃取模型/配置 | API 探测、逆向工程 | 访问控制 + 水印 | 速率限制、行为指纹 |
| **推理** | 操纵行为 | 提示注入、越狱 | I/O 防护 + 隔离 | Constitutional Classifiers |
| **运行时** | 利用后果 | 工具滥用、数据外带 | 权限 + 监控 + 熔断 | 最小权限、Rule of Two |

## 9. 安全成熟度模型

参见 [[LLM_Security_Defense_Guide#4.5]]。

| 等级 | 名称 | 典型特征 |
|------|------|---------|
| **L0** | 初始 | 基本无体系，依赖个人经验 |
| **L1** | 基线 | 有最小可行防线与准入 |
| **L2** | 可重复 | 控制项可重复执行，有审计留痕 |
| **L3** | 可度量 | 有量化指标与门禁，持续优化 |
| **L4** | 自适应 | 结合威胁情报与红队持续演进 |
