# FDE 交付证据包

## 为什么需要交付证据包？

**交付证据包 = 下一个项目的销售武器**

每完成一个项目，沉淀结构化的交付证据，用于：
1. **新客户获客**：展示你有能力交付
2. **方法论迭代**：每一次交付都让下一次更好
3. **团队培训**：新人可以从证据包中学习
4. **风险控制**：保护自己，有据可查

## 标准交付证据包结构

```
project-name-delivery-package/
├── 01-discovery/
│   ├── requirements.md           # 需求规格说明
│   ├── stakeholders.md           # 利益相关方地图
│   ├── success-metrics.md        # 成功指标及达成情况
│   └── risk-assessment.md        # 风险评估报告
├── 02-architecture/
│   ├── tech-selection.md         # 技术选型及理由
│   ├── architecture-diagram.png  # 系统架构图
│   ├── deployment-guide.md       # 部署指南
│   └── security-design.md        # 安全设计方案
├── 03-delivery/
│   ├── runbook.md                # 运维手册
│   ├── test-report.md            # 测试报告
│   ├── training-materials.md     # 培训材料
│   └── user-manual.md            # 用户手册
├── 04-iteration/
│   ├── feedback-summary.md       # 用户反馈汇总
│   ├── improvement-plan.md       # 改进计划
│   └── metrics-dashboard.md      # 关键指标仪表盘
└── 05-evidence/
    ├── delivery-evidence.md      # 交付证据总览
    ├── acceptance-letter.pdf     # 客户验收单
    ├── customer-testimonial.md   # 客户证言/推荐信
    └── project-retrospective.md  # 项目复盘
```

## 各文件模板要点

### requirements.md
- 原始需求 vs 最终需求对比
- 需求变更记录
- 未实现的需求及原因

### architecture-diagram.png
- 必须包含：组件关系、数据流、网络边界
- 推荐工具：Excalidraw / Draw.io / Mermaid

### runbook.md
- 启动/停止/重启步骤
- 常见故障排查
- 备份恢复流程
- 监控指标阈值

### customer-testimonial.md
- 客户原始评价（征得同意后）
- 量化成果（效率提升 X%、成本降低 Y 万）
- 可对外展示的版本（去敏后）

---

> **记住**：没有证据包的交付 = 白做。每次交付都必须留下可复用的资产。
