# Iteration（迭代优化阶段）

## 目标

让系统从"能用"到"好用"到"智能"。交付上线不是终点，**持续产生价值才是**。

## 核心活动

### 1. 反馈收集体系

```
三级反馈机制：

Level 1: 自动采集（零成本）
├── 使用频率（DAU/MAU）
├── 功能使用分布（哪些功能有人在用）
├── 响应时间（端到端延迟）
├── 错误率（4xx/5xx 比例）
└── 搜索无结果率（知识库未覆盖）

Level 2: 主动收集（低成本）
├── 每月 NPS 调研（1 个问题：你会推荐给同事吗？）
├── 核心用户季度访谈（30 分钟/人）
├── 客户对接人月度 sync（15 分钟）
└── 功能投票（让用户选下一个做什么）

Level 3: 深度洞察（中成本）
├── 用户行为路径分析
├── A/B 测试
├── 用户旅程地图
└── 竞品对比分析
```

### 2. 数据飞轮

```
使用 → 数据 → 洞察 → 优化 → 更好用 → 更多使用
  ↑_____________________________________________↓

每个循环的产出：
├── 哪些知识库内容需要更新？
├── 哪些 Prompt 需要调优？
├── 哪些功能没人用可以砍掉？
└── 哪些场景用户自己发明了新用法？
```

### 3. 模型持续优化

| 优化维度 | 方法 | 频率 |
|---|---|---|
| Prompt 优化 | 分析 bad case + A/B 测试 | 每两周 |
| 知识库更新 | 增量导入 + 过期清理 | 每周 |
| 模型微调 | 收集用户反馈数据做 LoRA | 每季度 |
| 模型升级 | 升级到更强模型 | 每半年 |

### 4. 运维效率提升

```
从救火 → 防火 → 自动化

阶段1（救火）：用户报修 → FDE 手动处理
阶段2（防火）：监控告警 → FDE 主动发现
阶段3（自动）：自动诊断 → 自动修复 → FDE 只需审核
```

### 5. 范围管理与增购

```
客户：“能不能顺便做一下 XXX？”

判断框架：
├── 这个需求对多少用户有价值？（1个 vs 所有人）
├── 投入产出比如何？（1天 vs 1个月）
├── 是否在核心路线上？（偏离核心功能吗？）
└── 客户愿意为此付费吗？（新合同还是免费帮忙？）

策略：
✅ 高频高价值 → 纳入迭代计划
✅ 高频低价值 → 标准化为自助功能
⚠️ 低频高价值 → 单独报价（新合同）
❌ 低频低价值 → 礼貌拒绝
```

## 迭代节奏

| 频率 | 内容 |
|---|---|
| 每日 | 自动监控 + 用户反馈群消息 |
| 每周 | Prompt 微调 + 知识库更新 + 小 bug 修复 |
| 每两周 | 功能小版本发布 |
| 每月 | 客户月度报告 + NPS 调研 |
| 每季度 | 功能大版本发布 + 商业复盘 |
| 每半年 | 技术栈升级评估 |

```

├── 活跃用户：XX 人（环比 +X%）

└── 系统可用性：XX.XX%
```

> **迭代哲学**：**不追求一次做对，追求快速修正。** 上线只是开始，持续优化才是 FDE 的真正价值。
