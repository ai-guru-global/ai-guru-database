# 10 MLOps 流水线 — 小白版 🔄

> **一句话秒懂**: MLOps 就是 AI 版的"自动化工厂流水线"——从数据处理、模型训练、测试到部署，全流程自动化，让 AI 系统像正规产品一样持续迭代、稳定运行。

## 为什么要学 MLOps？

想象一下：
- 🔄 以前：手动训练模型、手动部署，繁琐又容易出错
- 🔄 现在：代码提交自动触发训练、测试、部署，省时省力
- 📊 以前：不知道哪个版本的模型效果更好
- 📊 现在：所有版本都有记录，随时可以回滚

**MLOps = Machine Learning + DevOps（机器学习 + 开发运维）**

## MLOps 解决什么问题？

```
【没有 MLOps 的痛苦】

数据科学家小王:
- "我上周训练的模型参数是什么来着？" ← 记不住
- "这个数据集是哪个版本？" ← 不知道
- "模型上线后效果怎么样？" ← 没监控
- "线上出 bug 了，回滚到哪个版本？" ← 混乱！

【有了 MLOps】

✅ 每次训练自动记录参数、数据版本、结果
✅ 自动化测试，不合格的模型不让上线
✅ 监控模型在生产环境的性能
✅ 一键回滚到稳定版本
```

## 核心工具

| 阶段 | 工具 | 作用 |
|------|------|------|
| 数据版本 | DVC | 像 Git 一样管理数据和模型版本 |
| 实验追踪 | MLflow, W&B | 记录每次实验的参数和结果 |
| 模型管理 | MLflow, Vertex AI | 统一管理所有模型 |
| CI/CD | GitHub Actions, Jenkins | 自动化构建和部署 |
| 监控 | Prometheus, Grafana | 监控模型性能 |

## 与 DevOps 的区别

```
【DevOps】
代码 → 构建 → 测试 → 部署 → 监控

【MLOps】
代码 + 数据 → 构建 → 训练 → 测试 → 部署 → 监控
              ↑
         多了数据处理
         多了模型训练
         多了模型验证
```

## 应用场景

### 1. 持续训练

```
场景: 电商推荐模型需要每天更新

MLOps 流程:
1. 每天凌晨自动获取最新数据
2. 自动训练新模型
3. 自动在测试集评估
4. 达到指标则自动部署
5. 没达到则告警人工检查
```

### 2. 快速迭代

```
场景: NLP 模型需要快速迭代新功能

MLOps 流程:
1. 开发者提交代码
2. 自动触发训练和测试
3. 通过则部署到预发环境
4. 通过预发验证则部署到生产
全程自动化，代码提交到上线只需 30 分钟！
```

## MLOps核心流程对比

| 阶段 | 关键活动 | 工具链 | 质量指标 |
|------|----------|--------|----------|
| 数据管理 | 采集/清洗/标注/版本化 | DVC/LakeFS/Label Studio | 数据质量分/覆盖率 |
| 模型训练 | 实验管理/超参搜索/分布式训练 | MLflow/W&B/Ray | 收敛速度/最终精度 |
| 模型评估 | 离线评估/对比实验/偏差检测 | Great Expectations/Evidently | 准确率/公平性指标 |
| 模型部署 | 容器化/服务化/灰度发布 | K8s/Seldon/vLLM | 延迟/吞吐/可用性 |
| 模型监控 | 漂移检测/性能退化/告警 | Prometheus/Evidently/Grafana | 漂移分数/告警准确率 |
| 模型迭代 | A/B测试/自动重训/版本回滚 | Argo/Kubeflow/MLflow | 迭代周期/线上指标 |

## 常见运维问题与解决方案

| 问题 | 根因 | 解决方案 | 预防措施 |
|------|------|----------|----------|
| 模型性能退化 | 数据分布漂移 | 触发重训/回滚 | 漂移监控+自动告警 |
| 推理延迟飙升 | 流量突增/资源不足 | 自动扩容+限流 | 容量规划+压测 |
| GPU OOM | 批处理过大/显存泄漏 | 减小batch/重启 | 显存监控+限制 |
| 数据管道中断 | 上游变更/格式错误 | Schema验证+告警 | 契约测试+版本化 |
| 模型版本混乱 | 缺乏版本管理 | MLflow统一注册 | 强制版本化流程 |
