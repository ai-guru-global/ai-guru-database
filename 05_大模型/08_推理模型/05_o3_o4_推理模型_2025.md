# OpenAI o3 与 o4-mini：新一代推理模型深度解析（2025）

> 中文简称：OpenAI o3 与 o4-mini：新一代推理模型深度解析

> **一句话理解**: o3 和 o4-mini 不是"更大的 GPT"，而是"会用工具思考的推理专家"——它们在思考过程中主动调用代码执行、网络搜索等工具，推理能力因此产生质的飞跃。

---

## TL;DR

- **o3** (2025年4月正式版)：多模态推理 + 思考中工具调用，在数学/科学/编程上达到或超越人类专家水平
- **o4-mini**：轻量高效版，成本仅为 o3 的 1/5，STEM 能力仍超过 o1
- **核心突破**：思考过程中可以调用工具（Code Interpreter、搜索），不再是"纯语言推理"
- **训练方法**：大规模强化学习 + 过程奖励模型（PRM）+ 自适应计算预算

## 1. o1 到 o3/o4-mini 的演进路径

### 1.1 o 系列时间线

```
2024年9月  o1-preview   → 第一代推理模型，内部链式思考，数学/科学突破
2024年12月 o1           → 正式版，多模态支持（图像理解）
2025年1月  o3-mini      → 轻量快速版，STEM 性能超越 o1
2025年4月  o3           → 旗舰推理模型，思考中工具调用
2025年4月  o4-mini      → 新一代高效版，超越 o1 全线指标
```

### 1.2 o1 的核心局限

o1 的突破是让模型"多想"，但存在几个核心局限：

| 局限 | 描述 | o3/o4-mini 的解决方案 |
|------|------|----------------------|
| 思考过程封闭 | 内部 CoT 不可见/不可干预 | 部分可见 thinking traces |
| 工具调用在思考外 | 先思考后用工具，非交织 | 思考过程中可调用工具 |
| 纯语言推理 | 数值计算、搜索需单独步骤 | 内嵌代码执行验证 |
| 图像理解弱 | 对视觉内容推理能力不足 | o3 原生多模态推理 |

### 1.3 架构演进对比

```
o1 推理流程：
用户问题 → [隐式长思维链] → 最终答案

o3/o4-mini 推理流程：
用户问题 → [思考: 分析问题]
         → [思考: 需要计算 → 调用 code_interpreter]
         → [代码执行: 返回结果]
         → [思考: 验证结果是否合理]
         → [思考: 需要查证 → 调用 web_search]
         → [搜索结果: ...]
         → [思考: 综合分析]
         → 最终答案
```

## 2. o3 核心架构与能力

### 2.1 关键技术特征

**多模态原生推理**

o3 不是"语言模型 + 图像编码器"的拼接，而是在推理阶段本身整合了视觉信息：

```
传统多模态 LLM：图像 → 图像特征 → 拼接文本 → 语言模型处理
o3 多模态推理：图像/文本 → 统一思考空间 → 可以在"思考"中来回参考图像细节
```

**自适应思考预算（Adaptive Thinking Budget）**

o3 引入了思考预算的概念，用户可以控制模型"想多久"：

```python
from openai import OpenAI

client = OpenAI()

# 快速模式（较少思考）
response_fast = client.chat.completions.create(
    model="o3",
    messages=[{"role": "user", "content": "解方程 2x+3=7"}],
    reasoning_effort="low"  # low / medium / high
)

# 深度推理模式（充分思考，更准确）
response_deep = client.chat.completions.create(
    model="o3",
    messages=[{"role": "user", "content": "证明黎曼猜想的一个特殊情形"}],
    reasoning_effort="high"
)
```

**思考 Token 可见性**

```python
# 获取思考过程（部分可见）
response = client.chat.completions.create(
    model="o3",
    messages=[{"role": "user", "content": "分析这段代码的时间复杂度"}],
    include=["reasoning"]  # 请求包含推理摘要
)

# reasoning_content 包含思考摘要（非完整 CoT）
thinking_summary = response.choices[0].message.reasoning_content
final_answer = response.choices[0].message.content
```

### 3.1 设计目标

o4-mini 的设计目标是在 STEM 任务上**以 o1 成本的 1/5 匹配甚至超越 o1 性能**：

```
o3         输入: $10    输出: $40    思考: $10
o4-mini    输入: $1.1   输出: $4.4   思考: $1.1

o4-mini 成本约为 o3 的 11%，约为 o1 的 7%
```

**结论**：对于 STEM/编程任务，o4-mini 是明显更优的选择（更便宜且更准确）。

## 4. 思考中工具调用：最关键的突破

### 4.1 什么是"思考中工具调用"？

这是 o3/o4-mini 相比 o1 最本质的进步：

**o1 的方式（思考和工具调用分离）**：
```
1. 模型生成内部思考链（纯语言）
2. 思考完毕后，决定调用工具
3. 工具返回结果
4. 模型再次生成语言输出（不再"思考"）
```

**o3/o4-mini 的方式（思考中融合工具调用）**：
```
1. 开始思考：「这道题需要数值计算...」
2. 思考中调用工具：→ [执行 Python 代码: numpy 计算]
3. 继续思考：「结果是 42.7，但这合理吗？让我验证...」
4. 再次调用工具：→ [执行验证代码]
5. 继续思考：「验证通过，但还需要查证参数...」
6. 调用搜索：→ [搜索: 最新参数值]
7. 最终输出基于完整推理+工具结果的答案
```

### 4.2 工具调用内置化的技术实现

```python
# o3/o4-mini 内置工具：无需手动定义
response = client.chat.completions.create(
    model="o4-mini",
    messages=[{
        "role": "user",
        "content": "分析 2020-2024 年中国 GDP 增长趋势，生成可视化图表"
    }],
    tools=[
        {"type": "code_interpreter"},  # 代码执行（自动使用）
        {"type": "web_search_preview"}  # 网络搜索（自动使用）
    ]
)

# 模型会在思考过程中自动决定何时调用哪个工具
# 用户无需管理工具调用细节
```

### 4.3 代码执行作为验证工具

o3/o4-mini 最大的实际价值在于用**代码执行**替代"语言猜测"：

```
数学问题的传统 LLM 方式：
问：1337 * 8712 = ?
答：让我计算... 1337 * 8000 = 10,696,000, 1337 * 712 = 951,944
    总计约 11,648,000（存在计算错误风险）

o3/o4-mini 的方式：
思考：这个乘法计算我应该用代码执行确保准确
→ [代码: print(1337 * 8712)]
→ 输出: 11,648,544
答：1,164,8544（精确答案，通过代码验证）
```

## 5. 训练方法：强化学习与奖励模型

### 5.1 整体训练流程

o 系列模型的训练（OpenAI 公开部分）遵循以下框架：

```
阶段 1: 监督预训练（SFT）
- 基础语言能力
- 数学、代码、科学知识
- 基础指令跟随

阶段 2: 思维链数据生成
- 合成长推理轨迹
- 人类专家验证（数学/科学问题）
- 过程级别标注（每个推理步骤是否正确）

阶段 3: 大规模强化学习
- 结果奖励: 最终答案是否正确（0/1）
- 过程奖励: 每个思考步骤的质量（由 PRM 评估）
- RLHF 精调: 对齐人类偏好
- 安全约束: 拒绝有害请求

阶段 4: 思考预算优化
- 训练模型根据问题难度分配思考量
- 避免"过度思考"（简单问题）
- 确保"充分思考"（复杂问题）
```

### 5.2 结果奖励 vs 过程奖励

**结果奖励模型（Outcome Reward Model, ORM）**：

```python
# ORM 只关心最终答案是否正确
def orm_reward(problem: str, reasoning: str, final_answer: str) -> float:
    correct_answer = get_ground_truth(problem)
    return 1.0 if final_answer.strip() == correct_answer else 0.0
```

**局限**：无法区分"碰巧答对"和"正确推理得出答案"。

**过程奖励模型（Process Reward Model, PRM）**：

```python
# PRM 评估每个推理步骤
def prm_reward(problem: str, reasoning_steps: list[str]) -> list[float]:
    rewards = []
    for step in reasoning_steps:
        # 评估：这个步骤是否逻辑正确且有助于解题？
        step_score = evaluate_step_quality(problem, step, context=rewards)
        rewards.append(step_score)  # 每步都有奖励信号
    return rewards
```

**PRM 的优势**：

| 维度 | ORM | PRM |
|------|-----|-----|
| 奖励密度 | 稀疏（只有最终结果） | 密集（每步都有信号） |
| 训练效率 | 低（需要大量样本） | 高（更快收敛） |
| 错误定位 | 无法定位错误步骤 | 可精确定位错误步骤 |
| 标注成本 | 低（只需正确答案） | 高（需要步骤级别标注） |
| 推理能力 | 较弱 | 强 |

### 5.3 OpenAI 的 PRM 实现思路

根据 OpenAI 发表的论文 "Let's Verify Step by Step"（2023）：

```
PRM 训练数据构建：
1. 让模型生成多条完整推理轨迹（每道题 N 条）
2. 对每条轨迹，人类标注者标记每个步骤是否正确
3. 用步骤级别标注训练 PRM
4. PRM 的输出：P(step_i is correct | problem, step_1, ..., step_i)

在推理时的使用：
- 使用 Best-of-N 采样：生成 N 条思维链
- PRM 对每条链的每个步骤打分
- 选择 PRM 综合评分最高的思维链作为最终答案
```

## 6. Chain-of-Thought vs Process Reward Models

### 6.1 标准 CoT（Chain-of-Thought）

**2022年 Google Brain 提出**，让模型在回答前逐步思考：

```
标准 CoT 提示：
"解题时，请一步步思考，写出推理过程，最后给出答案。"

效果：GPT-3 级别模型在多步推理任务上准确率 +10~30%
局限：思考步骤质量无法保证，模型可能生成流畅但错误的"伪推理"
```

### 6.2 扩展 CoT（Extended / Long CoT）

o 系列采用的方法，又称 **System 2 Reasoning**：

```
扩展 CoT 的关键特征：
1. 思考 Token 可以远多于输出 Token（o1 典型：思考 2000T，输出 200T）
2. 允许回溯和自我纠正
3. 探索多种解题策略
4. 在思考中进行子问题分解

典型思维链片段：
<thinking>
  这道积分 ∫x²sin(x)dx 需要分部积分...
  设 u = x², dv = sin(x)dx
  则 du = 2x dx, v = -cos(x)
  ∫x²sin(x)dx = -x²cos(x) + 2∫xcos(x)dx
  
  等等，让我再对 ∫xcos(x)dx 做一次分部积分...
  设 u = x, dv = cos(x)dx
  则 du = dx, v = sin(x)
  ∫xcos(x)dx = xsin(x) - ∫sin(x)dx = xsin(x) + cos(x)
  
  所以原式 = -x²cos(x) + 2(xsin(x) + cos(x)) + C
  = -x²cos(x) + 2xsin(x) + 2cos(x) + C
  
  验证：对结果求导应该得到 x²sin(x)
  d/dx[-x²cos(x) + 2xsin(x) + 2cos(x)]
  = -2xcos(x) + x²sin(x) + 2sin(x) + 2xcos(x) - 2sin(x)
  = x²sin(x) ✓
</thinking>

最终答案：-x²cos(x) + 2xsin(x) + 2cos(x) + C
```

### 6.3 CoT 的四个进化层次

```
层次 1: Few-shot CoT（2022）
  - 提示中给出几个思维链示例
  - 模型模仿示例的推理格式
  
层次 2: Zero-shot CoT（2022）
  - 只用"让我一步步想"触发推理
  - 不需要示例
  
层次 3: o1 Extended CoT（2024）
  - 专门训练的隐式长思维链
  - 规模化 RL 训练
  
层次 4: o3/o4-mini Tool-Augmented CoT（2025）
  - 思考中可调用外部工具
  - 代码执行作为"计算验证器"
  - 搜索作为"事实验证器"
```

### 6.4 PRM 如何提升 CoT 质量

```
没有 PRM 的 CoT 训练（ORM only）：
模型学到：只要最终答案对，不管中间推理是否合理
→ 产生"后见之明推理"（Hindsight Reasoning）
→ 推理步骤看起来合理但实际上是逆推

有 PRM 的 CoT 训练：
模型学到：每个推理步骤都需要有意义
→ 推理更可靠、可解释
→ 错误的中间步骤会被惩罚
```

### 7.3 GRPO vs PRM+RL

**DeepSeek 的 GRPO（Group Relative Policy Optimization）**：

```python
# GRPO 的核心思想：用同一问题的多个答案互相比较
# 不需要单独训练奖励模型
def grpo_reward(problem, responses: list[str]) -> list[float]:
    """
    对同一问题的 G 个回答，计算相对奖励
    - 正确答案：得到正奖励
    - 错误答案：得到负奖励
    - 奖励是相对于组内平均的归一化值
    """
    correctness = [verify_answer(r, problem) for r in responses]
    # GRPO 不需要绝对奖励，只需要相对排名
    baseline = sum(correctness) / len(correctness)
    return [c - baseline for c in correctness]
```

**优点**：无需昂贵的 PRM 标注，纯 RL 自举，可发现"顿悟时刻"
**缺点**：训练稳定性较低，需要大量对比样本

```python
# 测试推理能力的代表性题型
```

### 9.3 成本优化策略

```python
# 分层路由：根据任务复杂度选择模型
class ReasoningRouter:
    def __init__(self):
        self.client = OpenAI()

    def classify_complexity(self, task: str) -> str:
        """简单分类器，实际可用 LLM 分类"""
        if any(word in task for word in ["证明", "优化", "分析架构"]):
            return "high"
        elif any(word in task for word in ["计算", "解题", "代码"]):
            return "medium"
        else:
            return "low"

    def route(self, task: str) -> tuple[str, str]:
        complexity = self.classify_complexity(task)
        mapping = {
            "low": ("gpt-4o-mini", "N/A"),    # 不需要推理模型
            "medium": ("o4-mini", "medium"),   # 高效推理
            "high": ("o3", "high")             # 最强推理
        }
        return mapping[complexity]

    async def solve(self, task: str) -> str:
        model, effort = self.route(task)
        kwargs = {"model": model, "messages": [{"role": "user", "content": task}]}
        if effort != "N/A":
            kwargs["reasoning_effort"] = effort
        response = self.client.chat.completions.create(**kwargs)
        return response.choices[0].message.content
```
