# 11 RAG 系统 — 小白版 🔍

> **一句话秒懂**: RAG 就是给 AI 装上"资料库"——让它在回答问题前先查资料，而不是只靠记忆硬答，这样 AI 回答得更准确，还能引用原文出处！

## 为什么要学 RAG？

想象一下：
- 📚 AI 经常"胡说八道"？→ RAG 让 AI 先查资料再回答
- 📄 你想让 AI 看你的公司文档？→ RAG 把文档变成 AI 的知识
- 🔍 AI 回答太抽象？→ RAG 让 AI 基于具体资料回答

**RAG = Retrieval-Augmented Generation（检索增强生成）**

## RAG vs 传统 AI

```
【传统 AI（闭卷考试）】
AI 只靠训练时的记忆回答
✗ 知识有限
✗ 可能"胡说八道"
✗ 不知道最新信息

【RAG AI（开卷考试）】
AI 先查资料，再基于资料回答
✓ 知识无限（取决于资料库）
✓ 回答有据可查
✓ 可以是最新的信息
```

## RAG 工作流程

```
┌─────────────────────────────────────────────────────────┐
│                    RAG 三步走                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  📚 步骤 1: 建立索引（建图书馆）                        │
│                                                         │
│     文档 → 分块 → 向量化 → 存入向量数据库              │
│                                                         │
│  ─────────────────────────────────────────────────────│
│                                                         │
│  🔍 步骤 2: 检索（查资料）                             │
│                                                         │
│     用户问题 → 向量化 → 相似度搜索 → 相关文档          │
│                                                         │
│  ─────────────────────────────────────────────────────│
│                                                         │
│  🤖 步骤 3: 生成（写答案）                             │
│                                                         │
│     用户问题 + 相关文档 → LLM → 回答 + 引用来源        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 核心技术

### 1. 文档切分

```
【问题】文档太长怎么办？

【解决】分块 (Chunking)

方法:
- 固定大小切分（500 tokens 一块）
- 按段落切分
- 按句子切分
- 递归切分（更智能）

关键参数:
- chunk_size: 每块多大
- chunk_overlap: 块之间重叠多少
```

### 2. 向量化

```
【问题】怎么让电脑理解语义？

【解决】Embedding（向量化）

"苹果水果" → [0.12, -0.34, 0.56, ...]
"苹果手机" → [0.13, -0.31, 0.58, ...]
"橙子" → [0.89, 0.12, -0.21, ...]

相似的词，向量也相似！
```

### 3. 向量数据库

```
【作用】存储和检索向量

常见选型:
- Milvus (开源)
- Pinecone (云服务)
- Weaviate (开源)
- Chroma (轻量级)

核心操作:
- 插入向量
- 相似度搜索（Top-K）
```

## RAG 进阶

### 1. 混合检索

```
【问题】纯向量搜索可能遗漏关键词匹配？

【解决】混合检索

混合检索 = 向量检索 + 关键词检索

用户问题: "OpenAI 的 GPT-4 发布于哪一年？"

- 向量检索: 语义相似的内容
- 关键词检索: 精确匹配 "GPT-4"

两者结合，效果更好！
```

### 2. Agentic RAG

```
【问题】复杂问题需要多步推理？

【解决】Agentic RAG

AI Agent 自主决定:
- 查什么资料
- 查几次
- 怎么综合结果

例子:
"对比 BERT 和 GPT 的架构差异"
→ Agent 决定先查 BERT，再查 GPT，再对比
```

### 3. 重排序 (Reranking)

```
【问题】检索结果顺序不对？

【解决】重排序

步骤:
1. 向量检索 → Top 100 结果
2. 重排序模型 → 按相关性重新排序
3. 返回 Top 10 更准确的结果
```

## 应用场景

### 1. 企业知识库

```
场景: 员工问 "年假政策是什么？"

RAG 流程:
1. 在公司文档中检索
2. 找到 HR 手册中的年假政策
3. AI 基于找到的内容回答

优势:
✓ 回答基于真实文档
✓ 员工能看原文出处
✓ 文档更新，AI 答案自动更新
```

### 2. 智能客服

```
场景: 用户问产品问题

RAG 流程:
1. 在产品文档、FAQ 中检索
2. 找到相关信息
3. AI 生成回答

对比传统客服:
✓ 回答更准确
✓ 24 小时服务
✓ 可处理大量并发
```

### 3. 代码助手

```
场景: 开发者问 "怎么用 Python 读取 Excel？"

RAG 流程:
1. 在代码库、文档中检索
2. 找到相关示例
3. AI 结合找到的内容回答

优势:
✓ 基于实际代码回答
✓ 可以引用项目特定代码
```
