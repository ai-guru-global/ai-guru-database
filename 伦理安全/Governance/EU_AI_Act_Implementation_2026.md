# EU AI Act 实施指南 2026

> **一句话理解**: EU AI Act 是全球首部全面的 AI 监管法规，采用基于风险的四级分类体系，2025年8月 GPAI 条款生效，2026年8月高风险系统条款全面执行，违规罚款最高3500万欧元或全球营收7%，对所有在欧盟市场运营 AI 系统的企业具有域外管辖效力。

---

## 1. 概述 (Overview)

### 1.1 立法背景与目的

EU AI Act (Regulation (EU) 2024/1776) 于2024年8月1日正式生效，是全球首部横向覆盖所有AI应用场景的综合性法规。其核心目标：

- **保护基本权利**：确保AI系统不侵犯欧盟公民的基本权利与自由
- **促进创新**：通过明确规则降低法律不确定性，鼓励可信AI开发
- **统一市场**：消除成员国间AI监管碎片化，建立单一市场规则
- **全球标准**：通过"布鲁塞尔效应"(Brussels Effect)输出全球AI治理标准

### 1.2 适用范围与域外效力

```
EU AI Act 管辖范围:

┌─────────────────────────────────────────────────────────────┐
│              Territorial & Extraterritorial Scope             │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  直接适用:                                                    │
│  ├── 在欧盟境内设立/注册的AI系统提供者(Provider)             │
│  ├── 在欧盟境内设立/注册的AI系统部署者(Deployer)             │
│  └── 在欧盟境内的进口商(Importer)和分销商(Distributor)       │
│                                                              │
│  域外管辖 (Article 2):                                        │
│  ├── 在第三国设立但AI系统输出在欧盟内使用的Provider          │
│  ├── 在第三国设立但AI系统输出在欧盟内使用的Deployer          │
│  └── 关键: 中国企业的AI产品若服务欧盟用户，同样受管辖       │
│                                                              │
│  排除适用:                                                    │
│  ├── 军事/国防/国家安全目的                                   │
│  ├── 科学研究与开发(纯研究阶段)                             │
│  └── 开源AI(非商业目的，但GPAI除外)                         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 核心定义

| 术语 | 定义 | 说明 |
|------|------|------|
| AI System | 基于机器的系统，具有不同程度自主性，可生成输出 | 涵盖ML、逻辑推理、统计方法 |
| Provider | 开发AI系统或GPAI模型并投放市场的实体 | 类似"制造商"角色 |
| Deployer | 在其职权范围内使用AI系统的实体 | 类似"使用者"角色 |
| GPAI Model | 通用人工智能模型，具有显著通用性 | 如GPT、Claude、Gemini等 |
| High-risk AI System | 附件III所列高风险领域的AI系统 | 需符合严格合规要求 |

## 2. 风险分级体系 (Risk Classification)

### 2.1 四级风险金字塔

```
风险等级金字塔:

         /\
        /  \        不可接受风险 (Prohibited)
       / 禁止 \     → 完全禁止，无例外
      /________\
     /          \    高风险 (High-risk)
    /   高风险    \   → 严格合规要求 + 上市前评估
   /______________\
  /                \  有限风险 (Limited risk)
 /    有限风险      \  → 透明度义务
/____________________\
/                      \ 最小风险 (Minimal risk)
/      最小风险         \ → 自愿行为准则
/________________________\
```

### 2.2 不可接受风险 (Prohibited Practices) — Article 5

以下AI实践被**完全禁止**，自2025年2月2日起生效：

| 禁止行为 | 具体描述 | 示例 |
|----------|----------|------|
| 潜意识操纵 | 使用潜意识技术实质性扭曲人的行为 | 利用声音/图像进行潜意识广告 |
| 利用脆弱性 | 利用年龄、残疾等脆弱性进行操纵 | 针对儿童的操纵性AI玩具 |
| 社会评分 | 基于社会行为进行评分导致不利待遇 | 类似中国社会信用评分系统 |
| 实时远程生物识别 | 在公共空间进行实时远程生物识别(执法) | 公共场所实时人脸识别(有限例外) |
| 情感识别(工作/教育) | 在工作场所或教育机构进行情感推断 | 面试AI分析候选人情绪 |
| 无差别面部抓取 | 从互联网/监控录像无差别抓取面部图像 | Clearview AI式数据抓取 |
| 预测性执法 | 仅基于画像预测犯罪可能性 | 少数派报告式预防性逮捕 |

**例外条款**：执法中的实时远程生物识别在满足严格条件下可获司法授权（如寻找失踪儿童、防止恐怖袭击）。

### 2.3 高风险AI系统 (High-risk) — Article 6 & Annex III

#### 高风险领域清单

| 领域 | 具体应用 | 典型场景 |
|------|----------|----------|
| 生物识别 | 远程生物识别、情感识别、分类 | 机场安检、身份验证 |
| 关键基础设施 | 交通、水电气、数字基础设施管理 | 智能电网、自动驾驶 |
| 教育与职业培训 | 学习评估、考试评分、入学筛选 | AI阅卷、在线考试监控 |
| 就业与人力资源 | 招聘筛选、绩效评估、解雇决策 | AI简历筛选、员工监控 |
| 基本服务 | 信贷评估、保险定价、紧急服务调度 | AI贷款审批、保险核保 |
| 执法 | 犯罪风险评估、证据分析、测谎 | 预测性警务、AI测谎仪 |
| 移民与边境 | 签证审批、庇护申请评估、边境监控 | AI签证审核系统 |
| 司法与民主 | 法律研究辅助、选举影响 | AI法律分析、竞选内容推荐 |
| 产品安全组件 | 作为受欧盟产品安全法规管辖产品的安全组件 | 医疗器械AI诊断、电梯AI控制 |

#### 高风险系统合规要求 (Article 8-15)

```
高风险AI系统合规清单:

□ 风险管理系统 (Article 9)
  ├── 建立、实施、记录、维护全生命周期风险管理
  ├── 识别和分析已知及可预见风险
  └── 采取适当的风险管理措施

□ 数据治理 (Article 10)
  ├── 训练/验证/测试数据集的质量标准
  ├── 数据相关性、代表性、无错误、完整性
  └── 考虑特定地理/行为/功能环境的数据特征

□ 技术文档 (Article 11)
  ├── 详细技术文档证明合规性
  ├── 附件IV规定的最低内容要素
  └── 上市前完成并持续更新

□ 记录保存 (Article 12)
  ├── 自动记录事件日志(Logging)
  ├── 确保可追溯性(Traceability)
  └── 日志保存期限符合规定

□ 透明度 (Article 13)
  ├── 向Deployer提供使用说明(Instructions for Use)
  ├── 系统能力与局限性的清晰描述
  └── 人类监督措施的说明

□ 人类监督 (Article 14)
  ├── 设计允许有效的人类监督
  ├── 监督人员可理解系统输出
  ├── 监督人员可选择不使用/覆盖/停止系统
  └── 防止"自动化偏见"(Automation Bias)

□ 准确性、鲁棒性、网络安全 (Article 15)
  ├── 达到适当的准确性和鲁棒性水平
  ├── 抵御错误、故障、不一致性
  └── 防范对抗性攻击和数据投毒

□ 合规评估 (Article 43)
  ├── 内部合规评估(大部分领域)
  ├── 第三方合规评估(生物识别等)
  └── CE标志 + EU符合性声明
```

### 2.4 有限风险 (Limited Risk) — 透明度义务

| AI类型 | 透明度要求 | 生效时间 |
|--------|-----------|----------|
| 与人交互的AI (Chatbot) | 告知用户正在与AI交互 | 2026.8 |
| 情感识别/生物分类 | 告知用户正在被AI分析 | 2026.8 |
| AI生成内容 (文本/图像/音频/视频) | 标记为AI生成/操纵 | 2026.8 |
| Deepfake | 明确披露为深度伪造 | 2026.8 |

### 2.5 最小风险 (Minimal Risk)

- 垃圾邮件过滤器、AI游戏NPC、库存管理等
- 无强制义务，鼓励自愿行为准则 (Voluntary Codes of Conduct)
- 占AI应用绑大多数（约80%+）

## 3. GPAI (通用人工智能) 义务

### 3.1 生效时间与适用范围

**2025年8月2日**起，GPAI条款正式生效。适用于：

- 在欧盟市场投放GPAI模型的Provider（含非欧盟企业）
- 具有"系统性风险"(Systemic Risk)的GPAI模型面临额外义务

### 3.2 系统性风险判定标准

```
系统性风险GPAI模型判定:

条件一 (量化标准):
  训练计算量 > 10^25 FLOPs (浮点运算次数)
  → 目前约对应 GPT-4、Claude 3.5、Gemini Ultra 级别

条件二 (定性标准):
  欧盟委员会指定，考虑:
  ├── 模型能力与通用性
  ├── 用户数量与影响范围
  ├── 对内部市场的潜在影响
  └── 对基本权利、安全、民主的潜在风险
```

### 3.3 GPAI Provider 义务清单

| 义务类别 | 所有GPAI模型 | 系统性风险GPAI模型 |
|----------|:---:|:---:|
| 技术文档 (附件XI) | ✅ | ✅ |
| 下游Provider信息提供 (附件XII) | ✅ | ✅ |
| 版权政策 (Copyright Policy) | ✅ | ✅ |
| 训练数据摘要公开 | ✅ | ✅ |
| 模型评估 (含对抗性测试) | — | ✅ |
| 系统性风险评估与缓解 | — | ✅ |
| 严重事件报告 | — | ✅ |
| 网络安全保护 | — | ✅ |
| 向AI Office报告计算量 | — | ✅ |

### 3.4 开源豁免

- 免费开源GPAI模型（非系统性风险）可豁免技术文档和信息提供义务
- 但仍需遵守版权政策和训练数据摘要公开
- 系统性风险模型**不享受**开源豁免

## 4. 合规评估流程

### 4.1 合规评估路径

```
合规评估决策树:

AI系统是否属于禁止行为(Article 5)?
├── 是 → 禁止投放市场，无合规路径
└── 否 → 是否属于高风险(Annex III)?
    ├── 是 → 是否为Annex I产品安全组件?
    │   ├── 是 → 第三方合规评估(Notified Body)
    │   └── 否 → 内部合规评估(Self-assessment)
    │         └── 例外: 远程生物识别 → 第三方评估
    └── 否 → 是否属于有限风险(透明度义务)?
        ├── 是 → 满足透明度要求即可
        └── 否 → 最小风险，自愿准则
```

### 4.2 内部合规评估流程 (Annex VI)

1. **建立质量管理体系** (QMS)
   - 合规策略与程序
   - 设计、开发、测试流程文档
   - 风险管理程序
   - 上市后监控计划

2. **验证技术文档** (Annex IV)
   - 系统一般描述
   - 设计规格与开发过程
   - 训练/验证/测试数据集信息
   - 性能指标与评估结果

3. **签署EU符合性声明** (EU Declaration of Conformity)

4. **加贴CE标志**

5. **在EU数据库注册** (Article 71)

### 4.3 第三方合规评估 (Notified Body)

- 适用于：远程生物识别、Annex I产品安全组件
- 由欧盟成员国指定的认证机构执行
- 评估内容：技术文档审查 + QMS审核 + 系统测试
- 颁发EU技术文档评估证书

## 5. 罚款机制与执法

### 5.1 罚款等级

| 违规类型 | 最高罚款 | 适用情形 |
|----------|----------|----------|
| 违反禁止行为 (Article 5) | **3500万欧元**或全球年营收**7%** (取高者) | 使用被禁止的AI实践 |
| 违反高风险义务 | **1500万欧元**或全球年营收**3%** (取高者) | 不满足高风险合规要求 |
| 违反透明度/其他义务 | **750万欧元**或全球年营收**1%** (取高者) | 不满足透明度要求等 |
| 提供不正确信息 | **750万欧元**或全球年营收**1%** (取高者) | 向监管机构提供虚假信息 |

### 5.2 执法机构

```
执法架构:

EU层面:
├── AI Office (欧盟委员会内)
│   ├── GPAI模型监管
│   ├── 协调成员国执法
│   └── 制定实施指南与标准
├── AI Board (成员国代表)
│   ├── 提供建议与意见
│   └── 促进一致适用
└── Scientific Panel (独立专家)
    └── 技术支持与风险评估

成员国层面:
├── 国家主管当局 (National Competent Authority)
│   ├── 市场监督
│   ├── 合规检查
│   └── 罚款执行
└── 数据保护当局 (DPA)
    └── 涉及个人数据的AI系统
```

### 5.3 执法时间线

- **2025年2月**：禁止行为条款开始执法
- **2025年8月**：GPAI条款开始执法
- **2026年8月**：高风险系统、透明度义务全面执法
- **2027年8月**：Annex I产品安全组件AI全面适用

## 6. 对中国企业的影响

### 6.1 受影响的中国企业类型

| 企业类型 | 影响程度 | 具体影响 |
|----------|----------|----------|
| AI大模型出海企业 (如百度、阿里、字节) | 极高 | GPAI义务全面适用，需技术文档、版权政策 |
| 跨境电商AI工具 (如SHEIN、Temu的推荐算法) | 高 | 可能涉及高风险(消费者影响)或透明度义务 |
| 智能硬件/机器人 (如大疆、小米) | 高 | 产品安全组件AI需第三方评估 |
| SaaS/云服务 (如华为云、阿里云欧洲) | 中高 | 作为AI系统Provider或Deployer |
| 游戏/社交AI (如米哈游、TikTok) | 中 | 透明度义务(与用户交互的AI) |
| 纯国内运营企业 | 低 | 不直接适用，但供应链可能间接受影响 |

### 6.2 中国企业合规要点

1. **域外管辖认知**：只要AI系统输出在欧盟使用，即受管辖
2. **指定授权代表**：非欧盟Provider须在欧盟指定授权代表 (Article 22)
3. **GPAI合规准备**：大模型企业需在2025年8月前完成合规
4. **数据跨境**：与[[GDPR]]数据跨境规则叠加适用
5. **标准对接**：关注CEN/CENELEC制定的协调标准 (Harmonised Standards)

### 6.3 合规成本估算

```
中国企业EU AI Act合规成本估算:

GPAI模型Provider:
├── 法律合规咨询: 50-200万欧元
├── 技术文档编制: 30-100万欧元
├── 合规团队建设: 100-300万欧元/年
├── 模型评估与测试: 50-150万欧元
└── 总计首年: 约230-750万欧元

高风险AI系统Provider:
├── QMS建设: 20-80万欧元
├── 技术文档: 15-50万欧元
├── 合规评估: 10-30万欧元
├── 持续监控: 20-60万欧元/年
└── 总计首年: 约65-220万欧元
```

## 8. 合规技术工具

### 8.1 合规技术栈

| 工具类别 | 代表产品/框架 | 用途 |
|----------|--------------|------|
| AI治理平台 | IBM OpenPages, ServiceNow AI Governance | 全生命周期合规管理 |
| 模型卡片/文档 | Hugging Face Model Cards, MLflow | 技术文档自动化 |
| 偏见检测 | AIF360, Fairlearn, What-If Tool | 数据与模型偏见审计 |
| 可解释性 | SHAP, LIME, Captum | 满足透明度要求 |
| 对抗性测试 | Microsoft Counterfit, ART (Adversarial Robustness Toolbox) | 鲁棒性评估 |
| 数据治理 | Collibra, Alation, Informatica | 数据质量与血缘追踪 |
| 监控与日志 | Evidently AI, WhyLabs, Fiddler | 上市后监控 |
| 隐私保护 | Microsoft Presidio, OpenMined | GDPR + AI Act联合合规 |

### 8.2 合规自动化流程

### 9.3 常见合规陷阱

| 陷阱 | 说明 | 解决方案 |
|------|------|----------|
| 忽视域外管辖 | "我们不在欧盟注册" | 只要输出在欧盟使用即受管辖 |
| 低估分类复杂度 | 同一系统可能跨多个风险等级 | 逐用例评估，取最高风险 |
| 忽视供应链义务 | 仅关注自身，忽视上下游 | 明确Provider/Deployer角色 |
| 文档滞后 | 技术文档未随系统更新 | 建立文档版本控制与更新机制 |
| 形式化合规 | 仅满足纸面要求 | 将合规嵌入开发流程(Compliance by Design) |

### 9.5 中小企业(SME)合规支持

EU AI Act特别考虑了中小企业的合规负担：

- **简化文档**：SME可使用简化版技术文档模板
- **费用减免**：合规评估费用对SME有折扣
- **监管沙盒**：成员国须设立AI监管沙盒(Article 57)
- **优先支持**：AI Office为SME提供优先技术指导
- **过渡期**：部分义务对SME有额外过渡时间
- **标准简化**：协调标准制定考虑SME可操作性
