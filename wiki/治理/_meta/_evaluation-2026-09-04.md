# AI Guru 知识库项目整体评估报告（2026-09-04）

> 中文简称：AI Guru 知识库项目整体评估报告

> **一句话理解**: 对全库内容、治理体系、工具链与前端应用的一次全面体检——骨架 90 分、执行 70 分，断链门禁未闭环是当前唯一高危项。

> **评估日期**: 2026-09-04
> **数据来源**: 自动化脚本当日实测（`工具/count_words.py`、`工具/check_links.py`、`工具/check_wikilinks.py`、`工具/wiki_health.py`、`工具/eval_scan_2026_07.py`）+ git 历史统计，非引用历史报告数据
> **评估范围**: 25 个知识章节 + 概念/治理 图谱层 + 前端应用/ + git 仓库治理
> **方法论**: 内容五维体检（规模 / 链接健康 / 孤立 / tier 规范 / 枢纽密度）+ 治理纸面与执行对照 + 风险清单与建议排序

## 一、执行摘要

**综合评分：4 / 5。骨架（内容结构、治理设计、工具箱）约 90 分；当前执行状态（数据真实性、门禁闭环）约 70 分。**

最大短板不在内容，而在质量门禁未闭环：[[治理/ROADMAP|路线图]] 宣称清零的断链正在静默回归，多套工具的度量口径互相矛盾，治理文档中的关键数字已经失真。所有大问题的修复方案在 [[治理/_meta/_evaluation-2026-07-27|全库评估 2026-07-27]] 中均已给出，当前缺口是执行闭环。

### 核心结论（3 句话）

1. **内容资产仍然优质**：2,821 文件 / 90 万行中，孤立页接近清零（严格语料目录内仅 2 个且均在外部克隆中）、stub 仅 5 个、语料层 tier 规范几乎 100% 达标、枢纽页反向链接健康（最高 41 条入链）——内容基本面是 90 分。
2. **断链两个月恶化约 4 倍**：严口径真断链从 07-27 的 679 次 / 446 唯一目标升至 2,944 次 / 879 唯一目标，根因是目录重组后的 stale_path 残留（1,873 次）；而本应阻断回归的 P2-6「巡检工具 CI 化」至今未落地。
3. **度量口径分裂已造成实际伤害**：文档总数有 2,131 / 2,821 / 3,085 三个答案，断链有 0 / 679 / 2,944 三个答案，[[治理/ROADMAP|路线图]] OKR 的「文档 690 / 683 万字」与实际相差 3 倍以上——没有单一事实源，质量门禁就无法判断改动是变好还是变坏。

### 3.2 断链回归分析（当前最大质量风险）

stale_path 类占 1,873 次（约 62%），典型如 `15_智能体/Agent_Production_Deployment_Runbook`（14 处引用失效）、`11_模型运维/LLM_Guardrails_and_Safety_Ops_2026`（13 处）——均为文件移动 / 重命名后旧路径未同步。bare_name 类 302 次多为 `[[AI_New_Architectures]]` 式裸名称引用。这正是 [[治理/_meta/_evaluation-2026-07-27|07-27 报告]] P0-3「旧路径断链脚本批量映射」要解决但未完成的部分。

防回归机制缺位是关键：[[治理/ROADMAP|路线图]] P2-6（check_wikilinks + orphan_scan 接入 pre-commit / CI，预计 2026-08）至今 ⏳。当前 pre-commit 只拦截 iCloud 同步垃圾文件，拦不住断链——两个月 4 倍恶化即是直接后果。

## 四、治理与工具链：纸面成熟度极高，执行存在断层

### 4.1 亮点（个人项目中罕见）

- **双层 AGENTS.md 契约**：根目录操作手册 + [[治理/AGENTS|安全风险规则]]（每条命令强制风险标签、高危操作禁止自动执行）。
- **完整 Python 维护工具箱**：3 种链接检查器、wiki 健康度、孤立扫描、中英间距修复、断链自动修复、索引生成——纯标准库、可维护性好。
- **治理文档链完整**：「只增不减」原则、页面模板、tier 生命周期、[[治理/Quality_Metrics|质量度量]]、季度审计、带 OKR 的滚动路线图，可追溯性好。
- **诚实的自评估文化**：[[治理/_meta/_evaluation-2026-07-27|07-27 报告]] 主动校准宽口径假象（5.0 → 4.6），不掩盖问题。

### 4.2 断层（纸面与现实的差距）

1. **度量口径分裂**：五套工具五种范围（见 §4.3），[[治理/ROADMAP|路线图]] 关键指标「文档 690 / 683 万字」对照实际 2,821 文件 / 1,928 万字符相差 3 倍。
2. **[[治理/KNOWN_ISSUES|已知问题]]与仓库现实脱节**：记录的是 GPU 显存碎片化、流式响应中断等 AI 应用运行时问题（疑似模板演示内容），仓库真实问题（断链回归、口径分裂）一条未记录。
3. **Q3 排期大面积逾期**：容量规划、测试时计算、多模态 LLM、MCP 指南计划 2026-07/08 完成，9 月初全部 ⏳ 且无阻塞登记。
4. **提交历史不可追溯**：145 次提交中大量为 "update"，单人项目更依赖 commit message 承载历史，「哪次改动引入断链」无法回查。

**建议以 eval_scan 为唯一事实源**（覆盖面最全且与 07-27 基线可比），其余工具在输出中显式声明 scope。

## 七、建议（按投入产出排序）

1. **本周可做——断链批修 + CI 门禁**：用 `工具/smart_fix_links.py` + `工具/batch_fix_links.py` 批量消化 stale_path 类断链（1,873 次大多可自动映射），再把 `工具/check_wikilinks.py` 挂进 pre-commit 或 GitHub Actions——即 07-27 报告 P0-5 / 路线图 P2-6 的原方案，纯执行问题。完成后把断链率拉回 <1% 并锁定。
2. **统一度量口径**：指定 eval_scan 为唯一事实源，其余工具显式声明 scope；一次性刷新 [[治理/ROADMAP|路线图]] 与 README 中的全部失真数字。
3. **仓库瘦身**：release/ 快照迁出或走 Git LFS；code/ 克隆保持 clone.sh 按需拉取、内容不追踪。目标把 clone 成本从 GB 级降回百 MB 级。
4. **重写 [[治理/KNOWN_ISSUES|已知问题]]**：换成真实问题清单（断链回归、口径分裂、Q3 逾期项），让该文档恢复存在意义。
5. **提交规范**：自即日起采用 conventional commits（`content: …` / `fix-links: …`），单人项目尤其依赖可追溯历史。
