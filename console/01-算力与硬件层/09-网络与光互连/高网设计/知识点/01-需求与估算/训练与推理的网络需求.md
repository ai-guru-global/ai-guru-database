# 训练与推理的网络需求

> 训练网络为"全体同步的大流量集合通信"而建，推理网络为"低时延小消息与 KV 搬运"而建——一套网通吃两种负载是配比灾难的开始。

## 解决什么问题

同一批 GPU 资产上，训练与推理对网络的诉求在算子、消息大小、时延带宽敏感度、故障语义上几乎相反。本篇给出对照表与各自的组网推论，避免用训练网思维建推理集群（或反过来），并界定 PD 分离、KV 专网、EP 推理三类新负载的位置。

## 核心原理

**训练侧**：主体是集合通信（AllReduce/ReduceScatter/AllGather/A2A），MB–GB 级大消息、带宽敏感、全局同步栅栏（最慢者定步长）。负载周期性强（每步重复同一模式），可预测、可压测；故障代价高（checkpoint 恢复以小时计），要求收敛比/轨比设计加弹性续训。

**推理侧**：
- prefill 与 decode 计算特征不同：prefill 大批并行、算力受限；decode 逐 token、显存带宽受限、消息小。
- PD 分离（prefill/decode 分离部署）后，prefill 产出的 KV Cache 要搬到 decode 实例，形成 KV 传输专网需求——mooncake 类方案（以 KVCache 为中心、RDMA 搬运+分层存储，2024 公开）是该平面的代表形态；它要大带宽与高吞吐 KV 池，而非极端无损。
- EP 推理的 All-to-All：prefill 批大时是带宽问题；decode 批小时是纯时延问题（每 token、每层都要 A2A），对跳数与协议时延（LL 类）极敏感。
- 推理无全局栅栏：单路径劣化只伤该请求的 TTFT/ITL，故障语义是"局部降质"，可小集群 cell 化横向扩展。

## 关键数字

| 维度 | 训练 | 推理（PD 分离 + EP） |
|---|---|---|
| 主要算子 | AllReduce/RS/AG、A2A（MoE） | KV P2P 拉取、A2A（EP）、少量 AG |
| 消息大小 | MB–GB（梯度/参数） | decode：KB 级；KV 搬运：百 MB–GB 级 |
| 敏感度 | 带宽为主，全局同步定步 | 时延为主（ITL/TTFT），KV 网带宽 |
| 同步模型 | 全局栅栏，最慢卡定步长 | 无全局栅栏，单请求 SLA |
| 故障影响 | 全局（需续训） | 局部（请求重路由） |
| 压缩/精度 | 梯度 BF16/FP8 | KV 原样传输为主（页化/压缩普及度待核实） |
| 典型组网 | 无收敛/低收敛胖树、轨道优化 | 低时延 Clos + 独立 KV 专网（mooncake 类） |
| 验收指标 | MFU、步长 P99、续训成功率 | TTFT P99、ITL P99、KV 搬运吞吐 |

## 设计要点与权衡

- 训练网：优先做高对分带宽与可预测性（轨比、双平面），配无损三件套；预算堆在"每卡带宽×收敛比"上。
- 推理网：decode 集群可 cell 化、选低时延 Clos；KV 专网独立建或硬隔离 QoS，避免与 A2A 抢队列；KV 池用 RDMA+分层存储（mooncake 类实践）。
- 训推混部署必须 QoS 分级：decode 的 KB 级消息会被训练的 GB 级大流挤死；训练侧 PFC 反压也会拖垮 decode 时延——两边都要保护。
- EP 推理组大小受时延预算约束：每层 A2A×层数×RTT 要小于 ITL 预算，把 EP 收进超节点（NVL72 级）是当前主流解。
- PD 调度把网络距离计入代价函数：prefill 与 decode 的对接选择，本质是 KV 搬运成本与负载均衡的权衡。

## 常见坑

- 用训练的 busbw 压测验收推理网：小消息时延矩阵（每对节点 RTT/抖动）才是推理网的健康指标。
- KV 搬运走训练无损网：大流量 KV 与梯度流互相触发 PFC，两边都受害。
- 低估 decode 的 A2A 频次：大 MoE 每 token 每层一次 A2A，几十层×毫秒级劣化直接击穿 ITL SLA。
- 把"推理不用无损"绝对化：EP 训推一体集群里 A2A 仍怕丢包重传，需按消息大小分级处理。
