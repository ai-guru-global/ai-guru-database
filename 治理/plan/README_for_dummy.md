## 评估体系

### 双轨评估机制

```
【角色视角评估】      【数据驱动评估】
      ↓                    ↓
 Agent 工程师视角    ←→   结构一致性检查
 大模型工程师视角   ←→   内容深度分析
 架构师视角        ←→   交叉引用密度
 集成测试视角      ←→   覆盖完整度
      ↓                    ↓
   识别需求缺口          量化质量指标
```

### 评估维度

| 维度 | 说明 |
|------|------|
| 结构一致性 | README / for_dummy / nutshell 覆盖率 |
| 内容深度 | 各章节行数分布与质量 |
| 交叉引用 | 内部链接密度与连通性 |
| 覆盖完整度 | 代码示例、图表、更新时效 |

## 常见问题与解决方案

| 问题 | 根因分析 | 解决方案 | 预防措施 |
|------|----------|----------|----------|
| 效率低下 | 流程不规范/工具不当 | 优化流程+引入工具 | 标准化+培训 |
| 质量不稳定 | 缺乏检查机制 | 引入质量门禁 | 自动化测试 |
| 协作困难 | 职责不清/沟通不畅 | 明确分工+定期同步 | 文档化+工具 |
| 技术债务 | 赶工忽略质量 | 定期重构+代码审查 | 质量优先文化 |
| 安全风险 | 意识不足/措施缺失 | 安全培训+工具扫描 | 安全左移 |
