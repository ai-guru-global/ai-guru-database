# AGENTS.md — Agent 操作手册

> 中文简称：Agent 操作手册

This is the primary entry point for any AI agent (Claude / Codex / Crush / etc.)
working in this repository. It covers the **operational** knowledge an agent needs:
commands, structure, conventions, and gotchas.

For the **production-safety risk-assessment rules** (mandatory risk tags on every
command, HIGH/MEDIUM/LOW-RISK definitions, rollback requirements), see
[`治理/AGENTS.md`](治理/AGENTS.md) — those rules are the highest-priority contract
and are **not** duplicated here. Read both before doing any write operation.

---

## What this repository is

This is the **AI Guru knowledge base** (`ai-guru-database`) — an Obsidian wiki,
**not** a traditional application codebase. The content is ~2,200+ Markdown files
(~16M+ characters), primarily in **Chinese**, covering the full AI stack from math
fundamentals to production LLM/Agent deployment.

There are two distinct working surfaces:
1. **The wiki** — Markdown content + Python maintenance scripts (the bulk of the repo).
2. **The frontend app** (`前端应用/`) — a React + TypeScript + Vite SPA that browses the wiki.

Typical agent work is **document editing, link maintenance, content ingestion, and
wiki restructuring** — not feature development. Almost all production risk comes
from bulk file deletion, force-pushing, or corrupting the index/manifest/tooling.

## Commands

### Wiki maintenance scripts (Python 3, run from repo root)

These are the everyday tools. Most have no dependencies beyond the stdlib.

| Command | Purpose |
|---------|---------|
| `python3 工具/count_words.py` | Total doc/character statistics (powers the README badges). |
| `python3 工具/check_links.py [--strict] [--json out.json]` | Broken-link check across md-links + wikilinks. `--strict` flags directory-level wikilinks. |
| `python3 工具/check_wikilinks.py` | Wikilink-specific broken-link classification (missing_concept / stale_path / dir_reference). |
| `python3 工具/wiki_health.py` | Orphan pages, tier distribution, backlink density, missing-tier report. |
| `python3 工具/orphan_scan_2026_07.py` | Precise orphan scan (3-level link resolution: full path → basename → dir). |
| `python3 工具/eval_scan_2026_07.py` | Full corpus evaluation: chapter stats, coverage, wikilinks, orphans. |
| `python3 工具/fix_spacing.py` | Auto-fix Chinese–English/Latin spacing in Markdown. |
| `python3 工具/smart_fix_links.py` | Auto-fix broken wikilinks by searching the repo for the filename. |
| `python3 工具/batch_fix_links.py` | Batch-fix broken links by resolving path mismatches. |
| `python3 工具/cross_link_orphans.py` | Cross-link orphan concept pages into the graph. |
| `python3 工具/gen_subdir_indexes.py` | Generate/update `index.md` for subdirectories. |

**One-time migration scripts — DO NOT RE-RUN.** Scripts with a date suffix
(`restructure_2026.py`, `reorganize_scattered_2026.py`, `add_number_prefix_2026.py`,
`rename_to_chinese.py`, `merge_micro_subdirs.py`, `rewrite_merge_links.py`,
`fix_broken_links_2026_07.py`, `inject_tier_aliases.py`, `fix_tiers.py`, …) were
already executed during the 2026 restructure. Re-running them can corrupt the
directory structure. Read them for context only.

**Python deps:** `mkdocs-material` (`工具/requirements.txt`); `pytest>=7.0`
(`工具/requirements-dev.txt`). The mkdocs build is invoked via the frontend's
`pnpm build:mkdocs` (uses `.venv/bin/mkdocs` in the parent dir).

### Frontend app (`前端应用/`)

Separate Node toolchain. Requires **Node >=18** and **pnpm >=8** (`packageManager: pnpm@8.12.0`).

```bash
cd 前端应用
pnpm install
pnpm dev              # Vite dev server
pnpm build            # tsc && vite build
pnpm build:gh-pages   # GitHub Pages build (sets GITHUB_PAGES=true, runs copy-docs.js)
pnpm build:mkdocs     # builds mkdocs from parent dir via .venv/bin/mkdocs
pnpm test             # vitest (unit)
pnpm test:e2e         # playwright
pnpm test:coverage    # vitest --coverage
pnpm lint             # eslint (ts,tsx), --max-warnings 0
pnpm lint:fix
pnpm format           # prettier
pnpm type-check       # tsc --noEmit
```

Stack: React 18, Vite 5, TypeScript 5, TailwindCSS, Radix UI, TanStack Query,
Zustand, react-i18next, react-markdown. Husky + lint-staged are configured.

## Content conventions (mandatory — enforced by review)

Every Markdown page must follow these. 2,700+ existing files already conform —
match them exactly.

### Frontmatter (YAML, required on every page)

```yaml
---
title: Page Title
category: -concepts          # or a chapter category / "root" / "meta"
tags: ["tag-one", "tag-two"]
summary: "One-sentence value summary."
created: 2026-05-31
updated: 2026-07-25
tier: supporting             # core | supporting | peripheral
aliases: [Alias One, Alias Two]
sources: []                  # source material references
name_zh: "中文短名"           # REQUIRED — Chinese short name
---
```

- **`name_zh` is mandatory** (present on 2,742 pages). Immediately after the `# H1`,
  repeat it as a blockquote: `> 中文简称：<name_zh>`. This bilingual naming contract
  is how the wiki disambiguates pages.
- **`tier`** drives wiki health/lifecycle tooling. Distribution: `supporting` (~4050),
  `core` (~1520), `peripheral` (~260). Use `core` for hub/foundational pages,
  `supporting` for normal content, `peripheral` for low-priority.
- **`updated`** must be bumped whenever you edit a page (review gate checks this).

### Body structure

```markdown
# Title (中文为主，可附 English)
> 中文简称：<name_zh>

> **一句话理解**: One plain-language sentence a non-expert can grasp.

---

[content, sections separated by `---`]

---

*Last updated: YYYY-MM-DD*
```

- The **"一句话理解"** blockquote is required right after the title.
- Separate major sections with `---` horizontal rules.
- Footer line `*Last updated: YYYY-MM-DD*`.

### File naming

- Topic files use **PascalCase with underscores**: `Distributed_Training_2026.md`.
- Chapter index is always `README.md` (exact case).
- Special suffixes carry meaning:
  - `_in-nutshell` — 30-min quick guide (500–800 lines)
  - `_for_dummy` — beginner-friendly, emoji-heavy, short code (<30 lines)
  - `_Deep_Dive` — deep technical doc (don't combine with `_2026`)
  - `_2026` — current-year topic/roundup
- Filenames are **English** even when content is Chinese.

### Formatting rules

- **CJK–Latin spacing**: insert a space between Chinese and English/numbers
  (`使用 Python 训练`, not `使用Python训练`). `工具/fix_spacing.py` enforces this.
- Use full-width parentheses `（）` for Chinese parenthetical content.
- Preserve proper-noun capitalization (`PyTorch`, `GPT-4`).
- Mermaid diagrams: prefer `flowchart` + `subgraph`; add 1–2 sentence explanation below.
- Tables: bold headers, ≥3 data rows.

### Cross-references

- Use Obsidian-style wikilinks: `[[概念/rlhf]]` or `[[概念/rlhf|display text]]`.
- Wikilinks resolve **by path** (and basename as fallback). The concept graph
  (`概念/`) is the interconnection layer — concept pages carry `relationships:`
  frontmatter linking to related concepts.
- Markdown relative links for chapter refs: `[深度学习](../03_深度学习/README.md)`
  — always point to a file, never a bare directory.
- Every page should have **≥2** outgoing cross-references (anti-pattern: "孤岛文档").

Full detail: [`治理/Document_Templates.md`](治理/Document_Templates.md).

## Gotchas & non-obvious behavior

1. **Pre-commit hook blocks sync duplicates.** `.githooks/pre-commit` rejects files
   matching iCloud/editor-sync junk (`* 2.md`, `*conflicted copy*`, `*.copy.md`).
   Install once: `git config core.hooksPath .githooks`. Bypass with `--no-verify`
   only if genuinely needed.

2. **"只增不减" (only-add-don't-delete) governance principle.** Per
   `治理/Content_Governance.md`, prefer supplementing/updating over deletion.
   Deleting wiki pages is a HIGH-RISK action (see `治理/AGENTS.md`).

3. **Risk tags are mandatory on EVERY command/step output.** Per `治理/AGENTS.md`,
   append `# 🟢/🔶/⚠️ — <impact> [rollback: …]` to each command. Production
   operations and batch/loop commands auto-escalate one level. HIGH-RISK commands
   must not auto-execute — present plan + rollback and wait for confirmation.

4. **Auto-generated files — don't hand-edit:** root `index.md`,
   `.code-up/knowledge-cards/*.json`, `.code-up/diagrams/*`. Regenerate via tooling.

5. **`code/` is external clones.** It holds reference repos (vLLM, flash-attention,
   anthropics_skills, …) cloned via `code/clone.sh`. Treat as read-only references,
   not project source.

6. **Link checkers exclude many dot-dirs** (`.claude`, `.obsidian`, `.github`,
   `node_modules`, `dist`, …). A broken link inside an excluded dir won't be flagged.

7. **Two `AGENTS.md` files, different jobs:** this root file = operational how-to;
   `治理/AGENTS.md` = mandatory safety contract. Both apply.

8. **Language:** the repo is Chinese-first. Respond and write content in Chinese
   unless the task is explicitly English. Comments in code stay minimal.

## When you create or edit a page — checklist

- [ ] Frontmatter complete: `title`, `name_zh`, `tier`, `tags`, `summary`, `created`,
      `updated` (bump `updated`), `sources`, `aliases`.
- [ ] `> 中文简称：<name_zh>` blockquote right after H1.
- [ ] `> **一句话理解**: …` present.
- [ ] Sections separated by `---`; `*Last updated: YYYY-MM-DD*` at footer.
- [ ] Filename matches naming conventions (PascalCase / correct suffix).
- [ ] ≥2 outgoing cross-references; no broken wikilinks (`check_links.py`).
- [ ] CJK–Latin spacing correct.
- [ ] Run `python3 工具/check_links.py` and `python3 工具/wiki_health.py` after
      structural changes.
