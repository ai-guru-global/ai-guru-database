# Computer Use 评测与失败模式

> 中文简称：Computer Use 评测与失败模式

> **一句话理解**: 评 Computer Use 不能只看「任务完成率」——真实生产还要看每一步点得准不准、会不会做多余动作、以及有没有违反安全约束；本页给基准格局、四层指标和五大失败模式的归因表。

---

## 1. 三大基准

| 基准 | 环境 | 规模 | 考什么 | 发布方（年份） |
|------|------|------|--------|---------------|
| **OSWorld** | 真实 Ubuntu 桌面（含真实应用） | 369 任务 | 端到端跨应用操作：文件/办公/浏览器/系统设置 | 港大 + Salesforce（2024） |
| **WebArena** | 自托管仿真网站 | 812 任务 | 长程 Web 任务（多约束、多页面） | CMU（2023） |
| **AndroidWorld** | Android 模拟器 | 116 任务 | 移动端手势与跨应用 | Google Research（2024） |

评测口径提醒：各家报告的设置差异极大（分辨率、步数上限、是否给 DOM 辅助）——**同榜内对比才有意义**；数字随代际快速变化（2026-02 快照见 [[概念/Agent/gui-agent|概念卡对比表]]，本页 `review_by: 2027-01-25` 复核）。

## 2. 指标体系

| 层 | 指标 | 测什么 |
|----|------|--------|
| 成果 | 任务完成率 | 端到端 0/1（终态校验） |
| 过程 | 步骤准确率 | 每步动作是否正确（需人工或规则标注） |
| 过程 | grounding 精度 | 坐标落在目标元素内的比例 |
| 过程 | 效率 | 完成任务的动作数 / 冗余动作率 |
| 安全 | 安全违规率 | 触发 L3 敏感动作未确认、白名单外操作的次数 |

生产视角优先盯两个：**安全违规率**（一次违规就可能否决整个落地）和**冗余动作率**（多余点击会改变应用状态，是后续步骤失败的常见根源）。

## 3. 五大失败模式

| 失败模式 | 现象 | 根因 | 缓解 |
|----------|------|------|------|
| **Grounding 错误** | 点到相邻按钮、点空 | 小元素、缩放换算、动态布局 | SoM 标注 / 两级定位 / DOM 优先路由 |
| **长任务漂移** | 20+ 步后忘记原始目标、循环空转 | 轨迹历史稀释目标 | 计划回锚（提纲常驻）/ 步数硬闸 / 子目标分解 |
| **验证缺失** | 做完了但做错了，自己不知道 | 执行后不校验终态 | 每步截图回填 + 终态断言（成功/失败可判定） |
| **动态 UI 失明** | 弹窗、加载态、动画期间操作失效 | 感知滞后于界面状态 | 动作前重截屏 / wait 原语 / 弹窗检测 |
| **过度操作** | 无意义点击、乱滚动、重复输入 | 模型「必须做点什么」倾向、纠错策略缺失 | 动作最小化原则、步内重试上限、冗余动作率监控 |

失败归因口径与 Deep Research 一致（[[14_RAG系统/08_Deep_Research/04_Deep_Research_评测|四分类归因法]]）：每次失败标注到五类之一再修——**混在一起修等于瞎修**。

## 4. 自建评测 checklist

给自建 Computer Use（接 [[15_智能体/21_Computer_Use/02_技术拆解_感知_决策_执行|02 页的多后端架构]]）搭最小评测：

1. **任务分层**：10 道单步（grounding 专项）+ 10 道三至五步（流程专项）+ 5 道长任务（漂移专项）。
2. **终态可验证**：每个任务定义可脚本断言的终态（文件存在/页面 URL/表单值），不靠「看起来对了」。
3. **录像回放**：结构化日志（截图+动作序列）可回放——失败归因与回归定位全靠它。
4. **成本记录**：每任务 token/步数/墙钟，效果回归必须连成本一起回归。
5. **失败归因五分类**：grounding / 漂移 / 验证缺失 / 动态 UI / 过度操作，修法各不相同。
6. **安全用例独立成集**：注入诱饵页面（「忽略指令」藏在前台内容里）、敏感操作误触发，单独测通过率。
