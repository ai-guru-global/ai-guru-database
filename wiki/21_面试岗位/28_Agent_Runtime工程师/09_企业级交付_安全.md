# 企业级交付与安全 (Enterprise Delivery & Security)

> 中文简称：企业级交付与安全

> **一句话理解**: Demo 到生产的距离就是这一页——身份、凭证、审计、灰度、容灾、版本兼容六道关，一关不过企业就不敢把 Agent 接进自己的系统。

---

## 1. 身份与权限（IAM）

- **Agent 是一种新的身份类型**：既不是人也不是普通服务——它代表用户行动（on-behalf-of），又有自己的工具权限，必须区分三主体：用户身份、Agent 工作负载身份（workload identity）、工具/下游系统身份；
- **委托链（delegation chain）**：Agent 以用户名义调下游时，下游要能验证"哪个用户、通过哪个 Agent、为什么"——用 token 交换（token exchange）传递委托链，而不是共享一个超级账号；
- **最小权限落地**：per-session 短时凭证、按工具+资源粒度授权（RBAC/ABAC）、敏感操作二次确认（human-in-the-loop）；
- 深入：[[15_智能体/10_企业级Agent/01_Agent_Auth_Authorization|Agent Auth 鉴权专题]]。

## 2. 凭证管理（面试最爱问的安全点）

- **铁律：凭证永不进入模型上下文**——prompt 里出现 API key 等于写进日志、写进轨迹、可能被注入诱导外发；
- 正确姿势：**网关代持**——Agent 调用走平台网关，网关按会话身份注入凭证；或环境注入到沙箱（secret 挂载），模型只见"调用成功与否"不见凭证本身；
- 配套：凭证轮换、per-tenant 隔离的 secret 存储、泄露检测与吊销演练。

## 3. 审计（Audit）

- Agent 的每一步都该有"四要素"记录：**who（委托链）、when、what（动作+参数）、why（触发它的模型决策/轨迹链接）**；
- 审计日志**不可变**（append-only/对象存储 WORM），与 trace 同源（见 [[21_面试岗位/28_Agent_Runtime工程师/08_可观测_评测|08 可观测评测]]），满足合规检查时可回放；
- 高风险动作（删数据、转账、发邮件）单独分级：前置审批 + 事后审计双保险。

## 4. 灰度与版本兼容

- Agent 系统有**四个会漂移的版本**：模型版本、prompt 版本、工具/MCP Server 版本、Runtime 自身版本——任意一个变都可能让行为退化；
- 灰度打法：按租户/流量比例灰度新模型或新 prompt；每类灰度都挂**回归评测集**看门（见 [[21_面试岗位/28_Agent_Runtime工程师/08_可观测_评测|08 评测体系]]）；
- 兼容策略：模型行为漂移用评测拦截 + prompt 回归；协议演进（如 MCP 规范修订）用网关做多版本并存；工具契约变更走 deprecation 周期。

## 5. 容灾与稳定性

- 会话状态外置（Checkpoint 可跨机恢复）→ 单机故障只丢执行现场不丢任务；
- 多可用区部署控制面；模型上游故障时**降级路由**（备用模型/降级响应/排队），而不是硬失败；
- 入口限流 + 租户级配额隔离，防止单租户雪崩拖垮全平台（衔接 [[21_面试岗位/28_Agent_Runtime工程师/05_编排调度_云原生|05 编排调度]]）。

## 6. 公有云 vs 专有云（私有化）交付

| 维度 | 公有云 SaaS | 专有云/私有化 |
|------|------------|--------------|
| 隔离假设 | 逻辑隔离（多租户共享集群） | 物理或专属集群隔离 |
| 模型部署 | 平台托管 API | 可能要求模型也私有化部署 |
| 数据边界 | 出租户不出平台 | 数据不出企业内网 |
| 升级节奏 | 平台统一灰度 | 版本列车+客户窗口，向后兼容压力大 |
| 关键挑战 | 单集群多租户密度与公平性 | 交付自动化、环境差异适配、远程运维受限 |

- 面试表述："私有化交付的难点不是功能裁剪，而是**把平台做成'环境无关'**——依赖清单化、配置声明式、诊断工具自带。"

---

## 7. 高频面试题速练

1. **"为什么凭证不能放 prompt 里？"** —— 上下文会进日志/轨迹/模型供应商侧，且注入攻击可诱导模型外发；正确做法是网关代持+会话级注入，模型无感。
2. **"Agent 权限和传统服务权限最大的不同？"** —— Agent 动作是运行时动态决定的，无法像微服务那样静态声明全部权限边界，所以要"动态最小授权+敏感操作人审+全程审计"三层兜底。
3. **"模型供应商要升级版本，你怎么保证不翻车？"** —— 评测集回归+小流量灰度+行为基线对比（轨迹统计分布）+ 一键回滚预案。
