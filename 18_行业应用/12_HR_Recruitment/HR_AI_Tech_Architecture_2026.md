## 2. HR AI 平台参考架构

2026 年成熟企业的 HR AI 已从"单点工具"演进为"平台化能力"，典型分层如下：

```
┌─────────────────────────────────────────────────┐
│  应用层: 招聘 Copilot / 员工助手 / 分析看板       │
├─────────────────────────────────────────────────┤
│  编排层: 工作流引擎 + Agent 编排 + 人工审核卡点   │
├─────────────────────────────────────────────────┤
│  模型层: 简历解析 LLM / 匹配双塔 / 预测 GBDT      │
├─────────────────────────────────────────────────┤
│  数据层: 人才库 / 职位库 / 行为事件流 / 向量索引  │
├─────────────────────────────────────────────────┤
│  治理层: 偏见监测 / 决策日志 / 权限与脱敏         │
└─────────────────────────────────────────────────┘
```

关键架构决策：

| 决策点 | 主流选择 | 理由 |
|--------|----------|------|
| LLM 部署方式 | 私有化/VPC 内推理 | 简历含大量 PII，公有 API 面临数据出境风险 |
| 匹配模型 | 双塔 Embedding + 重排 | 千万级人才库需先召回再精排 |
| 预测类任务 | GBDT (XGBoost/LightGBM) 而非 LLM | 结构化特征上 GBDT 更准、可解释、成本低两个数量级 |
| 人机分工 | AI 推荐 + 人类决策 | 雇佣决策全自动化在多数司法辖区违规（见 §7） |

平台选型方法论参见 [[18_行业应用/01_Industry_Overview/AI_Platform_Selection_2026|AI 平台选型 2026]]。

## 3. 场景一：简历解析与筛选流水线

### 3.1 架构

```
简历文件 (PDF/DOCX/图片)
  → 版式解析 (OCR + Layout 模型)
  → LLM 结构化抽取 (JSON Schema 约束输出)
  → 字段校验 + 去重 (规则引擎)
  → 匿名化 (去除姓名/性别/年龄/照片)
  → 入库 + 向量化 (人才库 + 向量索引)
```

### 3.2 工程要点

- **约束解码**：用 JSON Schema/函数调用强制 LLM 输出结构化字段，抽取错误率从自由文本的 ~8% 降到 <1%，提示词设计参见 [[05_大模型/08_Prompt_Engineering/Prompt_Engineering|Prompt Engineering]]
- **匿名化前置**：在进入任何评分环节之前剥离受保护属性（性别、年龄、照片、毕业年份），这是偏见治理的第一道闸门
- **双通道评估**：新简历同时走"旧规则引擎"与"LLM 通道"影子运行 2-4 周，对齐后才切流
- **成本控制**：版式简单的简历（约 70%）走小模型（7B 级），复杂版式才升级到大模型，推理成本降低约 60%

### 3.3 量化效果基准（行业中位数）

| 指标 | 人工 | AI 流水线 |
|------|------|-----------|
| 单份简历处理时间 | 23 秒（浏览）| <2 秒 |
| 初筛周期 | 3-5 天 | <1 小时 |
| 字段抽取一致率 | 人际一致率 ~85% | ~97% |
| 高潜候选人漏筛率 | 基线 | 下降 30-40% |

## 4. 场景二：人岗匹配与面试 Copilot

### 4.1 人岗匹配双塔架构

```
候选人塔: 技能/经历/项目 → Embedding
职位塔:   JD 要求/团队画像 → Embedding
        ↓ ANN 召回 (Top 200)
        ↓ 精排模型 (交叉特征 + 业务规则)
        ↓ LLM 生成匹配理由 (可解释性输出)
```

- 召回层复用推荐系统技术栈，原理见 [[02_机器学习/10_Recommendation_Systems/Recommendation_Systems|推荐系统]]
- "匹配理由生成"是 2026 年的关键增量：不只给分数，还生成"该候选人匹配/不匹配的具体证据"，供招聘官快速核验，将误判申诉率降低约一半

### 4.2 面试 Copilot

| 能力 | 实现方式 | 红线 |
|------|----------|------|
| 面试题生成 | JD + 简历 → 定制化题库 | 题目需人工复核入库 |
| 实时转写与摘要 | ASR + LLM 摘要 | 必须获得候选人知情同意 |
| 评价辅助 | 结构化评分卡 + 证据引用 | AI 不得直接输出录用/淘汰结论 |
| 知识支持 | 企业制度/薪酬政策 RAG 问答 | 检索架构见 [[14_RAG系统/01_RAG_Fundamentals/RAG_Fundamentals|RAG 基础]] |

## 5. 场景三/四：离职预测与员工助手

### 5.1 离职预测系统

```
特征体系（示例，需按合规审查裁剪）:
  行为类: 内部系统活跃度变化、会议参与度
  职业类: 晋升间隔、薪酬分位、司龄
  组织类: 团队流失率、管理者变动
      ↓
  GBDT 月度批量打分 → 分层预警 (高/中/低)
      ↓
  输出给 HRBP（永不直接触达员工本人）
```

工程与伦理要点：
- **只到管理动作，不到个体标签**：输出形式是"团队健康度 + 建议保留动作"，避免"给员工贴离职标签"引发的信任危机
- **特征合规审查**：私人通讯内容、健康数据、工会活动等特征绝对禁用
- **效果基准**：成熟实施企业的关键人才非期望流失率可下降 15-25%，预测 AUC 通常在 0.75-0.85 区间

### 5.2 员工自助 Agent

政策问答、假勤办理、证明开具等高频事务由企业级 Agent 承接，生产化要点（工具权限、审计、灰度）与通用企业 Agent 一致，参见 [[15_智能体/10_Enterprise_Agent/Agent_Production_2026|Agent 生产化 2026]]。行业基准：HR 服务台工单量下降 40-60%，员工问题首次解决率提升至 80%+。

## 6. ROI 测算框架与案例

### 6.1 测算框架

```
年化收益 = 效率收益 + 质量收益 + 留存收益
  效率收益 = 节省工时 × 人力成本单价
  质量收益 = (错聘率下降 × 单次错聘成本)     # 错聘成本 ≈ 该岗位年薪 0.5-2 倍
  留存收益 = (流失率下降 × 人均替换成本)     # 替换成本 ≈ 年薪 0.5-1.5 倍
年化成本 = 平台订阅/推理成本 + 实施集成 + 治理审计人力
```

### 6.2 案例基准（2026 年公开报道口径汇总）

| 场景 | 企业类型 | 关键数字 |
|------|----------|----------|
| 招聘流水线 | 万人级科技公司 | 招聘周期 42 天 → 26 天；单招聘官年处理量 +70% |
| 高流量初筛 | 连锁零售（季节性用工）| 初筛自动化率 85%，招聘成本/人下降 ~35% |
| 面试 Copilot | 金融企业 | 面试官准备时间 -50%，评分卡完整率 65% → 96% |
| 离职预测 | 制造业集团 | 关键岗位非期望流失 -18%，年化留存收益超项目成本 4 倍 |

> ⚠️ 使用外部基准时注意口径：厂商案例普遍报告"最好情况"；内部立项建议按公开数字的 50-70% 做保守测算。

## 7. 合规红线与审计设计

HR 是 AI 高风险监管的"风暴眼"，2026 年的三层约束：

| 法规 | 核心要求 | 架构含义 |
|------|----------|----------|
| 欧盟 AI Act（高风险类别）| 雇佣类 AI 属高风险：需符合性评估、人类监督、日志留存 | 决策日志不可变存储 ≥ 法定年限 |
| 美国州法（如 NYC Local Law 144）| 自动化雇佣决策工具需年度偏见审计并公示 | 偏见指标（如不同群体选择率之比）需可随时导出 |
| 中国个保法 + 算法备案 | 自动化决策需透明、可拒绝，重要算法需备案 | 提供"人工重审"通道是硬性产品需求 |

工程落地清单：

- [ ] 每次 AI 参与的筛选决策记录：输入快照、模型版本、分数、人类最终决定
- [ ] 按受保护群体每月计算通过率差异（四分之三规则等），越限自动告警
- [ ] 偏见测试纳入模型发布流程，方法参见 [[17_伦理安全/01_Ethics_Fundamentals/Bias_Fairness_Testing|偏见与公平性测试]]
- [ ] 候选人知情告知与人工申诉通道（含 SLA）

| 阶段 | 时间 | 里程碑 | 典型陷阱 |
|------|------|--------|----------|
