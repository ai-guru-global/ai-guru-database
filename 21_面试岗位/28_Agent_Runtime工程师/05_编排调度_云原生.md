# Agent 任务编排与资源调度（云原生）

> 中文简称：编排调度与云原生

> **一句话理解**: 把"一万个并发 Agent 会话、一百个租户、有限的 CPU 和 GPU"排得井井有条——这就是 JD 第 3 条前半句的全部内容。

---

## 1. Agent 工作负载的调度特殊性（先讲这个再讲 K8s）

| 传统无状态服务 | Agent 会话 |
|---------------|-----------|
| 请求毫秒级，Pod 随时可换 | 会话分钟-小时级，中间挂了要恢复 |
| 副本对等，任意调度 | 绑定沙箱环境与会话状态，重建有代价 |
| 资源画像平稳 | token 突发 + 工具执行空窗（CPU 空转等待模型） |
| 流量可预测 | 租户间配额竞争激烈，需优先级抢占 |

- 面试表述："Agent 是一种**有状态的长周期工作负载**，调度要兼顾亲和性（会话粘住沙箱）、弹性（空闲会话回收）和公平性（租户配额）"。

---

## 2. Kubernetes 落点清单（JD 关键词逐个映射）

| JD 关键词 | K8s 机制 | 要点 |
|-----------|---------|------|
| 多租户隔离 | Namespace + RBAC + NetworkPolicy | 租户=Namespace，网络默认拒绝跨租户 |
| 配额管理 | ResourceQuota / LimitRange | 租户级会话数、CPU/内存上限 |
| 优先级 | PriorityClass + 抢占 | 付费租户抢占空闲资源，付费任务不被饿死 |
| 弹性伸缩 | HPA（指标）+ KEDA（队列长度） | 按沙箱池水位/排队深度扩缩 |
| 高并发任务 | 批量 Job / 自定义 controller | 会话生命周期用 operator 管理（CRD=AgentSession） |
| GPU 异构 | device-plugin + 调度器扩展 | GPU 池服务模型推理，CPU 池跑沙箱，MIG/vGPU 切分 |
| 会话粘性 | 自定义调度器/亲和性 | 会话恢复优先回原节点（本地缓存热） |

- 延伸：[[12_架构基建/04_Kubernetes核心/01_Kubernetes核心_Components_深入分析|K8s 核心组件深入分析]]、[[概念/K8s/kubernetes|K8s 概念页]]。

## 3. 调度算法常识（要求 3"分布式任务调度"）

- **优先级调度 + 抢占**：高优任务可驱逐低优任务，注意驱逐风暴与低优任务的"可抢占副本"设计；
- **公平共享（DRF 思想）**：多租户下按主导资源份额公平分配，防止单租户吃满；
- **装箱 vs 打散**：bin-packing 提高利用率 vs 打散降低爆炸半径，Agent 沙箱通常偏装箱（密度经济），关键控制面打散；
- **队列与背压**：入口限流 + 排队 + 超时熔断，宁可排队也不雪崩；
- **一致性哈希/会话亲和**：会话路由到持有其沙箱的节点。

---

## 4. 云原生四件套在 Agent 平台中的角色

| 组件 | 在 Agent 平台里干什么 |
|------|----------------------|
| API Gateway | 统一入口：租户鉴权、限流配额、token 计量计费、灰度路由 |
| Service Mesh | 会话服务↔沙箱↔工具服务的东西向流量：mTLS、重试/超时策略、流量观测 |
| 微服务拆分 | 会话服务、编排服务、沙箱池管理、工具网关（MCP Gateway）、评测服务各司其职 |
| 中间件 | 消息队列削峰（任务队列）、Redis（会话缓存/分布式锁）、对象存储（Checkpoint/轨迹） |

## 5. 高频面试题速练

1. **"给多租户 Agent 平台设计隔离，分几层？"** —— 五层：账号与权限（IAM）、网络（NetworkPolicy/egress 代理）、计算（Namespace 配额+沙箱 per 会话）、数据（存储隔离+加密）、配额与计费（ResourceQuota+token 预算）。
2. **"会话 Pod 扩容怎么扩？缩容会不会杀掉正在跑的任务？"** —— 扩的是"沙箱池"而非活跃会话；缩容只回收空闲池成员，活跃会话靠租约与 Finalizer 保护，必要时先 Checkpoint 再驱逐。
3. **"GPU 和 CPU 负载怎么混部？"** —— 节点池分池 + 污点容忍隔离，GPU 节点专供模型推理与 GPU 工具，沙箱跑 CPU 池；对推理服务用 KEDA 按队列深度伸缩。
4. **"Agent 任务比普通 API 流量难调度在哪？"** —— 有状态、长周期、突发成本、暂停等待（人审）四点，详见 [[21_面试岗位/28_Agent_Runtime工程师/03_Agent_Runtime_核心机制|03 Runtime 机制]]。
