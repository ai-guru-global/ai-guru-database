## 一、旗舰文：为什么 AI 行业需要一个开源坐标系

### 1. 我们缺的不是资讯，是坐标

每天都有新的模型、芯片、融资和监管消息。它们被写进时间线、快讯、日报和群聊，然后迅速过期。

真正难回答的问题不是「今天发生了什么」，而是：

- 这条新闻落在产业链的哪一层？
- 它改变的是成本曲线、竞争格局，还是分发入口？
- 这个判断的上游证据是什么，反证又是什么？
- 半年后回看，哪一部分已经被证伪？

资讯是流，坐标是结构。没有坐标，信息越多，判断越便宜。

### 2. 现有的三种地图，各缺一块

我们试着把市面上的「AI 行业地图」分成三类：

| 类型 | 代表形态 | 强项 | 缺的那块 |
|---|---|---|---|
| 资讯聚合 | 新闻站、Newsletter、日报 | 快、广 | 没有稳定坐标，事件无法沉淀 |
| 链接地图 | VC landscape、awesome list | 覆盖公司多 | 只收藏，不拆解；没有证据层 |
| 单点数据 | 算力数据集、模型排行榜 | 某一维度很深 | 只覆盖一个切片，接不住全行业 |

据我们所知，开源界还没有一份同时做到「**逐层拆解 × 证据附着 × 可核验**」的等价物。这不是因为我们更聪明，而是因为这件事很笨：要手工策展骨架，要一条条追来源，要公开承认不知道。

### 3. 我们的答案：一张可被引用、可被机器消费、可被修订的坐标系

AI GURU 工作台把 AI 全行业拆成五层价值流：

```
L1 算力与硬件 → L2 数据与模型 → L3 平台与工具 → L4 行业应用 → L5 商业与生态
```

再往下拆到 **69 个节点、207 个二级细分**，横向用 **18 个主题域**切开。每个节点是一页，聚合全库证据；聚合为零的节点不隐藏，直接标成采集缺口。

它有三个刻意的设计：

1. **事实与观点分离**。线索时间线、大事记是证据层；节点的成熟度、护城河、瓶颈、领先指标是观点层。观点可以被证据整段推翻，修正走 git 留痕。
2. **六态核验**。✅ 已核验 / ⚠️ 部分可取 / ❓ 未核验 / 🔍 检索缺口 / ✗ 已证伪 / E 证据不足。存疑事件不删，公开挂账。
3. **稳定 ID + 机器可读**。每个实体有 `ai-guru:chain/L1/gpu` 这样的坐标，`data/*.json` 可直接被 Agent、RAG、看板和研究工具消费。

### 4. 为什么必须开源

因为这三件事都不是一个人能长期做对的：

- **分类法**需要被同行挑战。哪一层该拆、哪个节点该并，只有一线从业者知道。
- **证据**需要很多双眼睛。一个数字错三个月，比没有这个数字更糟。
- **数据**需要被消费。只有被别人拿去建 Agent、做看板、写周报，坐标系才真正成立。

所以我们把最里面那层先打开：`chain.json`、`clues.json`、`chronicle.json`、`verify.json`，以及 JSON Schema 和稳定 ID。界面留给我们自己，插座交给社区。

### 5. 它不是什麼

- 不是新闻站：新闻只是证据，不是产品本体。
- 不是「最全」：我们只承诺结构完整、证据可查；缺口清单是公开的。
- 不是投资建议：所有份额、规模、毛利都是量级估算，带口径，可被证伪。

### 6. 邀请

如果你是一个：

- 正在建集群、选网络、算 TCO 的基础设施工程师；
- 在写 Agent、RAG、行业看板的开发者；
- 做 AI 产业研究的分析师或记者；
- 或者只是受够了「一天十条快讯、一周零个判断」的读者；

欢迎从最小的一步开始：**修一个数字，补一个来源**。

- 数据集：`data/`
- 节点页：`site/nodes/`
- 贡献阶梯：`CONTRIBUTING.md`
- 待认领队列：`docs/good-first-issues.md`

坐标先立住，内容慢慢长。

## 二、渠道文案

### Hacker News（Show HN）

**Title:** Show HN: An open, machine-readable map of the AI industry

**Body:**

I kept running into the same problem: AI news is abundant, but there is no stable coordinate system to attach it to. So I built one.

AI GURU Industry Graph is an open dataset and static site that decomposes the AI industry into:

- 5 value-chain layers (compute → models → platforms → applications → business)
- 69 nodes and 207 sub-segments, hand-curated
- 18 cross-cutting topic domains
- 95 clue timelines, 169 chronicle events, 154 verification items

What makes it different:

1. Structure first: every news item is attached to a node, not a feed.
2. Evidence and opinion are separated. Facts live in timelines; judgments live in node cards and can be overturned by evidence.
3. A six-state verification ledger (verified / partial / unverified / search gap / falsified / insufficient evidence).
4. Stable IDs and JSON exports: `ai-guru:chain/L1/gpu`, plus `chain.json`, `clues.json`, `chronicle.json`, `verify.json` and JSON Schema.

It is not a news site and not "the most complete". The gaps are public.

Repo: https://github.com/ai-guru-global/ai-guru-console
Data: https://github.com/ai-guru-global/ai-guru-console/tree/main/data
Site: https://ai-guru-global.github.io/ai-guru-console/

Feedback on the taxonomy is especially welcome — which node is wrong, missing, or should be merged?
