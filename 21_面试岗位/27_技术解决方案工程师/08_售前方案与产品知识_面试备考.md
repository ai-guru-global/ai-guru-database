# 售前方案与产品知识面试备考 (Pre-Sales & Product Prep)

> 中文简称：售前方案与产品知识备考

> **一句话理解**: SSE 的本职是"把技术讲成客户愿意付钱的方案"——这章补三件事：产品知识底盘、售前方法论、一个能直接讲的完整方案示例。

---

## 1. 弹性计算产品知识必会清单

> 原则：**面试前浏览一遍官网产品页**，不认识的名词列清单清掉。以下为知识框架，具体规格参数以官网为准。

### 1.1 三层产品协同图（必须能白板画）

```text
┌─ 应用层：客户的 Agent（推理 + Harness + 技能）─────┐
├─ 沙箱层：Agent 会话隔离执行（我方核心售卖）─────────┤ ← 卖点
├─ 编排层：ACK 容器服务 —— K8s 生态、调度、弹性 ─────┤
└─ 算力层：ECS —— 实例族、弹性伸缩、网络存储底座 ────┘
```

**一句话串讲**："客户的 Agent 跑在算力集群上——ECS 是底座、ACK 是编排、沙箱是面向 Agent 会话的隔离执行层，三层叠起来就是 Agent Infra 方案的骨架。"（呼应纪要中"推动客户 Agent 跑在阿里云算力集群上"）

### 1.2 ECS 必会概念

| 概念 | 要能讲什么 |
|------|-----------|
| 实例族分类 | 通用/计算/内存优化 + **异构 GPU 实例**（AI 推理选型入口） |
| 弹性伸缩 | 伸缩组/策略；Agent 流量峰谷明显 → 弹性是刚需卖点 |
| 可靠性机制 | 多 AZ 部署、快照/镜像、重启策略 |
| 网络 | VPC/安全组/ENI——方案题里网络隔离的基础词汇 |
| 竞品对照 | AWS EC2 / GCP GCE 的对应概念（证明云素养通用） |

### 1.3 ACK（容器）必会概念

| 概念 | 要能讲什么 |
|------|-----------|
| 集群形态 | 托管 vs 自建控制面；ASK Serverless（突发负载） |
| 弹性 | HPA/VPA、节点池弹性——Agent 推理并发场景 |
| 插件生态 | CNI/CSI/Ingress——与沙箱 K8s 部署（CubeSandbox v0.6 也支持 K8s）对话无卡顿 |
| GPU 共享 | MIG / vGPU / GPU 共享调度（HAMi 类）——推理降本话题 |

### 1.4 高可用白板模板（5 分钟版）

任意"设计高可用架构"题，按四层展开：

1. **接入层**：SLB 负载均衡 + 多 AZ 无状态服务；
2. **服务层**：弹性伸散组 + 健康检查 + 滚动发布；
3. **数据层**：主备/多副本、读写分离、跨 AZ 存储；
4. **兜底层**：限流熔断、降级预案、混沌演练。
   收尾："架构无银弹——按 RTO/RPO 目标和成本预算做取舍。"

## 2. 售前方法论（JD 核心流程）

### 2.1 完整链路

```mermaid
flowchart LR
    A[需求挖掘] --> B[方案设计]
    B --> C[POC 立项]
    C --> D[POC 执行]
    D --> E[生产转化]
    E --> F[扩容/交叉销售]
```

### 2.2 每步的关键动作与坑

| 步骤 | 关键动作 | 常见坑 |
|------|---------|--------|
| **需求挖掘** | 问业务目标而非直接推产品：场景、并发、数据边界、合规、预算、决策链 | 没搞清"谁拍板"，方案讲给不会买的人 |
| **方案设计** | 业务语言 + 架构图 + 分期路线（先 POC 后全量） | 堆参数没故事，客户听不懂价值 |
| **POC 立项** | **书面约定成功指标**与时间盒 | 口头 POC → 永远"再看看" |
| **POC 执行** | 周报可见、失败项给修复计划 | 黑盒执行，客户失去信心 |
| **生产转化** | 生产化清单：安全/监控/SLA/成本 | POC 成功后没人推上线 |
| **扩容** | 用数据讲 ROI，谈规模折扣 | 只会卖不会养 |

### 2.3 SPIN 提问法（需求挖掘骨架）

| 类型 | 含义 | 例句（Agent 场景） |
|------|------|-------------------|
| **S** 现状 | 客户现在怎么做的 | "现在工单/代码执行是在什么环境里跑的？" |
| **P** 问题 | 痛在哪 | "多用户数据会互相可见吗？出过事吗？" |
| **I** 影响 | 痛的代价 | "一次数据串扰的合规代价大概多少？" |
| **N** 收益 | 解决后的好处 | "如果每会话彻底隔离 + 秒级弹性，能支撑你们上线节奏吗？" |

- [ ] 用 SPIN 给客服 Agent 场景写 4 个问题

## 3. 完整方案示例：企业客服 Agent（5 分钟宣讲骨架）

> 直接对应 06 号清单第 6.1 题，写成可背讲稿。

### 3.1 开场与需求确认（30 秒）

"假设贵司要做多租户在线客服 Agent：日均 X 万会话、涉及用户隐私数据、要满足等保——我先确认三个问题：并发峰值多少？数据能不能出 VPC？有没有合规审计要求？"

### 3.2 方案架构（2 分钟，白板）

| 层 | 选型 | 理由（讲给客户听） |
|----|------|-------------------|
| 推理层 | GPU 实例 + vLLM（或百炼托管推理） | 按峰值弹性伸缩，前缀缓存降本 |
| Agent 层 | Harness：技能 + 工具 + 护栏 + 评测 | 客服技能白名单化，敏感操作人审 |
| 执行层 | **我方沙箱**：每会话隔离 | 用户数据互不可见——合规底线 |
| 数据层 | 向量库（知识库）+ 会话存储 | RAG 答疑，跨 AZ 副本 |
| 观测层 | Trace + 转化率/解决率看板 | POC 与生产共用指标体系 |

### 3.3 POC 计划（1 分钟）

- 范围：2 个高频场景、1000 条真实分布工单；
- 成功指标（**POC 前书面约定**）：自助解决率 ≥X%、答案合规率 ≥Y%、单会话成本 ≤Z 元；
- 时间盒：4 周，第 2 周中期对齐。

### 3.4 商务收尾（30 秒）

"POC 通过后，生产化清单是安全加固、监控告警、SLA 约定——算力和沙箱可以打包成年框，规模上去后单位成本还有优化空间。要不要我们先约一次技术对齐会？"

- [ ] 5 分钟宣讲脱稿 ×2 遍

## 4. 影响三类团队的话术（JD 第 5 条）

同一方案，三种语言：

| 对象 | 关心什么 | 切入话术 |
|------|---------|---------|
| **基础设施团队** | 隔离、成本、稳定性、运维归属 | "沙箱把逃逸面收到 microVM 级；密度上去后单会话成本降 X%；开源自建的补丁和扩容责任在你们 SRE，买我们责任边界清晰" |
| **工程团队** | 集成难度、API/SDK、可观测 | "E2B 兼容 SDK，你们现有 Agent 代码基本不用改就迁进来；Trace 和告警接你们现有监控" |
| **算法团队** | 模型效果、迭代速度、评测 | "沙箱提供干净的评测环境和黄金集回归；推理侧前缀缓存让你们多轮调参数不心疼成本" |

**收尾金句**："给管理层一句话——这是**用确定的方案预算，买一个能规模化的 Agent 生产线**。"

- [ ] 三类话术各读 3 遍，能随机应变切换

---

## 5. 竞品对话守则（客户已在看竞品时）

1. **不贬低**：先说出竞品的真优点（如 CubeSandbox 的 60ms 与 CoW 快照，见 [04 文档](04_沙箱技术_面试备考.md)）——懂行才有信任。
2. **换维度**：从"功能对比"拉到"**责任边界与总体成本**"（谁打内核补丁、谁扛规模、谁负合规）。
3. **给验证方法**："出对比 POC，用数据说话"——永远把对话推进到下一步动作。
