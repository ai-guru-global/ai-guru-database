# 模拟项目 1：政企 RAG 知识库交付

## 项目背景

**客户**：某省级政府办公厅  
**需求**："我们要一个 AI 助手，能帮公务员快速查询政策文件、写公文、做数据分析"  
**环境**：内网、信创服务器（鲲鹏 CPU + 麒麟 OS）、无 GPU  
**预算**：80 万  
**周期**：3 个月  

## 实战步骤

### Week 1-2: Discovery

```
Day 1-3: 客户现场调研
├── 访谈 3 个处室（秘书处、法规处、信息处）
├── 了解当前工作流：查政策 → 手动检索 PDF → 人工撰写
├── 识别痛点：政策文件 10 万+ 份，检索效率极低
└── 确定核心场景：政策问答 + 公文辅助写作

Day 4-5: 技术环境评估
├── 服务器：2 台鲲鹏 920（64 核/256GB/无 GPU）
├── OS：麒麟 V10 SP3
├── 网络：纯内网，无互联网访问
└── 数据库：达梦 DM8

Day 6-10: 需求文档与方案设计
├── 完成需求规格文档
├── 定义成功指标：检索准确率 >85%、响应时间 <3s
├── 输出技术方案：轻量级 RAG + 国产模型 + 离线部署
└── 签订合同
```

### Week 3-4: Architecture

```
技术选型：
├── 模型：Qwen2.5-7B（GGUF 量化，CPU 推理）
├── 推理引擎：llama.cpp
├── 向量数据库：Milvus（ARM64 适配版）
├── Embedding：BGE-large-zh（CPU 推理）
├── 框架：FastAPI + LangChain
├── 前端：Vue.js（内网 npm 离线包）
└── 部署：Docker Compose（3 个服务）

架构图：
```

### Week 5-8: Delivery

```
Week 5-6: 快速原型
├── 搭建 Docker 环境
├── 导入 1000 份政策文件到 Milvus
├── 接入 Qwen 模型
├── 开发核心 API（查询 + 生成）
└── 给客户 demo → 反馈"检索不够准"

Week 7-8: 迭代优化
├── 优化文档切分策略（按条款切分）
├── 增加混合检索（向量 + 关键词）
├── 增加 BGE-Reranker 重排序
├── 检索准确率从 60% → 88% ✅
└── 再次 demo → 客户满意

Week 9-10: 试点部署
├── 选择秘书处 5 人试用
├── 部署监控（Prometheus + Grafana）
├── 收集反馈 → 增加"历史记录"功能
└── 培训 5 位种子用户

Week 11-12: 生产上线
├── 全量 10 万份政策文件导入
├── 性能测试：100 并发，响应 <2s ✅
├── 安全加固：审计日志 + 访问控制
├── 全处 50 人培训（半天）
├── 交付运维手册 + 用户手册
└── 客户验收签字 ✅
```

### 后续 Iteration（Month 4+）

```
Month 4:

└── 签第二期合同（30 万）

Month 5-6:
├── 扩展到其他 3 个处室
```


## 心得总结

1. **信创环境是最大挑战**：ARM64 + 麒麟 OS 兼容性问题多，预留了 30% 调试时间
2. **快速原型是关键**：2 周出 demo 建立了客户信任，后续沟通顺畅
3. **种子用户选得好**：秘书处的 5 人变成了内部推广者
4. **别一上来就全量**：先用 1000 份文档验证可行性，再扩大到 10 万份

---

> **这个项目的核心价值**：不是技术多先进，而是**真正解决了公务员"找不到政策文件"的痛点**。一个能节省每天 30 分钟的工具 = 每年为 50 人节省 6000+ 小时。
