## TL;DR

内容库已完成「从 0 到 1」：结构成立、数据足够厚、质量门在跑。下一阶段的核心矛盾不再是「有没有内容」，而是三个问题：

1. **它只存在于本机（未 push）**——单点故障风险；
2. **读者进来只能翻文件夹**——没有检索与订阅形态；
3. **手工更新流程依赖每次全量操作**——没有固化成可重复的节奏。

---

## P0 立即做（保住资产）

### 1. Push 到远端 + 仓库描述 — 状态：✅ 2026-09-04
一个定位「数据库」的项目长期不 push 是唯一不可接受的风险。仓库描述决定搜索与 star 转化。

### 2. 格式校验脚本固化入库 + CI — 状态：✅ 2026-09-04
把每次沉淀后的临时校验（frontmatter 完整性、月份/日期倒序、无重复月份、双链不断、大事记逐节倒序）固化为 `tools/scripts/validate.py`，加 `md-lint` workflow。任何人（包括未来 agent 会话）提交坏格式会被自动拦截——「结构即价值」从约定变成制度。

### 3. 内容许可声明 — 状态：✅ 2026-09-04
代码 MIT（已有 LICENSE），内容 **CC BY-SA 4.0** 双许可，README 声明。不声明则转载无授权路径，而时间线库的传播恰恰靠转载。

## P1 一个月内（让库被看见）

### 4. RSS/Atom 订阅源 — 状态：✅ 2026-09-04
`tools/scripts/build_feed.py` 从 `_2026大事记.md` / `_2025大事记.md` 生成 `feed.xml`；周更 workflow 自动重建并提交。零构建链。对新闻沉淀库，RSS 是零成本获得持续读者的通道。

### 5. 静态阅读站（轻路） — 状态：✅ 2026-09-04
GitHub Pages（actions/deploy-pages，artifact 部署，无需 Jekyll）：`build_feed.py` 同步产出 `site/index.html`（大事记索引 + 指向仓库 blob 的链接）。`tools/cmd/web` 的 Go 方案需要运行时，读者不会为此装环境——重路等有真实流量再说。

### 6. 回溯 `_2025大事记.md` — 状态：✅ 2026-09-04
47 条线索的时间线已覆盖 2023–2025，但年份索引只有 2026，读者从大事记进来看不到「演进脉络」。从现有线索时间线回抽 2025 年重点事件建 `_2025大事记.md`，把时间线库的纵深直接翻倍。规则：只抽取线索中已有条目、跳过 ⚠️ 存疑、沿用既有链接、不引入新事实。

## P2 一个季度内（结构与可持续性）

### 7. 更新节奏 — 状态：✅ 2026-09-04（每 3 天定时任务，可随时删除）
流程已验证可重复（同步 → 并行沉淀 → 大事记 → 校验 → 提交）。选定定时自动化方案：每 3 天自动执行一轮，人工只审 diff。手动节奏仍可随时切换（暂停任务即可）。

### 8. 消化待核实清单 — 状态：🔄 进行中（2026-09-04 首轮核验 Grok 4.6 / SpaceX 双案）
「宁可漏收不可错收」的信用需要用行动兑现。每轮更新带核验配额（2–3 条），核完移入正文或证伪删除，避免清单变成烂尾页。

### 9. 内容补盲区 — 状态：✅ 2026-09-04（新建 3 条）
- `基础模型/微软MAI.md`——微软是唯一没有模型线索的巨头（MAI-Thinking-1 等被两轮沉淀报告「无处安放」）；
- `评测与基准/ARC系列基准.md`——ARC-AGI 系列在本期新闻反复出现（o3 → GPT-6 Astra 99.9%）；
- `评测与基准/ArtificialAnalysis指数.md`——第三方评测事实上的行业记分牌（Code Arena、智能指数）。

### 10. 降低共建门槛 — 状态：✅ 2026-09-04
- 每个 `_index.md` 末尾加「候选线索（待建）」清单（素材在 mirror 里躺着，列出名字就是贡献者路标）；
- `.github/ISSUE_TEMPLATE/` 新闻线索投稿表单（标题/URL/日期/建议线索），维护者只做筛选；
- README 顶部「最近大事」段由周更 workflow 自动刷新，让路过的人第一屏看到库是活的。

## 优先级总览

| 优先级 | 事项 | 成本 | 回报 |
|---|---|---|---|
| P0 | push + 仓库描述 | 5 分钟 | 消除单点故障 |
| P0 | 校验脚本入库 + CI | 半天 | 质量保障制度化 |
| P1 | 内容许可声明 | 半小时 | 传播合规 |
| P1 | RSS 订阅源 | 半天 | 持续读者通道 |
| P1 | `_2025大事记.md` 回溯 | 一次会话 | 纵深翻倍 |
| P2 | 静态阅读站（轻路） | 1 天 | 读者体验 |
| P2 | 更新节奏（定时） | 决策题 | 新鲜度 SLA |
| P2 | 待核实清单消化 | 持续小额 | 信用兑现 |
| P3 | 盲区线索 + 共建入口 | 零散 | 生态起步 |

一句话：**先 push，再让内容有「出口」（RSS/站点/2025 回溯），最后把「更新这件事本身」产品化。**
