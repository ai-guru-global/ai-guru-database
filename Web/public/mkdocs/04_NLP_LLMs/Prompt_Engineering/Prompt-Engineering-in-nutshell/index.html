    Prompt Engineering 速成指南

    🎯 目标：掌握如何编写有效的提示词，让大语言模型产出高质量结果。

    🤔 什么是 Prompt Engineering？

    Prompt Engineering = 设计输入文本，引导 AI 产出期望结果的技术。

    flowchart LR
    subgraph 差的提示
        Bad["写点东西"] --> BadOut["（随机、不可控的输出）"]
    end

    subgraph 好的提示
        Good["你是技术写作专家。<br/>为初级开发者写一篇<br/>300字的 Git 入门指南，<br/>包含3个常用命令示例"] --> GoodOut["（精确、高质量的输出）"]
    end

    类比： - 提示词就像点菜单 - 越具体，厨师越知道你要什么 - 差的提示 = "来点吃的" → 不知道给你什么 - 好的提示 = "一份中辣的宫保鸡丁，少油少盐" → 精确满足需求

    🧩 提示词基本结构

    完整提示词模板

    flowchart TB
    subgraph 提示词结构
        Role[角色设定<br/>你是谁] --> Context[背景信息<br/>上下文]
        Context --> Task[具体任务<br/>做什么]
        Task --> Format[输出格式<br/>怎么呈现]
        Format --> Constraints[约束条件<br/>限制和要求]
        Constraints --> Examples[示例<br/>期望的样子]
    end

### 1. Zero-Shot（零样本）

直接描述任务，不给示例。

```mermaid
flowchart LR
    Task[任务描述] --> LLM[大模型]
    LLM --> Output[输出]

将以下英文翻译成中文，保持专业术语准确：

"""

    适用场景：简单任务、模型能力足够时

    flowchart LR

    Pattern --> Task[新任务]
    Task --> Output[输出]

"""

## 🔧 高级技巧

### 1. 自我一致性 (Self-Consistency)

多次生成，选择最常见的答案。

```mermaid
flowchart TB
    Q[问题] --> R1[回答1: A]
    Q --> R2[回答2: A]
    Q --> R3[回答3: B]
    Q --> R4[回答4: A]
    Q --> R5[回答5: A]
    R1 --> Vote[投票]
    R2 --> Vote
    R3 --> Vote
    R4 --> Vote
    R5 --> Vote
    Vote --> Final["最终答案: A (4/5)"]

    import openai
from collections import Counter

def self_consistency(prompt, n=5):
    """多次生成并投票选择最佳答案"""
    responses = []

    for _ in range(n):
        response = openai.OpenAI().chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.7  # 需要一定随机性
        )
        responses.append(response.choices[0].message.content)

    # 投票选择最常见答案
    counter = Counter(responses)
    return counter.most_common(1)[0][0]

    4. 提示词链 (Prompt Chaining)

    将复杂任务分解为多个步骤。

    flowchart LR
    Input[用户输入] --> P1[提示1: 理解意图]
    P1 --> P2[提示2: 收集信息]
    P2 --> P3[提示3: 生成方案]
    P3 --> P4[提示4: 格式化输出]
    P4 --> Output[最终结果]

    def complex_task_chain(user_request):
    # 步骤 1：理解意图
    intent = call_llm(f"""
    分析用户请求的意图，返回：
    - 任务类型
    - 关键需求
    - 隐含假设

    用户请求：{user_request}
    """)

    # 步骤 2：收集所需信息
    info = call_llm(f"""
    基于以下意图分析，列出完成任务需要的信息：
    {intent}
    """)

    # 步骤 3：生成解决方案
    solution = call_llm(f"""
    基于以下信息，生成详细解决方案：
    意图：{intent}
    所需信息：{info}
    """)

    # 步骤 4：格式化输出
    final = call_llm(f"""
    将以下方案整理成用户友好的格式：
    {solution}
    """)

    return final

    多轮对话管理

    def build_messages(system_prompt, conversation_history, user_message):
    """构建消息列表"""
    messages = [
        {"role": "system", "content": system_prompt}
    ]

    # 添加历史对话（保留最近 N 轮）
    for turn in conversation_history[-10:]:
        messages.append({"role": "user", "content": turn["user"]})
        messages.append({"role": "assistant", "content": turn["assistant"]})

    # 添加当前用户消息
    messages.append({"role": "user", "content": user_message})

    return messages

    提示词模板管理

    # prompts/templates.py
from string import Template

class PromptManager:
    """提示词模板管理器"""

    def __init__(self):
        self.templates = {}

    def register(self, name: str, template: str):
        """注册模板"""
        self.templates[name] = Template(template)

    def render(self, name: str, **kwargs) -> str:
        """渲染模板"""
        if name not in self.templates:
            raise ValueError(f"未知模板: {name}")
        return self.templates[name].safe_substitute(**kwargs)

# 使用
manager = PromptManager()

manager.register("code_review", """
你是代码审查专家。请审查以下 $language 代码：

```$language
$code

    关注点：$focus_areas """)

    prompt = manager.render( "code_review", language="python", code="def foo(): pass", focus_areas="安全性、性能" )

    A/B 测试提示词

    import random
from dataclasses import dataclass

@dataclass
class PromptVariant:
    name: str
    template: str
    weight: float = 0.5

class PromptABTest:
    def __init__(self, variants: list[PromptVariant]):
        self.variants = variants
        self.results = {v.name: {"count": 0, "scores": []} for v in variants}

    def get_variant(self) -> PromptVariant:
        """根据权重随机选择变体"""
        weights = [v.weight for v in self.variants]
        return random.choices(self.variants, weights=weights)[0]

    def record_result(self, variant_name: str, score: float):
        """记录结果"""
        self.results[variant_name]["count"] += 1
        self.results[variant_name]["scores"].append(score)

    def get_stats(self):
        """获取统计数据"""
        stats = {}
        for name, data in self.results.items():
            if data["scores"]:
                stats[name] = {
                    "count": data["count"],
                    "avg_score": sum(data["scores"]) / len(data["scores"])
                }
        return stats

# 使用
test = PromptABTest([
    PromptVariant("v1_concise", "简洁版提示词...", 0.5),
    PromptVariant("v2_detailed", "详细版提示词...", 0.5),
])

variant = test.get_variant()

    ⚠️ 常见问题与解决方案

    flowchart TB
    subgraph 问题诊断
        P1[输出太长/太短] --> S1[明确指定长度<br/>字数/段落数]
        P2[格式不对] --> S2[提供示例<br/>明确格式要求]
        P3[答非所问] --> S3[重述问题<br/>分解任务]
        P4[幻觉/编造] --> S4[要求引用来源<br/>提供上下文]
        P5[拒绝回答] --> S5[重新措辞<br/>解释用途]
        P6[输出不稳定] --> S6[降低temperature<br/>Few-shot]
    end
    问题 症状 解决方案
    输出太长 啰嗦、重复 "用3句话总结"、"不超过100字"
    输出太短 过于简略 "详细解释"、"至少500字"
    格式错误 不符合要求 提供示例、JSON Schema
    答非所问 偏离主题 重述问题、分解任务
    幻觉 编造信息 "仅使用提供的信息"、RAG
    拒绝回答 过度谨慎 重新措辞、解释合法用途

    💡 最佳实践

    1. 明确具体

    # ❌ 差
prompt = "写个报告"

# ✅ 好
prompt = """
写一份关于 2024 年 Q1 销售业绩的分析报告，包含：
1. 执行摘要（100字以内）
2. 数据概览（表格形式）
3. 趋势分析（3个关键发现）
4. 改进建议（可操作的3条建议）

语气：专业但易懂
长度：800-1000字
"""

    2. 使用分隔符

    prompt = """
请翻译以下文本：

---原文开始---
Hello, world!
---原文结束---

翻译成：中文
风格：正式
"""

    3. 给模型"思考时间"

    # 让模型先分析再回答
prompt = """
问题：{question}

请按以下步骤回答：
1. 首先，分析问题的关键点
2. 然后，考虑可能的答案
3. 最后，给出你的最终答案和理由
"""

    4. 迭代优化

    flowchart LR
    V1[版本1] --> Test1[测试]
    Test1 --> Analyze[分析结果]
    Analyze --> V2[版本2]
    V2 --> Test2[测试]
    Test2 --> Improve[持续改进]

    📚 核心要点

    flowchart TB
    A[好的提示词 = 好的结果] --> B[结构清晰<br/>角色+任务+格式+约束]
    B --> C[具体明确<br/>避免模糊表述]
    C --> D[提供示例<br/>Few-shot 效果更好]
    D --> E[迭代优化<br/>测试、分析、改进]
    E --> F[版本管理<br/>记录和比较不同版本]
