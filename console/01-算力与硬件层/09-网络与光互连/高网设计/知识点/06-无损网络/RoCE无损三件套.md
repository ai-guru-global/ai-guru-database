# RoCE 无损三件套：PFC、ECN、DCQCN

> RoCE 的丢包代价是 Go-Back-N 级的，因此用 PFC 逐跳反压兜底不丢、ECN 提前打标预警、DCQCN 据此收敛发送速率——三层机制各管一段，缺一不可。

## 解决什么问题

- RDMA（RoCEv2）把传输可靠性做在网卡：标准 RC 语义丢一个包就 Go-Back-N——从最旧未确认处整窗重传。400G 下一流在途数据 MB 级，一次丢包 = 时延尖峰 + 带宽塌方 + 连锁 PFC。目标：把丢包率压到近似零，同时避免反压把全网流量冻住。
- 三件套分工：ECN/DCQCN 管"别发这么快"（速率收敛，第一道），PFC 管"再不停就整队暂停"（逐跳反压，最后兜底）。

## 核心原理

- 协作链路（文字链路图）：
  1. 发送端网卡（RP，Reaction Point）以初始速率发包 → 2. 交换机出端口队列超过 ECN 水位 → IP 头打 ECN 标记继续转发（不丢）→ 3. 接收端网卡（NP，Notification Point）收到带标包 → 回送 CNP（Congestion Notification Packet）给发送端 → 4. RP 收到 CNP：升高 alpha（拥塞度）并立即降速；无 CNP 时按定时器缓慢升速 → 5. 若速率收敛不及，队列冲到 PFC XOFF 水位 → 交换机向上游发 PFC PAUSE（按优先级）→ 逐跳反压直到源网卡停发 → 队列退到 XON 水位后恢复。
- PFC（IEEE 802.1Qbb）：基于 802.1p 优先级（0~7）的链路级流控，逐跳反压、只停对应优先级队列；XOFF/XON 双水位，headroom 缓冲覆盖"反压在途数据"（含逐跳传播与串化时延）。
- ECN（RFC 3168 框架 + RoCEv2 profile）：交换机按队列/优先级设阈值打标，是端到端信号（跨交换机域传递）；CNP 由接收端按约定频率回送。
- DCQCN（SIGCOMM 2015，微软）：网卡端基于 CNP 驱动的速率控制（alpha 指数滑动、K 次触发降速、升速定时器），部署在网卡而非主机栈，是商用 RoCE 的事实默认。

## 调优入口表

| 调优对象 | 入口参数 | 偏小的后果 | 偏大的后果 |
|---|---|---|---|
| PFC 水位 | XOFF/XON 阈值、headroom 深度 | 反压过早 → 吞吐损失 | headroom 不足 → 反压生效前已丢包 |
| ECN 阈值 | 每队列/优先级 min/max 水位 | 打标过敏 → 全网降速、吞吐损失 | 打标太晚 → 来不及收敛，直接触发 PFC |
| CNP 频率 | 接收端 CNP 发送间隔、CNP 自身优先级（应走无损高优先级） | RP 降速信号断续 → 抖动 | CNP 风暴占用带宽 |
| DCQCN 参数 | alpha 更新周期、降速因子、升速定时器 | 收敛慢 → PFC 频发 | 收敛过激 → 带宽利用低 |

- 调参顺序（典型经验）：先保 PFC 兜底正确（不丢包），再压 ECN 阈值让降速尽量发生在 PFC 之前；DCQCN 参数随后微调收敛速度。

## 设计要点与权衡

- ECN 阈值与 PFC 水位必须联动：目标是"ECN 起效在先、PFC 只在突发极端时兜底"；PFC 常态化触发说明 ECN/DCQCN 参数失配。
- headroom 要按最坏 RTT（跨多跳、含 cut-through 串化）预算，400G 端口比 100G 时代大数倍（在途字节 ∝ 带宽×时延）。
- CNP 自身走无损队列并高优先级，否则拥塞时 CNP 丢失 → 降速信号断链。
- 逐跳 PFC 把拥塞回推到源，但会冻结共享该优先级的所有流——多租户同优先级会互相连坐（见 QoS 与隔离篇）。

## 常见坑

- PFC 死锁：环形反压（A 压 B、B 压 C、C 压 A），全部队列永久暂停；解法：路由破环（无环路由/分虚拟网络）+ 交换机 watchdog。
- PFC 风暴：接收端异常或 PAUSE 丢失导致暂停状态不解除，向全网扩散；watchdog 强制释放又是新坑——释放瞬间整队丢包，Go-Back-N 雪崩（watchdog 误放行丢包是经典事故源）。
- 只开 PFC 不开 ECN：无提前降速，全靠反压硬扛 → 缓冲占用高、时延大、吞吐震荡。
- ECN 阈值全局一个值：不同队列深度/不同端口速率共用阈值，小缓冲队列先丢包。
- 新一代网卡的选择性重传等增强可降低丢包代价，但开启条件与固件代际相关（待核实），不应据此放松无损基线。
