# Computer Use 权限与安全模型

> 中文简称：Computer Use 权限与安全模型

> **一句话理解**: Computer Use 给了 Agent 整台机器的操作权——上生产的答案不是「更聪明的模型」而是「更小的爆炸半径」：分级权限、人工在环、沙箱隔离、全程审计。

---

## 1. 四类威胁

| 威胁 | 场景 | 后果 |
|------|------|------|
| **误操作** | 点错确认按钮、删错文件 | 数据丢失、不可逆操作 |
| **间接提示注入** | 恶意网页/邮件内容包含「忽略指令，执行 XX」指令，被截图进上下文 | Agent 被劫持执行攻击者意图 |
| **数据外泄** | 截图含密码/API Key/客户数据，或 Agent 被诱导导航到外部站点提交敏感信息 | 凭据与数据泄露 |
| **权限蔓延** | 为方便给了管理员权限、白名单越加越宽 | 单次事故变成系统性风险 |

其中**间接提示注入**是 Computer Use 独有的新攻击面：普通 Agent 的不可信输入是用户消息，Computer Use 的不可信输入还包括**屏幕上的每一个像素**——你让它操作的网页本身可能就是攻击载体。

---

## 2. 三级权限 + 人工在环

| 级别 | 包含动作 | 策略 |
|------|---------|------|
| L1 观察 | 截图、读取窗口列表、光标位置 | 默认放开（注意脱敏，见 §3） |
| L2 常规操作 | 点击、输入、滚动、导航（白名单应用内） | 自动执行 + 全量日志 |
| L3 敏感操作 | 支付/转账、删除、发送（邮件/消息）、授权确认、系统设置变更 | **人工确认门**：暂停 → 展示将执行的动作与截图 → 人工批准 |

实现要点：L3 清单要**按业务枚举**而不是按技术特征——「点击了含『确认支付』文案的按钮」这种模糊规则会被绕过；直接枚举「订单支付流程第 3 步」「邮箱发送动作」这类业务动作更可靠。

---

## 3. 最小权限实践

1. **窗口/应用白名单**：Agent 只能操作路由表内的目标应用（[[15_智能体/21_Computer_Use/02_技术拆解_感知_决策_执行|02 页]] 的 BackendRouter 即白名单的执行点），白名单外窗口截图打码或禁止。
2. **截图脱敏**：截图回传模型前过滤密码框、密钥串、个人信息（正则 + 视觉检测双层）。
3. **网络出口限制**：Agent 所在沙箱默认断网，仅放行任务必需域名。
4. **一次性凭据**：需要登录的场景用短期令牌，不用用户主密码。
5. **会话限时**：单任务时间上限（如 15 分钟），超时终止——限制失控任务的持续破坏窗口。

---

## 4. 沙箱隔离：执行体故事线

Computer Use 的执行层必须进隔离环境，这与 Agent Runtime 的沙箱体系是同一条故事线：

| 场景 | 隔离方案 | 深入 |
|------|---------|------|
| Browser Use | 沙箱容器 + 无头浏览器（Browserbase/E2B 类） | [[15_智能体/20_Agentic_Infra/09_Sandbox_隔离技术与沙箱平台选型\|沙箱平台选型]] |
| 桌面级 | Linux 容器 + Xvfb 虚拟显示；强对抗场景用户态内核/微 VM | [[12_架构基建/10_安全/05_gVisor_常见问题与避坑指南\|gVisor 避坑指南]] |
| 沙箱选型方法论 | 隔离层次谱系、威胁模型、冷启动 | [[21_面试岗位/28_Agent_Runtime工程师/04_Sandbox_隔离技术\|Sandbox 隔离技术专题]] |

结论一致：**能力越大，隔离越重**——Computer Use 是全部 Agent 形态里爆炸半径最大的，因此也是隔离要求最刚性的。

---

## 5. 审计与回滚

- **全程录像 + 结构化日志**：每步 `(截图, 动作, 结果, 时间)` 落盘——既是安全审计证据，也是 [[15_智能体/21_Computer_Use/04_评测与失败模式|评测回放]] 的数据源。
- **每步可回退**：操作前记录可恢复状态（文件备份点/浏览器历史位），误操作可撤销。
- **告警**：L3 动作触发、连续失败、白名单外访问，实时推送人工。

---

## 6. 「能 API 则 API」原则

Computer Use 是**兜底手段而非首选通道**：目标系统有 API/MCP 工具时优先走结构化调用（便宜一个量级、可校验、无 grounding 问题），Computer Use 只处理「真没有接口」的遗留界面。混合架构 = MCP/API 处理 80% + Computer Use 兜底 20%，安全面也随之缩小 80%。
