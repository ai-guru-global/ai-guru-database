# LLMs in Production

> 中文简称：LLM 生产化实战

> **一句话理解**: LLM 生产化实战指南,覆盖从原型到生产的全流程——把"能跑的 Demo"变成"能扛住流量、控得住成本、看得见质量"的生产系统。

## 书籍概述

### 作者与出版背景

《LLMs in Production》由 Manning 出版社出品,属于 Manning 经典的"in Production"系列(同系列还包括 *Microservices in Production*、*Machine Learning in Production* 等),延续该系列"以工程实践为核心、以真实生产场景为驱动"的写作风格。本书面向 2024-2026 年 LLM 应用大规模落地这一时代背景,聚焦"原型 → 生产"这一最难的工程鸿沟。

### 本书定位

在 LLM 工程书籍谱系中,本书的定位是:

- **不是**讲 Prompt 技巧的书(那是 [[90_学习/05_参考资料/books/02_prompt_engineering_for_llms]] 的领域)
- **不是**讲架构哲学的书(那是 [[90_学习/05_参考资料/books/15_ai_engineering_huyen]] 的领域)
- **而是**讲"上线之后怎么办"的工程实操手册:部署、监控、成本、安全、评估的完整闭环

它与 [[90_学习/05_参考资料/books/10_designing_ml_systems_huyen]] 形成"传统 ML 系统设计 → LLM 时代生产化"的进阶关系,与 [[90_学习/05_参考资料/books/05_llm_engineers_handbook]] 形成"架构设计 → 工具链落地"的互补关系。

## 核心内容

### Part 1 — 生产化的认知转变

#### Ch 1: 从 Demo 到 Production

- **核心命题**: Demo 与生产系统的差距不是 10%,而是 10 倍工作量
- **关键差异**:
  - Demo 关心"能不能跑",生产关心"在 99.9% 情况下都能跑"
  - Demo 用 5 个测试用例,生产要面对 100 万种用户输入
  - Demo 不计成本,生产每个 Token 都要算账
- **生产化的四个维度**: 可靠性(Reliability)、可观测性(Observability)、经济性(Cost)、安全性(Safety)
- **常见反模式**: "Jupyter Notebook 直接上线"、"没有评估就发布"、"Prompt 硬编码在代码里"

#### Ch 2: LLM 系统的生产架构

- **典型架构分层**: 接入层 → 路由层 → 推理层 → 缓存层 → 监控层
- **同步 vs 异步**: 实时聊天用同步流式,批处理任务用异步队列
- **多模型路由**: 根据任务复杂度路由到不同模型(小模型/05_大模型/专用模型)
- **降级策略**: 主模型不可用时的 Fallback 链路设计
- **关键决策点**: 自建推理 vs 调用 API、单区域 vs 多区域部署

### Part 2 — 部署与推理优化

#### Ch 3: 部署架构选型

- **三种部署模式对比**:

| 模式 | 适用场景 | 优势 | 劣势 |
|------|----------|------|------|
| **云 API**(OpenAI/Anthropic) | 早期产品、流量波动大 | 零运维、按需付费 | 数据出域、成本不可控 |
| **托管推理**(Bedrock/Vertex) | 中型企业、合规要求 | 平衡便利与可控 | 锁定云厂商 |
| **自建推理**(vLLM/TGI) | 大规模、高敏感数据 | 完全可控、成本可优化 | 运维复杂、需 GPU 资源 |

- **边缘部署**: 小模型在手机/IoT 设备上的本地推理(如 llama.cpp、MLX)
- **混合部署**: 敏感数据本地处理 + 通用任务调用云 API
- **容器化**: Docker + Kubernetes 的 LLM 服务编排
- **GPU 调度**: 多模型共享 GPU、动态批处理、抢占式调度

#### Ch 4: 推理性能优化

- **量化(Quantization)**:
  - INT8 / INT4 / FP8 量化的精度-性能权衡
  - GPTQ、AWQ、GGUF 等主流量化方案
  - 量化对长尾任务质量的影响评估
- **KV Cache 优化**:
  - PagedAttention(vLLM 的核心创新)
  - Prefix Caching(共享前缀的 KV 复用)
  - KV Cache 量化
- **批处理策略**:
  - Continuous Batching(连续批处理)
  - 动态批大小调整
  - 优先级队列
- **推测解码(Speculative Decoding)**: 小模型草稿 + 大模型验证
- **延迟优化指标**: TTFT(Time To First Token)、TPS(Tokens Per Second)、E2E Latency

#### Ch 5: 缓存与成本控制

- **语义缓存(Semantic Cache)**: 用 Embedding 相似度命中缓存
- **精确缓存**: 基于 Prompt Hash 的精确匹配
- **多级缓存架构**: 客户端缓存 → CDN → 语义缓存 → 模型推理
- **缓存失效策略**: TTL、版本化 Prompt、模型升级时的缓存清理
- **成本归因**: 按用户/功能/会话维度的 Token 成本追踪

### Part 3 — 评估与质量保障

#### Ch 6: LLM 评估体系

- **评估的三个层次**:
  - **组件级**: Prompt、检索器、工具调用各自的评估
  - **端到端**: 整体输出质量评估
  - **业务级**: 用户满意度、转化率、留存率
- **自动评估方法**:
  - 基于规则的评估(正则、JSON Schema 校验)
  - LLM-as-a-Judge(用强模型评估弱模型)
  - 参考答案对比(BLEU/ROUGE 的局限与替代)
- **评估数据集构建**:
  - 黄金集(Golden Set)的标注与维护
  - 对抗集(Adversarial Set)的设计
  - 真实流量采样与脱敏
- **回归测试**: Prompt/模型变更时的自动化质量门禁

#### Ch 7: 在线评估与 A/B 测试

- **在线指标设计**:
  - 显式反馈(👍/👎、评分)
  - 隐式反馈(会话长度、复制率、重试率)
- **A/B 测试框架**:
  - 流量切分与统计显著性
  - LLM 输出的高方差对样本量的影响
  - 多臂老虎机(MAB)在 Prompt 优化中的应用
- **影子部署(Shadow Deployment)**: 新模型/新 Prompt 与生产并行运行,只对比不上线
- **Canary 发布**: 渐进式流量切换与自动回滚

### Part 4 — 监控与可观测性

#### Ch 8: LLM 可观测性体系

- **三大支柱在 LLM 场景的扩展**:
  - **Logs**: 完整的 Prompt + Response 追踪(注意脱敏)
  - **Metrics**: 延迟、Token 用量、错误率、质量分
  - **Traces**: 多步 Agent/RAG 链路的端到端追踪
- **LLM 专属指标**:
  - 幻觉率(Hallucination Rate)
  - 拒答率(Refusal Rate)
  - 工具调用成功率
  - 上下文截断率
- **追踪工具**: LangSmith、Langfuse、Phoenix(Arize)、Helicone
- **告警设计**:
  - 质量分突降告警
  - 成本异常告警(单日 Token 用量超阈值)
  - 错误模式聚类告警

#### Ch 9: 数据飞轮与持续改进

- **生产数据的价值**: 真实流量是最宝贵的评估与训练数据
- **数据飞轮闭环**:
  1. 收集生产 Prompt/Response
  2. 自动质量打分
  3. 低分样本人工复审
  4. 加入评估集 / 微调数据集
  5. 改进 Prompt 或微调模型
  6. 上线验证 → 回到第 1 步
- **隐私合规**: PII 脱敏、数据保留策略、用户授权
- **主动学习(Active Learning)**: 优先标注模型最不确定的样本

### Part 5 — 安全与合规

#### Ch 10: LLM 安全攻防

- **Prompt Injection 攻防**:
  - 直接注入 vs 间接注入(通过 RAG 文档)
  - 防御策略: 输入过滤、指令隔离、输出验证
  - 红队测试(Red Teaming)方法论
- **越狱(Jailbreak)防护**: 系统提示加固、输出审查
- **数据泄露防护**:
  - 训练数据提取攻击
  - 上下文中的敏感信息泄露
  - 系统提示泄露
- **输出安全**:
  - 有害内容过滤
  - 事实性校验(关键场景)
  - 结构化输出的 Schema 强制

#### Ch 11: 合规与治理

- **主要法规框架**: EU AI Act、GDPR、中国《生成式 AI 服务管理暂行办法》
- **企业级治理**:
  - 模型使用审计日志
  - 数据分类分级
  - 模型卡片(Model Card)与系统卡片
- **可解释性需求**: 高风险场景的决策可追溯
- **供应商管理**: 第三方模型 API 的合规审查

### Part 6 — 成本与运营

#### Ch 12: 成本工程

- **成本结构分析**:
  - 推理成本(Input/Output Token 计价差异)
  - 基础设施成本(GPU、存储、网络)
  - 人力成本(标注、评估、运维)
- **优化杠杆**(按 ROI 排序):
  1. **模型路由**: 80% 简单任务用小模型,可降本 60%+
  2. **缓存**: 高重复率场景命中率可达 30-50%
  3. **Prompt 压缩**: 删除冗余上下文,降本 20-40%
  4. **批处理与异步**: 非实时任务用 Batch API(通常 50% 折扣)
  5. **量化与自建**: 大规模场景下自建推理可降本 50%+
- **成本预算与配额**: 用户级、功能级、组织级配额管理

## 关键概念与公式

### 核心指标定义

```
TTFT (Time To First Token) = 用户发送请求 → 收到第一个 Token 的时间
TPS  (Tokens Per Second)   = 流式输出阶段的 Token 生成速率
E2E  Latency               = 完整请求的端到端响应时间
Cost Per Query             = (Input Tokens × Pin + Output Tokens × Pout) / 请求数
Quality Score              = Σ(评估维度分数 × 权重)
```

### 缓存命中率与成本节省

```
有效成本 = 原始成本 × (1 - 缓存命中率 × 缓存折扣)
例: 命中率 40%, 缓存折扣 90% → 有效成本 = 原始成本 × 64%
```

### 模型路由的期望成本

```
E[Cost] = Σ P(任务路由到模型i) × Cost(模型i, 任务)
路由优化目标: min E[Cost] s.t. Quality ≥ Quality_threshold
```

### 推理吞吐与 GPU 利用率

```
Throughput = Batch Size × Tokens per Request / Latency
GPU Utilization = 实际计算时间 / 总时间
理想目标: GPU Utilization > 80%, P99 Latency < SLA
```

## 成本优化速查

按 ROI 排序的成本优化手段：

| 优化手段 | 预期降本 | 实施难度 | 适用场景 |
|----------|----------|----------|----------|
| **模型路由** | 60%+ | 中 | 任务复杂度差异大 |
| **语义缓存** | 30-50% | 中 | 高重复率查询 |
| **Prompt 压缩** | 20-40% | 低 | 上下文冗长 |
| **Batch API** | 50% | 低 | 非实时任务 |
| **量化** | 20-30% | 中 | 自建推理 |
| **自建推理** | 50%+ | 高 | 大规模、稳定流量 |

### 成本优化决策树

```
流量规模如何?
├─ 小（<10万请求/月）→ 云 API + 缓存 + Prompt 压缩
├─ 中（10万-1000万）→ 模型路由 + Batch + 缓存
└─ 大（>1000万）→ 评估自建推理 + 量化 + 全面优化
```

**核心原则**: 先做低难度高 ROI 的优化（路由、缓存、压缩），再考虑高投入的方案（自建推理）。优化前后都要量化收益，避免盲目优化。
