# Process Reward Models (PRM) 深度解析

> 中文简称：Process Reward Models 深度解析

## 一句话理解

结果奖励模型（ORM）只知道"答案对不对"，而过程奖励模型（PRM）知道"第 3 步推理错了"——这种步骤级的反馈是教会模型复杂推理的关键。

---

## 一、信用分配问题 (Credit Assignment Problem)

### 1.1 问题的本质

推理过程示例：
  步骤 1: 设 x = 5  ✓
  步骤 2: y = x + 3 = 8  ✓
  步骤 3: z = y × 2 = 20  ✗ (应该是 16)
  步骤 4: 最终答案 = z + 1 = 21  ✗

ORM 的视角:
  "最终答案是 21，但正确答案是 17 → 错了"
  → 不知道哪一步错了

PRM 的视角:
  "步骤 1: +0.2, 步骤 2: +0.2, 步骤 3: -0.5, 步骤 4: -0.1"
  → 精确知道问题出在步骤 3

**信用分配问题**: 当一个多步推理的最终答案错误时，如何确定是哪个步骤导致的？

### 1.2 为什么这很重要

ORM 训练的问题:
  模型生成 100 步推理 → 答案错误 → 全部 100 步被同等惩罚
  → 模型不知道哪里错了，学习效率低

PRM 训练的优势:
  模型生成 100 步推理 → PRM 指出第 42 步错了
  → 模型只修正第 42 步，其他 99 步保留
  → 学习效率提高 100 倍

MCTS 搜索中的差异:
  ORM: 只能剪枝整个分支（因为最终答案已知错误）
  PRM: 可以在中间步骤就剪枝（因为步骤 10 已经被判定错误）
  → 搜索空间减少 10-100 倍

## 二、PRM 的架构设计

### 2.1 基本架构

PRM 的核心设计:
- 复用 LLM 的 backbone 作为 encoder
- 添加 value head 输出每步的奖励值
- 输入: 推理步骤序列
- 输出: 每个步骤的奖励分数 [r_1, r_2, ..., r_n]

### 2.2 两种 PRM 变体

**PRM-Last**: 只评估每个步骤的"最终正确性"
 对于步骤 k，评估: "如果从这里继续推理，最终能答对吗？"
 优点: 容易实现（只需要最终答案）
 缺点: 信用分配仍然模糊

**PRM-Step**: 评估每个步骤本身的"质量"
 对于步骤 k，评估: "这个步骤本身是否正确/合理？"
 优点: 精准定位错误步骤
 缺点: 需要步骤级标注

## 三、PRM 的训练方法

### 3.1 人工标注法

流程:
1. 收集大量推理问题
2. 让模型生成多条推理路径
3. 人工标注每个步骤的正确性 (✓ / ✗ / ?)
4. 用标注数据训练 PRM

成本: 每条推理路径约 $5-10，需要专家标注者

### 3.2 自动标注法 (Math-Shepherd)

核心思想: 用蒙特卡洛 rollout 自动估计每个步骤的价值。

对于步骤 k，从该步骤出发做多次随机 rollout。
如果大多数 rollout 最终答对，则步骤 k 是好的。

奖励 = 成功 rollout 的比例

优势: 不需要人工标注，可大规模自动生成
劣势: 需要大量计算，只在答案可自动验证的领域有效

### 3.3 对比学习法

核心思想: 学习区分"好步骤"和"坏步骤"。

构造正负样本对:
  正样本: "x = (13 - 5) / 2 = 4" (正确步骤)
  负样本: "x = 13 - 5 = 8" (错误步骤)

训练 PRM 给正样本高分、负样本低分。

负样本构造策略:
1. 错误类型采样: 收集常见的推理错误
2. 对抗生成: 用另一个模型生成"看似合理但错误"的步骤
3. 扰动法: 在正确步骤上做微小修改

## 四、PRM vs ORM 深度对比

### 4.1 训练成本

| 维度 | ORM | PRM |
|---|---|---|
| 数据标注 | 只需最终答案 | 需要每步标注 |
| 标注成本 | 低 | 高 |
| 自动标注 | 容易 | 困难 |
| 数据量 | 100K 即可 | 需要 500K+ |

### 4.2 训练效果

OpenAI 实验结果 (MATH 数据集):
 基线 (无奖励模型): 准确率 12%
 ORM (结果奖励模型): 准确率 39% (+27)
 PRM (过程奖励模型): 准确率 78% (+66)
 PRM + Best-of-N: 准确率 85% (+73)

结论: PRM 的效果是 ORM 的 2 倍以上

原因: PRM 能区分"好推理"和"坏推理"，而 ORM 只能区分"好答案"和"坏答案"

### 4.3 与 MCTS 的结合

PRM 在 MCTS 中的三个作用:
1. Selection: 优先扩展 PRM 评分高的节点
2. Expansion: PRM 评分低的节点直接剪枝
3. Evaluation: 结合 PRM（步骤质量）和 ORM（最终结果）

## 五、PRM 的工程实践

### 5.1 模型大小选择

实验发现:
  PRM-7B  → MCTS 准确率 72%
  PRM-13B → MCTS 准确率 78% (+6)
  PRM-34B → MCTS 准确率 81% (+3)
  PRM-70B → MCTS 准确率 82% (+1)

Sweet spot: 13B-34B

### 5.2 推理加速

优化策略:
1. 量化: PRM 用 INT8，精度损失 < 1%，速度提升 2×
2. 批处理: 同时评估多个候选步骤
3. 缓存: 相同步骤的 PRM 评分缓存复用

### 5.3 领域适配

通用 PRM vs 专用 PRM:
  通用 PRM: 跨领域推理，准确率中等
  数学专用 PRM: 代数/几何/微积分，准确率高
  代码专用 PRM: 16_编程/算法，准确率高
  科学专用 PRM: 物理/化学/生物，准确率高

建议: 如果资源允许，为每个主要领域训练专用 PRM。

## 六、前沿挑战

### 6.1 步骤边界的模糊性

问题: 模型的推理输出没有明确的"步骤"边界。

当前最佳实践: 在训练数据中用特殊 token 显式标记步骤边界。

### 6.2 累积错误 (Error Accumulation)

问题: 早期的小错误可能在后期被放大。

示例:
 步骤 1: x = 5 (正确)
 步骤 2: y = x + 2 = 7 (错误，应该是 +3)
 步骤 3: z = y × 2 = 14 (基于错误 y 的计算"正确")

PRM 对步骤 3 的评估困境:
 - 如果只看步骤 3 本身: "7 × 2 = 14" 是对的 → 高奖励
 - 但如果考虑步骤 2 的错误: 步骤 3 基于错误前提 → 应该低奖励

解决方案: 训练 PRM 时加入上下文感知。

### 6.3 创造性推理的评估

问题: PRM 在开放式任务上难以判断步骤的"正确方向"。

研究方向: 学习评估"策略价值"而非"步骤正确性"。

---

## 七、总结

| 维度 | ORM | PRM |
|---|---|---|
| 反馈粒度 | 粗（最终答案） | 细（每个步骤） |
| 训练成本 | 低 | 高 |
| 效果 | 中等 | 优秀 |
| 适用领域 | 所有可验证任务 | 尤其适合多步推理 |
| 与 MCTS 结合 | 弱 | 强 |
| 推荐场景 | 简单任务、资源受限 | 复杂推理、追求性能 |

实践建议:
- 如果做推理模型，PRM 几乎是必需的
- 可以从 ORM 开始，逐步引入 PRM
- 在数学/代码领域，自动标注 PRM 数据是可行的
