# 知识库（深潜库）模板与规范

> 适用对象：围绕一个**产业环节或知识领域**展开的系统化知识库（如 [`01-算力与硬件层/09-网络与光互连/高网设计/`](../01-算力与硬件层/09-网络与光互连/高网设计/README.md)）。
> 本文件定义它的定位、结构与台账纪律；证据时间线怎么写见 [`docs/线索模板.md`](线索模板.md)。

## 一、它和证据层的关系：三层下钻

工作台对一个细分领域提供三种深度的内容，各层职责不重叠：

| 层 | 载体 | 回答的问题 | 性质 |
|---|---|---|---|
| **节点**（拆解） | `console/chain.js` 节点页（拆解卡 + 运行时聚合） | 这个环节是什么、在产业链哪个位置、格局如何 | 结构与判断 |
| **线索**（证据） | `证据层/<主题>/<线索名>.md` 时间线 | 这个环节**发生过什么**、何时、谁说的 | 事实（带出处） |
| **知识库**（深潜） | `<层>/<NN-节点>/<领域名>/`（本模板） | 这个环节**如何工作**——知识点、厂家档案、各角色视角 | 系统知识（可含「待核实」标注） |

接线方式：知识库在对应主题下建**一张入口线索卡**（见第四节），证据层负责事件流，知识库负责体系；两边互链。深潜子库放在分层树的节点目录下，`build_console.py`（只读 `证据层/<主题>/*.md`）与 `validate.py`（只扫 `证据层/`）均不触达——改知识库不需要重建 `data.js`。

## 二、什么时候值得开一个深潜库

满足任一条再开，避免为开而开：

1. **证据时间线装不下**：该领域的核心内容是「怎么设计/怎么选型」而非「发生了什么」，时间线卡片频繁出现大段非事件性叙述；
2. **知识点可分域递进**：内容天然分成 5–10 个域（如需求→机内→跨机→拓扑→软件→运维→趋势），每域 3–8 篇；
3. **厂家档案成规模**：≥10 个厂家值得各开一页档案；
4. **多视角有真实差异**：架构师/采购/运维/投研看同一领域的关注点显著不同。

开库前先在对应主题 `_index.md` 的候选区或研判层确认需求，避免与既有线索卡重复。

## 三、目录与文件结构

```
<层>/<NN-节点>/<领域名>/
├── README.md            # 定位、篇数统计、阅读路径、全库索引、编写约定、口径基线
├── 知识点/<NN-域名>/     # 两位数编号保证递进顺序；每篇一个知识点
│   └── <知识点名>.md
├── 厂家/<厂家名>.md      # 一厂一档；阵营/器件类可合并为群像档
└── 角度/<角色名>.md      # 一个角色视角一页（架构师/选型/采购/运维/投研…）
```

脚手架直接复制 [`docs/深潜库模板/`](深潜库模板/) 下的四个模板文件。命名沿用全库惯例：中文为主、专有名词保留英文。

## 四、统一篇目结构（frontmatter → 定位 → 主体 → 关联）

每篇 md 的骨架：

```markdown
---
层: 知识点|厂家|角度|拆解
域: <所在域/厂家/角度/总览>
更新: YYYY-MM-DD
---

# <标题>

> 一句话定位：这是什么、解决什么问题。

## <主体小节>（2–5 节，按模板）

## 关联
- [相对链接互链](../知识点/02-xxx/yyy.md)
```

**入口线索卡**（建在对应主题目录，如 [`证据层/推理与基础设施/GPU高速网络.md`](../证据层/推理与基础设施/GPU高速网络.md)）负责把台内流量接入深潜库：概述段声明分工（台内=证据时间线，知识库=系统知识），分析段给领域判断，正文链接指向深潜库 `README.md`。

## 五、事实纪律（与全库真实性门同源）

1. **数字必须带世代/年代锚点**（型号、带宽、日期、口径来源）；
2. **不确定就标「（待核实）」**，核实后删标注并更新 `更新:` 字段——宁可标注，不可编造；
3. 知识库内容是**公开产业常识的结构化整理**，不是新闻事实；与证据层严格分离，引用事件时链到线索卡而不是复述；
4. README 维护「口径基线」小节：建库时已核实的关键数字集中列出，避免散落各篇互相打架。

## 六、维护动作清单

- 新增知识点：放进对应两位数域目录，并在 README 全库索引与相关篇 `## 关联` 补链接；
- 新增厂家/角度：同理，一厂一档、一视角一页；
- 口径基线变动（如新一代规格发布）：改基线小节 + 受影响篇目同步，`更新:` 字段留痕；
- 深潜库不进 `data.js`、不进 sitemap——对外可见性由入口线索卡承担。
