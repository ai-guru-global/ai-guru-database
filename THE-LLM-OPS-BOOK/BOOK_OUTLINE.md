## 一、书名与定位

**书名（已定稿，2026-11-25）**：

《大模型运维指南：LLM-Ops 稳定性工程技术实战》

> 使用口径：正文统称「本书」；营销物料可单独使用副题《LLM-Ops 稳定性工程技术实战》。书名关键词即全书承诺——**「稳定性」是主轴**：第五篇（可靠性 SRE）为全书重心与试写样章所在，其余各篇均以稳定性视角收束（选型评稳定性、参数调优为稳定性、成本服务于稳定性）。

**定位一句话**：中文第一本以「稳定性工程」为主轴、系统覆盖「推理系统 → GPU 资源 → 可靠性 SRE → Agent 平台」全链路的大模型运维书——不讲训练、不讲调参，只回答「生产环境里怎么跑得稳、出了事怎么救、怎么让『稳』成为默认态」。

**三个差异化卖点**（写作与营销都围绕这三点）：

1. **稳定性主轴 + 全链路**：市面上 LLM 图书集中在原理与微调，运维侧无系统化中文书；本书以稳定性工程为主线贯穿推理、资源、SRE、Agent 四层——本库「中文最深的推理运维/Agent Runtime 深水区」优势直接转化。
2. **三件套范式**：每章配「故障场景 + 决策树 + 参数速查表」三件套——本库 37 性能专题验证过的可复用范式，读者拿来即用。
3. **面向 Agent 时代**：传统运维书写到推理服务为止；本书延伸到 Agent Runtime/沙箱/记忆基础设施——超前 6–12 个月窗口。

## 二、目标读者与前置

| 读者画像 | 占比预估 | 核心诉求 |
|----------|---------|---------|
| SRE / 系统运维转型 LLM 运维 | 40% | GPU 资源模型变了，原有知识怎么迁移 |

| 转型求职者（培训业务联动） | 10% | 面试题库、能力模型 |

**前置要求**：Linux 与 K8s 基础、Python 阅读能力、用过任意 LLM API。不需要模型训练与数学背景（第 1 章把必要原理压进 20 页）。

## 三、与知识库的关系（素材规则）

- **素材映射**：每章标注 repo 素材页（约 60–70% 内容可从素材改写），新写比例 = 行业叙事 + 章间连贯性 + 案例。
- **三条红线**：① 素材映射到章后 repo 侧标 `book-used`（防双改漂移）；② 代际数字（vLLM 版本、模型名、带宽数字）付印前全部 web 复核；③ 行业研判不进书（归 console 仓库）。
- **体量目标**：正文 25–28 万字（28 章 × 8–10K 字），纸质 450–520 页；附录 3–4 万字。
