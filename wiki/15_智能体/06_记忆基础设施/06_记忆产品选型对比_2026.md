# Agent 记忆产品选型对比 2026

> 中文简称：Agent 记忆产品选型对比 2026

> **一句话理解**: 2026 年记忆有三条供给路线——平台原语（模型厂商自带）、中间件（Mem0/Zep/Letta/LangMem）、自建——本文按四条决策轴给你选型结论，并给出单用户本地场景（Mac M4 办公 Agent）的具体答案。

---

## 1. 候选名单与谱系

2025 H2 起记忆正在从「自建中间件」变成**平台标配原语**（详见 [[15_智能体/06_记忆基础设施/01_Agent_Memory_系统_2026|01 页 2026-10 前沿增量]]），候选名单因此分成三档：

- **平台原语**：Claude Memory Tool（file-based、client 维护）、OpenAI Memory / Memory API、ChatGPT 持久记忆。
- **中间件**：Mem0（检索层 + LLM-as-Judge）、Zep + Graphiti（时序知识图谱）、Letta（MemGPT 商业化，OS 式分层）、LangMem（LangChain 官方）、Cognee（ECL 流水线知识图谱）。
- **自建**：向量库 + 事实抽取 prompt + 自己的冲突消解（20 行到 2000 行皆可）。

---

## 2. 七方案对比表

| 方案 | 架构范式 | 检索 | 时序与冲突消解 | 多租户 | 部署运维 | 生态绑定 |
|------|---------|------|---------------|--------|---------|---------|
| **Mem0**（开源 + 商业托管） | 检索层：LLM-as-Judge 自动提取（ADD/UPDATE/DELETE/NOOP）+ 向量库 | 向量（可混 BM25） | 基础（UPDATE 覆盖） | user_id/agent_id 隔离 | 轻：Docker 起，或直接托管 | 框架无关 |
| **Zep + Graphiti** | 时序知识图谱（bi-temporal：事件时间 vs 摄取时间） | 图遍历 + 向量混合 | **强项**：事实演变追踪、时间推理 | 用户/会话隔离 | 重：图谱存储 + 服务 | 框架无关 |
| **Letta**（原 MemGPT） | OS 式分层：核心上下文 + 外部存储分页调度 | 分页换入 + 记忆搜索 | 记忆块可编辑 + 衰减 | 多 Agent 共享记忆块 | 中：agent server 自托管 | 自有 agent server |
| **LangMem** | 框架记忆层：semantic / episodic / procedural 三类 | 向量 + 存储 backend 可插拔 | 基础更新 | 依托 LangGraph state | 轻（随应用部署） | **LangChain/LangGraph 深度绑定** |
| **Cognee** | ECL 流水线（Extract-Cognify-Load）知识图谱 + 向量 | 图 + 向量 | 中（图谱结构化） | 项目级 | 中 | 框架无关 |
| **Claude Memory Tool** | 平台原语：file-based 记忆文件，client 读写维护 | 模型自主检索文件 | 客户端自管（无内建） | 自管 | **零服务依赖** | Claude API / Claude Code |
| **自建** | 向量库 + 抽取 prompt + 自写冲突消解 | 自定 | 自定（最容易做出差异化） | 自定 | 从 20 行脚本到一套服务 | 无 |

> 许可证与版本状态以各仓库当前 README 为准（本页 `review_by: 2027-01-25` 到期复核）。

## 3. 四条决策轴

**轴一：用户事实会随时间变吗？**（最重要的分叉）
会变（搬家、换团队、改偏好、项目状态流转）→ 选 **Zep/Graphiti** 路线：bi-temporal 让「上个月他说什么」和「现在他说什么」都可查，冲突消解是内建能力而非自研补丁。不变或很少变 → 任意方案，按轴二到轴四选。

**轴二：长对话需要 OS 式分层吗？**
单会话动辄数万 token、需要「虚拟内存」式自动换入换出 → **Letta**。对话短平快、重点是跨会话个性化 → 检索层方案足够。

**轴三：框架绑定可接受吗？**
已 deep-dive LangGraph → **LangMem** 顺路且状态模型天然整合。框架未定或多框架并存 → Mem0 / 自建保持自由身。

**轴四：运维预算多少？**
零运维 → 平台原语或商业托管（代价：锁定与数据出境评估）。可运维 → 开源自托管（数据主权完整）。单机本地 → file-based 自建是下限。

## 4. 本地千问办公 Agent 的选型结论

约束：单用户、Mac M4 24GB、隐私优先（数据不出机）、编排层未定。

| 候选 | 结论 | 理由 |
|------|------|------|
| **Mem0 OSS + 本地向量库** | ✅ 首选 | LLM-as-Judge 省掉自写抽取与四动作逻辑；配本地 Qdrant/Chroma + 本地 embedding 全程不出机；后续迁 Zep/托管都兼容（数据是文本事实） |
| file-based 自建 | ✅ 可行的更轻替代 | Claude Memory Tool 模式（markdown 记忆文件 + agent 读写），零服务依赖，M4 上最省资源；冲突消解靠模型自觉，规模大了会乱 |
| Zep/Graphiti | ❌ 暂不 | 图谱 + 服务的运维重量与单用户场景不匹配；事实追踪收益在多用户/长周期才显著 |
| LangMem | ⏳ 观望 | 绑定 LangGraph；若办公 Agent 编排最终选 LangGraph 再回头评估 |
| 平台原语 | ❌ 不适用 | 记忆数据出机，违背隐私约束 |

迁移预留：Mem0 存的是「原子事实文本」，未来升级到 Zep 只需重建图谱、不需要重写业务——这是选检索层路线做起点的重要原因。完整落地路径见 [[15_智能体/20_Agentic_Infra/04_本地千问办公Agent实战|本地千问办公 Agent 实战]]（先 Dify 快跑再自建的迁移思路与本结论衔接）。

## 5. 成本与运维速查

| 维度 | Mem0 OSS | Zep | Letta | 平台原语 |
|------|---------|-----|-------|---------|
| 写入成本 | 每条 1 次 LLM 判定调用 | 抽取 + 图谱写入 | 分页调度（模型内） | 模型内建 |
| 检索延迟 | 向量检索，毫秒级 | 图 + 向量混合，十毫秒级 | 模型内换页，无额外 RTT | 模型内建 |
| 额外组件 | 向量库 1 个 | 图存储 + API 服务 | agent server | 无 |
| 数据主权 | 完整（自托管时） | 完整（自托管时） | 完整 | 归厂商 |
| 适合规模 | 单用户 → 中型多租户 | 中型 → 大型多租户 | 长对话重度场景 | 已在该平台生态的团队 |
