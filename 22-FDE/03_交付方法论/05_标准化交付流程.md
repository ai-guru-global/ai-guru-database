# FDE 标准化交付流程（DADI）

## DADI 方法论概述

```
DADI = Discovery → Architecture → Delivery → Iteration
```

这是 FDE 项目的标准生命周期，从第一次接触客户到持续迭代优化。

---

## Phase 1: Discovery（发现）- 1~2 周

### 目标
把"模糊的客户需求"转化为"清晰的项目定义"

### 关键活动

**1. 业务场景梳理**
- 客户当前工作流是什么？
- 痛点在哪里？（时间、成本、质量、风险）
- 理想状态是什么？

**2. 利益相关方识别**
```
决策者：谁能签合同/批预算？
使用者：谁每天用这个系统？
影响者：谁的意见会影响决策？
反对者：谁可能阻碍项目？
```

**3. 成功指标定义**
```
业务指标：效率提升 X%、成本降低 Y 万、用户满意度 Z
技术指标：可用性 99.9%、响应时间 <2s、准确率 >85%
交付指标：按时上线、培训完成、知识转移
```

**4. 数据与技术评估**
- 数据在哪？格式如何？质量如何？
- 客户现有 IT 环境（OS、网络、硬件）
- 集成点（需要对接哪些系统？）

**5. 风险评估**
- 技术风险、数据风险、人员风险、合规风险

### 产出物
- `01-discovery/requirements.md` - 需求规格
- `01-discovery/stakeholders.md` - 利益相关方地图
- `01-discovery/success-metrics.md` - 成功指标

---

## Phase 2: Architecture（架构）- 1~2 周

### 目标
把"项目定义"转化为"可执行的技术方案"

### 关键活动

**1. 技术选型**
- 模型选型（DeepSeek/Qwen/GPT/开源）
- 框架选型（LangChain/Dify/自研）
- 基础设施（裸机/Docker/K8s）

**2. 部署方案设计**
- 网络拓扑（内网/外网/混合）
- 高可用设计（是否要 HA？）
- 灾备方案（备份策略、恢复流程）

**3. 安全方案**
- 认证授权（SSO/LDAP 对接）
- 数据加密（传输 + 存储）
- 审计日志

**4. 应急预案**
- 模型不可用怎么办？
- 数据损坏怎么办？
- 硬件故障怎么办？

### 产出物
- `02-architecture/tech-selection.md` - 技术选型理由
- `02-architecture/architecture-diagram.png` - 架构图
- `02-architecture/security-design.md` - 安全方案

---

## Phase 3: Delivery（交付）- 4~8 周

### 目标
把"技术方案"转化为"可运行的生产系统"

### 三个阶段

**Stage 1: 快速原型（1-2 周）**
```
目标：让客户 1-2 周内看到东西
做法：用最简技术栈跑通核心流程
交付：一个能演示的最小可用版本
```

**Stage 2: 试点部署（2-4 周）**
```
目标：在真实环境中让部分用户试用
做法：选择 3-5 个种子用户，收集反馈
交付：生产级部署 + 监控 + 日志
```

**Stage 3: 生产上线（2-4 周）**
```
目标：全量用户正式使用
做法：性能优化、安全加固、文档完善
交付：生产系统 + 运维手册 + 培训
```

### 产出物
- `03-delivery/runbook.md` - 运维手册
- `03-delivery/test-report.md` - 测试报告
- `03-delivery/training-materials.md` - 培训材料

---

## Phase 4: Iteration（迭代）- 持续

### 目标
让系统持续进化，从"能用"到"好用"到"智能"

### 关键活动

**1. 反馈收集**
- 用户使用频率与行为分析
- 满意度调研（NPS）
- Bug 和 Feature Request 管理

**2. 数据飞轮**
```
用户使用 → 产生数据 → 反馈优化 → 更好用 → 更多使用
```

**3. 模型持续优化**
- Prompt 优化
- 知识库更新
- 模型微调（如果需要）

**4. 流程改进**
- 运维自动化
- 监控告警优化
- 成本优化

### 产出物
- `04-iteration/feedback-summary.md` - 反馈汇总
- `04-iteration/improvement-plan.md` - 改进计划

## DADI 检查清单

### Discovery ✅
- [ ] 业务场景文档完成
- [ ] 利益相关方地图完成
- [ ] 成功指标达成共识
- [ ] 数据评估完成
- [ ] 风险评估完成

### Architecture ✅
- [ ] 技术选型文档完成
- [ ] 架构图完成
- [ ] 安全方案完成
- [ ] 应急预案完成

### Delivery ✅
- [ ] 快速原型已演示
- [ ] 试点部署运行稳定
- [ ] 生产上线完成
- [ ] 运维手册交付
- [ ] 客户团队培训完成

### Iteration ✅
- [ ] 反馈收集机制运行
- [ ] 迭代计划制定
- [ ] 客户满意度 > 8/10

---

> **核心**：DADI 不是僵硬的流程，是思考框架。小项目可能 4 周走完，大项目可能 6 个月。但四个阶段的逻辑不变。
