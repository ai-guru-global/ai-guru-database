# AI 系统 A/B 测试完全指南 (A/B Testing for AI Systems)

> A/B 测试是 AI 系统上线前的最后一道质量关——从实验设计到统计分析，系统解析 AI 系统 A/B 测试的方法论和工程实践。

---

## 1. 概述 (Overview)

A/B 测试是一种随机对照实验，通过将用户随机分配到不同版本（A=对照组，B=实验组），比较新旧模型或策略的效果差异。它是 AI 系统从离线评估到在线验证的关键桥梁。

### 为什么 AI 系统需要 A/B 测试？

```
离线评估的局限:
  - 离线指标 ≠ 在线指标
  - 数据分布可能偏移
  - 无法捕捉用户行为反馈
  - 无法评估长期影响

A/B 测试的价值:
  - 真实用户环境验证
  - 统计显著性保证
  - 量化业务影响
  - 降低上线风险
```

### AI A/B 测试 vs 传统 A/B 测试

| 维度 | 传统 A/B 测试 | AI A/B 测试 |
|------|-------------|------------|
| **变量** | UI 设计、文案 | 模型、算法、策略 |
| **评估指标** | 点击率、转化率 | 准确率、延迟、用户满意度 |
| **样本需求** | 较少 | 较多（模型差异可能小） |
| **延迟影响** | 较小 | 可能显著（推理延迟） |
| **副作用** | 可能影响用户体验 | 可能产生有害输出 |

## 2. 实验设计 (Experiment Design)

### 2.1 实验类型

```
模型 A/B 测试:
  - 对照组: 当前生产模型
  - 实验组: 新训练模型
  - 比较: 在线指标差异

灰度发布 (Canary):
  - 小比例用户 (1-5%) 使用新模型
  - 监控关键指标
  - 逐步扩大比例

多臂老虎机 (MAB):
  - 动态调整流量分配
  - 优胜模型获得更多流量
  - 适合快速迭代

交错实验 (Interleaving):
  - 同一用户同时看到 A 和 B 的结果
  - 更灵敏，样本需求更少
  - 适合排序/推荐场景
```

### 2.2 指标设计

```
主要指标 (Primary Metric):
  - 直接衡量实验目标
  - 例: 推荐点击率、对话满意度、搜索相关性

护栏指标 (Guardrail Metrics):
  - 确保实验不会损害关键业务
  - 例: 响应延迟、错误率、用户流失率

AI 特定指标:
  - 模型质量: 准确率、F1、BLEU、ROUGE
  - 推理性能: TTFT、TPOT、QPS
  - 安全性: 有害输出率、幻觉率
  - 用户体验: 满意度评分、对话完成率
```

### 2.3 样本量计算

```
所需样本量:

  n = (Z_α/2 + Z_β)² · 2σ² / δ²

  Z_α/2: 显著性水平对应的 Z 值 (通常 1.96 for α=0.05)
  Z_β: 统计功效对应的 Z 值 (通常 0.84 for β=0.2)
  σ²: 方差
  δ: 最小可检测效应 (MDE)

例:
  - 基线点击率: 5%
  - 最小提升: 0.5% (相对提升 10%)
  - 显著性水平: 0.05
  - 统计功效: 0.8
  → 每组需要 ~30,000 用户

AI 系统特殊考虑:
  - 模型差异可能很小 → 需要更多样本
  - 延迟影响需要更长时间观察
  - 安全性指标需要更大样本
```

## 3. 流量分配 (Traffic Allocation)

### 3.1 分流策略

```
用户 ID 哈希:
  user_id → hash → mod N → 分配到实验组
  
  优点: 确定性、可复现
  缺点: 需要处理用户 ID

随机分流:
  随机数生成器决定分组
  
  优点: 简单
  缺点: 不可复现

分层分流:
  按用户特征分层，在每层内随机分流
  
  优点: 保证各组用户特征均衡
  缺点: 实现复杂
```

### 3.2 分流注意事项

```
1. 互斥实验 vs 正交实验
   - 互斥: 同一用户只能在一个实验中
   - 正交: 不同实验独立分流

2. 新用户 vs 老用户
   - 新用户行为不稳定
   - 建议分开分析或排除

3. 时间效应
   - 新奇效应: 用户对新功能暂时更感兴趣
   - 建议运行足够长时间 (至少 1-2 周)

4. 网络效应
   - 社交网络中用户行为相互影响
   - 需要聚类随机化
```

## 4. 统计分析 (Statistical Analysis)

### 4.1 假设检验

```
零假设 H₀: 新模型和旧模型没有差异
备择假设 H₁: 新模型优于旧模型

检验方法:
  - 比例检验 (z-test): 适用于点击率、转化率
  - t 检验: 适用于连续指标 (延迟、评分)
  - Mann-Whitney U: 非参数检验，不假设正态分布

p 值解释:
  - p < 0.05: 拒绝零假设，认为有显著差异
  - p ≥ 0.05: 无法拒绝零假设
```

### 4.2 置信区间

```
置信区间 = 点估计 ± 边际误差

例:
  - 点击率提升: 5.2% → 5.5%
  - 95% 置信区间: [0.1%, 0.5%]
  - 解释: 95% 置信度下，真实提升在 0.1% 到 0.5% 之间

实践建议:
  - 报告置信区间，不只是 p 值
  - 关注效应大小，不只是统计显著性
```

### 4.3 多重比较校正

```
问题: 同时检验多个指标或多个实验组，假阳性率膨胀

解决方案:
  - Bonferroni 校正: α' = α / m (m 为比较次数)
  - Benjamini-Hochberg (FDR): 控制错误发现率
  - 分层测试: 先测主要指标，再测次要指标
```

## 5. AI 特殊考量 (AI-Specific Considerations)

### 5.1 延迟影响评估

```
新模型可能更慢，影响用户体验:

监控指标:
  - P50 延迟: 中位数延迟
  - P95 延迟: 95 分位延迟
  - P99 延迟: 99 分位延迟
  - 超时率: 超过阈值的请求比例

护栏设置:
  - 延迟增加 > 10% → 暂停实验
  - 超时率增加 > 1% → 暂停实验
```

### 5.2 安全性评估

```
AI 系统可能产生有害输出:

监控指标:
  - 有害输出率: 有害内容的比例
  - 幻觉率: 事实错误的比例
  - 偏见指标: 不同群体的公平性

护栏设置:
  - 有害输出率增加 > 0.1% → 暂停实验
  - 任何严重安全事件 → 立即回滚
```

### 5.3 长期影响评估

```
短期指标可能误导:

例:
  - 推荐系统短期点击率提升
  - 但长期用户满意度下降 (信息茧房)

解决方案:
  - 运行实验足够长时间 (2-4 周)
  - 监控长期留存率
  - 定期回顾历史实验
```

## 6. 工程实现 (Engineering Implementation)

### 6.1 A/B 测试平台架构

```
用户请求
    │
┌───┴───┐
│ 分流层 │ → 决定用户属于哪个实验组
└───┬───┘
    │
┌───┴───┐
│ 模型层 │ → 加载对应模型版本
└───┬───┘
    │
┌───┴───┐
│ 日志层 │ → 记录请求和响应
└───┬───┘
    │
┌───┴───┐
│ 分析层 │ → 统计分析和报告
└───────┘
```

### 6.2 实验配置管理

```yaml
experiment:
  name: "new-rec-model-v2"
  description: "新推荐模型 A/B 测试"
  start_time: "2026-07-01T00:00:00Z"
  end_time: "2026-07-15T00:00:00Z"
  
  variants:
    - name: "control"
      weight: 50
      model_version: "rec-model-v1.2"
    - name: "treatment"
      weight: 50
      model_version: "rec-model-v2.0"
  
  metrics:
    primary: "click_through_rate"
    guardrail:
      - "latency_p95"
      - "error_rate"
      - "user_satisfaction"
  
  targeting:
    user_segment: "all"
    exclude_new_users: true
    min_requests: 100
```

## 7. 最佳实践 (Best Practices)

```
1. 明确假设
   - 实验前明确预期效果
   - 定义成功标准

2. 足够样本量
   - 使用样本量计算器
   - 避免过早下结论

3. 运行足够时间
   - 至少 1-2 周
   - 覆盖工作日和周末

4. 监控护栏指标
   - 设置自动告警
   - 准备回滚方案

5. 分层分析
   - 不同用户群体可能有不同效果
   - 新用户 vs 老用户

6. 记录实验
   - 记录假设、设计、结果
   - 建立实验知识库

7. 避免窥探效应
   - 不要频繁检查结果
   - 使用序贯检验或预注册
```
