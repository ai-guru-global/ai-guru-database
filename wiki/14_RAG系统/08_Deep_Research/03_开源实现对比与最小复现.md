# Deep Research 开源实现对比与最小复现

> 中文简称：Deep Research 开源实现对比

> **一句话理解**: 开源 Deep Research 有三条路——拿现成模型权重（Tongyi）、拿编排框架接自己的模型（GPT-Researcher / smolagents）、或读一个 400 行的单文件项目看懂全部循环——本文给你选型表、复现路线和一台 Mac 就能跑的最小清单。

---

## 1. 六大开源项目对比

| 项目 | 形态 | 核心思路 | 检索源 | 适合谁 |
|------|------|---------|--------|--------|
| **Tongyi DeepResearch** | 模型权重（30B-A3B MoE）+ 训练范式 | agentic mid-training + post-training，模型本身就会做研究 | 接入任意搜索工具 | 要自托管深度研究底座、数据敏感的团队 |
| **HuggingFace open-deep-research** | smolagents 编排 | CodeAgent 用写代码的方式调搜索/浏览工具 | 文本浏览器 + 搜索 API | 学 Agent 代码行动范式、GAIA 刷榜思路 |
| **LangChain Open Deep Research** | LangGraph 工作流 | 报告工作流：多轮循环 + 结构化章节产出 | 可插拔（Tavily 等） | 工程化集成、要接进 LangChain 技术栈 |
| **GPT-Researcher** | 编排框架 | 规划 Agent + 执行 Agent 分工，生态成熟、Web UI 完整 | 可插拔多引擎 | 快速搭产品原型、不想改底层循环 |
| **dzhng/deep-research** | 单文件（~400 行） | 递归式 clarify → search → synthesize，广度/深度两参数 | Tavily/类 Searx | 读源码入门——一晚上看懂全部逻辑 |
| **WebThinker / Search-R1** | 训练范式参考 | RL 训练模型「何时搜、搜什么、怎么读」 | 搜索即环境动作 | 复现训练而非部署的研究者 |

> 开源协议与活跃度以各仓库当前状态为准（本页 `review_by: 2027-01-25` 到期复核）。

## 2. 三档复现路线

### 2.1 最小版：递归研究循环（一晚上）

dzhng/deep-research 的骨架只有三个函数，是理解四阶段流水线（[[14_RAG系统/08_Deep_Research/02_架构拆解_四阶段流水线|架构拆解]]）的最佳教材：

```python
async def deep_research(query, breadth=4, depth=2):
    followups = generate_clarifications(query, k=3)      # 规划：先问 3 个澄清问题
    answers = collect_user_answers(followups)
    if depth == 0:
        return write_final_report(query, answers)        # 综合：递归到底，直接写报告
    results = await search_and_read(queries=query, n=breadth)   # 编排：并行检索 + 阅读
    learnings, urls = extract_learnings(results)          # 交叉验证：抽出论断与来源
    new_queries = generate_next_queries(query, learnings, n=breadth)  # 生成下一层查询
    sub_reports = await gather(
        deep_research(q, breadth, depth - 1) for q in new_queries
    )
    return write_final_report(query, learnings, sub_reports, urls)
```

注意它把「增益闸」简化成了**固定深度递归**（depth 2–3）——生产系统应换成架构拆解页 3.2 节的增益饱和检测，否则深了烧钱、浅了不饱和。

### 2.2 标准版：编排框架接自有模型

选 GPT-Researcher（产品化快）或 LangChain 版（工程集成好），把生成端换成自己的模型端点（vLLM/SGLang 起的本地服务或云 API），检索端换自有知识库 + 搜索 API 的混合。适合已有 RAG 基建（见 [[14_RAG系统/05_RAG生产实践/05_RAG生产实践_架构_深入分析|RAG 生产架构]]）想升级成研究能力的团队。

### 2.3 进阶版：Tongyi DeepResearch 权重自托管

用 vLLM 部署 30B-A3B 权重（激活仅 3B，单张 24GB 消费卡经量化后可跑推理），外接搜索工具即为完整的自托管 Deep Research。训练侧的 mid-training 范式复现成本高，先做推理侧部署，性价比最高。

## 3. Mac M4 本地最小复现清单

给本地千问办公 Agent（[[15_智能体/20_Agentic_Infra/04_本地千问办公Agent实战|实战文档]]）加一个「研究模式」的最小配置：

| 组件 | 选择 | 说明 |
|------|------|------|
| 模型 | Qwen 系列 32B 级（MLX/Ollama 量化） | 24GB 统一内存可跑；7B 级只够做综合、不够做规划 |
| 检索 | Tavily / Brave Search API（免费档） | DuckDuckGo 免费但限流严；本地知识库走已有向量库 |
| 编排 | 最小版递归循环（2.1 节）depth=2, breadth=4 | 一次任务 ≈ 12 次搜索 + 数十次模型调用 |
| 混合建议 | **规划用云端强模型，综合用本地模型** | 本地小模型做规划的分解质量明显不足，这是最常见的翻车点 |

**预期效果与限制**：简版报告（1–2 千字带引用）约 3–8 分钟；长任务漂移和引用幻觉会比商用产品明显——这正是最小实现省掉了交叉验证阶段的代价。

## 4. 一次任务的成本账

以标准版配置（depth 2 / breadth 4）跑一次中等问题量级任务的经验值（随模型定价与任务复杂度浮动一个数量级）：

| 项目 | 量级 | 说明 |
|------|------|------|
| 搜索调用 | 10–20 次 | 免费档 API 基本够单次任务 |
| 输入 token | 30 万–80 万 | 阅读内容占大头——笔记本外置是省 token 的第一杠杆 |
| 输出 token | 1 万–3 万 | 笔记 + 反思 + 报告 |
| 墙钟时间 | 3–15 分钟 | 并行度是主要变量 |
| 费用（云 API 模型） | 美元级 | 高频使用必须自托管或缓存（见 [[14_RAG系统/05_RAG生产实践/02_RAG_成本优化|RAG 成本优化]]） |

成本优化三板斧：笔记外置（重复阅读不进窗口）、URL 与内容指纹去重（省搜索费）、子报告缓存（相似子问题直接复用）。
