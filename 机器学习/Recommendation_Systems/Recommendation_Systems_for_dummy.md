# 推荐系统 - 小白版

> **一句话秒懂**: 推荐系统就像"一个超聪明的导购员"——它观察你看了什么、买了什么，然后猜出你可能还想要什么，并且猜得特别准。

---

## 你将学到什么

- 推荐系统是什么，为什么淘宝/抖音/Netflix 能"猜到"你喜欢什么
- 协同过滤："买这个的人还买了"
- 基于用户："和你口味像的人还喜欢"
- 基于内容："你喜欢这类，再给你推荐类似的"
- 混合推荐：把所有方法组合起来
- 真实世界中推荐系统的工作流程

---

## 为什么这个很重要？

打开你的手机：

- **淘宝** 首页的商品，好像都是你想要的
- **抖音** 刷着刷着停不下来，每条都好看到
- **网易云** 的每日推荐，怎么这么懂你的音乐品味
- **YouTube** 推荐的视频，总是忍不住点进去

**这不是魔法，这是推荐系统在工作！**

好的推荐系统：
- 让用户开心（找到喜欢的东西）
- 让平台赚钱（更多点击、更多购买）
- 让长尾内容被发现（不只是推荐热门）

## 核心概念

### 概念一：协同过滤 - "买这个的人还买了"

#### 生活中的例子

```
你去书店买书:

你: "我要买《三体》"
店员: "买《三体》的人，通常也会买《银河帝国》和《流浪地球》，
       要不要看看？"

你: "哇，我确实也想看这些!"

这就是协同过滤!
```

```
用户购买记录:
        书A  书B  书C  书D  书E
你       ✅   ❌   ❌   ❌   ❌
小明     ✅   ✅   ❌   ❌   ✅
小红     ✅   ✅   ✅   ❌   ❌
小刚     ❌   ✅   ✅   ✅   ❌

你买了书A
小明买了书A，还买了书B和书E
→ 推荐书B和书E给你!

因为"买了书A的人还买了书B和书E"
```

#### 简单来说

**协同过滤** = 利用"大家"的行为来推荐

核心逻辑：
1. 很多人买了 A 又买了 B
2. 你买了 A
3. 所以推荐 B 给你

#### 记住这个

> 协同过滤 = "大家觉得好的东西，大概率你也觉得好"
> 就像选餐厅：看大众点评评分高的去吃，通常不会踩雷

---

### 概念二：基于用户 - "和你口味像的人还喜欢"

#### 生活中的例子

```
找到和你一样的人:

你: 喜欢科幻、动作、悬疑
小明: 喜欢科幻、动作、爱情
小红: 喜欢科幻、动作、悬疑  ← 和你最像!
小刚: 喜欢喜剧、爱情、动画

你和红红口味最相似!
小红还喜欢一部你没看过的悬疑片
→ 推荐给你!（因为和你口味像的人喜欢）

  你    小红
  │      │
  │  相似度很高!
  │      │
  ▼      ▼
科幻  ←→  科幻  ✅ 一样
动作  ←→  动作  ✅ 一样
悬疑  ←→  悬疑  ✅ 一样
      →   悬疑片X  ← 推荐给你!
```

#### 简单来说

**基于用户的推荐** = 找到和你"品味最像"的人，推荐他们喜欢但你还没看过的

步骤：
1. 计算每两个用户之间的"相似度"
2. 找到和你最像的 K 个用户
3. 推荐他们喜欢但你还没接触的东西

#### 记住这个

> 基于用户 = "和你口味像的人，还喜欢什么？"
> 就像"你朋友推荐的电影，你大概率也会喜欢"

---

### 概念三：基于物品 - "喜欢这个的人还喜欢"

#### 生活中的例子

```
和已购商品找相似:

你买了: iPhone 15

iPhone 15 的"好兄弟"们:
  - AirPods Pro    ← 很多买 iPhone 的人也买了
  - iPhone 手机壳  ← 配套商品
  - Apple Watch    ← 生态产品
  - MagSafe 充电器 ← 同系列配件

→ 推荐这些给你!

  ┌─────────────────────────────┐
  │         买 iPhone 的人       │
  │   也买了什么？               │
  │                             │
  │   📱 iPhone   →  🎧 AirPods │
  │                →  ⌚ Watch   │
  │                →  📱 手机壳  │
  └─────────────────────────────┘
```

#### 简单来说

**基于物品的推荐** = "和你已购买/已喜欢的商品最相似的商品"

步骤：
1. 计算每两个商品之间的"相似度"（被同样的用户喜欢/购买）
2. 找到你喜欢的商品的"相似商品"
3. 推荐给你

#### 记住这个

> 基于物品 = "喜欢这个东西的人，还喜欢什么？"
> Amazon 就是用这个方法："购买此商品的用户也购买了..."

---

### 概念四：基于内容 - "先看你喜欢什么，再推荐类似的"

#### 生活中的例子

```
你看了这些电影:
🎬 《复仇者联盟》→ 类型: 动作, 科幻   特点: 超级英雄
🎬 《速度与激情》→ 类型: 动作, 犯罪   特点: 赛车
🎬 《星际穿越》  → 类型: 科幻, 冒险   特点: 太空

你的偏好画像:
  动作: ████████████  (很高!)
  科幻: ██████████    (高)
  冒险: ██████        (中)
  犯罪: ████          (有点)
  爱情: █             (低)
  喜剧: █             (低)

新电影来了:
🎬 《黑豹》→ 类型: 动作, 科幻  → 匹配度 95% → 推荐! ✅
🎬 《泰坦尼克号》→ 类型: 爱情, 剧情 → 匹配度 20% → 不推荐 ❌
🎬 《盗梦空间》→ 类型: 科幻, 动作 → 匹配度 90% → 推荐! ✅
```

#### 简单来说

**基于内容的推荐** = 分析你喜欢的东西有什么特征，然后推荐有类似特征的东西

步骤：
1. 给每个物品打上特征标签（类型、关键词、属性）
2. 根据你喜欢的东西，建立你的"偏好画像"
3. 找到和你的偏好画像最匹配的新物品

#### 记住这个

> 基于内容 = "你喜欢动作片，我就给你找更多动作片"
> 就像一个厨师知道你爱吃辣，就不断给你做辣菜

### 概念五：混合推荐 - "把所有方法组合起来"

#### 生活中的例子

```
一个完整的推荐过程:

  ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ 协同过滤  │   │ 基于内容  │   │ 热门推荐  │
  │ 推荐了:  │   │ 推荐了:  │   │ 推荐了:  │
  │ 书B 书E  │   │ 书F 书G  │   │ 书H 书I  │
  └────┬─────┘   └────┬─────┘   └────┬─────┘
       │              │              │
       ▼              ▼              ▼
  ┌─────────────────────────────────────┐
  │          融合 + 排序 + 去重          │
  │                                     │
  │  最终推荐: 书B, 书F, 书E, 书H, 书G  │
  └─────────────────────────────────────┘
```

```
为什么需要混合?

只用协同过滤的问题:
  ❌ 新书没人看过 → 无法推荐 (冷启动)
  ❌ 只推荐大家都喜欢的 → 缺少个性化
  ❌ 你只看到"大众口味" → 信息茧房

只用基于内容的问题:
  ❌ 只推荐类似的 → 没有惊喜
  ❌ 无法发现"意外的好东西"
  ❌ 需要准确的标签/描述

混合起来的好处:
  ✅ 协同过滤解决"发现意外好物"
  ✅ 基于内容解决"新物品冷启动"
  ✅ 热门推荐解决"新用户冷启动"
  ✅ 取长补短，效果最好!
```

#### 简单来说

**混合推荐** = 把多种推荐方法的结果融合在一起，取长补短

#### 记住这个

> 混合推荐 = "集思广益"
> 就像做决定时，听多个朋友的建议，综合考虑，做出最好的选择

## 推荐系统的完整流程

```
你在淘宝看到一个推荐的流程:

    你的行为
      │
      │  (你点击了"运动鞋")
      ▼
┌─────────────────────────────┐
│  第一步: 召回 (从百万商品中   │
│  选出几千个候选)              │
│                              │
│  ├ 协同过滤召回 → 500个商品   │
│ ├ 内容召回     → 300个商品   │
│ ├ 热门召回     → 200个商品   │
│ └ 标签召回     → 100个商品   │
│                              │
│  合并去重: ~1000个候选        │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│  第二步: 排序 (给每个候选     │
│  打分，选出最可能被点击的)     │
│                              │
│  商品A: 点击概率 0.85 ← #1   │
│  商品B: 点击概率 0.72 ← #2   │
│  商品C: 点击概率 0.68 ← #3   │
│  ...                         │
│  商品Z: 点击概率 0.12        │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│  第三步: 重排 (调整顺序)      │
│                              │
│  ├ 保证多样性 (不全是一种)    │
│  ├ 加入新品 (给新商品机会)    │
│  ├ 过滤已购买的              │
│  └ 加入广告 (商业需求)       │
│                              │
│  最终展示给你的 10~20 个商品  │
└─────────────────────────────┘
```

## 真实世界的例子

### 淘宝

```
淘宝怎么推荐商品?

你: 看了运动鞋，加了购物车但没买

淘宝分析:
  ├ 你的历史: 喜欢运动品牌，常买 Nike
  ├ 相似用户: 买了这双鞋的人还买了运动裤
  ├ 商品特征: 运动鞋 → 相关商品: 运动袜/运动裤
  ├ 热门趋势: 最近跑步装备很火
  └ 你的预算: 常买 300-800 元的商品

推荐结果:
  1. Nike 运动裤 (协同过滤 + 品牌)
  2. 运动袜 3 双装 (搭配推荐)
  3. 那双鞋的降价通知 (你关注过的)
  4. 跑步手环 (相似用户还买了)
  ...
```

### 抖音

```
抖音怎么推荐视频?

你: 看了一个猫咪视频，看了 2 遍，点了赞

抖音分析:
  ├ 看了 2 遍 → 很喜欢! (完播率高)
  ├ 点了赞 → 确认喜欢
  ├ 这个视频标签: 宠物/猫咪/搞笑
  └ 你的历史: 也喜欢美食视频

推荐策略:
  ├ 立刻推荐更多猫咪视频 (基于内容)
  ├ 推荐宠物类热门视频 (热门)
  ├ 推荐和你口味像的人喜欢的视频 (协同过滤)
  └ 偶尔穿插美食视频 (保持多样性)

结果: 你根本停不下来! 📱
```

### Netflix

```
Netflix 怎么推荐电影?

你: 看了《怪奇物语》全部季，给了 5 星

Netflix 分析:
  ├ 你喜欢: 科幻、悬疑、80年代怀旧
  ├ 看完了所有季 → 非常投入
  ├ 给了 5 星 → 非常满意
  └ 相似用户还看了: 《暗》、《黑镜》、《X档案》

推荐:
  ├ 《暗》 (相似用户推荐)
  ├ 《黑镜》 (科幻标签匹配)
  ├ 《伞学院》 (类型相似)
  └ "因为你看过怪奇物语" ← 推荐理由
```

## 方法对比：小白版

```
我该用哪种推荐方法?

你有用户行为数据吗? (购买/点击/评分)
  │
  ├── 有很多 → 协同过滤
  │     │
  │     ├── 用户少、商品多 → 基于物品
  │     └── 用户多、商品少 → 基于用户
  │
  ├── 有商品描述/标签 → 基于内容
  │
  ├── 都有 → 混合推荐 (最好!)
  │
  └── 都没有 → 热门排行榜 (最简单)
```

| 方法 | 一句话 | 优点 | 缺点 |
|------|--------|------|------|
| 协同过滤 | "大家都喜欢的，你也喜欢" | 发现意外好物 | 新物品冷启动 |
| 基于用户 | "和你像的人喜欢什么" | 个性化 | 用户多时计算慢 |
| 基于物品 | "和你买的相似的" | 物品稳定好算 | 只推荐相似的 |
| 基于内容 | "你喜欢这类，再来更多" | 新物品可推荐 | 信息茧房 |
| 混合推荐 | "综合所有方法" | 效果最好 | 复杂 |

## 代码示例：10 行代码写个推荐系统

```python
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

ratings = np.array([
    [5, 3, 0, 1],  # 用户1
    [4, 0, 0, 1],  # 用户2
    [0, 2, 4, 0],  # 用户3
])

similarity = cosine_similarity(ratings)
print(f"用户相似度:\n{np.round(similarity, 2)}")

user_id = 0
similar_users = np.argsort(similarity[user_id])[::-1][1:]
print(f"和用户1最像的用户: 用户{similar_users[0]+1}")

for item_id in range(ratings.shape[1]):
    if ratings[user_id, item_id] == 0:
        sim_users_who_rated = [
            u for u in similar_users 
            if ratings[u, item_id] > 0
        ]
        if sim_users_who_rated:
            pred = np.mean([ratings[u, item_id] for u in sim_users_who_rated])
            print(f"推荐物品{item_id+1}给用户1, 预测评分: {pred:.1f}")
```

## 冷启动：推荐系统的最大难题

```
冷启动问题:

新用户来了，我们什么都不知道:
  ❓ 不知道他喜欢什么
  ❓ 没有历史数据
  ❓ 没法和别人比较
  
  怎么办?
  ├── 先推荐热门商品 (大家都在买的)
  ├── 让他选兴趣标签 (你喜欢什么类别?)
  ├── 根据注册信息推测 (年龄/性别/地区)
  └── 用前几次点击快速学习

新商品上架，没人买过:
  ❓ 没有用户交互数据
  ❌ 协同过滤用不了
  
  怎么办?
  ├── 用商品描述/标签 (基于内容)
  ├── 推荐给相似商品的买家
  └── 给新商品一些曝光机会
```

## 常见问题

| 问题 | 回答 |
|------|------|
| 推荐系统需要多少数据？ | 至少几百个用户的交互数据才能做好 |
| 哪种方法最好？ | 混合方法通常效果最好 |
| 会推荐我不喜欢的东西吗？ | 会的，没有任何系统是 100% 准确的 |
| 为什么总推荐同类型的？ | 这是"信息茧房"，需要增加多样性 |
| 新用户怎么推荐？ | 热门排行 + 引导选择兴趣 |
| 推荐和搜索有什么区别？ | 搜索是你主动找，推荐是系统主动推 |
