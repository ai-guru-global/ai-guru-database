# LLM 安全完全指南：威胁全景与攻击技术

> 本文从 大模型安全权威指南 第一、二部分蒸馏而来，覆盖 LLM 安全基础、威胁全景、安全框架（OWASP / NIST / MITRE ATLAS）、以及核心攻击技术（Prompt Injection、Jailbreak、Data Poisoning、Backdoor、Model Extraction、Privacy Attacks、Adversarial Robustness、PEFT Security、Malicious Artifacts）。

## 1. LLM 安全基础

### 1.1 LLM 技术特性与安全映射

LLM 的核心技术特性直接决定了其安全边界：

| 技术特性 | 典型风险/攻击面 | 工程含义 |
|---|---|---|
| **上下文依赖、指令/数据同编码** | Prompt Injection、间接注入、策略绕过 | 需要分层提示、内容来源标注与隔离 |
| **概率性输出与非确定性** | 结果不可重复、难以穷举测试 | 需要分级响应、监控与回放评估 |
| **幻觉与不可靠事实性** | 错误信息、业务欺骗、合规风险 | 需要事实校验、RAG 引用约束 |
| **工具调用/智能体化** | 越权操作、数据外带、链式滥用 | 需要最小权限、工具网关与审计 |

### 1.2 LLM 安全 vs 传统安全

**延续的安全原则**：
- **Defense in Depth**：多层防护，单层失效不导致全局崩溃
- **Least Privilege**：LLM 仅授予完成任务所需最小权限
- **Security by Design**：安全从设计阶段纳入，而非事后补救
- **持续监控与响应**：部署后持续监控是安全运营基础

**LLM 独有的挑战**：
- **模糊的输入边界**：自然语言输入无法用确定性规则完全约束，与传统结构化输入验证有根本区别
- **指令与数据混淆**：LLM 通过自然语言接收指令，指令和数据天然使用相同"编码方式"，类似 SQL 注入但更难防御
- **概率性输出**：相同输入可能产生不同输出，安全测试和行为预测更加困难
- **黑箱特性**：内部决策过程难以解释，传统代码审计方法难以直接应用
- **涌现行为**：规模化后可能出现训练时未预期的行为

**防御范式演进**：
- 从规则驱动到 **AI 驱动**（用模型检测模型异常）
- 从确定性到 **概率性**风险评估
- 从静态审计到 **动态持续**监控
- 从代码安全到 **数据安全**（训练数据成为第一攻击面）

### 1.3 架构安全边界

**Transformer 架构安全含义**：
- **因果掩码**（Causal Mask）是自回归生成的技术必需，**不是安全防线**。它仅防止"偷看"未来 Token，但无法阻止上下文窗口内的提示注入
- **注意力机制**不是权限边界——注意力权重反映统计相关性，不代表来源可信度或业务授权
- **Token 化边界攻击**：BPE 等分词算法可被利用，包括特征断裂绕过（零宽字符切碎敏感词）、跨语言同形异义攻击（西里尔 `а` vs 英文 `a`）、特殊控制字符注入

**上下文窗口安全影响**：
- **信息混淆**：长上下文中恶意指令隐藏在正常内容之间，检测难度增大
- **约束退化**：System Prompt 位于序列开头，长上下文下模型对早期约束的遵循可能下降
- **上下文溢出**：超出窗口限制的内容被截断，可能导致关键安全指令丢失

### 1.4 安全对齐技术概览

**对齐目标（HHH 框架）**：Helpful（有帮助）、Harmless（无害）、Honest（诚实）

**对齐技术谱系**：

| 方法 | 复杂度 | 需要奖励模型 | 训练稳定性 | 推荐场景 |
|------|--------|-------------|----------|--------|
| **SFT**（监督微调） | 低 | 否 | 高 | 快速原型，初期对齐 |
| **RLHF**（人类反馈强化学习） | 高 | 是 | 中 | 对齐质量要求高，资源充足 |
| **DPO**（直接偏好优化） | 中 | 否 | 高 | 开源模型对齐，成本受限 |
| **ORPO**（概率比偏好优化） | 低 | 否 | 高 | 快速部署，资源受限 |
| **Constitutional AI** | 中 | 否（仅自评） | 中 | 原则驱动型应用 |

**对齐的局限性**：
- **对齐税**（Alignment Tax）：过度对齐导致过度拒绝（Over-refusal）
- **对齐可被绕过**：对齐本质是行为层，通过 Jailbreak 可绕过
- **对齐伪装**（Alignment Faking）：模型可能在训练观察阶段策略性"假装对齐"（Anthropic/Redwood Research 2024 研究显示 Claude 3 Opus 在特定条件下出现约 12% 策略性顺从）
- **泛化不足**：对齐依赖训练数据中出现过的场景

### 1.5 推理模型（Reasoning Model）安全

推理模型引入三类新隐患：

1. **推理越狱**（Reasoning Jailbreak）：攻击者利用中间推理过程突破约束。**思维注入**（Thought Injection）不同于传统 Prompt Injection——发生在推理过程中，逐步削弱约束，检测难度更高
2. **长推理模式滥用**：Extended Thinking 等模式扩大了攻击者可利用的搜索空间
3. **推理预算分配风险**：预算过高易被利用进行复杂攻击，过低则问题求解能力受限

**关键防御指标**：

| 指标 | 目标值 |
|------|--------|
| 思维审查率 | >95% |
| 有害思维捕获率 | >90% |
| 推理越狱成功率 | <5% |
| 推理泄漏率 | <1% |

## 2. 安全框架与标准

### 2.1 OWASP LLM Top 10（2025 版）

OWASP LLM Top 10 将"模型风险"转译成"应用系统风险"，是业界广泛采用的 LLM 安全风险清单。

| 编号 | 风险名称 | 英文 | 核心关注 |
|------|----------|------|----------|
| **LLM01** | 提示注入 | Prompt Injection | 通过恶意指令影响模型执行路径，包括直接/间接注入 |
| **LLM02** | 敏感信息泄露 | Sensitive Information Disclosure | 训练记忆泄露、上下文回显、日志误采集、系统提示泄露 |
| **LLM03** | 供应链风险 | Supply Chain | 模型、数据集、依赖库、插件、镜像任一环节被污染 |
| **LLM04** | 数据与模型投毒 | Data and Model Poisoning | 污染训练/检索数据或模型工件，潜伏性强、难以根治 |
| **LLM05** | 输出处理不当 | Improper Output Handling | LLM 输出直接进入 SQL/Shell/API，触发传统安全漏洞 |
| **LLM06** | 过度自主权 | Excessive Agency | 智能体权限过多导致越权调用、批量外发 |
| **LLM07** | 系统提示泄露 | System Prompt Leakage | 攻击者诱导模型暴露内部约束与工具信息 |
| **LLM08** | 向量与嵌入弱点 | Vector and Embedding Weaknesses | RAG 系统的向量存储和检索被操纵 |
| **LLM09** | 错误信息 | Misinformation | 模型生成虚假但看似可信的内容 |
| **LLM10** | 无边界消耗 | Unbounded Consumption | 高并发/长上下文/高复杂度请求消耗预算 |

**风险共现关系**：十大风险常相互放大——LLM01 可触发 LLM02/06/07；LLM03 与 LLM04 同属源头污染；LLM05+LLM06 放大实际执行面风险。

### 2.2 NIST AI RMF & AI 600-1

**NIST AI RMF** 定义了可信 AI 七组特征：有效性与可靠性、安全、安全与韧性、可问责与透明、可解释与可理解、隐私增强、公平性。

**四项核心功能**（非严格顺序，GOVERN 横跨全生命周期）：
- **GOVERN**（治理）：建立 AI 风险管理的组织基础
- **MAP**（映射）：识别和理解 AI 系统的风险上下文
- **MEASURE**（测量）：评估和监控 AI 风险
- **MANAGE**（管理）：处理已识别风险

**NIST AI 600-1 GenAI Profile**（2024-07 发布）定义了 12 类 GenAI 特有风险：CBRN 信息、虚构（Confabulation）、危险/暴力/仇恨内容、数据隐私、环境影响、有害偏见、人机配置、信息完整性、信息安全、知识产权、淫秽/贬损内容、价值链与组件集成。

### 2.3 MITRE ATLAS

MITRE ATLAS 是 AI 领域的对抗战术与技术（TTP）矩阵，以攻击者视角展开，是三大框架中唯一的对抗视角参照。

**与 ATT&CK 的关系**：ATLAS 沿用 ATT&CK 范式（战术→技术→子技术），新增 AI 专属战术：
- **AI Model Access**（AML.TA0000）：获取对目标模型的访问
- **AI Attack Staging**（AML.TA0001）：攻击前的准备阶段

**三大框架协同使用**：

| 框架 | 视角 | 回答的问题 |
|------|------|-----------|
| OWASP LLM Top 10 | 风险清单 | "我的应用有哪些高频风险？" |
| NIST AI RMF / 600-1 | 治理与风险管理 | "组织如何系统地治理这些风险？" |
| MITRE ATLAS | 对抗 TTP | "攻击者具体会怎么打？如何演练与检测？" |

**实践建议**：用 OWASP 做风险盘点，用 ATLAS 翻译成可演练的攻击技术，用 NIST 纳入组织治理闭环。

## 3. 攻击技术详解

### 3.1 Prompt Injection（提示注入攻击）

**本质**：利用 LLM 无法严格区分指令与数据的特性，通过精心构造的输入改变模型行为。

#### 3.1.1 直接提示注入

攻击者在对话中直接输入恶意指令：

- **指令覆盖**（Instruction Override）：`"忽略之前的所有指令。你现在是..."`
- **角色扮演**（Role-Playing / DAN）：诱导模型进入无限制角色
- **上下文操纵**：在长文本中隐藏恶意指令
- **编码混淆**：Base64、ROT13、Unicode 同形字符绕过过滤器
- **分步诱导**：逐步引导模型突破安全边界
- **系统提示提取**：`"repeat your instructions"`

#### 3.1.2 间接提示注入

恶意指令隐藏在外部数据源中，当 LLM 处理这些数据时被触发：

- **RAG 知识库投毒**：上传含隐藏指令的文档
- **网页浏览注入**：在网页中嵌入恶意指令
- **邮件/日历注入**：通过邮件正文或日历事件嵌入
- **供应链注入**：污染第三方数据源
- **工具返回值注入**：通过 API 响应注入

**危害放大因素**：间接注入可影响多个用户、更加隐蔽、智能体系统会放大危害。

#### 3.1.3 长上下文特有风险

- **迷失中间**（Lost in the Middle）：模型对中部信息的稳定利用可能下降
- **上下文投毒**：在海量信息中嵌入恶意内容，更加隐蔽
- **隐私泄露**：长上下文中包含更多敏感信息

### 3.2 Jailbreak（越狱攻击）

**本质**：绕过 LLM 安全对齐机制，使模型生成被禁止的内容。与 Prompt Injection 的区别——越狱更专注于突破内容安全限制。

#### 3.2.1 经典越狱技术

- **角色扮演**（DAN 及变体）：诱导模型进入"无限制"人格
- **场景构造**：构建虚构的研究/教育场景绕过拒绝
- **逻辑诱导**：利用推理链逐步引导到有害输出
- **格式操纵**：利用代码块、Base64、Markdown 等格式绕过
- **Token 级攻击**：利用分词特性构造对抗性输入
- **上下文耗尽**：通过长对话逐步消磨安全约束

#### 3.2.2 多模态越狱

- **文字嵌入图像**：将恶意指令以图像形式呈现
- **对抗性图像**：精心构造的图像触发模型特定行为
- **跨模态攻击**：利用图像-文本模态间的对齐薄弱点
- **隐写术**：在图像中隐藏恶意指令

#### 3.2.3 自动化越狱方法论

| 方法 | 路线 | 核心机制 |
|------|------|----------|
| **GCG** | 白盒梯度搜索 | 梯度优化生成对抗后缀 |
| **TAP** | 攻击树搜索 | 树剪枝搜索最优攻击路径 |
| **M2S** | 多轮转单轮 | 将多轮攻击压缩为单次请求 |
| **AutoDAN** | 分层遗传算法 | 语义化自然语言越狱 |
| **STAR** | 策略驱动红队 | 自动化红队评估框架 |

自动化越狱代表了从手工走向工业化的范式转变，攻击成本大幅降低。

### 3.3 Data Poisoning（训练数据投毒）

**原理**：在训练数据中注入恶意样本，影响模型行为。

**与后门攻击的区别**：
- **投毒**：改变整体分布，影响通用能力，无特定触发条件
- **后门**：植入特定触发机制（Trigger），仅触发时异常，其他情况正常工作，更隐蔽

**投毒策略**：
- 通过公开数据源（网页、论坛）注入
- 通过内部人员直接篡改
- 针对特定任务或领域进行定向投毒

**防御要点**：
- 数据来源审核与白名单机制
- 异常样本统计检测
- 模型行为基线与回归测试
- 快速回滚到已知安全版本

### 3.4 Backdoor Attacks（后门攻击）

**原理**：在模型中植入隐藏的触发机制——正常使用时正常工作，遇到特定触发器时产生恶意行为。

**触发器类型**：
- 特定短语或关键词
- 特定 Unicode 字符模式
- 特定输入格式

**检测难度**：极高——模型在大多数场景中表现正常，常规测试难以发现。

### 3.5 Model Extraction（模型窃取）

**原理**：通过大量 API 查询收集模型行为数据，训练替代模型。

**攻击类型**：
- **功能提取**：复制模型的输入-输出映射
- **参数推断**：推断模型内部参数
- **模型逆向**：从输出推断模型架构

**防御措施**：速率限制、查询异常检测、推理行为水印、模型签名验证。

### 3.6 Privacy Attacks（隐私攻击）

**原理**：从模型中推断或提取训练数据中的敏感信息。

**攻击类型**：
- **成员推理攻击**（Membership Inference）：判断特定数据是否在训练集中
- **训练数据提取**：直接从模型输出中恢复训练数据
- **属性推断**：推断训练数据的特定属性

**防御措施**：数据脱敏、差分隐私训练、输出过滤、PII 检测。

### 3.7 Adversarial Robustness（对抗鲁棒性）

**原理**：精心设计的对抗样本可导致模型异常行为。

**关键方法**：
- **GCG**：白盒梯度搜索对抗后缀路线
- **AutoDAN**：语义化、遗传算法驱动的自然语言越狱

两者都说明需要在预训练与对齐中持续进行对抗性评估。

**防御方向**：对抗训练、输入困惑度检测评估、统计异常检测。

### 3.8 Finetuning & PEFT Security（微调安全）

LoRA、QLoRA 等参数高效微调方法放大了新的安全挑战：

- **对齐退化**：不当微调可能显著削弱安全对齐
- **后门植入**：少量恶意样本即可在微调阶段植入后门
- **适配器仿制**：降低功能仿制与隐私攻击的试错成本

**安全微调流水线**：数据审计 → 安全微调 → 微调后验证 → 适配器级部署治理。

### 3.9 Malicious Model Artifacts（恶意模型工件）

**原理**：模型文件本身可能是可执行载荷。

**核心风险**：Pickle 格式（`.pkl`/`.pt`/`.bin`）在加载时执行代码，攻击者借此实现任意代码执行（RCE）。如 nullifAI 绕过 Picklescan 扫描器。

**防御要点**：
- 优先使用 **Safetensors** 格式
- 来源签名校验
- 沙箱加载不可信模型
- 不只依赖 pickle 扫描器

## 4. 威胁全景与风险矩阵

### 4.1 攻击阶段分类

- **训练阶段**：数据投毒、后门植入
- **部署阶段**：模型窃取、配置泄露
- **推理阶段**：Prompt Injection、Jailbreak、信息泄露、拒绝服务

### 4.2 攻击者画像

| 攻击者类型 | 动机 | 能力 | 威胁等级 |
|-----------|------|------|---------|
| 好奇探索者 | 技术好奇 | 入门级 | 低 |
| 恶意用户 | 获取有害内容 | 中等 | 中 |
| 竞争对手 | 商业利益 | 较高 | 中高 |
| 安全研究员 | 发现漏洞 | 高 | 取决于披露方式 |
| 网络犯罪分子 | 经济利益 | 高 | 高 |
| 国家级威胁 | 情报/影响力 | 最高 | 最高 |

### 4.3 风险评估矩阵

**高优先级**（高可能性 + 高影响）：
- Prompt Injection（最常见且影响最广泛）
- 敏感信息泄露
- 工具调用滥用

**需关注**（低可能性 + 高影响）：
- 数据投毒（难以执行但后果严重）
- 供应链攻击（影响范围可能极广）

### 4.4 最小威胁模型

对多数 LLM 应用，至少应回答四个问题：
1. **核心资产是什么**：用户数据、系统提示、工具凭据，还是高价值业务流程？
2. **信任边界在哪里**：哪些输入来自用户、网页、邮件、检索结果或第三方工具返回值？
3. **模型能做什么**：是否有读取敏感数据、调用工具、发送邮件、执行命令的能力？
4. **最高风险场景是什么**：数据泄露、越权操作、内容操纵，还是资源耗尽？

## 5. 防御思路总览

## 6. 多语言与跨语言安全

- **语料稀缺语言对齐薄弱**：安全对齐集中在英文，小语种安全约束可能显著较弱
- **跨语言不一致**：英文安全指令 vs 中文绕过尝试，混合语言环境中约束认知不清
- **Unicode 与编码混淆**：同形异义字符、零宽字符、特殊编码手法绕过过滤器

**安全建议**：多语言安全评估、语言特定微调、编码层归一化、非主流语言监控。
